## 三、分工声明:与 11-微服务 的 MQ 内容怎么分

本专题与微服务目录下的 MQ 内容**分工明确、互为补充**:

- **本专题(13-消息队列)是"可靠性深潜"视角**:回答"消息怎么才算不丢、重复了怎么办、积压了怎么治"。RabbitMQ/Kafka/RocketMQ 的机制与源码级细节都在这里。
- **[11-微服务/05 的 RocketMQ 篇](../11-微服务/05-SpringCloudAlibaba实战/17-消息队列：基于 RocketMQ 实现服务异步通信.md)是"接入视角"**:在 Spring Cloud Alibaba 体系里如何部署 NameServer/Broker、如何用客户端收发消息,聚焦"接入与部署",不展开可靠性机制。
- **[11-微服务/06 的 Spring Cloud Stream 系列(20-24 篇)](../11-微服务/06-SpringCloud原理与实战/20-消息驱动：如何理解 Spring 中对消息处理机制的抽象过程？.md)是"框架抽象视角"**:讲 Spring Messaging/Stream 的 Binder 架构与消息驱动风格,同样不深入中间件本身的可靠性机制。

需要"消息不丢不重"时读本专题;需要"怎么接进 Spring 体系"时读微服务那三代篇目,两处已在各自篇目中互相链接。

# 项目拷打与回答框架

## 目标

让每个项目案例都说得清楚：**背景 + 技术 + 挑战 + 结果**，并能结合问题说清解决思路。

## 框架

1. **项目背景**：业务形态、团队规模、现有架构、痛点需求；
2. **你的角色**：负责的模块、技术栈、团队协作方式；
3. **关键技术点**：Spring Boot/Redis/消息队列/数据库/安全的落地细节；
4. **核心难题与解决**：如并发控制、分布式事务、缓存一致性、防止重复消费、Actuator 监控等；
5. **工程成果**：性能提升、稳定性改进、部署效率、安全强化；
6. **反思与复盘**：如果重做，会调整哪些选型和流程。

## 拷打技巧

- 对每一项技术准备一个简练的两句话版本，便于面试官追问；
- 每个回答后主动补几个“如果遇到 XX 情况怎么处理”的延伸；
- 讲项目时用“问题 -> 实现 -> 验证”三段式，避免只是功能罗列。

## 版本差异(项目拷打 → 2026)

| 维度 | 旧视角 | 当前视角 |
|------|--------|----------|
| 技术栈口径 | Spring Boot 2.x + JDK 8 | Spring Boot 3.5.x + JDK 21（虚拟线程、record） |
| 难点话题 | 并发、缓存一致性 | 新增：AI 接口集成、大模型应用、性能预算（SLO） |
| 工程化 | Docker 部署 | 容器化 + CI/CD + 可观测性（链路追踪、压测） |
| 验证方式 | 手工测试 | 压测数据（P99 延迟）、监控面板、全链路追踪 |

> 背景→技术→挑战→结果框架不变；技术口径需更新到 Java 21/Boot 3.5.x，并准备 AI 相关项目的拷打话术。

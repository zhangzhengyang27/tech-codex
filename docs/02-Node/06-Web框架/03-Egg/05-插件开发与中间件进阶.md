# Egg 插件开发与中间件进阶

Egg 的「约定优于配置」落到实处，靠的是**插件（Plugin）**、**中间件（Middleware）** 与 **框架扩展（Extend）** 三套机制。掌握它们，你才能在 Egg 生态里复用能力、封装团队基建。

> **前置知识**：先读 [Egg 核心概念](03-核心概念.md) 与 [快速入门](02-快速入门.md)。

## 一、三者分工

| 机制 | 目录 | 用途 | 粒度 |
|------|------|------|------|
| 插件 Plugin | 安装到 `node_modules` / 本地 `lib/plugin` | 封装可复用能力并暴露给应用 | 组件级 |
| 中间件 Middleware | `app/middleware/` | 请求阶段拦截（洋葱模型） | 请求级 |
| 扩展 Extend | `app/extend/` | 给 `ctx/helper/application` 挂方法 | 对象级 |

> 插件内部通常包含自己的中间件、扩展、配置与 Service；中间件和扩展也可独立存在于应用/插件层。

## 二、中间件进阶

### 2.1 编写与启用

Egg 中中间件是基于 Koa 洋葱模型包一层工厂函数：

```javascript
// app/middleware/requestlog.js
module.exports = (options, app) => {
  return async function requestLog(ctx, next) {
    const start = Date.now();
    await next();
    const ms = Date.now() - start;
    ctx.logger.info(`${ctx.method} ${ctx.url} - ${ms}ms`);
  };
};
```

启用（在中间件或配置中加载）：

```javascript
// config/config.default.js
exports.middleware = ["requestlog"];          // 全局启用
// 传配置
exports.requestlog = { enabled: true };
```

单路由/单 Controller 级使用：

```javascript
// app/router.js
module.exports = (app) => {
  const { router, controller, middleware } = app;
  const requestLog = middleware.requestlog({ verbose: true });
  router.get("/detail", requestLog, controller.detail.index);
};
```

### 2.2 中间件的洋葱执行顺序

多个中间件按加载顺序「入」，响应阶段按逆序「出」，与 Koa 一致。注意**显式依赖**：

```javascript
// 依赖其他中间件
exports.middleware = [
  "compress",
  "bodyparser",       // 依赖在 bodyparser 之后
  "auth",
];
```

### 2.3 常见中间件编排（限流/鉴权/日志）

```javascript
// app/middleware/auth.js
module.exports = (options) => async (ctx, next) => {
  const token = ctx.get("Authorization");
  if (!token) ctx.throw(401, "未登录");
  ctx.state.user = ctx.service.token.verify(token);
  await next();
};
```

## 三、插件开发

插件把一组完整能力封装成可复用的 Egg 模块。骨架如下：

```
egg-x (插件根目录)
├── app/
│   ├── extend/
│   │   └── application.js   # 挂到 app.* 的方法/属性
│   ├── middleware/          # 插件自带中间件
│   └── service/             # 插件自带 Service
├── config/
│   ├── config.default.js    # 默认配置
│   └── config.unittest.js   # 环境覆盖
├── lib/                     # 底层实现
│   └── client.js
└── index.js                 # 插件入口
```

### 3.1 插件入口

```javascript
// index.js
module.exports = (app) => {
  app.addSingleton("redis", createClient); // 通过 addSingleton 提供连接
};
```

`app.addSingleton(name, getInstance)` 会给 app 挂载 `app.${name}`，并根据 `config.${name}.client / clients` 自动建连。

### 3.2 在应用中使用插件

```javascript
// config/plugin.js
exports.redis = {
  enable: true,
  package: "egg-redis",
  client: { host: "127.0.0.1", port: 6379 },
};

// 使用
await app.redis.get("key");
```

### 3.3 插件的加载顺序与依赖

```javascript
// config/plugin.js
exports.redis = {
  enable: true,
  package: "egg-redis",
  dependencies: ["session"],   // 依赖别的插件先加载
  env: ["prod"],               // 仅生产环境
};
```

- `enable`：是否启用
- `package` / `path`：来源（npm 包或本地目录）
- `dependencies`：依赖的其它插件
- `env`：命名环境（`prod`/`test`/`unittest`）才加载

## 四、框架扩展（Extend）

### 4.1 扩展 Application

```javascript
// app/extend/application.js
const SESSION_KEY = Symbol("app#session");
module.exports = {
  get session() {
    if (!this[SESSION_KEY]) this[SESSION_KEY] = { views: 0 };
    return this[SESSION_KEY];
  },
  execShell(cmd) {
    // 业务扩展方法
  },
};
```

### 4.2 扩展 Context（对 Controller/Service 最常用）

```javascript
// app/extend/context.js
module.exports = {
  // 统一响应
  ok(data = null, msg = "ok") {
    this.body = { code: 0, msg, data };
    this.status = 200;
  },
  fail(msg = "失败", code = 1) {
    this.body = { code, msg };
    this.status = 400;
  },
};
```

Controller 中即可 `ctx.ok(user)` / `ctx.fail("密码错误")`。

### 4.3 请求全局替换协议隐藏

可在 `app/extend/request.js` / `response.js` 继续扩展跟请求/响应相关的便捷能力。

## 五、Container 与挂载时机

Egg 使用一套统一的 Container 让不同来源（框架/插件/应用）的对象能互相访问：

| 宿主对象 | 挂载点 | 使用方 |
|----------|--------|--------|
| Application | `app.x` | 全局 / 插件 |
| Context | `ctx.x` | 单请求内 |
| Request | `ctx.request.x` | 请求级 |
| Response | `ctx.response.x` | 响应级 |
| Helper | `ctx.helper.x` | 通用工具 |

加载顺序概览（省略细节）：
```
框架扩展 → 插件扩展 → 应用扩展
中间件在应用加载前注册，路由在中间件注册后加载
```

## 六、将一个能力固化为插件的流程

以「给应用加一个 `svc` 配置访问器」为例：

1. 建目录 `lib/plugin/egg-svc`，写 `config.default.js` + `app/extend/application.js`；
2. `config/plugin.js` 里 `exports.svc = { enable: true, path: path.join(__dirname, "../lib/plugin/egg-svc") };`
3. 在任意 Controller/Service 用 `app.svc` 读取；
4. 编写 `test/xxx.test.js` 用 `mm.app` 做单测。

```javascript
// test
const { app, mock } = require("egg-mock/bootstrap");
it("app.svc 可读配置", async () => {
  await app.ready();
  assert(app.svc && app.svc.baseDir);
});
```

## 常见问题

### Q1: 全局中间件与路由级中间件如何选择？

全局放 `config.middleware`，适合通用横切（日志、鉴权、限流）；路由级只为特定接口挂载，降低无关开销。

### Q2: 插件怎么暴露给其它插件做依赖？

用 `app.addSingleton` 把实例化好的客户端挂到 `app.x`，其它插件即可通过 `app.x` 访问，并在 `plugin.js` 用 `dependencies` 声明依赖顺序。

### Q3: 扩展 Application 时为什么用 `get`？

Egg 提供的挂载查询往往涉及无锁重入，用 `get` 可做懒加载只初始化一次，避免多进程/多请求重复实例化。

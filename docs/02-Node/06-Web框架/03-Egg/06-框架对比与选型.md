# Egg 框架对比与选型

Egg 是阿里出品的企业级 Node 框架，解决的是「团队协作下如何高质高效开发」这一命题。本专题把它放进 Node 生态横向对比，帮助你判断它是否适配你的团队与业务。

> **前置知识**：建议先读 [Egg 基础](01-Egg基础.md)、[核心概念](03-核心概念.md) 与 [插件开发与中间件进阶](05-插件开发与中间件进阶.md)。

## 一、Egg 的核心设计主张

| Egg 主张 | 说明 | 落地机制 |
|----------|------|----------|
| 约定优于配置 | 统一目录/命名，新成员零学习成本上手 | `app/controller`、`app/service` 等约定目录 |
| 多进程模型 | Master/Worker/Agent 开箱即用 | 内置 `cluster` 封装 + IPC |
| 插件化 | 能力即插件，按需组合 | `egg-*` 插件体系 |
| 框架可扩展 | 支持基于 Egg 二次封装业务框架 | Agent 与应用、框架层继承 |
| 内置工程化 | 有测试、部署、环境约定 | `egg-mock`、`egg-scripts` |

## 二、横向框架对比

| 维度 | Express | Koa | Egg | NestJS | Midway |
|------|---------|-----|-----|--------|--------|
| 基准 | Express 原班 | 极简洋葱 | 基于 Koa | 装饰器/DI | 装饰器/DI（基于 Koa） |
| 路由 | 内置 | `@koa/router` | 约定式 + 中间件 | 装饰器式 | 装饰器式 |
| 多进程 | 自配 | 自配 | 内置 | 自配 | 自配 |
| TS 支持 | 弱 | 弱 | 一般 | 强 | 强 |
| 约定规范 | 少 | 少 | 多而强 | 中 | 中 |
| 企业开箱 | 需组合 | 需组合 | 强 | 强 | 强 |
| 学习成本 | 低 | 低-中 | 中（约定多） | 中高 | 中高 |

## 三、Egg vs Koa

- **Egg 基于 Koa**，继承了洋葱模型，但在其上加了一层约定与工程化。
- Koa 是「半成品」，需要自建路由/结构/多进程；Egg 是「成品框架」，把路由、中间件、插件、多进程、测试全约定好。
- 简言之：想快速获得规范团队底座 → Egg；想极致裸写 → Koa。

## 四、Egg vs NestJS

- **NestJS** 用 TypeScript + 依赖注入 + 装饰器 + 模块化，适合大型长期项目与强类型团队。
- **Egg** 中文生态成熟、文档全、上手曲线相对平缓，JS 团队友好；多进程内置是其明显优势。
- 选型参考：
  - 团队全面 TypeScript、需要高度抽象 → NestJS
  - 团队以 JS 为主、更看重内置多进程与约定一致 → Egg

## 五、Egg vs Fastify

- **Fastify** 以性能见长（Radix Tree + 预编译序列化），Schema 校验内建。
- **Egg** 强在规范和内部生态（部分依赖的小组件维护不活跃，但框架本身在阿里内部大量落地），性能上双方差距在量级不明显的中小型业务内可忽略。
- 吞吐敏感、需要精细 Schema → Fastify；团队协同与规范优先 → Egg。

## 六、选型决策指南

### 6.1 什么时候选 Egg

✅ 企业内部系统、管理后台、中台服务，重视协作规范
✅ 需要多进程、插件、测试、部署等「开箱工程化」
✅ 团队以 JS 为主、期望中文文档与成熟生态
✅ 从 Koa/Express 演进、需要重构为统一规范架构

⚠️ 若你：
- 追求极致性能与大流量网关 → 考虑 Fastify
- 全面拥抱 TypeScript + DI → 倾向 NestJS/Midway
- 只需一个极简 API → Koa/Express 更轻

### 6.2 团队协作视角

Egg 的价值不只是代码，而是一套「约定」，体现在：

- Controller/Service/Model 分层明确，项目结构统一；
- 环境配置（`config.prod` / `config.test`）约定清晰；
- 多进程模型让部署与运维行为可预期；
- `egg-mock` 让单元/集成测试有规范模板。

这使得新人上手、多人协作、交接维护的成本显著下降。

## 七、在 Egg 基础上如何演进

- 需要更强类型：可配合 TypeScript（参考 Egg + TS 工程模板），或迁往 Midway/Nest。
- 需要 GraphQL：接入 `egg-graphql` 插件。
- 需要微服务：Egg 可作服务节点配合网关（如接入 `egg-gateway` 生态或自定义）。

---

## 总结

**Egg 最大的资产是「约定 + 多进程 + 生态」**，特别适合需要强协作规范、以企业内部业务为主、JS 技术栈的团队。相比裸写 Koa/Express，它以「牺牲一点自由度」换来了「工程化与一致性」的大幅提升。

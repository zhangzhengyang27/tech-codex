# 调试、平台与文件上传

## 一、Nest 项目的调试

### 概念说明:为什么要用断点调试

console.log 是常见的调试手段,但有一个致命缺点:只能看到某个点的变量值,看不到代码的整个执行路线。

对于复杂项目来说,断点调试是必须的:它可以看到作用域、调用栈,也就是代码的执行路线,然后单步运行来观察变量的变化。

### Node 的调试模式

创建项目:

```
mkdir debug-test
cd debug-test
npm init -y
```

添加 index.js:

```javascript
const os = require('os');

const homedir = os.homedir();

console.log(homedir);
```

这段代码通过 os 模块拿到 home 目录的路径。直接 node 执行会输出结果。

以调试模式跑起来:

```
node --inspect-brk index.js
```

`--inspect` 是调试模式运行,而 `--inspect-brk` 还会在首行断住。启动后可以看到它起了一个 ws 服务,然后用调试客户端连上它,比如 Chrome DevTools:打开 <chrome://inspect/>,可以看到可以调试的目标;如果没有,就配置 network target,加上 localhost:9229。点击 inspect 进入调试界面,代码在首行断住,右侧可以看到作用域和调用栈,支持单步调试。

### 调试 Nest 项目

Nest 也是 node 项目,调试方式相同。`nest start` 有一个 `--debug` 选项,原理就是 node --inspect。

注意:`--inspect` 并不会像 `--inspect-brk` 一样在首行断住,启动后调试目标列表是空的。此时在 controller 里加一个 debugger 语句,然后访问 <http://localhost:3000>,代码就会在断点处断住,并能看到代码的整个执行路线。

### VSCode 调试

在 VSCode 里写代码的同时直接调试是更高效的方案。VSCode 实现了 Debugger 的客户端:点击调试面板的 create launch.json file,它会创建 `.vscode/launch.json` 的调试配置文件,输入 node 即可快速创建一个 node 调试配置。

用它调试前面的 index.js:`stopOnEntry` 是在首行断住,和 `--inspect-brk` 一样的效果。这样就可以在 VSCode 里调试 node 代码了。VSCode 调试的好处是可以边改代码边调试:调试过程中修改代码后,点击重新调试就能马上看到改动后的效果。

调试 Nest 的第一种方式:仍用 `nest start --debug` 启动 Nest 服务,添加一个 attach 类型的调试配置连接上去,然后在 controller 里打断点,访问 <http://localhost:3000>,代码同样会在断点处断住。

更简便的方式是创建 npm scripts 类型的调试配置(如果创建出的调试配置 type 是 pwa-node 也可以,和 node 类型差不多,据说 pwa-node 功能多一点):

```json
{
    "type": "node",
    "request": "launch",
    "name": "debug nest",
    "runtimeExecutable": "npm",
    "args": [
        "run",
        "start:dev",
    ],
    "skipFiles": [
        "<node_internals>/**"
    ],
    "console": "integratedTerminal",
}
```

效果和命令行执行 npm run start:dev 一样。其中 runtimeExecutable 代表执行什么命令,args 传参数。要指定 console 为 integratedTerminal,即用 VSCode 的内置终端来打印日志,否则默认用 debug console 跑,那个没有颜色。点击调试模式启动后,浏览器访问 <http://localhost:3000>,代码会在断点处断住。这是最方便的调试 Nest 项目的方式。

### 断点类型

几种常用断点类型:

- **logpoint**:只想打印日志、不想断住,又不想加 console.log 污染代码时使用。右键选择 logpoint,输入打印的信息(变量用 {} 包裹),代码执行到这里就会打印,适合不需要断住但想打印日志的情况;
- **条件断点**:表达式成立才会断住;
- **异常断点**:可以在没有处理的异常处自动断住。

### 小结

复杂的代码需要用断点调试查看调用栈和作用域,即代码的执行路线,然后单步执行。node 代码可以加上 `--inspect` 或者 `--inspect-brk` 启动调试 ws 服务,然后用 Chrome DevTools 或者 VSCode debugger 连上来调试。Nest 项目的调试也是 node 调试:可以使用 `nest start --debug` 启动 ws 服务后在 VSCode 里 attach 上来调试,也可以添加调试配置来运行 npm run start:dev,后者最方便。此外还有 logpoint、条件断点、异常断点等断点类型。

## 二、HTTP 平台适配器:Express 与 Fastify

### Nest 与 Express 的关系

Nest 的 request、response 对象都是 Express 的,而且 Nest 也支持 Express 的中间件机制。

Express 是一个处理请求、响应的库,用法如下:

```javascript
const express = require('express')
const cookieParser = require('cookie-parser')
const cookieValidator = require('./cookieValidator')

const app = express()

async function validateCookies (req, res, next) {
  await cookieValidator(req.cookies)
  next()
}

app.use(cookieParser())

app.use(validateCookies)

app.use((err, req, res, next) => {
  res.status(400).send(err.message)
})

app.listen(3000)
```

通过 use 一个个中间件来处理请求、返回响应,这种调用链叫做洋葱模型。基于中间件能完成各种功能,但 Express 只是一个处理请求的库,并没有提供组织代码的架构能力,代码可能写成各种样子。

所以企业级开发会用在它之上封装一层的库,比如 Nest。Nest 提供了 IOC、AOP 等架构特性,规定了代码组织的形式,而且对 websocket、graphql、orm 等各种方案都提供了开箱即用的支持。

也就是说,用 Node 写一个 http 服务有三个层次:

*   直接使用 http、https 的模块
*   使用 express、koa 这种库
*   使用 Nest 这种企业级框架

类比 Java:开发者不会直接处理 http 请求并手动集成各种方案,而是直接用 Spring 这种一站式企业级开发框架。同样的道理,Nest 就是 node 生态里的 Spring。

### 适配器抽象

Nest 没有和 Express 强耦合,它做了一层抽象:定义了 [HttpServer 的 interface](https://github.com/nestjs/nest/blob/d352e6f138bc70ff33cccf830053946d17272b82/packages/common/interfaces/http/http-server.interface.ts#L21C1-L85),然后封装了 [AbstractHttpAdapter 的 abstract class](https://github.com/nestjs/nest/blob/d352e6f138bc70ff33cccf830053946d17272b82/packages/core/adapters/http-adapter.ts#L12C1-L131),之后分别提供了 express 和 fastify 的实现。

Adapter 是适配器的意思。Nest 内部并没有直接依赖任何一个 http 处理的库,只是依赖了抽象的接口;想用什么库,需要实现这些接口的适配器。因此可以用 express,也可以灵活地切换成 fastify,对 Nest 没有任何影响。这两个适配器分别在 @nestjs/platform-express 和 @nestjs/platform-fastify 的包里,默认用的是 platform-express 的包。

### 切换到 Fastify

用 @nestjs/cli 创建一个 Nest 项目并跑起来:

    nest new fastify-test -p npm

    nest start --watch

浏览器访问 <http://localhost:3000> 看到 hello world 即服务跑成功,此时用的是默认的 express。

安装 fastify 和 @nestjs/platform-fastify:

    npm install fastify @nestjs/platform-fastify

然后修改 Nest 创建的方式:在 NestFactory.create 时传入 FastifyAdapter 实例,即可切换到 fastify 平台。这里还可以再传一个类型参数,这样返回的 app 就会提示 fastify 平台特有的方法——这也是为什么之前要传入 NestExpressApplication 才有 useStaticAssets 方法。

然后在 controller 里可以注入 fastify 的 request 和 reply 对象:

```javascript
import { Controller, Get, Request, Response } from '@nestjs/common';
import { FastifyReply, FastifyRequest } from 'fastify';
import { AppService } from './app.service';

@Controller()
export class AppController {
  constructor(private readonly appService: AppService) {}

  @Get()
  getHello(@Request() request: FastifyRequest, @Response() reply: FastifyReply) {
    reply.header('url', request.url)
    reply.send('hello')
  }
}
```

注入了 fastify 的 request 和 reply 对象,然后用它来设置 header 发送响应。

注意:一旦用 @Response 注入了响应对象,就不能通过 return 的方式来返回响应内容,需要手动调用 res.send,这点用 express 时也一样。原因很直观:方法里可能已经用 response 对象发送了数据,如果 Nest 再把返回值作为响应内容,就会冲突。如果仍想用返回值,可以给 @Response 传一个 passthrough 参数,代表不会在方法里自己发送响应内容,这样返回值就生效了。

### 设计动机

Nest 之所以让 http 处理库可以被轻松切换,是因为它的核心在于 IOC、AOP 这些架构特性;express、fastify 只不过是请求、响应的方法不同而已,区别并不大。如果强依赖于 express,万一出现更好的 http 处理库就难以替换。这种加一层抽象和适配器的方式,能让 Nest 更加通用、灵活,有更强的扩展性。

### 小结

express 是基于中间件的洋葱模型处理请求、响应的库,它并没有提供组织代码的架构特性。为了更好的可维护性,一般使用 Nest 这种一站式企业级开发框架(就像 Java 里会用 Spring 框架一样)。Nest 底层默认是 express 但不完全是:它内部实现是基于 interface 的,并提供了 @nestjs/platform-express、@nestjs/platform-fastify 两个 adapter 包,从而可以轻松切换 express、fastify 或其他的 http 请求处理库——这就是适配器模式的魅力。

## 三、接口版本控制

### 场景

应用开发完一版上线之后还会不断迭代。后续可能需要修改已有的接口,但为了兼容,之前版本的接口还要保留。Nest 内置了同一接口多版本的支持。

创建项目:

```
nest new version-test
```

进入项目,创建 aaa 模块:

```
nest g resource aaa --no-spec
```

把服务跑起来:

```
npm run start:dev
```

在 postman 里访问,得到的是版本一的接口。

### 版本标注:version 与 @Version

假设后面又开发了一版接口,路由还是 aaa,写法如下:

```javascript
import { Controller, Get, Version } from '@nestjs/common';
import { AaaService } from './aaa.service';

@Controller({
    path: 'aaa',
    version: '1'
})
export class AaaController {
    constructor(private readonly aaaService: AaaService) {}

    @Version('2')
    @Get()
    findAllV2() {
      return this.aaaService.findAll() + '222';
    }

    @Get()
    findAll() {
      return this.aaaService.findAll();
    }
}
```

在 controller 上标记 version 1,默认全部接口都是 version 1;然后单独用 @Version 把 version 2 的接口标识出来。

在 main.ts 里调用 enableVersioning 开启接口版本功能:

```javascript
import { VersioningType } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.enableVersioning({
    type: VersioningType.HEADER,
    header: 'version'
  })
  await app.listen(3000);
}
bootstrap();
```

这里指定通过 version 这个 header 来携带版本号:带上 version:1 的 header 访问版本 1 的接口,带上 version:2 的 header 访问版本 2 的接口,它们是同一个路由。

### VERSION_NEUTRAL 与匹配顺序

问题:不带版本号会 404。这符合预期,因为接口显式声明了版本。如果希望所有版本都能访问某个接口,可以用 VERSION_NEUTRAL 常量——现在带不带版本号、版本号是几都可以访问这些接口。

但要注意:接口从上到下匹配,加了 VERSION_NEUTRAL 后版本 2 的专用接口可能不起作用。解决办法有两种:把版本 2 的接口移到上面去;或者单独建一个 version 2 的 controller:

```
nest g controller aaa/aaa-v2 --no-spec --flat
```

把 AaaController 里 version 2 的接口删掉,移到这里:

```javascript
import { Controller, Get,Version } from '@nestjs/common';
import { AaaService } from './aaa.service';

@Controller({
    path: 'aaa',
    version: '2'
})
export class AaaV2Controller {
    constructor(private readonly aaaService: AaaService) {}

    @Get()
    findAllV2() {
      return this.aaaService.findAll() + '222';
    }
}
```

现在版本 2 走 AaaV2Controller,其他版本走 AaaController。一般推荐的做法就是:一个 Controller 标记为 VERSION_NEUTRAL,其他版本的接口放在单独的 Controller 里。注意 controller 之间同样要注意顺序,前面的 controller 先生效。

### 四种版本号携带方式

除了用自定义 header 携带版本号,还有别的方式。MEDIA_TYPE 在 accept 的 header 里携带版本号:

```javascript
app.enableVersioning({
    type: VersioningType.MEDIA_TYPE,
    key: 'vv='
})
```

URI 方式则在 url 里指定版本号:

```javascript
app.enableVersioning({
    type: VersioningType.URI
})
```

但 URI 方式不支持 VERSION_NEUTRAL,必须指定明确的版本号才可以。

如果这些方式都不满足需求,可以自己实现 extractor:

```javascript
import { VersioningType } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { Request } from 'express';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  const extractor = (request: Request)=> {
    if(request.headers['disable-custom']) {
      return '';
    }
    return request.url.includes('guang') ? '2' : '1';
  }

  app.enableVersioning({
    type: VersioningType.CUSTOM,
    extractor
  })

  await app.listen(3000);
}

bootstrap();
```

这里自定义了版本号逻辑:如果 url 里包含 guang,就返回版本 2 的接口,否则返回版本 1 的;此外,如果有 disable-custom 的 header 就返回空,即 404。由此可以实现各种灵活的版本号规则。

### 小结

Nest 内置了同一路由多版本的功能:在 main.ts 里调用 enableVersioning 即可开启,有 URI、HEADER、MEDIA_TYPE、CUSTOM 四种指定版本号的方式。HEADER 和 MEDIA_TYPE 都是在 header 里指定,URI 是在 url 里指定,CUSTOM 是自定义版本号规则。可以在 @Controller 通过 version 指定版本号,或者在 handler 上通过 @Version 指定版本号;指定为 VERSION_NEUTRAL 则匹配任何版本号(URI 方式不支持)。开发同一接口的多个版本时可直接使用这些内置功能。

## 四、Express 中使用 multer

### multipart/form-data 与文件接收

Nest 的文件上传基于 Express 的中间件 multer 实现,先学习 multer 包的使用。

新建目录,用 npm init -y 创建 package.json,然后安装 express 和 multer 还有 cors 包:

    npm install express multer cors

其中 cors 包是处理跨域 header 的。创建 index.js:

```javascript
const express = require('express')
const multer  = require('multer')
const cors = require('cors');

const app = express()
app.use(cors());

const upload = multer({ dest: 'uploads/' })

app.post('/aaa', upload.single('aaa'), function (req, res, next) {
  console.log('req.file', req.file);
  console.log('req.body', req.body);
})

app.listen(3333);
```

app.use 使用中间件 cors 来处理跨域;用 multer 处理文件上传,指定保存目录为 uploads/。

新建这样一个 index.html:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="https://unpkg.com/axios@0.24.0/dist/axios.min.js"></script>
</head>
<body>
    <input id="fileInput" type="file"/>
    <script>
        const fileInput = document.querySelector('#fileInput');

        async function formData() {
            const data = new FormData();
            data.set('name','光');
            data.set('age', 20);
            data.set('aaa', fileInput.files[0]);

            const res = await axios.post('http://localhost:3333/aaa', data);
            console.log(res);
        }

        fileInput.onchange = formData;
    </script>
</body>
</html>
```

前端通过 FormData + axios 上传文件,指定内容的传输格式 content-type 为 multipart/form-data(axios 会自动根据内容指定 content-type,不需要手动指定)。用 node 把 server 跑起来,并用 http-server 把静态服务跑起来,浏览器访问后,在 devtools 可以看到 aaa 请求的 body 是多个 boundary 分隔的格式,分隔符在 Content-Type 里指定——这就是 form-data 的传输格式。

服务端:req.file 可以拿到文件字段,其余非文件字段在 req.body;并且服务端多了 uploads 目录,下面就保存着上传的文件。

### 多文件上传与数量限制

多文件上传时,bbb 路由通过 array 方法来取上传的文件,并指定最大数量的限制,上传的文件通过 req.files 来取。前端 input 标签添加 multiple 属性允许多选,onchange 的时候取出每个 file,通过 append 方法添加到 bbb 字段(fileInput.files 是一个伪数组,要转成数组才能用 forEach 方法),这样 bbb 实际上就保存着上传的多个文件:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="https://unpkg.com/axios@0.24.0/dist/axios.min.js"></script>
</head>
<body>
    <input id="fileInput" type="file" multiple/>
    <script>
        const fileInput = document.querySelector('#fileInput');

        async function formData2() {
            const data = new FormData();
            data.set('name','光');
            data.set('age', 20);
            [...fileInput.files].forEach(item => {
                data.append('bbb', item)
            })

            const res = await axios.post('http://localhost:3333/bbb', data);
            console.log(res);
        }

        fileInput.onchange = formData2;
    </script>
</body>
</html>
```

node 服务的 req.files 接收到多个文件,uploads 目录下也会出现对应文件。

如果传了超过限制数量的文件(例如 array 指定 2 个却传了更多),会报错。此时添加一个错误处理中间件即可:在 express 里,约定有 4 个参数的中间件为错误处理中间件。一旦某个中间件出了错,express 就会向后找错误处理中间件来调用;如果没有,就用默认错误处理中间件,返回 500 响应。捕获错误并返回对应响应:

```javascript
app.post('/bbb', upload.array('bbb', 2), function (req, res, next) {
    console.log('req.files', req.files);
    console.log('req.body', req.body);
}, function(err, req, res, next) {
    if(err instanceof MulterError && err.code === 'LIMIT_UNEXPECTED_FILE') {
        res.status(400).end('Too many files uploaded');
    }
})
```

再次上传超过 2 个文件,就会收到服务端的 400 响应,提示文件上传过多。

### fields 与 any

更复杂的情况:多个字段都上传文件,且限制各不相同。通过 fields 方法指定每个字段的名字和最大数量,接收到请求后通过 req.files['xxx'] 来取对应的文件信息,其余非文件字段同样通过 req.body 来取:

```javascript
app.post('/ccc', upload.fields([
    { name: 'aaa', maxCount: 3 },
    { name: 'bbb', maxCount: 2 }
]), function (req, res, next) {
    console.log('req.files', req.files);
    console.log('req.body', req.body);
})
```

对应的前端代码(原本需要两个 file input 分别上传 aaa、bbb 的文件,示例为测试方便做了简化):

```javascript
async function formData3() {
    const data = new FormData();
    data.set('name','光');
    data.set('age', 20);
    data.append('aaa', fileInput.files[0]);
    data.append('aaa', fileInput.files[1]);
    data.append('bbb', fileInput.files[2]);
    data.append('bbb', fileInput.files[3]);

    const res = await axios.post('http://localhost:3333/ccc', data);
    console.log(res);
}
```

如果并不知道有哪些字段是 file,可以用 any 来接收:

```javascript
app.post('/ddd', upload.any(), function(req, res, next) {
    console.log('req.files', req.files);
    console.log('req.body', req.body);
});
```

前端设置 aaa、bbb、ccc、ddd 4 个 file 字段:

```javascript
async function formData4() {
    const data = new FormData();
    data.set('name','光');
    data.set('age', 20);
    data.set('aaa', fileInput.files[0]);
    data.set('bbb', fileInput.files[1]);
    data.set('ccc', fileInput.files[2]);
    data.set('ddd', fileInput.files[3]);

    const res = await axios.post('http://localhost:3333/ddd', data);
    console.log(res);
}
```

any 模式同样识别出了所有 file 字段,只不过这时候不是 key、value 的形式,需要自己遍历数组来查找。

### 自定义存储:diskStorage

之前通过 dest 指定了保存的目录。如果要自定义存储目录和文件名,使用 multer.diskStorage:

```javascript
const fs = require('fs');
const path = require('path');

const storage = multer.diskStorage({
    destination: function (req, file, cb) {
        try {
            fs.mkdirSync(path.join(process.cwd(), 'my-uploads'));
        }catch(e) {}
        cb(null, path.join(process.cwd(), 'my-uploads'))
    },
    filename: function (req, file, cb) {
        const uniqueSuffix = Date.now() + '-' + Math.round(Math.random() * 1E9) + '-' + file.originalname
        cb(null, file.fieldname + '-' + uniqueSuffix)
    }
});
```

multer.diskStorage 是磁盘存储,通过 destination、filename 参数分别指定保存的目录和文件名。destination 里要先创建用到的目录,再返回它的路径;filename 里用时间戳 Date.now() 加上 Math.random() 乘以 10 的 9 次方再取整,之后拼上原来的文件名。file 对象就是服务端打印出的那个结构。再次上传即可看到目录和文件名都修改了。

### 小结

express 的 multer 包用来处理 multipart/form-data 格式的文件上传请求:single 方法处理单个字段的单个文件,array 方法处理单个字段的多个文件,fields 方法处理多个字段的文件,any 处理任意数量字段的文件,分别用 req.file 和 req.files 来取解析出的文件;其余非文件字段不做处理,还是通过 req.body 来取。文件数量过多等错误会抛出对应的 error 对象,在错误处理中间件里处理并返回对应的响应即可。

## 五、Nest 中使用 multer

### 单文件上传

Nest 的文件上传同样基于 multer。新建 nest 项目:

```
nest new nest-multer-upload -p npm
```

安装 multer 的 ts 类型的包:

```
npm install -D @types/multer
```

在 AppController 添加这样一个 handler:

```javascript
@Post('aaa')
@UseInterceptors(FileInterceptor('aaa', {
    dest: 'uploads'
}))
uploadFile(@UploadedFile() file: Express.Multer.File, @Body() body) {
    console.log('body', body);
    console.log('file', file);
}
```

使用 FileInterceptor 来提取 aaa 字段,然后通过 UploadedFile 装饰器把它作为参数传入。用 npm run start:dev 把服务跑起来,保存后可以看到 uploads 目录被创建。

前端有两种配套方式:一种是让 nest 服务支持静态文件的访问;另一种是让 nest 服务支持跨域,再单独跑一个 http-server 提供静态服务。在根目录创建 index.html:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="https://unpkg.com/axios@0.24.0/dist/axios.min.js"></script>
</head>
<body>
    <input id="fileInput" type="file" multiple/>
    <script>
        const fileInput = document.querySelector('#fileInput');

        async function formData() {
            const data = new FormData();
            data.set('name','光');
            data.set('age', 20);
            data.set('aaa', fileInput.files[0]);

            const res = await axios.post('http://localhost:3000/aaa', data);

        }

        fileInput.onchange = formData;

```

浏览器访问后,服务端就打印了 file 对象,并且文件保存到了 uploads 目录;其他字段通过 @Body 装饰器获取。

### 多文件与多字段上传

多文件上传:把 FileInterceptor 换成 FilesInterceptor,把 UploadedFile 换成 UploadedFiles(都是多加一个 s),第二个参数指定最大数量:

```javascript
@Post('bbb')
@UseInterceptors(FilesInterceptor('bbb', 3, {
    dest: 'uploads'
}))
uploadFiles(@UploadedFiles() files: Array<Express.Multer.File>, @Body() body) {
    console.log('body', body);
    console.log('files', files);
}
```

前端代码:

```javascript
async function formData2() {
    const data = new FormData();
    data.set('name','光');
    data.set('age', 20);
    [...fileInput.files].forEach(item => {
        data.append('bbb', item)
    })

    const res = await axios.post('http://localhost:3000/bbb', data, {
        headers: { 'content-type': 'multipart/form-data' }
    });
    console.log(res);
}
```

多个文件字段的情况,和 multer 里类似,使用 FileFieldsInterceptor 指定每个字段的名字和最大数量:

```javascript
@Post('ccc')
@UseInterceptors(FileFieldsInterceptor([
    { name: 'aaa', maxCount: 2 },
    { name: 'bbb', maxCount: 3 },
], {
    dest: 'uploads'
}))
uploadFileFields(@UploadedFiles() files: { aaa?: Express.Multer.File[], bbb?: Express.Multer.File[] }, @Body() body) {
    console.log('body', body);
    console.log('files', files);
}
```

前端代码(应当用两个 file input 分别上传 aaa 和 bbb 对应的文件,示例为测试方便做了简化):

```javascript
async function formData3() {

    data.set('age', 20);
    data.append('aaa', fileInput.files[0]);

    console.log(res);

```

后端收到了上传的 aaa、bbb 的文件。

如果并不知道有哪些字段是 file,使用 AnyFilesInterceptor:

```javascript
@Post('ddd')
@UseInterceptors(AnyFilesInterceptor({
    dest: 'uploads'
}))
uploadAnyFiles(@UploadedFiles() files: Array<Express.Multer.File>, @Body() body) {
    console.log('body', body);
    console.log('files', files);
}
```

前端同样设置 4 个 file 字段:

```javascript
async function formData4() {

    data.set('name','光');
    data.set('age', 20);
    data.set('aaa', fileInput.files[0]);
    data.set('bbb', fileInput.files[1]);
```

同样识别出了所有 file 字段。Nest 中也同样可以指定 storage,把前面写的 storage 拿过来,在 controller 里使用:

```javascript
import * as multer from "multer";
import * as fs from 'fs';
import * as path from "path";

const storage = multer.diskStorage({
    destination: function (req, file, cb) {
        try {
            fs.mkdirSync(path.join(process.cwd(), 'my-uploads'));
        }catch(e) {}

        cb(null, path.join(process.cwd(), 'my-uploads'))

        cb(null, file.fieldname + '-' + uniqueSuffix)
    }
});

export { storage };
```

### 装饰器与 multer 的对应关系

Nest 上传文件的方式和直接使用 multer 非常相似,因为它就是对 multer 做了一层简单封装:

- multer 里通过 single 方法处理单个 file 的字段,FileInterceptor 里也是一样;
- multer 里通过 array 方法处理多个 file 的字段,FilesInterceptor 里也一样;
- FileFieldsInterceptor、AnyFilesInterceptor 分别对应 fields、any 方法。

而 UploadedFile、UploadedFiles 这些装饰器,只是从 request 中取出处理完的 file、files 等属性作为参数传入 handler。理解了这个对应关系,这些文件上传装饰器就非常清晰了。

### 文件校验:pipe 与 ParseFilePipe

对上传的文件做一些限制(如文件大小、类型等),这部分逻辑可以放在 pipe 里做。生成一个 pipe:

    nest g pipe file-size-validation-pipe --no-spec --flat

添加检查文件大小的逻辑:

```javascript
import { PipeTransform, Injectable, ArgumentMetadata, HttpException, HttpStatus } from '@nestjs/common';

@Injectable()
export class FileSizeValidationPipe implements PipeTransform {
  transform(value: Express.Multer.File, metadata: ArgumentMetadata) {
    if(value.size > 10 * 1024) {
      throw new HttpException('文件大于 10k', HttpStatus.BAD_REQUEST);
    }
    return value;
  }
}
```

大于 10k 就抛出异常,返回 400 的响应。把它加到 UploadedFile 的参数里,即可实现文件的校验。

像文件大小、类型的校验这种逻辑太过常见,Nest 已经封装好了,可以直接使用 ParseFilePipe:

```javascript
@Post('fff')
@UseInterceptors(FileInterceptor('aaa', {
    dest: 'uploads'
}))
uploadFile3(@UploadedFile(new ParseFilePipe({
    validators: [
      new MaxFileSizeValidator({ maxSize: 1000 }),
      new FileTypeValidator({ fileType: 'image/jpeg' }),
    ],
})) file: Express.Multer.File, @Body() body) {
    console.log('body', body);
    console.log('file', file);
}
```

ParseFilePipe 的作用是调用传入的 validator 来对文件做校验,例如 MaxFileSizeValidator 校验文件大小、FileTypeValidator 校验文件类型——常用的也就是校验这两项。校验不通过时返回 400 响应,并且 message 会说明具体的错误信息,错误信息也可以自行修改。

还可以自己实现 validator,只要继承 FileValidator:

```javascript
import { FileValidator } from "@nestjs/common";

export class MyFileValidator extends FileValidator{
    constructor(options) {
        super(options);
    }

    isValid(file: Express.Multer.File): boolean | Promise<boolean> {
        if(file.size > 10000) {
            return false;
        }
        return true;
    }
    buildErrorMessage(file: Express.Multer.File): string {
        return `文件 ${file.originalname} 大小超出 10k`;
    }
}
```

在 controller 中使用后,浏览器上传文件即可看到自定义的 FileValidator 生效。

### 小结

Nest 的文件上传基于 multer 实现,它对 multer api 封装了一层,提供了 FileInterceptor、FilesInterceptor、FileFieldsInterceptor、AnyFilesInterceptor 四个拦截器,分别用到 multer 包的 single、array、fields、any 方法;它们把文件解析出来放到 request 的某个属性上,再用 @UploadedFile、@UploadedFiles 装饰器取出来传入 handler。文件验证可以使用 ParseFilePipe,它内置了 MaxFileSizeValidator、FileTypeValidator,也可以继承 FileValidator 实现自定义校验。

## 实践要点

- 调试 Nest 首选 VSCode + npm scripts 的 launch 配置(runtimeExecutable + args + integratedTerminal);注意 `--inspect` 不在首行断住,需配合 debugger 语句或改用 `--inspect-brk`;
- logpoint 适合"只打印不断住"的场景,条件断点适合特定入参才中断的场景,异常断点适合捕获未处理异常;
- 切换 fastify 时传入 FastifyAdapter 并可搭配平台类型参数获得类型提示;一旦注入 @Response/@Reply 就必须手动 send,除非传 passthrough;
- 接口多版本的推荐组织方式:一个 VERSION_NEUTRAL 的 Controller 承载通用接口,其他版本放独立 Controller,并注意 controller 声明顺序对路由匹配的影响;
- 自定义文件存储用 multer.diskStorage 的 destination/filename;文件名建议加时间戳 + 随机数避免冲突;
- 文件校验优先使用内置 ParseFilePipe + MaxFileSizeValidator/FileTypeValidator,特殊规则再继承 FileValidator 自定义。

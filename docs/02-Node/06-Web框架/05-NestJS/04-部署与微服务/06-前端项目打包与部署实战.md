# 前端项目打包与部署实战

> 学习目标：掌握前端项目部署场景、Nginx 配置、静态资源部署、域名配置、文件上传、部署流程。

## 一、前端项目部署场景概述

### 1.1 三种部署场景

```
前端项目部署场景分类：
│
├── 场景一：纯静态资源部署（SPA）
│   ├── 技术栈：React、Vue（无 SSR）
│   ├── 构建产物：HTML、JS、CSS 静态文件
│   ├── 部署方式：Web 服务器（Nginx、Apache）
│   ├── 环境要求：无需 Node.js 环境
│   └── 复杂度：最简单
│
├── 场景二：SSG 静态站点生成（Static Site Generation）
│   ├── 技术栈：Next.js SSG、Nuxt.js SSG
│   ├── 构建产物：静态 HTML、JS、CSS 文件
│   ├── 部署方式：与场景一相同（Web 服务器）
│   ├── 环境要求：无需 Node.js 环境
│   └── 复杂度：最简单
│
└── 场景三：SSR 服务端渲染（Server Side Rendering）
    ├── 技术栈：Next.js SSR、Nuxt.js SSR、NestJS
    ├── 构建产物：服务端代码 + 客户端代码
    ├── 部署方式：Node.js 环境 + 进程管理（PM2）
    ├── 环境要求：需要 Node.js 环境
    └── 复杂度：较复杂
```

### 1.2 部署场景对比

| 场景 | 构建产物 | 部署方式 | 环境要求 | 进程管理 | 复杂度 |
|------|---------|---------|---------|---------|--------|
| SPA | 静态文件 | Web 服务器 | 无 | 无 | 最简单 |
| SSG | 静态文件 | Web 服务器 | 无 | 无 | 最简单 |
| SSR | 服务端代码 + 客户端代码 | Node.js + PM2 | Node.js | PM2 | 较复杂 |

### 1.3 部署核心要点

- 构建产物理解：SPA/SSG 是 dist/out 目录（静态文件），SSR 是服务端代码 + 客户端代码，入口文件是 index.html 或 server.js
- Web 服务器选择：Nginx（推荐）、Apache、Caddy
- 域名与 DNS：域名购买、DNS 解析配置、本地 hosts 测试
- 文件上传方式：FTP 工具、SCP 命令、rsync 命令、CI/CD 自动化部署
- 进程管理（SSR 场景）：PM2（推荐）、systemd、Docker

## 二、场景一：纯静态资源部署（SPA）

### 2.1 部署流程

```
SPA 项目部署流程：
│
├── 第一步：构建项目（npm run build → dist 目录）
│   ├── Vue3：dist/
│   └── React：build/
│
├── 第二步：准备服务器（安装 Nginx、配置 Nginx、启动 Nginx）
├── 第三步：配置域名（可选，购买域名、DNS 解析、或本地 hosts）
├── 第四步：上传文件（FTP 工具上传 dist 到 Nginx 根目录）
└── 第五步：测试访问（浏览器访问域名或 IP）
```

### 2.4 Nginx 配置详解

**基础 Nginx 配置**：

```11-Nginx基础概述
# /etc/11-Nginx基础概述/conf.d/site1.conf

server {
    listen 80;                                    # 监听端口
    server_name site1.com;                        # 域名

    root /home/website/project-front-vue3;        # 网站根目录
    index index.html;                             # 入口文件

    # 访问日志
    access_log /var/log/11-Nginx基础概述/site1.access.log;

    # 错误日志
    error_log /var/log/11-Nginx基础概述/site1.error.log;

    # 主要 location 配置
    location / {
        try_files $uri $uri/ /index.html;         # SPA 路由支持
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 1y;                               # 缓存 1 年
        add_header Cache-Control "public, immutable";
    }

    # 禁止访问隐藏文件
    location ~ /\. {
        deny all;
    }
}
```

### 2.5 域名配置

**本地测试：修改 hosts 文件**：

```bash
# Mac/Linux
sudo vi /etc/hosts

# Windows
# 路径：C:\Windows\System32\drivers\etc\hosts

# 添加域名映射
192.168.31.77 site1.com

# 测试域名解析
ping site1.com
```

**线上环境：配置 DNS 解析**：

- 第一步：购买域名（阿里云、腾讯云、GoDaddy 等）
- 第二步：进入域名解析控制台
- 第三步：添加解析记录（记录类型 A 记录、主机记录 www 或 @、记录值服务器 IP）
- 第四步：等待 DNS 生效（通常 10 分钟 - 2 小时，用 nslookup 或 dig 验证）

**DNS 解析类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| A 记录 | 域名指向 IPv4 地址 | site1.com → 192.168.31.77 |
| AAAA 记录 | 域名指向 IPv6 地址 | site1.com → 2001:db8::1 |
| CNAME 记录 | 域名指向另一个域名 | www.site1.com → site1.com |
| MX 记录 | 邮件交换记录 | 邮箱服务使用 |

### 2.6 文件上传

**方式一：使用 FTP 工具**：Mac 推荐 Transmit/FileZilla/Cyberduck，Windows 推荐 FileZilla/WinSCP/FlashFXP，Linux 用 FileZilla 或命令行。

**方式二：使用 SCP 命令**：

```bash
# 上传整个目录
scp -r dist/* user@server:/home/website/project-front-vue3/
# -r：递归上传目录
```

**方式三：使用 rsync 命令**：

```bash
# 同步文件（增量传输）
rsync -avz dist/ user@server:/home/website/project-front-vue3/
# -a：归档模式（保留权限、时间戳等）
# -v：显示详细信息
# -z：压缩传输
```

### 2.7 测试访问

```bash
# 第一步：检查 Nginx 配置
sudo 11-Nginx基础概述 -t

# 第二步：重新加载 Nginx 配置
sudo systemctl reload 11-Nginx基础概述

# 第三步：检查端口监听
sudo netstat -tulpn | grep :80
```

**常见问题排查**：

- 无法访问：检查 Nginx 是否启动、防火墙是否开放端口、域名解析是否正确
- 404 Not Found：检查 root 路径是否正确、index.html 是否存在、文件权限
- 403 Forbidden：检查文件权限（chmod 755）、SELinux 配置、Nginx 用户权限
- 静态资源 404：检查资源路径、publicPath 配置、Nginx location 配置

## 三、场景二：SSG 静态站点生成

### 3.1 SSG 与 SPA 的区别

| 维度 | SPA | SSG |
|------|-----|-----|
| 构建产物 | 单页应用，HTML 为空壳 | 多页应用，每个页面预渲染为 HTML |
| SEO 优化 | SEO 不友好（需要额外配置） | SEO 友好（内容已渲染） |
| 首屏加载 | 需要加载 JS 后渲染 | 直接显示 HTML 内容 |
| 部署方式 | 静态文件部署 | 静态文件部署（相同） |

### 3.2 SSG 构建

**Next.js SSG 构建**：

```bash
# next.config.js 配置
module.exports = {
  output: 'export',
}

# 构建项目
npm run build

# 构建产物
# out/
# ├── index.html
# ├── about/
# │   └── index.html
# └── _next/
```

**Nuxt.js SSG 构建**：

```bash
# nuxt.config.ts 配置
export default defineNuxtConfig({
  ssr: true,
  nitro: {
    prerender: {
      routes: ['/'], // 预渲染的路由
    },
  },
})

# 构建项目
npm run generate

# 构建产物
# dist/
# ├── index.html
# ├── about/
# │   └── index.html
# └── _nuxt/
```

SSG 部署流程与 SPA 相同：构建 → 准备服务器 → 配置域名 → 上传文件 → 测试访问。

## 四、场景三：SSR 服务端渲染

### 4.1 SSR 部署特点

- 环境要求：需要 Node.js 环境、进程管理工具（PM2）、反向代理（Nginx）
- 构建产物：服务端代码（.nuxt 或 .next）、客户端代码、入口文件（server.js）、package.json
- 进程管理：PM2（推荐）、systemd、Docker
- 架构设计：Nginx 反向代理 + PM2 集群模式 + 负载均衡 + 高可用架构

SSR 的 Node.js 安装（推荐 NodeSource 或 NVM）、PM2 详细用法、NestJS/Nuxt.js 部署脚本参见后续章节及 `PM2 进程管理` 文档。

### 4.2 SSR 项目部署流程

```
SSR 项目部署流程：
│
├── 第一步：构建项目（npm run build → .nuxt 或 .next，入口 server.js）
├── 第二步：准备服务器（安装 Node.js、PM2、Nginx）
├── 第三步：上传文件（构建产物、package.json、npm install --omit=dev、配置环境变量）
├── 第四步：启动应用（pm2 start、pm2 save、pm2 startup）
├── 第五步：配置 Nginx 反向代理（upstream、proxy_pass、重启 Nginx）
└── 第六步：测试访问
```

**Nginx 反向代理配置**：

```11-Nginx基础概述
# /etc/11-Nginx基础概述/conf.d/ssr-app.conf

upstream ssr_app {
    server 127.0.0.1:3000;
    keepalive 64;
}

server {
    listen 80;
    server_name site1.com;

    location / {
        proxy_pass http://ssr_app;
        proxy_http_version 1.1;

        # 请求头配置
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时配置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

### 5.3 Nginx 配置完整示例（含 Gzip 与 HTTPS）

```11-Nginx基础概述
# /etc/11-Nginx基础概述/conf.d/site1.conf

# HTTP 配置（端口 80）
server {
    listen 80;
    server_name site1.com;

    root /home/website/project-front-vue3;
    index index.html;

    access_log /var/log/11-Nginx基础概述/site1.access.log;
    error_log /var/log/11-Nginx基础概述/site1.error.log;

    location / {
        # 支持 Vue Router history 模式
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存（1 年）
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {

    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript application/x-javascript application/xml+rss application/json;

        deny all;
    }
```

## 六、常见问题与解决方案

### 6.1 常见问题排查

| 问题 | 排查/解决 |
|------|-----------|
| Nginx 配置语法错误 | 检查配置语法、分号、大括号匹配，用 `11-Nginx基础概述 -t` 测试 |
| 404 Not Found | 检查 root 路径、index.html 是否存在、文件权限 chmod 755/644 |
| 403 Forbidden | 检查文件权限、SELinux（`getenforce`，必要时 `setenforce 0`）、Nginx 用户权限 |
| 域名无法解析 | 检查 hosts、resolv.conf，使用公共 DNS（8.8.8.8） |
| 文件上传失败 | 检查 SSH 服务、防火墙（ufw allow 22）、磁盘空间、目录权限 |

### 6.2 权限问题

```bash
# 修改目录所有者与权限
sudo chown -R www-data:www-data /home/website/project-front-vue3/
sudo chmod -R 755 /home/website/project-front-vue3/
sudo find /home/website/project-front-vue3/ -type f -exec chmod 644 {} \;
```

## 七、最佳实践

- **构建优化**：开启 Gzip 压缩、代码分割、CDN 加速静态资源、缓存策略
- **Nginx 配置优化**：开启 Gzip、静态资源缓存、HTTP/2、SSL/HTTPS
- **安全性**：使用 HTTPS、配置 CSP、禁止访问隐藏文件、配置防火墙
- **监控与日志**：配置访问日志、错误日志、PM2 监控（SSR）
- **自动化部署**：使用 CI/CD（GitHub Actions）、自动化脚本、Docker 容器化、Kubernetes 编排

### 7.1 GitHub Actions 自动化部署

```yaml
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build project
        run: npm run build

      - name: Deploy to server
        uses: appleboy/scp-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          source: "dist/*"
          target: "/home/website/project-front-vue3"
```

### 7.2 Docker 容器化部署

```dockerfile
# 构建阶段
```

| `scp -r dist/* user@server:/path/` | 使用 SCP 上传 |
| `rsync -avz dist/ user@server:/path/` | 使用 rsync 同步 |
| `chmod 755 directory` / `chmod 644 file` | 修改权限 |
| `chown -R user:group directory` | 修改所有者 |

## 总结

前端项目部署是全栈开发的核心技能，掌握三种部署场景（SPA/SSG/SSR）、Nginx 配置、域名配置、文件上传、PM2 进程管理对实际项目部署非常重要。生产环境推荐使用 CI/CD 自动化部署和 Docker 容器化部署，提高部署效率和可靠性。

# 对象存储与文件上传

## 概念说明

文件上传是常见需求。一般不会把文件直接保存在应用服务器的某个目录下,原因有两点:

- 服务器存储容量有限,不好扩展;
- 文件散落在应用服务器上,不好管理。

工程实践中通常使用 OSS(Object Storage Service)对象存储服务来存文件。它支持分布式扩展,不存在存储容量瓶颈,且便于管理,例如阿里云的 OSS 服务。

某些业务场景下,数据需要保密、要求私有部署,即在自己的机房里部署一套 OSS 服务。这类需求一般使用 minio 实现,它可以提供与阿里云 OSS 一致的功能。

本篇覆盖四个主题:阿里云 OSS 与 minio 的管理界面和 SDK 上传下载、服务端生成预签名 URL 实现前端直传 minio、大文件分片上传与合并、阿里云 OSS 的 accessKey 安全体系与 PostSignature 临时凭证直传。

## 一、对象存储的原理

### 本地文件存储与对象存储的结构差异

本地文件存储是"目录-文件"的组织方式;OSS 服务的存储结构是一个 Bucket(桶)里放一些文件(Object)。

阿里云 OSS 的控制台明确提到:对象存储没有目录层级结构。控制台里看似支持"目录",其实只是模拟实现——Object 会存储 id、文件内容、元数据三部分信息,阿里云 OSS 是用元信息部分模拟实现了目录。这就像打了个 tag:文件并非真的存储在这个 tag 之下,只是可以用这个 tag 来检索文件。

### 阿里云的三种存储方式

除对象存储 OSS 外,阿里云还提供文件存储和块存储:

- **块存储**:把整块磁盘提供给使用者,需要自行格式化,存储容量有限;
- **文件存储**:有目录层次结构,可上传下载文件,存储容量有限;
- **对象存储**:key-value 存储,以分布式方式实现,存储容量无限。

绝大多数场景下使用的是 OSS 对象存储。

### S3 规范:各家 OSS 相似的原因

阿里云 OSS、minio 等对象存储服务的用法高度相似,根本原因是它们都遵循 AWS 的 Simple Storage Service(S3)规范,简称 S3 规范。所以不管哪家的 OSS,用起来都差不多。

## 二、阿里云 OSS 的使用

### 控制台操作

OSS 里的文件放在一个个 Bucket(桶)里。基本操作流程:

1. 创建 Bucket,可将访问权限设置为公共读;
2. 进入文件列表上传文件;
3. 因为 Bucket 设置了公共读,文件可以直接通过 URL 访问;若保持私有,访问每个文件都要带上身份信息。

关于地域与访问速度:静态文件存在北京的服务器上,全国各地访问速度是否会很慢?这不是 OSS 的职责,而是 CDN 的职责。接入 CDN 后,访问该域名会走到云服务的 DNS,返回一台最近的缓存服务器地址,该服务器从源站拿文件来缓存,之后不再访问源站——这里的源站就可以是 OSS 服务。生产环境下一般不会直接用 OSS 的 URL 访问,而是开启 CDN、用网站域名访问,最终回源到 OSS 服务。

## 三、使用 minio 搭建私有 OSS 服务

### Docker 部署

首先安装 [docker 桌面端](https://www.docker.com/),打开后可以看到本地的所有镜像和容器。搜索 minio(该步骤需要科学上网)并创建容器,填入的信息含义如下:

- **name**:容器名;
- **port**:映射本地 9000 和 9001 端口到容器内的端口;
- **volume**:挂载本地目录到容器内的目录。这里挂载本地一个目录到容器内的数据目录 `/bitnami/minio/data`,这样容器里的各种数据都保存在本地;
- **环境变量**:指定 `MINIO_ROOT_USER` 和 `MINIO_ROOT_PASSWORD`,用于登录。

点击 run 跑起来之后,可以看到数据目录被标记为 mounted,端口映射成功。访问 `http://localhost:9001`,输入环境变量中填写的用户名密码进入管理界面。其中 bucket 是管理桶的地方,object browser 是管理文件列表的地方。

### 管理界面操作

管理界面的用法与阿里云 OSS 一致:

1. 创建 bucket;
2. 在该 bucket 下上传一个文件;
3. 点击 share 可以看到这个文件的 URL。此时能在浏览器访问,但需要带上一长串签名参数,不带会提示拒绝访问——因为文件访问权限不是公开的;
4. 设置匿名访问规则:添加一个 `/` 的匿名访问规则,之后就可以直接访问了。

### SDK 上传下载

安装 minio 包:


创建 index2.js:

用法与阿里云 OSS 几乎完全一致,更多的 API 用法可以看 [minio 文档](https://min.io/docs/minio/linux/developers/javascript/minio-javascript.html)。由于部署容器时指定了挂载目录,所有数据都会保存在本地对应目录下。

## 四、前端直传方案

### 三种上传路径的对比

使用 OSS 服务后,上传文件有三种路径:

1. **服务器中转**:前端把文件上传到应用服务器,应用服务器再上传到阿里云或 minio。文件传两次,浪费流量,没有必要;
2. **客户端直接用 accessKey 直传**:前端把文件直接传给 OSS,再把文件 URL 给应用服务器。减少了流量消耗,但把 accessKey 暴露给前端不安全;
3. **临时凭证/预签名直传(推荐)**:应用服务器返回一个临时凭证或预签名 URL,前端用它直传 OSS,不需要把 accessKey 暴露给前端。阿里云 OSS 与 minio 都支持这种方式。

### minio 预签名直传

前端直传 minio 需要服务端生成临时凭证,因此先创建一个 Nest 服务:

```
nest new minio-fe-upload
```

安装 minio 包:

```
npm install --save minio
```

创建一个模块:

```
nest g module minio
```

```javascript
import { Global, Module } from '@nestjs/common';
import * as Minio from 'minio';

export const MINIO_CLIENT = 'MINIO_CLIENT';

@Global()
@Module({
    providers: [
        {
            provide: MINIO_CLIENT,
            async useFactory() {
                const client = new Minio.Client({
                        endPoint: 'localhost',
                        port: 9000,
                        useSSL: false,
                        accessKey: '',
                        secretKey: ''
                    })
                return client;
            }
          }
    ],
    exports: [MINIO_CLIENT]
})
export class MinioModule {}
```

这段代码把 minio client 封装成 provider,放到 exports 里,并设置模块为 `@Global`。其中用到的 accessKey 和 secretKey 需要提前创建。

在 AppController 里注入测试:

```javascript
import { Controller, Get, Inject } from '@nestjs/common';
import { AppService } from './app.service';
import { MINIO_CLIENT } from './minio/minio.module';
import * as Minio from 'minio';

@Controller()
export class AppController {
  constructor(private readonly appService: AppService) {}

  @Inject(MINIO_CLIENT)
  private minioClient: Minio.Client;

  @Get('test')
  async test() {
    try {
      await this.minioClient.fPutObject('aaa', 'hello.json', './package.json');
      return 'http://localhost:9000/aaa/hello.json';
    } catch(e) {
      console.log(e);
      return '上传失败';
    }
  }

  @Get()
  getHello(): string {
    return this.appService.getHello();
  }
}
```

注入 Minio Client,在 test 接口里上传文件。启动服务:

```
npm run start:dev
```

访问 test 接口即可上传成功。

接下来做前端直传。指定 public 为静态文件目录:

```javascript
import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);

  app.useStaticAssets('public');

  await app.listen(3000);
}
bootstrap();
```

编写前端代码 public/index.html(源自 [minio 官方文档](https://min.io/docs/minio/linux/integrations/presigned-put-upload-via-browser.html)):

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <input type="file" id="selector" multiple>
    <button onclick="upload()">Upload</button>
    <div id="status">No uploads</div>

    <script type="text/javascript">
        function upload() {
            var files = document.querySelector("#selector").files;
            for (var i = 0; i < files.length; i++) {
                var file = files[i];
                retrieveNewURL(file, (file, url) => {
                    uploadFile(file, url);
                });
            }
        }

        function retrieveNewURL(file, cb) {
            fetch(`/presignedUrl?name=${file.name}`).then((response) => {
                response.text().then((url) => {
                    cb(file, url);
                });
            }).catch((e) => {
                console.error(e);
            });
        }

        function uploadFile(file, url) {
            if (document.querySelector('#status').innerText === 'No uploads') {
                document.querySelector('#status').innerHTML = '';
            }
            fetch(url, {
                method: 'PUT',
                body: file
            }).then(() => {
                document.querySelector('#status').innerHTML += `<br>Uploaded ${file.name}.`;
            }).catch((e) => {
                console.error(e);
            });
        }
    </script>
</body>
</html>
```

页面逻辑:一个 type 为 file 的 input,支持多选;点击上传时遍历文件,对每个文件调用服务端的 presignedUrl 接口进行 URL 签名,之后用返回的 URL 直传 OSS。这里用 fetch 上传,换成 axios 也一样。

在服务端增加签名接口:

```javascript
@Get('presignedUrl')
async presignedUrl(@Query('name') name: string) {
    return this.minioClient.presignedPutObject('aaa', name, 3600);
}
```

参数说明:第一个参数是 bucketName,第二个参数是 objectName(需要文件上传时拿到 file.name 作为参数传过来),第三个参数是过期时间,这里指定 3600 秒即一小时。

签名后的 URL 其实就是在 URL 里带上了鉴权信息。这样,前端不需要 accessKey 也可以直传文件到 minio。

### 阿里云 OSS PostSignature 直传

服务端生成临时签名的代码如下([阿里云文档](https://help.aliyun.com/zh/oss/user-guide/authorized-third-party-upload)中给出的方案):

```javascript
const OSS = require('ali-oss')

async function main() {

    const config = {
        region: 'oss-cn-beijing',
        bucket: 'guang-333',
        accessKeyId: '你的AccessKeyId',
        accessKeySecret: '你的AccessKeySecret',
    }

    const client = new OSS(config);

    const date = new Date();

    date.setDate(date.getDate() + 1);

    const res = client.calculatePostSignature({
        expiration: date.toISOString(),
        conditions: [
            ["content-length-range", 0, 1048576000], //设置上传文件的大小限制。
        ]
    });

    console.log(res);

    const location = await client.getBucketLocation();

    const host = `http://${config.bucket}.${location.location}.aliyuncs.com`;

    console.log(host);
}

main();

```

运行后可以得到上传 OSS 的地址(host),以及临时 signature 和 policy。这段代码无需记忆,文档里都有。

网页端使用这些信息直传 OSS,创建 index.html:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="https://unpkg.com/axios@1.6.5/dist/axios.min.js"></script>
</head>
<body>
    <input id="fileInput" type="file"/>

    <script>
        const fileInput = document.getElementById('fileInput');

        async function getOSSInfo() {
            await '请求应用服务器拿到临时凭证';
            return {
                OSSAccessKeyId: '你的AccessKeyId',
                Signature: '服务端返回的签名',
                policy: '服务端返回的 policy',
                host: 'http://guang-333.oss-cn-beijing.aliyuncs.com'
            }
        }

        fileInput.onchange = async () => {
            const file = fileInput.files[0];

            const ossInfo = await getOSSInfo();


            const formdata = new FormData()

            formdata.append('key', file.name);
            formdata.append('OSSAccessKeyId', ossInfo.OSSAccessKeyId)
            formdata.append('policy', ossInfo.policy)
            formdata.append('signature', ossInfo.Signature)
            formdata.append('success_action_status', '200')
            formdata.append('file', file)

            const res = await axios.post(ossInfo.host, formdata);
            if(res.status === 200) {

                const img = document.createElement('img');
                img.src = ossInfo.host + '/' + file.name
                document.body.append(img);

                alert('上传成功');
            }
        }
    </script>
</body>
</html>
```

说明:getOSSInfo 应请求服务端的接口,拿到服务端输出的临时凭证;示例为简化流程直接写死在代码里。页面引入 axios,用这些信息构造 FormData(key、OSSAccessKeyId、policy、signature、success_action_status、file)后 POST 到 host 即可完成直传。

用静态服务器跑起来:

```
npx http-server .
```

上传文件时会提示跨域错误,需在 OSS 控制台开启跨域设置,之后即可上传成功,控制台文件列表中也能看到该文件。

这套方案的要点:服务端用 RAM 子用户的 accessKey 生成临时签名并返回给客户端,客户端用它直传文件到 OSS;由于临时签名过期时间很短(示例设置为一天),暴露的风险也不大;服务端完全没有接收文件的压力,只要等客户端上传完之后带上 URL 即可。

## 五、大文件分片上传

### 原理

文件上传只要指定 content-type 为 multipart/form-data,内容就会以这种格式传递到服务端,服务端按 multipart/form-data 的格式提取数据即可拿到文件。但当文件很大时,体验会变差:假设传一个 100M 的文件需要 3 分钟,那传一个 1G 的文件就需要 30 分钟。

大文件上传的优化方案是**分片上传**:

1. 把 1G 的大文件分割成 10 个 100M 的小文件;
2. 这些小文件并行上传;
3. 全部传完之后,发一个请求把这 10 个小文件合并成原来的大文件。

拆分与合并的技术基础:

- **拆分**:浏览器里 Blob 有 slice 方法,可以截取某个范围的数据,而 File 就是一种 Blob,所以在 input 里选择了 file 之后,可以通过 slice 对 File 分片;
- **合并**:fs 的 createWriteStream 方法支持指定 start(从什么位置开始写入),把每个分片按照不同位置写入文件里,即完成合并。

### 服务端接收分片

创建 Nest 项目:

```javascript
npm install -g @nestjs/cli

nest new large-file-sharding-upload
```

在 AppController 添加一个路由:

```javascript
@Post('upload')
@UseInterceptors(FilesInterceptor('files', 20, {
  dest: 'uploads'
}))
uploadFiles(@UploadedFiles() files: Array<Express.Multer.File>, @Body() body) {
  console.log('body', body);
  console.log('files', files);
}
```

这是一个 post 接口,会读取请求体里的 files 文件字段传入该方法。还需要安装用到的 multer 包的类型:

```
npm install -D @types/multer
```

### 前端分片上传

先做一个多文件上传的对照版本以理解 FormData 的行为。在 main.ts 里开启跨域支持,然后添加一个 index.html:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="https://unpkg.com/axios@0.24.0/dist/axios.min.js"></script>
</head>
<body>
    <input id="fileInput" type="file" multiple/>
    <script>
        const fileInput = document.querySelector('#fileInput');

        fileInput.onchange =  async function () {
            const data = new FormData();
            data.set('name','光');
            data.set('age', 20);

                data.append('files', item)

```

input 指定 multiple 可以选择多个文件;选择文件之后通过 post 请求 upload 接口,携带 FormData,FormData 里保存着 files 和其它字段。用 `npx http-server .` 起一个静态服务,在浏览器访问即可看到 Nest 服务端接收到了上传的文件和其他字段。

实际要上传的不是多个文件,而是一个大文件的多个分片,所以改为:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="https://unpkg.com/axios@0.24.0/dist/axios.min.js"></script>
</head>
<body>
    <input id="fileInput" type="file"/>
    <script>
        const fileInput = document.querySelector('#fileInput');

        const chunkSize = 20 * 1024;

        fileInput.onchange =  async function () {

            const file = fileInput.files[0];

            console.log(file);

            const chunks = [];
            let startPos = 0;
            while(startPos < file.size) {
                chunks.push(file.slice(startPos, startPos + chunkSize));
                startPos += chunkSize;
            }

            chunks.map((chunk, index) => {
                const data = new FormData();
                data.set('name', file.name + '-' + index)
                data.append('files', chunk);
                axios.post('http://localhost:3000/upload', data);
            })

        }

    </script>
</body>
</html>
```

这段代码对拿到的文件进行分片,然后单独上传每个分片,分片名字为"文件名 + index"。例如测试图片为 80k,每 20k 一个分片,一共 4 个分片。

### 分片归档

服务端把收到的分片移动到单独的目录:

```javascript
@Post('upload')
@UseInterceptors(FilesInterceptor('files', 20, {
  dest: 'uploads'
}))
uploadFiles(@UploadedFiles() files: Array<Express.Multer.File>, @Body() body: { name: string }) {
  console.log('body', body);
  console.log('files', files);

  const fileName = body.name.match(/(.+)\-\d+$/)[1];
  const chunkDir = 'uploads/chunks_'+ fileName;

  if(!fs.existsSync(chunkDir)){
    fs.mkdirSync(chunkDir);
  }
  fs.cpSync(files[0].path, chunkDir + '/' + body.name);
  fs.rmSync(files[0].path);
}
```

实现逻辑:用正则匹配出文件名;在 uploads 下创建 chunks_文件名 目录,把文件复制过去,然后删掉原始文件。

注意:直接以 chunks_文件名 作为目录名太容易冲突,可以在上传文件的时候给文件名加一个随机字符串,这样就不会冲突了。

### 合并分片

全部分片上传完之后,发送合并分片的请求。添加一个 merge 接口:

```javascript
@Get('merge')
merge(@Query('name') name: string) {
    const chunkDir = 'uploads/chunks_'+ name;

    const files = fs.readdirSync(chunkDir);

    let startPos = 0;
    files.map(file => {
      const filePath = chunkDir + '/' + file;
      const stream = fs.createReadStream(filePath);
      stream.pipe(fs.createWriteStream('uploads/' + name, {
        start: startPos
      }))

      startPos += fs.statSync(filePath).size;
    })
}
```

接口接收文件名,查找对应的 chunks 目录,把下面的文件读取出来,按照不同的 start 位置写入到同一个文件里,浏览器访问该接口即可完成合并。

合并完成之后把 chunks 目录删掉:

```javascript
@Get('merge')
merge(@Query('name') name: string) {
    const chunkDir = 'uploads/chunks_'+ name;

    const files = fs.readdirSync(chunkDir);

    let count = 0;
    let startPos = 0;
    files.map(file => {
      const filePath = chunkDir + '/' + file;
      const stream = fs.createReadStream(filePath);
      stream.pipe(fs.createWriteStream('uploads/' + name, {
        start: startPos
      })).on('finish', () => {
        count ++;

        if(count === files.length) {
          fs.rm(chunkDir, {
            recursive: true
          }, () =>{});
        }
      })

      startPos += fs.statSync(filePath).size;
    });
}
```

前端代码里,当分片全部上传完之后调用 merge 接口:

```javascript
const tasks = [];
chunks.map((chunk, index) => {
    const data = new FormData();

    data.set('name', randomStr + '_' + file.name + '-' + index)
    data.append('files', chunk);
    tasks.push(axios.post('http://localhost:3000/upload', data));
})
await Promise.all(tasks);
axios.get('http://localhost:3000/merge?name=' + randomStr + '_' + file.name);
```

连起来测试时,因为文件比较小,可开启 network 的 slow 3g 网速来测,分片上传和最后的合并都没有问题。此外还可以加一个进度条,用 axios 很容易实现。

[阿里云的大文件分片上传](https://help.aliyun.com/zh/oss/user-guide/multipart-upload)也是这样实现的,具体用法直接看文档即可。

## 六、accessKey 与阿里云安全体系

### 为什么用 accessKey 而不是用户名密码

本来身份认证都是通过用户名密码,但这样不够安全——密码泄漏就麻烦了。所以阿里云创建了 accessKey 来代表身份,用它做身份认证,即使泄漏了也可以禁用,且不影响别的凭证。

### RAM 子用户与最小权限

打开 accessKey 管理页面时,阿里云会提示不要直接用主账号的 accessKey,而是创建一个子用户(RAM 用户)再创建 accessKey。使用子用户的 accessKey 时,直接替换主账号 accessKey 会收到 403 没有权限的错误,需要为新用户授权:新增一个授权,把 OSS 的管理和读取权限给这个子用户,之后即可正常调用。

这套安全设计的层次:

1. 用户名密码验证:一旦泄漏就很麻烦;
2. accessKey 认证:泄漏了可以禁用;
3. RAM 子用户 + accessKey:先创建子用户再分配特定权限,即使泄漏,能做的事情也更少,更加安全。

另外,一般的文件直接上传即可,涉及大文件时就要分片上传:[阿里云的大文件分片上传](https://help.aliyun.com/zh/oss/user-guide/multipart-upload)与上述分片实现原理一致,具体用法直接看文档即可。

### 成本参考

购买 [阿里云的 OSS 服务](https://www.aliyun.com/product/oss) 成本很低,例如 40G 的 OSS 国内通用资源包花费 5 元。在北京创建 Bucket 后,文件就会存储在那里的服务器上。

## 实践要点

- 生产环境的文件存储使用 OSS 对象存储,敏感数据私有部署时用 minio 自建;
- Bucket 权限按需选择:公共读可直接访问,私有访问需带身份信息或签名;minio 中通过添加 `/` 的匿名访问规则放开公开访问;
- 前端上传一律走"服务端生成临时凭证/预签名 URL → 客户端直传 OSS"的路径,兼顾流量消耗与 accessKey 安全;minio 用 `presignedPutObject`,阿里云用 `calculatePostSignature`;
- 阿里云直传需要在控制台开启跨域(CORS)设置;
- accessKey 建议通过 RAM 子用户生成并授予最小权限,不要直接使用主账号 accessKey;
- 大文件上传采用分片方案:前端 `Blob.slice` 分片并行上传,分片名带上随机字符串避免目录冲突,后端按 `fs.createWriteStream` 的 start 参数合并,并在合并完成后清理分片目录;
- 各家 OSS 都遵循 S3 规范,API 形态高度相似,迁移成本小。

## 小结

文件上传一般不直接存服务器目录(不好扩展),而是使用阿里云 OSS 等对象存储服务;OSS 收费且敏感数据不能上云时,可以用 docker 跑一个 minio 容器私有部署,在管理界面或通过 npm 包完成上传下载,用法与阿里云 OSS 基本一致(同为 S3 规范实现)。上传路径上,客户端直传配合服务端预签名/临时凭证是最优解:minio 通过 `presignedPutObject` 生成带鉴权信息的 URL,阿里云通过 `calculatePostSignature` 输出 signature 与 policy,服务端零文件压力、accessKey 不暴露;大文件再叠加 Blob.slice 分片与 createWriteStream 指定 start 的合并方案,即可覆盖工作中 OSS 使用的完整场景。

# 会议室项目-统计与账号登录

本文覆盖四部分内容：统计模块（typeorm queryBuilder + echarts）、用 typeorm migration 替代 synchronize 管理表结构与初始化数据、头像直传 minio OSS、集成 passport 并实现 Google 三方登录。

## 一、统计模块

### 需求分析

用户模块、会议室模块、预订模块完成之后，还剩统计模块。该模块只有 2 个统计功能：统计会议室的使用频率、用户的预订频率。没有新的实体，只是对已有数据的统计。

在 [echarts 官网](https://echarts.apache.org/handbook/zh/how-to/chart-types/bar/basic-bar)可以看到，柱形图和饼图都只需要一个二维的数据，即 `[[a, b], [a, b], [a, b]]` 这样的形式。

### 统计 SQL

先在数据库里写下用户预订频率的 sql：

```sql
select u.username 用户名, count(*) 预订次数
from booking b
left join users u
on b.userId = u.id
where b.startTime between '2023-09-24' and '2023-09-30'
group by b.userId;

```

该 sql 关联 users 和 booking 表，过滤出这段日期内的预订记录，根据用户分组，统计每组的预订数量——查询出来的就是这段时间内每个用户预订了多少次会议室。

同理，统计会议室被预订的频率只需把关联的表换成 meeting_room：

```sql
select m.name 会议室名字, count(*) 预订次数
from booking b
left join meeting_room m
on b.roomId = m.id
where b.startTime between '2023-09-24' and '2023-09-30'
group by b.roomId;
```

当前数据不多，可以通过 mysql workbench 的 copy row 和 paste row 快速复制一些数据（复制出来的数据要修改 id 及其他信息），并指定不同的 userId 和 roomId，点击 apply 应用修改。之后重跑两个统计 sql 验证，结果无误即可进入 Nest 实现。

```javascript
                time1: '2023-09-24',
                time2: '2023-09-30'
            })
            .addGroupBy('b.user')
            .getRawMany();
```

## 二、typeorm migration 替代 synchronize

### 背景与问题

项目部署到阿里云后，已能在全球各地通过 ip 访问，方式是服务器上通过 git 下载代码、用 docker compose 跑。但 typeorm 的 synchronize 没有关掉，也就是仍在根据 entity 自动创建表。

这种方式并不安全：entity 一改，表结构就自动跟着改，容易丢数据。生产环境应该把 synchronize 关掉，用 migration 来管理创建表、数据初始化、表结构修改等操作。

### 导出现有数据

首先在 mysql workbench 里把现有数据导出。先按每表一个 sql 文件导出，再选择第二个选项重新导出，把所有表集中到一个 sql 文件里。打开生成的 sql 文件，包含所有表的 create table 和 insert into 语句——后面初始化数据时会用到。

### 配置 migration

在项目的 package.json 里加 migration 的 npm scripts：

```javascript
"typeorm": "ts-node ./node_modules/typeorm/cli",
"migration:create": "npm run typeorm -- migration:create",
"migration:generate": "npm run typeorm -- migration:generate -d ./src/data-source.ts",
"migration:run": "npm run typeorm -- migration:run -d ./src/data-source.ts",
"migration:revert": "npm run typeorm -- migration:revert -d ./src/data-source.ts"
```

migration 需要单独一个 data-source.ts 文件，创建 src/data-source.ts：

```javascript
import { DataSource } from "typeorm";
import { config } from 'dotenv';

import { Permission } from './user/entities/permission.entity';
import { Role } from './user/entities/role.entity';
import { User } from './user/entities/user.entity';
import { MeetingRoom } from "./meeting-room/entities/meeting-room.entity";
import { Booking } from "./booking/entities/booking.entity";

config({ path: 'src/.env-migration' });

console.log(process.env);

export default new DataSource({
    type: "mysql",
    host: `${process.env.mysql_server_host}`,
    port: +`${process.env.mysql_server_port}`,
    username: `${process.env.mysql_server_username}`,
    password: `${process.env.mysql_server_password}`,
    database: `${process.env.mysql_server_database}`,
    synchronize: false,
    logging: true,
    entities: [
      User, Role, Permission, MeetingRoom, Booking
    ],
    poolSize: 10,
    migrations: ['src/migrations/**.ts'],
    connectorPackage: 'mysql2',
    extra: {
        authPlugin: 'caching_sha2_password',
    }
});
```

synchronize 指定为 false，同时把 AppModule 里的 synchronize 也改为 false。

创建单独的 .env-migration 文件：

```javascript
mysql_server_host=localhost
mysql_server_port=3306
mysql_server_username=root
mysql_server_password=guang
mysql_server_database=meeting_room_booking_system
```

单独建一个 env 文件的原因：.env 里配置的 host 是容器名，只对 docker compose 内部生效；migration 时需要真实的 host 地址。

### 生成并执行建表迁移

跑 migration:generate 试试：

```
npm run migration:generate src/migrations/init
```

如果遇到找不到 entity 的错误，把绝对路径改为相对路径即可。此时没有更改，因为 entity 和数据库表是同步的。把数据表删掉后再跑：

```
npm run migration:generate src/migrations/init
```

成功生成迁移代码，里面包含所有表的 create table 语句。执行迁移：

```
npm run migration:run
```

## 三、头像直传 minio OSS

### 本地存储的问题

之前的头像上传实现：图片保存在服务器 uploads 目录下，把该目录设置为静态文件目录后图片可以直接访问，数据库里保存的也是这个路径。功能上能完成，但有两个问题：

- 文件直接保存在某个目录下，服务器磁盘空间有上限，满了之后无处安放；
- 这些文件没有管理界面，管理不方便。

所以实际项目中都用 OSS 来做文件管理，比如阿里云 OSS，或者用 minio 自己搭的 OSS 服务。以下把头像上传到 minio 搭建的 OSS。

### 启动 minio 服务

把 minio 的 docker 镜像跑起来：指定本地某个目录映射到容器里的 /bitnami/minio/data 目录；指定端口 9000 和 9001 的映射（9000 是文件访问端口，9001 是管理页面端口）；指定登录用户名、密码 MINIO_ROOT_USER、MINIO_ROOT_PASSWORD。

跑起来之后访问 http://localhost:9001 ，输入用户名密码登录，创建一个 bucket 并设置公开访问，然后上传一个文件，复制路径在浏览器访问：

```text
http://localhost:9000/meeting-room-booking-system/headpic1.jpg
```

文件就上传到了 OSS 的 bucket 并且可以访问——比直接放文件目录方便得多。前端直传 minio 的流程：上传完把 url 给服务端保存到数据库即可。但 accessKey 不能暴露到前端代码里，需要在服务端做预签名。

### 服务端封装 MinioModule 与预签名接口

进入 backend 项目，安装 minio 的包：

```
npm install --save minio
```

创建 minio 模块：

```
nest g module minio
```

```javascript

import * as Minio from 'minio';

@Global()
@Module({
    providers: [
        {
            provide: 'MINIO_CLIENT',
            async useFactory() {
                const client = new Minio.Client({
                        endPoint: 'localhost',

                        secretKey: ''

            }
          }

```

把 minio client 封装成 provider，放到 exports 里，并设置模块为 @Global。accessKey 和 secretKey 在 minio 管理界面创建。这些配置也可以放到配置文件里：

```

minio_port=9000
minio_access_key=xxx
minio_secret_key=xxx
```

因为 ConfigModule 声明为了全局模块，可以直接在 MinioModule 里注入 ConfigService：


```
nest g controller minio --no-spec
```

```javascript
import { Controller, Get, Inject, Query } from '@nestjs/common';
import * as Minio from 'minio';

@Controller('minio')
export class MinioController {

    @Inject('MINIO_CLIENT')
    private minioClient: Minio.Client;

    @Get('presignedUrl')
    presignedPutObject(@Query('name') name: string) {
        return this.minioClient.presignedPutObject('meeting-room-booking-system', name, 3600);
    }
}
```

presignedPutObject 的参数说明：

- 第一个参数 bucketName：即 meeting-room-booking-system（也可以抽到 .env 文件里用 configService 读取）；
- 第二个参数 objectName：上传文件时拿 file.name 作为参数传入；
- 第三个参数 expires：生成的临时签名的过期时间，指定 3600 秒（一小时）。

调用该接口会返回文件的预签名 url，前端不需要 accessKey 也可以用这个 url 上传文件到 minio。

### 前端 Dragger 直传

在 frontend_user 项目里使用。之前指定了 action 参数，选择文件后 antd 的 Dragger 组件会自动上传文件；它还支持函数形式，传入 file 做处理后返回 url——正好可以调用 presignedUrl 接口拿到直传 minio 的 url。

在 interfaces.ts 添加接口：

```javascript
export async function presignedUrl(fileName: string) {
    return axiosInstance.get(`/minio/presignedUrl?name=${fileName}`);
}
```

action 调用并配合 customRequest：

```javascript
action: async (file) => {
    const res = await presignedUrl(file.name);
    return res.data.data;
},
async customRequest(options) {
    const { onSuccess, file, action } = options;

    const res = await axios.put(action, file);

    onSuccess!(res.data);
},
```

**为什么要 customRequest？** 因为默认 Dragger 用 FormData 的格式上传（key value 格式，指定的 name 就是 key）；而 minio 要求直接把文件放到 body 里，所以要用 customRequest 自定义请求方式。

测试上传成功后，minio 管理界面可以看到该文件。接下来修改 onChange 的值和回显图片的 url 即可：

```javascript
onChange('http://localhost:9000/meeting-room-booking-system/' + info.file.name);
```

输入验证码、点击修改会提示更新成功，数据库里头像路径也已更新。基于 minio OSS 的图片上传功能完成。

## 四、集成 passport 与 Google 三方登录

### 三方登录的价值

网站此前实现了用户名密码登录，忘记密码可以通过邮箱验证码修改后再登录。功能没问题但不方便：用户会访问很多网站，每个网站都注册账号的话，不常用的网站很容易忘记账号密码。解决方式是支持三方账号登录——例如 [dockerhub 的登录](https://login.docker.com/u/login)：用 google、github 账号授权后 dockerhub 就可以自动登录，不需要单独的账号密码。

原理：网站用用户的 github、google 信息创建了一个账号，之后只要同样的 github、google 信息就可以自动登录。第一次授权时因缺少 username 信息，会跳转页面让用户填写后完成注册并自动登录；之后退出再用 google 登录，由于已授权过，短时间内不需要再次授权，直接登录。

### 集成 passport（用户名密码登录）

会议室预订系统集成 google 登录需要 passport-google 策略，因此先集成 passport。进入 backend 项目安装 passport 的包：

```
npm install --save @nestjs/passport passport
```

安装用户名密码认证的 passport-local 策略包：

```
npm install --save passport-local
npm install --save-dev @types/passport-local
```

创建认证模块：

```
nest g module auth
```

添加用户名密码认证的策略 auth/local.strategy.ts：

```javascript
import { Strategy } from 'passport-local';
import { PassportStrategy } from '@nestjs/passport';
import { Injectable, UnauthorizedException } from '@nestjs/common';

@Injectable()
export class LocalStrategy extends PassportStrategy(Strategy) {

  async validate(username: string, password: string) {

  }
}
```

LocalStrategy 里需要用到 UserService：在 UserModule 导出 UserService，然后 AuthModule 引入 UserModule，并把 LocalStrategy 声明为 provider。LocalStrategy 直接复用 userService.login 做登录认证，passport 会把返回的 user 信息放在 request.user 上。

然后 user/login 里不需要再手动调用 userService，改用 `AuthGuard('local')` 处理，处理完从 request.user 里拿 user 信息。


### Google 登录后端

在 [passport 的网站](https://www.passportjs.org/packages/)搜索 passport-google-oauth20，找下载量最多的那个，安装：

```
npm install --save passport-google-oauth20
npm install --save-dev @types/passport-google-oauth20
```

获取 client id 和 client secret 的步骤：打开 Google Cloud 控制台创建应用。授权的域名、callback url 要和应用中的对应，否则重新注册一个应用。

创建 auth/google.strategy.ts：

```javascript
import { Injectable } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { Strategy } from 'passport-google-oauth20';

@Injectable()
export class GoogleStrategy extends PassportStrategy(Strategy, 'google') {
  constructor() {
    super({
      clientID: '你的 clientID',
      clientSecret: '你的 clientSecret',
      callbackURL: 'http://localhost:3005/user/callback/google',
      scope: ['email', 'profile'],
    });
  }

  validate (accessToken: string, refreshToken: string, profile: any) {
    const { name, emails, photos } = profile
    const user = {
      email: emails[0].value,
      firstName: name.givenName,
      lastName: name.familyName,
      picture: photos[0].value,
      accessToken
    }
    return user;
  }
}
```

填入自己的 clientID、clientSecret、callbackURL，在 AuthModule 引入 GoogleStrategy。之后在 UserController 添加两个路由（一个触发登录、一个回调）：

```javascript

async googleAuth() {}

@Get('callback/google')
@UseGuards(AuthGuard('google'))
googleAuthRedirect(@Req() req) {
    if (!req.user) {
      return 'No user from google'
    }

    return {
      message: 'User information from google',
      user: req.user
    }
}
```

测试可见 google 的用户信息已拿到。只要在拿到用户信息时自动注册即可。

**google 授权后自动注册**。在 UserService 里添加 registerByGoogleInfo 方法：

```javascript
async registerByGoogleInfo(email: string, nickName: string, headPic: string) {
    const newUser = new User();
    newUser.email = email;
    newUser.nickName = nickName;
    newUser.headPic = headPic;
    newUser.password = '';
    newUser.username = email + Math.random().toString().slice(2, 10);
    newUser.loginType = LoginType.GOOGLE;
    newUser.isAdmin = false;

    return this.userRepository.save(newUser);
}
```

email、nickName、headPic 都基于 google 返回的信息；username 用 email + 随机数生成——反正不需要用户名密码登录，保证唯一即可。

在 UserController 调用：

```javascript
@Get('callback/google')
```

**二次登录直接查询**。google 第一次授权会自动注册并登录，后续不需要注册，所以要加判断：如果 email 能查到用户，就直接登录。

```javascript
@Get('callback/google')
@UseGuards(AuthGuard('google'))
async googleAuthRedirect(@Req() req) {
  if (!req.user) {
    throw new BadRequestException('google 登录失败');
  }

  const foundUser = await this.userService.findUserByEmail(req.user.email);

  if(foundUser) {
    const vo = new LoginUserVo();

    vo.accessToken = this.jwtService.sign({

      userId: vo.userInfo.id
    }, {
      expiresIn: this.configService.get('jwt_refresh_token_expires_time') || '7d'
    });

    return vo;
  } else {
    const user = await this.userService.registerByGoogleInfo(

    });

    vo.refreshToken = this.jwtService.sign({

```


**同步登录状态的思路**：之前的登录流程在 localStorage 里保存了 access_token、refresh_token、user_info 三个信息，这就是登录状态。现在只要判断有这三个 cookie，就设置到 localStorage，然后刷新页面即可。

安装操作 cookie 的包：

```
npm install --save js-cookie
npm i --save-dev @types/js-cookie
```

在 Index 组件里写逻辑：

```javascript
useEffect(() => {
    const userInfo = cookies.get('userInfo');
    const accessToken = cookies.get('accessToken');
    const refreshToken = cookies.get('refreshToken');

    if(userInfo && accessToken && refreshToken) {
        localStorage.setItem('user_info', userInfo);
        localStorage.setItem('access_token', accessToken);
        localStorage.setItem('refresh_token', refreshToken);

        cookies.remove('userInfo');
        cookies.remove('accessToken');
        cookies.remove('refreshToken');
    }
}, []);
```

如果 cookie 包含 userInfo、accessToken、refreshToken，就设置到 localStorage，然后把 cookie 删掉。再次测试登录成功；短时间内再次登录不需要再次授权（[dockerhub](https://hub.docker.com/u/login) 也是同样的机制）。

## 总结

- **统计模块**：用 typeorm queryBuilder 实现两个统计接口（用户预订次数、会议室使用频率），swagger 文档标注 query 参数与返回 vo，前端用 antd Form + echarts 渲染柱形图/饼图。
- **migration**：生产环境关闭 synchronize，用 migration:generate 管理建表与表结构变更，用 migration:create 手写 insert into 完成数据初始化；常见坑是列顺序（insert into 指定列名解决）与外键约束（调整插入顺序解决）。
- **minio OSS**：minio client 封装为全局 provider，通过 presignedPutObject 返回预签名 url 实现前端直传，避免 accessKey 暴露；Dragger 直传需 customRequest 覆盖 FormData 默认行为。
- **Google 三方登录**：passport 集成（local 策略复用 userService.login），GoogleStrategy 拿到 profile 后按 email 判断——已注册直接登录、未注册自动注册（loginType 标记来源），登录态通过 cookie 回传并重定向首页，前端读取 cookie 同步 localStorage 后清除。

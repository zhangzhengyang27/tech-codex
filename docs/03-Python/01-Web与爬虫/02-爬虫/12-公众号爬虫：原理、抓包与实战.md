# 公众号爬虫：原理、抓包与实战

> 前置要求：HTTP 请求与网页解析基础见 [爬虫概览与 HTTP 基础](01-爬虫概览与HTTP基础) 与 [数据解析全攻略](02-数据解析全攻略)；Requests 库的 GET/POST、请求头、Session 用法已在上两篇覆盖，本文不再重复。抓取环境与工具安装见 [爬虫工具链安装](03-爬虫工具链安装)。

本文完成公众号爬虫的完整闭环：**定位接口 → Fiddler 抓包 → 翻页抓取历史文章 → 存储到 MongoDB → 获取阅读数/点赞数等互动数据**。

## 一、原理与接口现状

爬虫本质上就是模拟浏览器行为：向目标服务器发送 HTTP 请求并解析返回数据。公众号文章数据通过微信服务器的 HTTP 接口以 JSON 返回，爬虫要做的就是定位接口、构造参数、解析响应。

公众号文章的两类来源接口：

| 接口 | 入口 | 说明 |
|------|------|------|
| `appmsgpublish` | **PC 端微信客户端** | 电脑端历史文章接口，返回 JSON 含 `general_msg_list` |
| `profile_ext` | **浏览器网页版** | `mp.weixin.qq.com` 历史消息页接口，`action=home` 取第一页、`action=getmsg` 翻页 |

> ⚠️ **现状说明（2024-2026）**：
> - **手机端微信已实施 SSL Pinning**，HTTPS 流量无法直接抓包——抓包环境应选 PC 端微信或浏览器
> - `key`、`pass_ticket`、`appmsg_token` 等参数均有有效期（`appmsg_token` 约 2-4 小时）且频繁变动，**每次抓取前都要实时抓包获取最新参数**，这是公众号爬虫的常态

## 二、Fiddler 抓包

### 抓包环境

| 方案 | 组合 | 说明 |
|------|------|------|
| 推荐 | PC 端微信 + Proxifier + Fiddler | 微信流量代理到 Fiddler（127.0.0.1:8888），可稳定抓取 `appmsgpublish` |
| 备选 | 浏览器打开历史消息页 | 直接抓网页版 `profile_ext` 接口 |
| 同类工具 | Charles / mitmproxy | 同样受手机端 SSL Pinning 限制，适合 PC/浏览器流量 |

### 抓包步骤（PC 端微信 + Fiddler 为例）

1. 启动 Fiddler，开启 HTTPS 解密（Tools → Options → HTTPS，勾选 Decrypt HTTPS traffic）
2. 用 Proxifier 将 PC 端微信进程流量指向 Fiddler 代理
3. 在 PC 端微信打开目标公众号的历史消息页
4. 筛选 `mp.weixin.qq.com` 请求，找到文章列表接口（PC 端 `appmsgpublish` / 网页版 `profile_ext`）
5. 在 Inspectors 面板查看完整 URL、Header、Body 与返回 JSON

### 用 Requests 复现请求

把抓包得到的 URL、Header、Cookie、参数复制进代码即可稳定复现：

```python
import requests
import json

session = requests.Session()
session.headers.update({
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Referer": "https://mp.weixin.qq.com/",
    "Cookie": "你的_cookie=xxx; wap_sid2=xxx; ...",   # 从 Fiddler 拷贝
})
```

## 三、抓取历史文章

### 解析接口返回

接口返回 JSON 的关键字段是 `general_msg_list`（**JSON 字符串**），需二次解析；每篇文章的核心数据在 `app_msg_ext_info`：

```json
{
  "general_msg_list": "{\"list\": [{\"comm_msg_info\": {...}, \"app_msg_ext_info\": {...}}]}"
}
```

| 字段 | 含义 |
|------|------|
| `title` / `digest` / `author` / `cover` | 标题 / 摘要 / 作者 / 封面 |
| `content_url` | 文章链接（含 HTML 转义，需反转义） |
| `multi_app_msg_item_list` | 多图文推送时的副标题列表 |
| `comm_msg_info.datetime` | 推送时间戳 |

接口返回的字段含 HTML 转义（`&amp;`），先准备一个反转义工具函数：

```python
import html

def sub_dict(d: dict, keys: list) -> dict:
    return {k: html.unescape(d[k]) for k in d if k in keys}
```

### 翻页抓取全部历史文章

网页版 `profile_ext` 用 `action=getmsg` + `offset` 翻页，`can_msg_continue == 0` 表示抓完；PC 端 `appmsgpublish` 用 `begin` 累加翻页，返回结构同理：

```python
import requests
import json
import time

def get_articles(session, url, params, data, offset):
    """抓取从 offset 开始的一批文章，返回 (文章列表, 是否还有下一页)"""
    params["offset"] = str(offset)
    resp = session.post(url, params=params, data=data)
    result = resp.json()

    msg_list = []
    if result.get("general_msg_list"):
        msg_list = json.loads(result["general_msg_list"])["list"]

    can_continue = result.get("can_msg_continue")  # 1=还有更多, 0=抓完
    return msg_list, bool(can_continue)


def crawl_all(session, url, params, data, start_offset=0):
    """抓取全部历史文章"""
    all_articles, offset = [], start_offset
    while True:
        msg_list, can_continue = get_articles(session, url, params, data, offset)
        all_articles.extend(msg_list)
        print(f"已抓取 {len(all_articles)} 篇, 是否继续: {can_continue}")

        if not can_continue:
            break
        offset += len(msg_list)   # offset 累加指向下一页
        time.sleep(1)             # 控制频率，避免风控
    return all_articles
```

> 💡 **要点**：
> - `params["action"]` 首页用 `home`、翻页用 `getmsg`；PC 端接口改用 `begin` 累加
> - **务必控制频率**（`time.sleep`），频繁请求触发风控会导致接口异常或 Cookie 失效
> - 抓取中途 `appmsg_token` 可能过期，注意检查返回并及时重新抓包

## 四、存储到 MongoDB

数据量大或需要结构化查询时，推荐 MongoDB（文档型、无需预定义表结构）。安装任选其一：`brew install mongodb-community`（macOS）、Docker（`docker run -d --name mongodb -p 27017:27017 mongo:8.0`，推荐）。

用 MongoEngine（ODM）定义模型并入库：

```python
from datetime import datetime
from mongoengine import (DateTimeField, Document, IntField, StringField,
                         URLField, connect)

connect("weixin", host="localhost", port=27017)


class Post(Document):
    """公众号文章"""
    title = StringField()
    content_url = StringField()
    digest = StringField()
    cover = URLField()
    author = StringField()
    p_date = DateTimeField()                       # 推送时间

    read_num = IntField(default=0)                 # 阅读数
    like_num = IntField(default=0)                 # 点赞数
    comment_num = IntField(default=0)              # 评论数
    c_date = DateTimeField(default=datetime.now)   # 入库时间


def save(msg_list: str):
    """msg_list 为接口返回的 general_msg_list JSON 字符串"""
    data = json.loads(msg_list.replace("\\/", "/"))
    for msg in data.get("list", []):
        p_date = msg.get("comm_msg_info").get("datetime")
        msg_info = msg.get("app_msg_ext_info")     # 非图文推送没有此字段
        if msg_info:
            _insert(msg_info, p_date)
            # 多图文推送：副标题列表字段与外层一致，复用同一插入逻辑
            for sub in msg_info.get("multi_app_msg_item_list") or []:
                _insert(sub, p_date)


def _insert(item: dict, p_date: int):
    keys = ("title", "author", "content_url", "digest", "cover")
    post = Post(**sub_dict(item, keys))
    post.p_date = datetime.fromtimestamp(p_date)
    try:
        post.save()
        print(f"保存成功: {post.title}")
    except Exception as e:
        print(f"保存失败: {post.title}", e)
```

## 五、获取互动数据（阅读数/点赞数）

阅读数、点赞数通过 `getappmsgext` 接口获取，**必须在微信登录态下**（未登录不返回 `read_num`/`like_num`）。参数中的 `mid`、`sn` 是文章标识，从文章链接或抓包中获取：

```python
import requests
import time

session = requests.Session()
session.headers.update({
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)",
    "Referer": "https://mp.weixin.qq.com/",
    "Cookie": "你的_cookie=xxx; ...",   # ⚠️ 必须为登录态 Cookie
})

url = "https://mp.weixin.qq.com/mp/getappmsgext"
params = {
    "__biz": "你的__biz",
    "mid": "你的_mid",              # 文章标识
    "sn": "你的_sn",                # 文章标识
    "idx": "1",
    "scene": "27",
    "ct": str(int(time.time())),
    "is_only_read": "1",
    "appmsg_like_type": "2",        # 新版点赞机制
    "f": "json",
}
data = {
    "key": "你的_key",
    "pass_ticket": "你的_pass_ticket",
    "appmsg_token": "你的_appmsg_token",   # 有效期 2-4 小时
}

resp = session.post(url, params=params, data=data)
result = resp.json()

if result.get("appmsgstat", {}).get("is_login"):
    stat = result["appmsgstat"]
    print("阅读数:", stat.get("read_num"), "点赞数:", stat.get("like_num"))
else:
    print("登录态失效，请重新抓包：", result.get("base_resp"))
```

> 💡 **批量更新**：从 MongoDB 读出已存文章列表，循环构造每篇的 `mid`/`sn` 调用上述请求即可；建议每批不超过 50 篇，超时重新抓包。

## 小结

公众号爬虫的完整闭环：

1. **定位接口**：PC 端 `appmsgpublish` / 网页版 `profile_ext`，返回 JSON
2. **Fiddler 抓包**：PC 微信 + Proxifier 环境抓取真实参数
3. **翻页抓取**：`getmsg` + `offset` 翻页，`can_msg_continue` 判断结束
4. **存储**：MongoEngine 定义模型，`sub_dict` 反转义后入库
5. **互动数据**：登录态下调用 `getappmsgext` 获取阅读数/点赞数

整条链路的关键是**实时抓包维护最新凭证**并控制抓取频率。仅用于学习研究，遵守目标平台的服务条款与相关法律法规。

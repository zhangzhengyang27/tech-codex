# 指标思维：如何搞清楚各种不同的指标类型

> 本篇讲解如何用指标衡量业务现状:区分数据与指标,并给出"确认主指标→拆分子指标→拆分过程指标→添加分类维度"的指标体系构建四步法。适合需要为业务搭建或理解指标体系、准备应对"指标异常如何排查"类面试题的数据分析师。相关主题:[目标导向](02-目标导向：如何走出取数的怪圈？.md)、[拆解问题](11-拆解问题：为什么总是拆解出一堆没用的数据？.md)。

要做到客观严谨,就要求所有观点都有事实依据;数据分析师要用数据来描述事实。但面对数据库中那么多的表、那么多字段,究竟用什么样的数据来准确描述业务现状?一般做法是提前制定需要的指标,然后根据指标的定义提取具体的数据。

## 数据、指标与指标体系

先说数据和指标的区别,不少从业者搞不清楚两者的关系。

业务环节下最原始的数据,一般来说不是指标。比如用户的登录数据,一般会记录用户 id、登录时间等基础信息,随着用户的登录一条一条地记录下来。这些都是数据,但不加工就没法直接从中获取有用的信息。

如果根据日期算出这一天所有登录的用户 id 的总数,就能知道这一天总共有多少用户来过 App——这个加工后的数据就是日访问用户数,对衡量整个 App 的健康度来说非常直观。**最后得出日访问用户数的具体数字是一个数据,日访问用户数的衡量方法就是一个指标。**

单一的指标能带来的意义是有限的,需要结合其他指标一起看。比如同样两个业务,A 销量是 100 万,B 销量是 50 万,哪个更好?答案是不一定:也许 A 业务销量高利润低,B 业务销量低但利润高,各有不同特点,用单一维度去评判是不合理的。

所以需要把相关的指标整合起来,做成指标体系。了解业务的指标体系对数据分析至关重要,有两个好处:

- 能了解业务是如何运转的,了解业务人员最关心什么;

- 当遇到数据异常时,顺着指标体系排查问题,能很快找出问题。

数据分析师面试有一道几乎必问的题目:"如果某个指标突然出现了异常,怎么排查问题?"有指标体系的概念,这是一道"送分题";没有指标体系的概念,就会东一榔头西一棒子,想到哪说到哪,回答说明没有基本的指标体系概念,就成了"送命题"。


罗列某个具体业务(如电商)的指标清单有局限性:电商的例子不适用于销售,销售的例子不适合直播。与其背清单,不如掌握构建指标体系的一般过程,根据自身业务搭建适合自己的指标体系。

## 如何构建指标体系

指标体系的构建分四步:确认主指标、拆分子指标、拆分过程指标、添加分类维度。

### 1. 确认主指标

主指标是用来评价所负责业务到底怎么样的最重要指标。比如销售部的责任是尽量多卖出产品,主指标是销售额;渠道运营的责任是拉来更多的有效新用户,主指标是有效新用户数。

主指标的制定要根据业务的实际情况:不同的业务主指标不同,同一个业务不同阶段的主指标也不同。以一款 App 的不同产品阶段为例:

| 产品阶段 | 阶段特点 | 常见主指标 |
|---|---|---|
| 引入期 | 产品刚刚启动,需要注重产品打磨 | **留存率**(达标后再大规模推广) |
| 发展期 | 用户量猛增 | **用户数、活跃率** |
| 成熟期 | 用户数稳定,重心转向商业化 | **销售额、利润率**等营收指标 |
| 衰退期 | 用户增长停滞、活跃下降 | **用户流失率**等 |

简化一下,就是**初期做留存,爆发期做增长,成熟期做营收,衰退期做回流**。

::: warning 主指标通常不止一个
主指标一般要多个综合使用,单一指标容易造成"虚荣指标"。比如成熟期只看销售额,可能出现销售额猛增但利润没变甚至变少的情况,这样的增长并不代表业务在变好。除销售额外,可以将毛利也作为主指标。
:::

主指标的制定是整个指标体系构建的重中之重,主指标选得不对,后面的所有工作都是无用功。确定业务的主指标可以使用 OSM 模型:

> **Objective(业务目标)**:用户使用产品的目标是什么?产品满足了用户的什么需求?
>
> **Strategy(业务策略)**:为了达成上述目标采取的策略是什么?
>
> **Measurement(业务度量)**:这些策略随之带来的数据指标变化有哪些?

第一步就是确定业务目标是什么。没有清晰的业务目标,就不可能制定出准确的指标——这也是目标思维被置于首位的原因,做什么事都要先思考目标(见[《目标导向》](02-目标导向：如何走出取数的怪圈？.md))。

以滴滴网约车为例,按 OSM 模型拆解:

- **O**:用户使用滴滴的需求是便捷、能快速打到车、并且安全到达目的地。

- **S**:
  - 便捷方面,提供多个产品入口:独立 App、小程序,以及高德、微信、支付宝等打车入口;
  - 快速方面,针对不同需求提供快车、优享、拼车、出租车等业务选择,并根据早晚高峰的出行需求调节运力,减少用户排队时间;
  - 安全方面,实行司机准入机制和司机合规机制。

- **M**(针对策略制定指标):
  - 便捷:渠道转化人数;
  - 快速:乘客取消率、供需比;
  - 安全:司机服务分。

### 2. 拆分子指标

确定主指标后,把主指标拆成子指标。比如主指标是毛利润,而毛利润根据销售额和成本计算出来:

> 毛利润 = 销售额 - 成本

销售额和成本就是毛利润的子指标,而且还可以继续往下拆解到更小层级:

> 毛利润 = 销售额 - 成本
>
> 销售额 = 用户数 × 付费率 × 客单价
>
> 经营成本 = 渠道成本 + 营销成本 + 商品成本 + 其他成本

放到滴滴的案例中:

- 便捷:渠道转化人数,子指标为渠道人数 × 渠道转化率;
- 快速:供需比 = 司机人数 / 乘客人数;
- 安全:司机服务分按公式综合得出,公式中的因子(驾龄、驾驶事故次数、信用风险分等)就是子指标。

::: tip 拆解要与组织结构对齐
实际工作中,如果主指标是整个公司的共同目标,子指标通常是部门的绩效考核目标,比如用户数、付费率、客单价可能由三个不同的部门负责;如果主指标是部门的共同目标,子指标一般分到小组或个人,比如供需比由司机人数、乘客人数两个小组分别负责。拆解子指标时,要注意与各部门的业务实际情况一致。
:::

### 3. 拆分过程指标

主指标和子指标通常是最终的结果,这类指标称作"结果指标"。结果指标能明确告诉业务到底做得好不好,但缺点是反应太慢:销售额是一连串销售行为的最终表现,当发现销售额下降时其实已经晚了——问题在平时的获客、跟进过程中就已出现。所以需要更灵敏的指标提前发现问题:监督销售流程各环节的表现,**这就是过程指标**。

过程指标最常见的形式是漏斗模型。比如一个产品的销售流程:落地页 → 购买页 → 支付页 → 支付成功,可以把"付费用户数"这个指标拆开,单独计算每一个环节的用户数。最后一步支付成功的人数与"付费用户数"相同,这样不用等到最终结果出问题才想办法,而是在结果出来之前,就通过过程指标提前预判会不会出问题。

除了各环节之间的转化率,每个环节内部还有一些衡量该步效果的指标,比如分享、收藏等,这些都是过程指标。

滴滴案例中,衡量便捷的主指标是渠道转化人数,可以拆出过程指标:渠道触达人数、渠道下载人数、渠道转化人数。

::: warning 建议要给到过程指标
为业务方提出分析建议时,尽量分析到过程指标。如果只把销售额拆解成用户数、转化率和客单价,建议只能是"提升用户数、提升转化率、提升客单价"——业务方自己难道不知道要提升这三个指标吗?问题是怎么提升,这是一句标准的废话。

而拆解到过程指标,建议就容易落地:过程指标对应具体环节,具体环节要解决的问题往往比较清楚。比如"要提升销售额,可以提升落地页的转化率",落地页的目的是引导用户浏览商品信息,业务方就容易讨论后续如何激发用户兴趣、产生购买意愿。
:::

### 4. 添加分类维度

拆完过程指标,还可以给指标添加维度。维度就是指标的某个特征,常见的分类维度有时间、地域、渠道、用户群体等。

给指标添加维度是拆解问题的基础,但如何选择好的维度非常困难,新手很容易拆出一堆维度,最后得出完全没用的结论。**维度的选择必须符合业务的特点**:滴滴的业务在不同城市、不同地段、不同时间差异较大,且都有对应的业务含义,所以可以选择城市维度、商圈维度、渠道维度、时间维度、用户标签等;而手机系统、机型、App 版本等维度,主要用来排查系统 Bug,对业务来说意义并不大。

## 三种拆解方法小结

经过主指标、子指标、过程指标和维度的罗列,一个业务的指标体系就建立起来了。指标的拆解有三种方法——分析问题必然要拆解问题,而拆解问题逃不开这三种拆分方法:

| 拆解类型 | 拆解方法 | 示例 |
|---|---|---|
| 子指标 | 按照指标公式拆解 | 销售额 = 用户数 × 付费率 × 客单价 |
| 过程指标 | 按照生成过程拆解 | 落地页 → 购买页 → 支付页 → 支付成功 |
| 分类维度 | 按照业务维度拆解 | 城市、渠道、时段、用户分层 |

::: tip 注意拆解方法的适用边界
子指标和过程指标的方法不一定适合所有指标。比如"用户数"这个指标拆不出子指标;新用户的获取有些外部数据无法拿到,就没法拆过程指标。按这三种方法思考如何拆解,无法拆解的跳过即可。面试中被问到"如何拆解",按这三类作答,思路就清晰有条理。
:::

# 报告撰写：怎样高效地写一份数据分析报告？

> 分析完成的最后一步是把结果汇报给业务同事。本篇说明如何以建议为起点逆向组织报告内容，避免流水账式的推导复述，并用五个部分组装出结构清晰、沟通效率高的分析报告。前置流程见[《分析流程：业务数据分析的通用流程》](09-分析流程：业务数据分析的通用流程.md)与[《提出建议》](13-提出建议：什么才是有价值的建议？.md)。

## 为什么不能按分析流程写报告

业务数据分析的流程需要解决五个问题：问题是什么、为什么要分析这个问题、问题的表面原因是什么、问题的根本原因是什么、怎么办。

一个常见的误区是把报告写成分析过程的流水账：按分析顺序写自己怎么拆解、得出什么结论、如何继续深挖，甚至把已被证伪的假设也搬出来。这样的报告讲了 10 分钟还不知道要说什么，领导只会问"然后呢？结论是什么？"

企业追求的是效果而非真理。别人花时间看报告，是要为业务决策提供支持，不是来听推导过程的。流水账式报告的沟通效率太低。

## 组织报告的四个准备问题

完成分析之后，动笔之前先想清楚四个问题。这四个问题考虑清楚，报告的思路就成型了。

1. 这份报告的目标是什么，看报告的人看完之后要做什么？
2. 为了达成这个目标，看报告的人需要知道哪些结论？
3. 哪些数据可以支持这些结论？
4. 找出关联性，看报告的人为什么要重视这件事？

### 找出报告的目标

写报告的目标不是展示自己找到了原因，而是让看报告的人看完之后做出改变。报告的目标就是推动分析流程最后一步"提出建议"落地，建议这一步做好了，报告的目标就找到了。

"有所改变"不单指落地具体方案或调整业务方向，**改变业务人员对业务现状的理解也算改变**。比如业务人员在做渠道获客，一直纠结要不要提升新用户留存率。如果报告建议暂时不用关注留存率、继续开拓优质渠道，报告分享完之后业务动作看似没变，但业务方不再纠结这件事、把精力放在渠道获客上，这也是一种改变。反过来说，如果业务人员原本没有这种顾虑，这条建议就完全没必要提——建议也要筛选，**找出对业务真正能起到改变作用的建议**。

### 支持建议的结论有哪些

建议是从之前的分析中逐步推导出来的，所以支持它的结论并不难找。但不能把推导过程复述一遍，沟通效率太低——需要提炼结论，只选择和最终建议相关的结论。

一个反面案例：面对一个问题提出 ABC 三个假设，验证假设 A 是错的，假设 B 也是错的，最后证明假设 C 成立；又因 C 成立提出 EFG 三个假设，再重复这个过程——把这些全部写进四五十页 PPT。分析过程中必然产生很多结论，和最终建议关系不大的就不要放进主线。

::: tip 无关结论放附录
没有人关心分析过程中发现的其他不重要结论。如果确有价值的假设验证过程，可以放在报告附录。报告主线穿插太多无关内容，很容易让看报告的人走神。
:::

### 支持结论的数据有哪些

结论由数据和逻辑推演得出，确定了需要的结论，基本就确定了需要的数据。整理数据时要注意：分析时习惯用明细数据，因为可以一次发现多种问题，但报告里明细数据的冗余信息会干扰读者。

以落地页停留时长为例，按日期提取每天的数据做出的曲线可以说明该落地页停留时长普遍低于其他落地页，但每天的波动并不大，曲线里的逐日细节反而会把看报告的人带进图形细节。实际上，用平均停留时长做一个对比就够了——图形简单清晰，配上结论"该落地页的平均停留时长较短"，一下就能看懂。

到这里，报告的内容结构已经成型：建议、支撑建议的结论、支撑结论的事实和数据。

### 如何让业务重视这些建议

报告的最终目标是推动建议落地，前提是业务方有兴趣关注这份报告，并且认为建议重要。这一步放在最后思考，是因为只有确定了最终建议，才能分析**这些建议跟谁有关、可能改变哪些指标、有哪些风险和机会、如何和关联人的绩效挂钩**。从用户思维的角度，这一步用来吸引关联业务方的兴趣、提高落地的动力。

**吸引兴趣的方法：**

- 标题与业绩挂钩、直接点明内容。《关于如何提升某产品销售额的数据分析报告》不如《提升某产品销售额的三点建议》——后者一看就知道有直接的落地建议，值得一看。
- 说明问题背景和严重性，不解决会带来怎样的影响。

**提高落地动力的方法：** 说明采纳建议后按历史数据推算能带来多少业务增量，算出具体数值（比如提升 100 万元收入）。业务领导看了会催着团队尽快落地。

## 报告的基本结构

想清楚上述问题之后，按五个部分组装报告。

### 1. 分析背景

即"如何让业务重视这些建议"一步的思考结果：问题的背景、严重性、与业务的关联，放进来让看报告的人理解这件事为什么重要。

### 2. 结论/建议

说清楚报告的目的、最终希望业务做哪些事，以及支撑建议的核心结论。

### 3. 分析框架

即建议与结论之间的金字塔结构，让看报告的人一眼看清整份报告的逻辑。

### 4. 支撑建议的结论和事实

展现整理出的结论和支撑数据，是整份报告篇幅最大的部分。

写这一部分有两个关键技巧：

- **每一页只讲一个结论。** 一页 PPT 上的所有信息都围绕这一页的结论组织，不要把几个结论放在一起说，否则看报告的人不知道这一页要说什么。
- **标题用具体的结论。** 小标题不要用"新用户的渠道分布情况"这类描述，结论应该类似"A 渠道是新用户的主要入口"这种有明确意义的内容。检验标准：如果看报告的人没时间细读，只把每页小标题读一遍就能理解所有内容，说明结论提炼和逻辑结构足够清晰。

### 5. 重申结论/建议

报告开头已经讲过建议，但看完十几页论证过程后，读者早就忘了结论是什么。报告主体结束时要重新强调这份报告的目的。

## 写报告与分析的顺序完全相反

写报告不能在分析结束后马上动笔。分析问题是从问题一步步向下推导出结论、再推导出建议；报告则相反——先提炼建议，再筛选需要的结论，最后才是支持结论的事实和数据。

新人觉得写报告难，往往是因为不假思索地把分析出的所有结论都堆进报告，导致整份报告没有结构。先确认报告目标，再根据目标组织报告思路，效率会大幅提升。

# 产品分析：如何将某功能的次日留存率提升 10%？

> 本篇以股票行情类 App"简况"功能的留存优化为完整案例，按"明确问题—找原因—提出方案"的流程演示产品数据分析的落地过程。案例的关键手法是用行为数据矩阵还原用户使用场景，找出功能留存问题的根本原因。

## 案例背景

日常工作中，业务数据分析可以分为运营分析和产品分析。产品数据分析面对的产品类型纷繁复杂，不同产品之间可相互借鉴的内容不多，产品数据分析师的经验积累非常困难，往往需要大量分析实战才能获得足够的业务理解和解决问题的能力。

案例的对象是股票行情类 App 的"简况"功能。股民买股票本质上是买一个公司的未来，需要先了解公司的基本情况，"简况"功能就是为了满足这一需求而出现的。

![Drawing 0.png](/data-law-images/i/image2/M01/05/49/Cip5yF_-rz6AHGiWABSVu9uQyYQ565.png)

*"简况"功能图*

当时的"简况"功能依次有主要指标、大事提醒、公司资料等多个模块，分别解决股民了解公司关键信息（财务状况、分红情况、业务范围）的需求。在简况页面点击不同模块右上角的"更多"按钮，会进入对应模块的二级页面。该功能已经很久没有改版。

产品经理认为"简况"功能的体验不太好，想改版优化，但希望在改版前有数据支持：想知道不同模块改版的优先级和改版方向，于是找到数据分析团队做一次产品分析。

## 明确问题

产品经理最初提出的需求是"优化一下'简况'的体验"。这个表述很模糊，需要先确定用什么业务指标来衡量所谓的"体验"。

衡量产品体验的经典框架有传统网站的 PULSE 指标框架、Google 的 HEART 指标框架等，可选指标还有使用时长、推荐率、留存率、核心功能使用率等。最终选择**次日留存率**：把信息展现功能的体验做好，用户第二天继续使用的概率会提高。其他指标存在缺陷：

- **使用时长**：时长提升不代表用户真的喜欢这个功能，也可能是功能难用，用户不得不花很多时间找要的东西。
- **核心功能使用率**：适合目的明确的工具类产品。"简况"这种满足获取信息需求的功能，用户使用方式非常多样，有的看 A 指标、有的看 B 指标，用户差异太大，不易找出"核心功能"。

确认目标是提升次日留存率之后，再确定具体数值：整个简况功能的次日留存率已经比较高，决定在原有基础上再提升 10%。

接下来论证为什么要分析这个问题。和业务方沟通后了解到，优化简况体验的目的在于提升 App 整体留存率（大盘留存率）；而当年 App 的整体年度目标之一是提升日活跃人数，提升大盘留存率是完成日活目标的其中一条线。问题框架如下。

![image.png](/data-law-images/i/image2/M01/05/DA/Cip5yGABNeCAbF5WAABk4EJx2jI531.png)

## 找原因

### 表面原因：按模块拆分对比

简况功能模块很多，不同用户对模块的需求不同，因此将功能按模块拆分分析。先提取各模块的日活跃人数和留存率，基本思路是：**留存率较低的模块，提升留存率；留存率较高的模块，提升使用人数。**

![image (1).png](/data-law-images/i/image2/M01/05/DA/Cip5yGABNemAOpEZAABSdk09A1w882.png)

从数据可以直接得出三个结论：

- "主要指标"功能人数最多，但留存率较低；
- "概念题材"的留存率最高，且人数也较多；
- 各模块的使用人数不是从上到下依次递减，说明用户是带着一定目的使用的，不是推荐什么就看什么。

结合业务理解还能得出四个结论：

- 左下角的功能冷门且低频，提升用户数和留存率都困难；
- 左上角的功能只适合小部分群体，受功能特性决定很难提升使用人数，不值得投入太多精力；
- 右下角的功能使用人数较多但留存率偏低，这类功能按业务理解使用频率应该较高，留存率偏低很可能是功能做得不够好，有优化空间，**分析优先级排第一**（后文以"主要指标"为例）；
- 右上角的功能人数多留存率也高，但人数只是相对较多，在简况整体使用人数中不超过 15%，仍有很大提升空间，**分析优先级排第二**（后文以"概念题材"为例）。

### 根本原因：行为数据矩阵还原用户场景

找出根本原因要靠用户的行为数据。选择"页面内点击率"和"页面停留时长"两个指标构建矩阵，将用户分类：

- 页面内点击率表示用户是否完整地体验了功能；
- 页面停留时长表示用户是否有探索的热情。

**针对留存率偏低的功能**，矩阵各象限的含义大致是：

![image (2).png](/data-law-images/i/image2/M01/05/DA/Cip5yGABNfKAIjugAABly4yexIU515.png)

| 象限 | 用户行为解读 |
|---|---|
| 点击率高、时长高 | 探索欲望很强但最终没留下来，可能找不到想要的功能，功能不能满足需求 |
| 点击率高、时长低 | 进入后马上点击，可能某个功能引导性强但不能满足需求 |
| 点击率低、时长高 | 页面信息太复杂需要长时间理解，即 Fogg 模型中"能力"遇到问题 |
| 点击率低、时长低 | 一进入什么都不干就走，很可能是被标题党链接骗进来 |

以上都是概率较大的猜测，还需结合业务实际对比验证。将"主要指标"功能的二级页面用这个矩阵分析：用户停留时间非常短，几乎一进入就走，页面内点击率也很低，非常符合"点击率低、时长低"的特点——**初步判定功能不符合用户的心理预期**。

查看"主要指标"二级页面的样式验证猜想：页面只有净利润、每股收益、营业收入三个指标。用户明明点击的是"更多"按钮，进入的二级页面指标却更少了，这明显不是用户想看到的。**二级页面内容太少，基本可以认定就是"主要指标"功能留存率偏低的根本原因。**

![Drawing 4.png](/data-law-images/i/image/M00/8D/63/Ciqc1F_-r22AHlKvAAFTCk-1oKI398.png)

**针对留存率较高的功能**，矩阵的含义有所不同：

![image (3).png](/data-law-images/i/image2/M01/05/DC/CgpVE2ABNfqADR4LAABicLco8aE039.png)

| 象限 | 用户行为解读 |
|---|---|
| 点击率高、时长高 | 每次要看很久、还要点击，才能满足需求 |
| 点击率高、时长低 | 进入后直奔目标 |
| 点击率低、时长高 | 无需点击，通过阅读即可满足需求，但需要较久 |
| 点击率低、时长低 | 一进入即可满足需求，无需额外动作 |

以留存率最高的"概念题材"模块为例：数据显示用户点击率很高、时长较短，且当天平均使用次数较高。也就是说用户当天会多次进入页面，每次直奔目标、马上离开，而且这么短的时间已经能满足需求。查看页面样式验证：二级页面结构很简单，最上面可切换"概念"和"题材"，下面只有一个"更多"按钮，点击后查看完整内容。

![Drawing 6.png](/data-law-images/i/image/M00/8D/63/Ciqc1F_-r32AJgOcAAHUwyWBVXU416.png)

综合来看，这个页面能满足用户需求（所以留存率高），但使用上稍显麻烦。**缩短链路可以让用户更方便地使用**，更好的体验能降低使用门槛、提升这个高留存模块的使用人数，从而让简况功能的整体留存率提升——跳转烦琐是限制使用人数的根本原因。其他功能模块基本都可以用这两个矩阵分析。

## 提出方案

找到根本原因后，提出方案就水到渠成。

**"主要指标"模块**

- 主要问题：页面内容不符合用户需求，用户没有再次使用的兴趣。运营引导、提示等手段解决不了问题，必须修改整个页面的内容。
- 建议：修改页面，增加更多指标信息，满足用户查看更多指标的需求。

建议已经很具体，再细化下去就是选取哪些指标、如何设计页面等产品经理的工作。产品经理后来把页面改成了信息更丰富的形式，上线后主要指标模块的使用时长、留存率均有 15% 左右的提升。

![Drawing 7.png](/data-law-images/i/image2/M01/05/4B/CgpVE1_-r46AF1M8AAFbGz9fTFU408.png)

**"概念题材"模块**

- 主要问题：使用起来比较烦琐。
- 建议：缩短使用链路，降低使用门槛，让用户更方便地使用。

产品经理选择了一套大改方案：二级页面不变，在入口位置直接提取关键信息，用户可以直接在简况一级页面看到详细信息，省去每次跳转二级页面的操作。

![Drawing 8.png](/data-law-images/i/image2/M01/05/49/Cip5yF_-r5aAAD0LAAIbWuBBFLs128.png)

改版后，使用概念题材模块的用户数提升了 2 倍左右，留存率相对提升了 13%，是一次非常成功的改版。综合其他模块的优化，整个简况功能基本达到了预期的优化目标。

## 案例复盘

| 阶段 | 本次做法 |
|---|---|
| 明确问题 | 把模糊的"优化体验"需求转化为可衡量的"次日留存率提升 10%"，并梳理出支撑大盘日活目标的问题背景 |
| 找出表面原因 | 按模块拆分功能，对比使用人数和留存率，确定整体状况与分析优先级 |
| 找出根本原因 | 用点击率 × 停留时长的行为矩阵还原用户场景："主要指标"的问题是二级页面内容太少、不符合心理预期；"概念题材"的问题是操作烦琐 |
| 提出改进方案 | 针对用户遇到的问题提出策略性建议，由产品经理细化落地 |
| 持续跟进 | 对改版后的数据验证效果，效果不好则重复以上过程 |

一款好的产品是后续运营增长的基础，产品分析是相当常见的数据分析需求。做好产品数据分析的关键在于：**通过数据还原用户场景，找出用户遇到的问题，并具备一些基础的产品设计知识，用来给出具体的落地方案。**

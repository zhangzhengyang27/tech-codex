# 转化分析：如何提升产品的购买转化率？

> 本篇以投资 App"买指数"按钮的转化优化为完整案例，演示从一次取数需求出发，通过指标体系拆解定位漏斗环节，再借助用户决策过程模型发现"中间页面根本不该存在"的本质问题。案例的核心启示：思考用户到底想要什么，而不是用户"在这个页面上"想要什么。

## 案例背景

案例涉及少量金融概念：

- **股票**是一个公司的股权凭证，买了一家公司的股票就是这家公司的股东，可以享有股票分红。
- **基金**可以理解成一堆股票的集合，买了一只基金，相当于买了这只基金持有的所有股票的集合。
- **指数**是衡量某一类行业股价状况的综合性指标。比如"芯片概念"指数，囊括所有和芯片产业相关的公司股票，按一定权重计算得出综合评分。

指数和基金的区别在于：指数只是一个评分，基金是真正可以购买的金融产品。它们相似是因为有一类指数基金，完全按照指数的计算规则配置股票权重，涨跌走势和指数完全相同。

行业的发展趋势容易预测，具体一家公司的趋势很难预测。十年前智能手机普及是必然趋势，但最后哪些公司能生存下来难以预判——曾经有几百家手机厂商，现在只剩华米 OV，投资了其他厂商很可能血本无归。既然行业红利可预测、公司红利无法预测，对冲风险最简单的办法就是投资行业内的所有公司：一部分投资会损失，但成功公司的巨额收益可以弥补损失，综合下来获得整个行业的发展红利。在金融市场上，购买一只重点投资该行业的基金，比自己去买所有相关股票更简单——管理方便、投资额要求低，很多基金 1 块钱就能买。

## 明确问题

业务人员在指数的行情走势下方增加了一个"买指数"按钮：用户查看某个指数（比如"芯片概念"）时想投资芯片行业，可以直接点击"买指数"投资这个行业的基金。

页面转化链路为：用户在指数行情走势图上点击"买指数"按钮，进入基金列表页；在基金列表页点击某个基金，进入基金详情页；在详情页点击购买按钮，进入支付页，最后购买完成。

功能上线一段时间后，业务人员写月度总结时提出需求：看一下新增的"买指数"按钮带来的转化情况。

先把需求描述清晰。衡量转化情况的核心结果指标选**转化人数**而非转化金额——这个入口的业务目标是带来更多用户而不是销售额，所以这次分析不往提升金额的方向走。从转化人数衍生出的指标还有曝光人数、转化率等。最终确认需求为：提取"买指数"按钮上线后带来的转化人数，以及转化过程中的曝光人数、转化率。

取数结果发现，新上线的购买入口转化人数不多，转化率也较低。按[《目标导向》](02-目标导向：如何走出取数的怪圈？.md)的目标思维，取数需求可以做成分析需求，于是决定继续深挖：**分析如何提升"买指数"入口的转化人数**。

## 找原因

### 表面原因：子指标与过程指标拆解

按指标体系拆解的三个步骤——子指标、维度、过程指标——找表面原因：

- **拆子指标**：转化人数可拆分为曝光人数和转化率，取数时已有这两个数据。两项数据表现都不好，即曝光人数和转化率都存在问题，先记下待深入分析。
- **拆维度**：考虑按不同指数拆分。但投资市场随热点变化非常大，现在找出的热点指数过几天热度过去就没人关注了，因此维度没有深挖。
- **拆过程指标**：把转化率拆分成购买流程中不同阶段的漏斗转化情况。

漏斗分析发现：基金列表页到基金详情页这一步转化率较低，导致整体转化率不高。表面原因整理为两点：

1. 通过子指标发现：曝光人数不足、转化率不高；
2. 通过过程指标发现：转化率不高主要集中在基金列表页的转化上。

### 根本原因：从页面问题到用户决策

**曝光人数不足**：先找业务人员沟通，了解到目前还是测试阶段、只开放了部分指数没有完全覆盖，全面覆盖后就会改善，不需要继续深挖。

**基金列表页转化率低**：采用用户行为分析。画出用户在页面上的点击率示意图：用户对上方的风险指数比较感兴趣，点击率最高；下方的基金列表，点击绝大部分集中在一只基金上。

还原用户场景：用户对投资价值指数的走势感兴趣，但之后不继续购买。两种可能：用户看不懂投资价值指数是什么意思；或者看了之后觉得投资有风险，放弃购买。两种假设大概率都成立——分析页面时花了很久才搞明白什么是"投资价值指数"，金融行业从业人员尚且如此，普通用户更困难；而且这个指数有风险提示作用，用户看到后放弃购买非常可能。

::: warning 数据分析不是万能的
想继续用数据验证这个猜想非常困难，必须借助用户调研、用户访谈等形式确认。数据可以提出可能的假设、缩小排查范围，但不能直接确定用户真实感受方面的问题根源。
:::

到此，表层原因已经清楚："投资价值指数"干扰了用户，取消或简化它、降低理解成本即可。但这个分析的着眼点还太窄：只想着优化列表页，看似站在用户视角，实际还是站在业务角度。用户没有"列表页"的概念，用户只是来解决需求的，页面的具体表现形式用户并不关心。**真正站在用户视角要思考的是：用户到底想要什么，而不是用户在"这个页面"上想要什么。**

用[《懂用户》](08-懂用户：数据分析+用户思维=精细化运营.md)的用户决策过程模型完整梳理：用户做一件事要经历产生兴趣、收集信息、评估价值、做出决策四个阶段。用户点击"买指数"按钮时处在什么决策阶段？按钮上有一个关键字——"买"，说明用户**已经做出了购买决策**。

以正常决策路径为例：

- 产生兴趣：国家重点扶持芯片产业，可能是个机会。
- 收集信息：看芯片行业有哪些公司、产业链情况、目前走势。
- 评估价值：评估这些信息，考虑是否可以投资、是否现在投资。
- 做出决策：做出投资决定，点击"买指数"按钮。

特殊情况也存在（二表哥推荐买了准没错），但不管哪条路径，点击"买指数"的用户肯定已经做出了购买决策。此时用户想要的是**赶紧付钱成交**。而产品提供的却是："投资价值指数"帮助用户评估要不要买，加上三五只基金供选择，让用户评估"买哪只"——用户的思路从"怎么付钱"被拉回到"该不该买、买哪个"。

所以，问题不是基金列表页做得不够好，而是**根本就不应该有这个页面**，应该直接跳转到支付页让用户付费交易。这一步不像"数据"分析，更像业务思考，但数据分析的目的是解决问题，只要逻辑严密、过程清晰，没必要纠结是否一定要有数据。

## 提出方案

用户点击"买指数"时想要直接购买，那么就去掉中间烦琐的流程。考虑到金融行业的特殊性——用户必须了解购买的产品特点——最终方案保留了一个落地页做承接：只保留一支和该指数关联度最高的基金，避免用户陷入"买哪只"的选择；并且去除了"投资价值指数"，页面理解成本不高。

改版后，"买指数"入口的转化率提升了 1 倍多。如果当时只是在基金列表页做改动，转化率不会有这样明显的提升。

## 小结

转化分析一定要站在用户的视角思考用户到底有什么需求。不要被现有的产品形态限制：落地页转化不行，就盯着用户在落地页上的行为做优化，这种用户思维是假的用户思维。回归真实的需求，思考**用户到底想要什么，而不是用户在这个页面上想要什么**。一旦真的找到用户需求，看到的问题就是本质问题，分析结果落地后才能实现质的飞跃。

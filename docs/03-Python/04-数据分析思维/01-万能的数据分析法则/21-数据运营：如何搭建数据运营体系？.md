# 数据运营：如何搭建数据运营体系？

> 数据运营由传统运营发展而来，利用数据驱动运营监控、原因排查、策略执行等动作，响应速度和迭代效率更高。本篇以用户运营体系为例，说明体系必须按"生命周期 → 分层 → 分群"的顺序逐层搭建，以及数据分析在其中承担的三类支持工作。

## 为什么用户运营项目常常失败

用户运营相关的概念很多：用户生命周期、用户分层、用户分群、用户画像等。这些知识在网上都很碎片化，没有成体系的介绍说明概念之间的关系，所以很多公司的用户运营是几个概念一起上、想到什么用什么。尤其是用户画像这种看起来高端的概念，公司领导看到别人做得高大上，往往抵不住诱惑要在公司内推行。

*（图片来源：神策数据）*

结果往往是轰轰烈烈推行下去，各个用户运营项目之间没有关联，最后一团乱麻，效果很一般。

原因很简单：**用户运营体系不是一蹴而就的，而是一点一滴按顺序搭建起来的**。知道了搭建顺序，就能避免出现混乱、没有关联的体系。

## 用户运营体系的搭建顺序

### 第一层：用户生命周期

运营的最终目的是让更多用户付费，盈利才是企业目标。但绝大部分产品从用户首次使用到最终付费的周期很长，有些甚至长达几个月。既然付费周期长，让用户付费的最好办法不是每天用转化类广告狂轰滥炸，而是先让用户留下来、感受到产品价值——留下来的用户多了，付费概率自然更大。

用户在不同时期的需求是不一样的：刚开始使用 App 时需要了解如何使用产品；用了几个月的用户需求可能是增加新功能。所以要把用户按使用产品的阶段划分开来，把用户从第一次接触到离开产品的整个周期，总结出一套适合绝大多数用户的使用轨迹——这就是用户生命周期。

用户生命周期一般分为引入期、成长期、成熟期、休眠期、流失期。按每个时期的用户价值大小画出曲线：

用户运营的目的是尽可能延长用户的生命周期，并在生命周期中产生更大的商业价值。每个阶段的运营关键点：

> 引入期：注重引导，希望用户尽快进入成长期。
>
> 成长期：提升用户留存，养成用户的使用习惯，尽快成为成熟期。
>
> 成熟期：希望用户保持在成熟期，或者在该阶段产生更多的收入。
>
> 休眠期：对用户进行促活，重新让用户回到成熟期，防止流失。
>
> 流失期：召回用户，延长用户的生命周期。

### 第二层：用户分层

有了生命周期模型，运营可以针对不同阶段的用户采取不同策略。但只分五种类型的话，运营效果很容易进入瓶颈，更精细的运营需要用户分层。

以成熟期用户为例：假设成熟期的定义是付费购买过一门课程的用户，现在希望提高这部分用户的付费金额，最好的办法是让用户再购买一门课程。虽然都买过一门课，但不同用户是否会买下一门课差异很大。分析成熟期用户可能发现这样几个特点：

- 首个购买的课程学习超过三天，则完整学习第一个课程的概率大大增加；
- 续费的用户，大多数都完整学完了第一个课程；
- 购买超过 3 门课程的用户，后续持续付费意愿很高。

据此可以把成熟期用户分成几类：首次付费的用户 → 学习超过 3 天的用户 → 完成第一门课学习的用户 → 再次购买的用户 → 购买超过 3 次的用户。这几类用户逐步递进，每一类都在上一类的基础上更深入，像一个金字塔从下到上逐步发展。

这就是金字塔结构的用户分层模型。每一层的运营目的非常清晰：让用户到更上一层。比如面对首次付费的用户，运营重点是让这些用户学习超过 3 天。

::: tip 分层不必覆盖所有用户
分层模型中的用户不会覆盖所有用户群体——总有一些用户不按常理出牌，比如买了第一门课之后马上买第二门课。只要分层模型可以圈选绝大部分人群，就有相当的代表性，在业务上就是有意义的。
:::

### 第三层：用户分群

有了分层模型，已经可以区分已购买用户、学习超过 3 天的用户等不同层级。要让单个分层内部继续精细化，就要用到用户分群。

还是上面的案例：为了让完成第一门课学习的用户复购第二门课，运营要考虑用户需求的差异：

- 有些用户第一门课买的是运营课程，有些是产品课程，可以推送和之前课程相关的课程；
- 有些用户是大学生需要入门课，有些是职场老鸟需要进阶课，可以推送不同难度的课程；
- 年龄、职业、使用习惯、行为特点等特征，都可以作为差异化运营的维度。

这种在分层基础上、按细分维度做差异化运营的做法，就是用户分群。

**用户分层和用户分群的区别**：分层每层用户之间是独立的，分群不考虑是否重叠——同一个用户既可以是"购买运营课程的用户"，也可以是"大学生群体"，这些特征可以交叉组合应用，也可以分开单独运营。

这个机制正是用户画像的服务对象：用户画像由一堆用户标签构成，通过分析标签识别用户是什么样的人，**用户画像本质上就是为了服务用户分群**。很多公司直接推行用户画像，却没有成体系的用户运营体系支持，这样的项目从一开始就注定失败。这类项目屡见不鲜的原因是：学习成功企业的方法时，用户画像看得见摸得着，而生命周期、分层、分群是具体的执行方法和运营流程，不参与日常运营工作就感受不到它们的存在。

## 数据分析的三类支持作用

| 支持类型 | 内容 | 产出 |
|---|---|---|
| 确定划分标准 | 为生命周期、分层、分群确定量化的用户划分口径 | 如"付费超过 100 元为成熟期用户" |
| 运营数据监控 | 按划分口径制作固定报表，跟踪各类用户的变化 | 各类型用户每日人数、活动对用户转化的影响 |
| 用户标签建设 | 从维度和颗粒度两方面建设标签体系 | 可直接用于分群运营的用户标签 |

### 确定划分标准

不管是生命周期、分层还是分群，最终都需要通过数据的方式选出特定用户，这就需要数据分析师确定划分标准。比如在线教育产品将付费超过 100 元的用户定义为成熟期用户，超过 3 个月没有新付费的用户定义为休眠期用户——"100 元"和"3 个月"就是数据分析师要确定的数字。一般用拐点法确认，操作难度不高，但要提取的数据很多，工作量比较大。

### 运营数据监控

确定划分标准之后，业务人员非常关心不同类型用户每天人数的变化、运营活动对各类型用户转化的影响等。这类数据需求非常固定而重复，所以一般按划分标准的口径制作相应的报表，方便业务人员查看数据变动情况。

### 用户标签建设

建设用户标签要考虑两件事：标签维度、颗粒度。

标签维度一般有五类：

| 维度 | 示例 |
|---|---|
| 自然属性 | 性别、姓名、年龄、地域等自然人属性 |
| 社会属性 | 学历、婚姻状况、孩子状况、职业、收入水平等体现社会关系与地位的属性 |
| 行为属性 | 作息习惯、出行习惯、饮食习惯、网购习惯等 |
| 消费属性 | 购物偏好、浏览偏好、使用偏好、交互偏好等 |
| 心理属性 | 生活方式、个性特征、价值观、信仰特征等 |

颗粒度是标签的精细程度：年龄标签粗一点可以是"21-30 岁"，细一点可以直接记录 25 岁。

确定了维度和颗粒度，再针对现有数据通过一定规则清洗成可直接使用的标签。比如年龄标签：先看内部数据能否获取（如注册时用户自主填写）；内部没有，尝试通过手机号获取年龄信息；手机号也没有，再尝试通过手机内安装的 App 大致推测年龄段。

一个完善的标签系统工作量非常大，一般需要三四人的小团队做几个月。用户标签属于量变引起质变的东西：标签少的时候看不出效果，标签多了之后，面对各类需要分析用户属性的业务问题就非常方便，交叉后的属性能更好地了解用户。

## 小结

用户运营体系的搭建顺序是：先进行用户生命周期运营，然后在此基础上开展用户分层，再在分层的基础上开展用户分群。数据分析在体系建设中主要提供三类支持：确定划分标准、运营数据监控、用户标签建设。

数据运营体系因公司业务不同，用户分群的界限并不一致，搭建时可以参考这套流程，而不必拘泥于细节。

::: warning 数据分析师要鉴别项目
数据分析师是一个辅助岗位，如果辅助的项目本身不靠谱，分析师再强也没用。不要看到成功的企业做了什么就学什么，要知道它们为什么要这么做——只学其形、不学其神的项目注定失败，要尽量避开。
:::

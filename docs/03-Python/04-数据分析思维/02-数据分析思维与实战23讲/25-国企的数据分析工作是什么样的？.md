# 国企的数据分析工作是什么样的？

> 本篇介绍国有银行与运营商（工行、招行、广发、电信）数据分析岗位的招聘要求差异、日常工作内容（日/周/月报、临时提数、常规优化）、专题分析的四个步骤，以及国企环境下的软技能与面试技巧。相关主题：[BAT 大厂的数据分析项目](./26-如何搞定 BAT 大厂的数据分析项目？.md)、[专题报告的标准化格式](./42-报告撰写：专题报告的完美标准化格式.md)。

## 岗位方向与招聘解析

招聘解析有两个目的：

- 通过对比分析工行、招行、广发、电信四家公司的数据分析岗位，找出不同类型企业对应聘者要求的共性与差异，从而有针对性地准备面试。
- 对岗位职责及相关要求进行提炼总结，匹配出适合自己的企业。

刚参加工作的人往往比较看重薪酬，但随着工作年限增长，自身能力能否在工作中得到提升变得更加重要。想找到适合的工作同时获得能力提升，首先需要明确数据分析师的三个发展方向：

- **业务型**：对分析师的业务理解能力要求非常高。
- **数据研发型**：要求技术非常熟练，能够通过技术对数据进行分析。
- **算法型**：要求数学功底好，课题研究能力强。

数据分析师应结合自身情况，在工作三年后找到自己的定位。如果在投递简历前就能从 JD（岗位职责）判断岗位是否适合自己，再决定是否投递，对最终进入心仪公司会事半功倍。

### 工行

![工商.png](/data-practice-images/i/image/M00/16/B6/Ciqc1F7WCSiAcc_sAALNycRf2SQ776.png)

工行的平台非常好，但对数据挖掘岗位的职责定义非常模糊，且要求一定的技术基础。如果不是对技术感兴趣的人，在错误的时间点进入，可能很快就会跳槽。

### 招行

招行的岗位职责包括分析大零售客户群、标签、客户细分及客户画像等，要求非常具体。专业上提出了明确要求：金融、统计、经济、管理和计算机专业。符合以上专业背景的候选人进入招行的机会较大。招行作为后起之秀，追求一定的创新，适合思维活跃、喜欢挑战的人。

### 广发

广发银行的岗位职责偏向业务型，事情繁杂，需要评估是否适合自身发展方向。但它的应聘要求并不十分明确——"优秀的数据分析能力""对数据敏感""有一定的市场敏感度"这些都是无法准确衡量的，面试时的临场表现就至关重要。

### 电信

![xxx.png](/data-practice-images/i/image/M00/16/C2/CgqCHl7WCWmAbJyOAARwZTMrdsI453.png)

相比于银行，电信的岗位职责中规中矩，日常工作主要是统计报表、专题分析，要求具备一定的独立思考能力。

::: tip 招聘信息的读法
看招聘信息时，一定要从岗位职责及能力要求两方面分析，综合考虑企业目前所处状态及日常工作内容。这对判断岗位是否适合自己起关键作用，在面试中同样重要。
:::

## 国企常规工作

国企数据分析的日常工作主要包括三个方面：日/周/月报、临时数据、常规工作的优化。

### 日/周/月报

日报是每天都需要关注的，但在日常工作中往往得不到足够的重视。分析日报主要有三个目的：了解业务现状、培养数据敏感性、提供业务发展建议。

- **了解业务现状**："每天数据就那样，没什么好看的"是一种浅层次的理解。如果数据一直不变，恰恰说明公司业务出了问题——此时若能指出问题，就能获得展现自己的机会。
- **培养数据敏感性**：招聘要求中的"数据敏感性"都是后天培养的，没有人天生对具体业务敏感。每天关注数据波动，潜移默化就能形成敏感性。例如之前每日收入在 500~600 万之间，某天突然变成 650 万，能及时发现并寻找原因，这就是数据敏感性。
- **提供业务发展建议**：数据波动时需要寻找波动原因，久而久之就会发现产品或运营在做出何种调整后数据会出现涨跌，进而能为业务发展提供更合理的建议。

在日报的基础上，周报可以看作短期趋势——很多公司的发版周期是一周，新版本的效果能直接体现在周报中，且一周的数据更稳定、更有说服力。月报的周期更长，月例会会对业务数据进行分析，更能为接下来的业务提供合理的发展建议。

数据敏感性和业务发展建议都来自日/周/月报分析的持续积累。而大部分公司的日/周/月报只是常规性的经营分析、罗列数字，很多时候失去了数据分析的本质意义。

**优秀的数据分析师一定要经常看这三种报，培养自身的敏感性，从而找到获取业务增长的发力点。**

### 临时数据

临时提数是大部分数据分析师职业生涯的第一个痛点。如果工作中最主要的事情是不断满足临时提数需求，就非常危险，一定要想办法优化。

临时提数需求分为两种：**管理层需求**和**业务执行人员需求**。

- 对于高管层的临时提数需求，优先级最高。但不能立马去做，而要先思考为何需要这个数据、通过这个数据能进行什么决策。例如 CEO 正在与外部公司商谈合作事宜，需要了解用户人均时长——如果不知道这个背景前提，给出的数据往往有误，这时需要及时与领导沟通。
- 业务线的临时提数需求非常繁多，比如数据指标口径、数据增长计算等，需要根据实际工作情况合理安排，学会合理拒绝业务线可以自己解决的事情，不断提升自己的工作价值。现实情况是，大部分数据分析师都陷在临时数据需求的泥潭。

**案例："掌上生活" App 线下餐饮优惠券功能**

产品经理需要快速得知优惠券的使用人数。如果拿到需求后立刻分析字段口径、写 SQL 返回结果，产品经理很可能接着要求提供优惠券下发人数，再从头做一遍——之后还有使用频次、消费金额等需求在等着。

应对原则是坚决不做提数机器：**针对每一个业务单点问题，先追根溯源，建立该业务类的分析框架，由点及面彻底解决该类问题。**具体做法：先了解业务背景，找到产品经理最关注的核心需求（优惠券的使用情况及如何优化），进一步分析出使用情况包括优惠券下发人数、使用人数、使用比例、消费金额、消费频次等指标。把这些指标因素都考虑到后再与产品经理沟通，分析结果就非常清晰。至于衍生需求——比如一个月后产品经理需要同样的数据——可以让产品经理根据数据模型自己计算。

::: warning 协作原则
分析师是一个支撑职位，需要和业务线保持良好关系，有理有据、不卑不亢，只给业务方做最核心的需求，其他衍生需求由业务方自己完成。双方的目标是一致的：把产品做得越来越好。
:::

### 常规工作的技巧

针对前面的难点，有三个技巧：

1. **日报自动化**：如果每天都要花很多时间分析日报，可以交给机器处理，例如通过 Python 搭建日报分析框架减轻工作压力。
2. **需求排期**：分析师每天都很忙，会有大量业务需求需要数据支撑，要保持清醒的头脑，对需求进行合理的优先级排期。
3. **及时求助**：遇到自己不能解决的问题时，及时与领导沟通。很多时候领导看得更高，难题往往可以迎刃而解。

## 专题分析

在实际工作中，各业务方都会定期给分析师提出一些比较专业的分析任务，称之为专题分析。专题分析比较考验分析师的思维、技术、时间管理、演讲能力等，做好一份专题分析并不容易，主要分为 4 步：

1. 需求解读；
2. 建立逻辑树；
3. SQL 提数及分析；
4. 撰写报告的三个建议。

大部分数据分析师对第 3 步比较熟悉，但对第 1、2、4 步掌握都不够好。专题分析也是最能体现分析师工作价值的环节。

### 需求解读

要把至少 20% 的时间分配在沟通需求上，一定要当面沟通，并且这个过程贯穿整个分析过程。需求解读是一个逐层深入的过程：从**原始需求**到**了解需求**再到**本质需求**。

以原始需求"负责活动的几个事业群同事希望看到活动的效果情况"为例：

- 如果直接抛出这个命题就提数写报告，结果一定是错的；
- 通过与需求方沟通，需求变成"目前活动对日活的帮助及活动出现哪些问题"——仍然比较模糊；
- 再进一步沟通，需求本质是"活动的拉新效果如何？活动拉新用户后续黏性如何？针对数据活动如何做出优化？"——这才足够具体，在此基础上即可构建逻辑树。

### 建立逻辑树

建立逻辑树的目的是让思路更加简洁清晰。以四月份的活动运营分析为例，涵盖活动前、中、后三个阶段：

- **活动前**：包括流量和收入。以流量为例，活动前往往会做一些预热，所以会出现流量波动，需要看活动前每天的流量效果。
- **活动中**：同样涉及流量和收入，如 DAU/MAU 是否提升、拉新情况、老用户唤醒情况、活动中连续访问情况、上线频次分布等。同时还需要注意各类活动的横向对比，进而对业务提出优化建议，而不只停留在简单的数字上。
- **活动后**：拉新用户的沉淀效果如何？不活跃的老用户在活动中的表现、后续活跃度如何？以及汇总数据和复盘数据分析。

面对需求一定要建立合理的逻辑树，有了逻辑树才能知道具体需要分析的点是哪些。

### SQL 提数及分析

SQL 提数需要遵循三段论，分析师一定要掌握 SQL——SQL 提数是所有想法验证的第一步。

第二步是分析。分析可以归为六类：

![image (8).png](/data-practice-images/i/image/M00/16/6A/Ciqc1F7VweiATMM6AABZklRsFCE951.png)

1. **组成部分**：产品目前用户是由哪几部分群体组成的？
2. **数量比较**：各个群体之间的数量程度比较是什么样子的？
3. **有何变化**：在时间维度上，各自的变化有哪些？
4. **各项分布**：具体的数据分布是什么样的？
5. **各项相关性**：各个指标之间的相关性是什么样的？
6. **其他深层次的挖掘**：更深入的下钻分析。

日常的分析基本就包括这些内容，所以在写报告或做数据分析的过程中一定要不断总结。

### 撰写报告的三个建议

**第一，报告应该是 90% 的图加 10% 的文。**以图为主，图表标题说结论。例如对比两张行业品牌市场占比的图表：一张标题直接点明"联想市场占比 62%"，另一张只写"各品牌市场占比"——前者更直观，直接给出结果。人类视觉反应往往首先被标题吸引，所以报告中一定要**以图为主、文字为辅、图表标题点明结论**。

**第二，结论前置。**如果报告要呈现给领导，邮件中一定要先把结论写出来，报告以附件形式发送，正文中也要**结论前置，节省阅读时间**。

**第三，逻辑性要非常强。**演讲的过程中也需要有故事感，站在领导的角度去想他要听什么。优秀专题报告的标准格式可参考[报告撰写：专题报告的完美标准化格式](./42-报告撰写：专题报告的完美标准化格式.md)。

## 软技能与面试技巧

### 软技能

进入一家公司靠能力，但想在一家公司向上发展往往需要靠软技能。在国企做好数据分析，除了专业技术过硬之外，情商的修炼必不可少：能够快速领会领导意图，并很好地表达及展示，往往决定了后续发展的高度。除了加强专业技能，平时还需要多看一些心理学、社会学类书籍并付诸实践。

一个典型场景：国企会有很多会议，大部分人被动接受会议内容。但如果认真准备，在会议开始前准备好内容并随时做好展示自己数据分析能力的准备，把每次会议都当作展示自己的机会，必定可以脱颖而出。

### 面试技巧

一个实际案例：候选人第一份工作在事业单位，工作内容基本与数据分析无关。他想进国企做数据分析，但经验不足，于是花大量时间学习市场上的数据分析书籍，把理论和案例背下来。虽然缺少实际经验，但凭借扎实的理论知识，他在国企面试中成功跳槽进入国企。

如果本身有一定的数据分析经验，面试时一定要带上一份自己的专题分析报告——展示理论基础的同时剖析具体业务场景，事半功倍，能显著增加面试成功率。

无论在谈心环节还是面试环节，都要表现得自信、谈吐大方。

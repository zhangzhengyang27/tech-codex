# 如何搞定 BAT 大厂的数据分析项目？

> 本篇解析阿里、腾讯、百度三家大厂数据分析师的岗位关键词与能力要求，讲解大厂日常工作中最重要的数据异常排查方法论（三步排查 + 六大类原因归类），并以今日头条新用户留存专项为例说明大厂专题分析"有目标、有节奏、有闭环"的特征，最后给出面试技巧与必问问题。相关主题：[数据波动分析](./35-流量分析：如何分析数据的波动？.md)、[转型或跳槽](./27-怎样才更好地转型或成功跳槽？.md)。

## 大厂招聘解析

了解大厂数据分析师的日常工作内容与岗位要求，一方面可以揭开大厂招聘的面纱，另一方面能对照出自身差距，做有针对性的面试准备或能力提升。

### 阿里

阿里的岗位职责描述关键词有"代理""方向""痛点""转化""风险""创新""落地""合作"，岗位要求关键词有"敏感度""方法论""管理整合"。可以看出，阿里的分析师岗位对技术要求不是很高，但对综合能力要求非常高，需要具备一定的数据敏感度和方法论。之所以没有特别要求技术能力，是因为市场上工作三五年的分析师基本都具备了一定的技术能力，但仍有很多人缺少宏观、中观与微观意识——这也是大部分人的职业瓶颈。

### 腾讯

腾讯的岗位职责描述关键词有"埋点""异常检测""决策""A/B 测试"等，岗位要求包括"海量数据处理""用户增长"等。腾讯的岗位职责中规中矩，基本涵盖了 80% 的互联网公司数据分析师的日常工作内容。值得关注的是腾讯特别提到了增长黑客的经验，目前独角兽企业都会要求有这样的经验。

### 百度

百度的岗位职责描述关键词有"分析体系""专项策略""用户增长""逻辑思维""敏感度"等。百度对个人的"发散思维"和"策略研究"要求非常高，同时在用户运营领域也要有自己的体系。

::: tip 共性：关注用户增长
BAT 三家都特别关注用户增长——独角兽企业只有持续增长才能获得发展。在实际工作中也可以感受到，所有项目都是为了用户增长而构建。
:::

## 日常工作

大厂数据分析师的日常工作主要包括数据异常排查和融入专项（做专项分析并负责 KPI、埋点、指标体系等）。

### 数据异常排查

BAT 的数据产品 DAU 动辄几百万上千万甚至过亿，业务方和管理层每天都会盯着核心数据，其中必然有一些数据波动比较大。分析师需要对这些波动进行排查并解释原因，如果没有一套方法论，面对问题就会无从下手，浪费大量时间做无用功。

实际上，数据有较大波动无非就两个原因：一是数据本身有问题；二是业务本身有问题。能够透过问题看本质，就可以在数据波动分析方面成为专家。

**前期准备**——数据异常排查需要三项准备：

- **业务理解**：例如某 App 的 DAU 低于 1000 万，这个 DAU 代表的是什么行为的 DAU——是在进程中、需要打开 App，还是必须有主动行为，理解起来是不一样的。
- **指标口径**：同样是 DAU 一千万，是 Android 还是所有系统。
- **数据产出过程**：DAU 一千万是由哪份日志经过哪些数据清洗计算出来的。

只有了解清楚这些，才能开始异常排查。例如市场部领导看到某张日活数据表与分析狮提供的数据相差较大前来询问，首先需要弄清楚他看到的数据表是怎样产出的、指标口径是什么、指标的业务含义是什么，只有熟悉这些情况后才能分析出产生差异的原因。有些分析师入职时产品已比较成熟但指标口径没有文档化，对业务理解不深，面对领导的提问就会手足无措，一旦不能解决问题就会失去信任，所以前期准备工作一定要做好。

**第一步：判断是否异常**，有四个关键点：

- **亲自去看数据准确性，不要人云亦云**。业务方说 DAU 下降了就立马去调查是不对的，应该亲自查看数据是否真实——业务方不一定专业，也会出错。
- **时间轴拉长，看是近期异常（3 个月内）还是历史异常**。很多分析师习惯只看近一两周或一个月的数据，出现波峰波谷就认为异常了，但实际往往不是。拉长时间轴后如果仍然出现波峰或波谷，才可能真的出现异常。
- **看关联指标是否也异常**。例如 DAU 异常时，查看自然量、渗透率是否异常。如果也异常就需要一起解决，而不是按下葫芦浮起瓢，反复做无用功。
- **找一个关键人物（产品/数据）提前沟通**。确认是数据异常后，找经验丰富的人提前沟通，往往能快速定位问题。

**第二步：最大概率法则原因归类**。很多分析师遇到异常时抓不到问题主线，无法对问题进行有效分类。异常问题可以归为六大类，基本覆盖所有情况：

| 原因类别 | 典型示例 |
|---|---|
| 假期效应 | 开学季、暑假、四大节、当地节日 |
| 热点事件 | 常规热点（世界杯）、突发热点（爆款 IP） |
| 活动影响 | 双 11、618，公司层面活动 |
| 政策影响 | 互联网金融监管、快递实名 |
| 底层系统故障 | 数据传输、存储、清洗有无问题 |
| 统计口径 | 业务逻辑更改、指标计算方式更改 |

遇到问题时，按照降序在这六大类中逐一排查即可找到问题原因。

**第三步：闭环**。排查出问题原因后，一定要形成闭环：

- 持续跟踪后期数据是否再次异常。排查出原因后产品做相应改进，若问题仍在，说明前期排查出了错。
- 记录、沉淀、文档化。后续可能还会遇到相同问题，记录文档利人利己。
- 邮件化。确认没有问题后再发邮件给相关方，描述影响范围和主要结论即可。

**案例：海外版 App 的 DAU 异常上涨**

某 App 海外版的主要用户在东南亚地区，某天 DAU 突然涨到 5000 万，与历史数据相比明显异常。数据采集、传输、活动、业务口径、常规热点等都没有变化。按照六大类逐一排查，发现"热点事件"中的爆款 IP 没有排查到——某国宝级明星突然去世带来了 App 大量访问。因为信息在海外传输较慢，国内用户无法快速知道，分析师发现流量提升后应该快速反馈给业务人员，业务确认没问题后立刻调动运营资源对该明星进行全方位解析，持续借势把事件发酵到最大化。

及时响应事件后，整个 App 的 DAU 上涨了 10 个点，而一般的产品运营优化很难达到这个效果。很多分析师排斥数据异常，但优秀的分析师能够从异常中发现业务增长点。

### 专题分析

对于 BAT 而言，专题分析有三个特征：

- **有目标**：紧贴项目 KPI；
- **有节奏**：2~3 周时间输出一份完整报告；
- **有闭环**：所有的报告都说人话，做人事。

以今日头条 App 新用户留存专项为例。

**项目背景**：2015 年今日头条 App 新用户次留、7 留（7 日留存）与竞品相比均低于竞品 5% 绝对值，且新用户流失速度高于竞品。目标是在数据分析基础上通过产品运营优化，提升用户留存 5% 绝对值。

**第一阶段：新用户留存整体分析**

目的：摸清数据现状，同时找到若干切入点。关键点：不要太注重细节，讲究报告产出的时效性，让其他人员感受到分析师的存在。

一个项目里会有产品、运营、研发等岗位，都是公认的必要岗位，但分析师往往不被认为是必要岗位——因为 BAT 的产品和运营都会一些基础数据处理、都会写 SQL。为了让其他人员感受到分析师的价值，一定要在项目前期各方都比较困惑、找不到切入点的时候，用两周左右的时间输出一份专题报告，把细节的数据体现出来。报告从三个侧展开：

- **渠道侧**：UV 是多少？一级渠道的次留、7 留是多少，二级渠道的次留、7 留是多少。
- **产品侧**：主要功能的渗透率情况、有没有问题、关键漏斗数据如何、漏斗数据上有什么发现。
- **用户侧**：目标用户群体是哪些、用户行为分布如何。例如人均浏览文章篇数是三四篇，那么具体分布是什么样？有多少用户只阅读一篇，有多少用户一篇都不看？

**第二阶段：寻找优化切入点（一般 1~2 个）**

- 关键路径数据发现曝光 PV 到点击 PV 的 CTR 很低。应细致分析：对于新用户，应该曝光什么、在什么时候、什么位置曝光。
- 某个量大的二级渠道次留明显低于其他渠道。应进一步分析：该渠道用户留存过低，是因为渠道质量本身存在问题？用户已安装竞品？当前产品设计与渠道用户不匹配？同时高留存渠道本身有什么特征？

切入以上两点，就已经能给产品运营不少建议，再配合 A/B 测试，就能看到数据分析的效果。要相信，一个项目或产品在开始阶段一定存在诸多问题，基于数据的深入分析和切入点选择往往就能提供很多优化建议；即使很多产品已经比较成熟，始终还有优化空间。

**第三阶段：不断重复前两个阶段，继续寻找其他切入点**

除了寻找本身产品的切入点，还需要同时进行竞品分析、营销活动分析、用户流失分析等，整个过程就是不断"试错"。每一次分析报告都要有能落地的点，并且真的落地了，这就是闭环——也是评判优秀分析师最重要的标准。

## 面试技巧与必问问题

### 面试技巧

BAT 的面试基本是五到六面，前三面最为关键：第一面电话面，第二面 Boss 一面，第三面 Boss 二面。所有面试都基于简历，所以简历一定要多下功夫。

- **第一面的关键点是逻辑性**。电话面看不到人，考察的就是基本功。说话要条理清晰，对简历上的数据要非常熟悉——例如活跃、留存、流失、渠道等。如果问"目前大概有哪些渠道、每个渠道的留存大概是多少"答不上来，肯定过不了关。
- **第二面的关键点是实操性**。现场面是人与人的互动，首先要尊敬对方、面带微笑；其次要多使用应聘岗位的产品 App，同时带上一份自己写的优秀专题分析报告，证明爱思考、有能力。
- **第三面要有亮点**。Boss 二面一般是总监面，总监的高度比较高，要从宏观的角度去说：目前整体的行业趋势是什么、行业里有哪些痛点、这些产品有哪些改进方法、之前做的项目的上下游是怎么考虑的——总之要多有一些想法。

### 面试必问的三个问题

1. **流量波动，数据突然涨了怎么分析？**——考察分析师的经验与条理性，参考解答见[转型或跳槽篇的三大问题解答](./27-怎样才更好地转型或成功跳槽？.md)。
2. **分析下你手机里最常用的三个 App 是哪三个？**——考察分析师的思考深度，回答策略同样见转型或跳槽篇。
3. **商业模式：你之前产品的 CPC/CPM 以及商业模式是什么样的，在这一块是怎么优化的？**——考察对商业变现的敏感度。

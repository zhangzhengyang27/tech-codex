# 如何挑选适合项目场景的数据分析工具？

> 本篇梳理各类数据分析工具的适用场景：先给出数据分析标准化流程的九个步骤，再以 Excel（对比分析、时间序列拆解、相关性分析、临界点分析）、SQL（提数训练与常见问题）、Python 与 R（流失预测建模、Python 的额外价值）为例说明工具选型原则。相关主题：[常见的 SQL 技巧和分析方法](./41-数据获取与分析：常见的 SQL 技巧和分析方法.md)、[AB 测试](./43-AB 测试：AB 测试的效果监控.md)。

## 数据分析整体流程

数据分析有一套标准化流程。很多人做数据分析时不知道怎么开展，或怀疑自己做出的分析报告是否合理、全面，原因就是对这套标准化流程没有真正理解。

标准化流程共九个步骤：

1. **明确问题**：先把问题定义清楚，很多人还没理清问题就直接去看数据了；
2. **搭建框架**：定义问题之后再把问题考虑全面、找到一条分析主线；
3. **数据提取**：用 MySQL、Hive、ClickHouse、Doris 等 SQL 引擎，或 Spark SQL、Trino 等查询引擎提取相关数据；
4. **数据处理**：用 Excel、Python（pandas）、R 处理数据；
5. **数据分析**：以数据分析方法论为主来分析数据；
6. **数据展现**：用 Tableau、Power BI、FineBI（帆软）、Excel、Python（matplotlib/plotly）等工具把数据展现出来；
7. **撰写报告**：考验文笔功底以及整体逻辑性；
8. **报告演讲**：考验沟通能力、表达能力、被提问能力。报告撰写完成后不要直接去讲，要先和业务方进行大量沟通，否则在会议或公众场合很容易被挑战；
9. **报告闭环**：最难也是价值最大的地方。

其中数据提取、数据处理、数据展现是数据分析师前期的基本功，以工具为主，比较容易学习和完成；而明确问题、搭建框架、撰写报告、报告演讲、报告闭环更多考验分析师的综合能力以及智商、情商，需要很长时间沉淀。

基于这套流程，有几类必学工具：

- **MySQL、Hive 及现代查询引擎**：数据获取主要通过 SQL 实现，常见引擎包括 MySQL、Hive，以及 ClickHouse、Apache Doris、Spark SQL、Trino（原 Presto）等；同时需要掌握一些 Linux 命令，排查数据异常时会用到。SQL 必须超级熟练——数据提取环节不能出错，这一步有问题后面就都有问题。
- **Excel**：最高频的数据处理与临时分析工具。工作中经常遇到 leader 让现场画个图的情况，这时最有可能用的是 Excel 而不是 Python/R。
- **Python（含 R）**：Python 是当前数据分析的主流语言——`pandas` 负责数据处理，`scikit-learn` 做机器学习，`matplotlib`/`plotly` 做可视化，配合 `numpy` 几乎覆盖全部分析场景。R 也是一门统计型语言，在统计建模与学术场景中仍有使用，但行业数据分析已普遍转向 Python，R 更适合作为补充而非主力。
- **BI 工具（Tableau / Power BI / FineBI 等）**：用于自助式数据展现与看板搭建。Tableau 交互能力强，Power BI 与微软生态集成好且普及度高，FineBI（帆软）在国内企业市场占有率高。日常报表与可视化尽量用 BI 工具，而不是全部依赖代码。

## Excel 常用操作

工作中一般通过 SQL 在数据库中提取数据，保存到本地 Excel，所以 Excel 是最基础也是最重要的一个数据分析工具——能用 Excel 解决的坚决不用其他工具。以下四个场景覆盖了 Excel 最有价值的分析功能。

### 对比分析（筛选和色阶功能）

对比分析是数据分析中常见的方法——所有的数据只有对比才有意义。例如每年的双 11 都会与之前的双 11 进行消费额对比；工作中最常见的对比对象是大盘：新上线一个功能，除了看功能使用人数，更要做这个功能和大盘的留存对比，如果高于大盘留存，代表这个功能有非常好的正向效应。

**案例：微视与抖音重合用户的消费偏好**。要分析自身 App 与竞品的重合用户和自身 App 全量用户在客户端内的消费差异，从而针对重合用户做针对性运营。第一列是微视与抖音的重合用户消费分类 CTR，第三列是微视大盘消费分类 CTR：

![Drawing 1.png](/data-practice-images/i/image/M00/1D/E5/CgqCHl7i9AqAH-TBAAELRUqsNwI056.png)

利用对比分析可以算出重合用户更偏爱哪些分类：相对值 diff 的计算方式是"重合用户的消费 CTR 除以大盘的消费 CTR 再减 1"。计算后发现搞笑、舞蹈、明星、美食分类的相对值是明显的正向，因此会针对这部分重合用户多推这些内容、减少其他内容权重。配合色阶功能展示，正向差异看起来更直观。

### 时间序列拆解分析（透视图功能）

看某指标时一般会把时序周期拉长看趋势，而数据都是波动的，所以会进行拆解分析，寻找具体波动项。

**案例：新增用户次日留存下降的渠道归因**。新增用户的次日留存近半年出现下降，需要进行渠道维度拆解，看整体下降是因为所有渠道都下降，还是个别渠道导致的。

### 相关性分析（常用函数功能）

相关性分析会用到函数功能以及加载项功能。典型场景：做某个子产品时，会被问"这个子产品对大盘的贡献度或者影响度是多少"，这时就可以用相关性说话。

**案例："想法"模块对大盘留存的影响度**。评估"微信读书"产品中"想法"底部 Button 子模块的留存对整体大盘留存的影响度，先看"想法"功能留存和大盘留存的趋势是否一致——趋势比较一致时，再利用 Excel 的高级工具中的分析工具库做相关性分析。

分析工具库的位置：文件—选项—加载项—点击分析工具库，确定之后，数据工具栏会出现"数据分析"模块，基于这个模块做相关性分析：

![Drawing 9.png](/data-practice-images/i/image/M00/1D/E6/CgqCHl7i9HuAfMtbAAIe05lP5us173.png)

相关系数计算完成后，Excel 会在指定位置输出相关性系数。无论是相关分析、回归分析还是傅里叶分析，甚至偏机器学习的场景，Excel 都可以应付。

### 临界点分析（插入图表复杂功能）

对于任何一款产品，高活跃用户与低活跃用户在产品使用上必然不同，所以会存在某个指标——一旦用户在这个指标上的消费超过某个临界值，后面会变得非常黏性，这就是 Magic number。

**案例：滴滴 App 的 Magic number**。滴滴新用户留存较低，分析过程中发现新用户在前三天一旦下单专车超过 3 次，留存就会大幅提升。所以滴滴做了很多优惠活动，让用户基本不花钱就可以坐车，留存因此大幅提升。

优惠券使用次数与对应的用户数及留存的原始数据：

![Drawing 11.png](/data-practice-images/i/image/M00/1D/DA/Ciqc1F7i9I-AKdfoAAFx2LKDOFs816.png)

把数据用插入图表的复合功能做成"柱状图 + 折线图"的组合图：柱状图对应用户数、折线图对应留存，横坐标是优惠券的使用次数。从图中可以发现当前优惠券使用次数主要集中在 0、1、2 三种情况，但折线留存上存在一个拐点——如果用户对优惠券的使用次数超过三次，留存就能发生质的变化。围绕这个点可以想各种办法刺激用户使用优惠券。

::: tip Excel 的定位
Excel 虽然简单，但它的分析功能非常强大：对比、拆解、相关性、临界点四类高频分析都可以直接完成，是分析师性价比最高的工具。
:::

## SQL 常见问题

不仅要会 SQL，而且要达到闭着眼睛都能写出来的水平。现在所有数据都存储在各种数据库里，如果 SQL 不熟练，写出的代码要么提不了数、要么提的数有问题，后面所有的工作都无法开展。

**常见现象**：一旦表关联较多、内部逻辑稍微复杂，就怀疑自己代码的准确性。

**解决方案**：

- 如果公司内有 SQL 高手，前期每次怀疑时把代码给对方 Review，多请教，模仿对方写代码的风格和逻辑，2 个月之后再评估自己水平。
- 如果公司内同事的 SQL 水平都差不多，只能靠自己：利用下班时间，把怀疑的代码按照自己认为的几种逻辑全部运行一遍，看哪个结果跟当前已知数据最靠近（一定要有一个已知数据作为参考，否则无法判断对错），再反推为何这样写更合理。

判断 SQL 是否熟练的标准：如果现在 CEO 或 Leader 直接让快速跑一个数，内心非常自信、非常高兴，就说明已经非常熟练了。

**常见问题与解法**：

**Max 函数**：对误认为是数值型但实际是字符串型的字段取最大值，结果一直有错，如 `'13'<'9'`、`'-60'<'-70'`。解法是在 MAX 括号里的字段加一个零，把字段转化为数值型再比较：

```sql
select max(a+0)
```

**日期处理**：日期取年月份、时间戳取日期、日期格式转换等需求经常出问题。解法是先查用什么函数来转，正式跑数据前，直接 `select 函数(a)` 测试。一种特殊的日期处理是北京时间和 Unix 时间转换：

```sql
select from_unixtime(time), from_unixtime(cast(substr(time,1,10) as int)) -- 第二个字段用于毫秒时间戳
```

**先聚合再计数**：计算某个维度下的用户数时，不要直接 `count(distinct imei)`，而应该先按 imei 聚合再去重计数：

```sql
Select city,count(1) as uv from (select city,imei,count(1) from a group by imei,city) t1 group by city
```

**一列变多行**：A/B 测试中会对一个用户打很多标签，标签存在一个字段里。要看标签维度的指标，就要对该字段做列变行拆解：

```sql
Select *,b from t1 Lateral view explode(a) tmp as b
```

**取 Top**：看某分类下的 Top10 消费额子分类（金额一致就并列）：

```sql
Select *,rank() over(partition by a order by b desc) as rk from t1
```

**避免数据倾斜**：小表在左、大表在右，使用 map join，同时对空值进行过滤：

```sql
Select /*+mapjoin(a)*/  t1.city,t2.type,count(t1.imei) as uv
From
(select imei,city,count(1) as pv from a where imei != '' group by imei,city) t1
Join
(select imei,type,count(1) as pv from a where imei != '' group by imei,type) t2
On t1.imei=t2.imei
Group by t1.city,t2.type
```

## R 语言以及 Python 脚本案例

R 语言的典型场景：对于一个产品的重要指标如留存，影响的因素非常多，需要找出这些影响因素的重要性，从而知道围绕哪些因素运营才能更好提升留存。产品经理一定会问这个问题，而 SQL 和 Excel 明显都解决不了。

换一种方式理解：哪些指标最能区分用户留存还是未留存——越是明显区分，越重要。再转化为机器学习语言：对于一个用户，有一个 y（留存/未留存）和很多 x（各种影响因素），需要找出 x 与 y 的关系，并给出 x 的重要度排序，可以用随机森林、逻辑回归、决策树来实现。

**案例：预测用户是否流失**。根据用户的基础信息和行为信息预测用户是否流失，并做出重要度排序。样本数据包含用户标志、基础信息（年龄、婚姻、教育水平、开通月数），以及行为信息（基本费用、无线费用、电子支付、套餐类型），可以直接用决策树实现。基础代码非常简单，虽然结果不算理想，但代码确实能帮助找到切入点：从变量重要度排序可以发现**开通月数**和**电子支付**这两个变量非常重要，由此可以给产品运营提出如何把这两个指标做起来的建议。

这个例子的复盘要点：先把业务提出的问题转化为机器学习语言，再用一些简单的代码实现，借此帮助业务找到切入点。

### Python 相比 R 的额外价值

Python 与 R 在机器学习算法上大多可以互相实现，但以下场景中 Python 更为方便：

- **爬虫**：爬虫在工作中价值很大，比如爬取竞品数据，用 R 不方便。例如资讯类 App 的很多文章是通过爬虫下发的，像今日头条的部分文章。
- **文本挖掘**：对评论数据的研究价值很大，比如分析 App 评论数据，从而知道如何做评论运营闭环。例如京东、网易 App 的评论运营，以及把其他 App 的热点评论置前。
- **UDF 函数**：Hive 自定义函数有时不能满足需求，需要自己定义函数实现，这时可以用 Python 写 UDF。例如基尼系数（Gini），Hive 中直接调用 UDF 能够很快输出。
- **算法研发**：个性化推荐、底层运维、Web 开发都是通过 Python 实现。

::: tip 选型结论
Python 配合丰富的第三方库，几乎能覆盖数据分析的全部场景；工具选择的重点在于掌握常见工具操作，以及如何用工具提升业务分析能力。
:::

# 指标体系搭建：指标体系的经典四步

> 指标体系是流量分析、路径分析、竞品分析、营销活动分析、用户增长分析等微观方法论的基础。本篇给出指标体系的定义与选取原则（根本性、可理解性、结构性），讲解建立指标体系的经典四步，并以知乎 App 为例完成一次实操。相关主题：[流量分析](./35-流量分析：如何分析数据的波动？.md)、[数仓的三种类型表](./45-数仓：数据仓库的三种类型表.md)。

## 指标体系的定义及选取原则

实际工作中会出现两种令人不悦的情况：

- **对核心数据知其然不知其所以然**。例如日活只知道数据在变化，不知道为何变化，特别是出现较大跌幅时，产品为了解释这种现象，会向数据分析师要各种维度的数据——年底汇报时尤其明显，要完数据发现跟现有数据对不上，数据团队内部又要花大量时间对各种口径。
- **埋点反复返工**。每隔一段时间，产品都会拉上数据、研发一起对埋点，总觉得当前字段不够用，底层日志越来越大，数仓修改越来越多，取数越来越慢、错误越来越多。

这两种情况的根本原因都在于缺少指标体系的建设、宣贯（宣传贯彻）以及实施，其中宣贯和实施更为关键：有些公司有指标体系的建设，但宣贯不到位，实施时就更不到位——开会时决定要做哪些指标体系，与会者拍手叫好，落地时很多动作却没有做到位。

业务方不重视指标体系，是感觉指标体系是基建活、离完成 KPI 太远，只有出问题时才临时重视；数据方不重视，是因为这是一个吃力不讨好的工作，做好了可以、做不好就背锅；甚至有些分析师认为，指标体系只是一张思维导图。

::: warning 作为一切前提的指标体系
指标体系是埋点、取数、分析的一切前提，如果做不好，数据工作始终会很乱。判断自己是否真的懂指标体系：能不能把它说明白——如果说不明白，就说明还不够懂。
:::

**指标体系是在业务的不同阶段，分析师牵头与业务方协助，制定的一套能从各维度去反映业务状况的待实施框架。**

几个关键点：

- 在业务的前期、中期、后期，指标体系不一样；
- 一定是由分析师牵头、业务方协助，而不是闭门造车；
- 从各维度反映业务的核心状况，指标有很多维度；
- 最终是一个待实施框架——一定要实施，否则就是浪费时间。

指标选取要注重三个原则：

- **根本性**：对核心数据一定要理解到位和准确，如果这里错了，后面基本不用看。
- **可理解性**：所有指标要配上业务解释，如日活的定义是什么——是产品的打开、内容的点击还是后台进程存活。
- **结构性**：能够充分对业务进行解读，如新增用户只是一个大数，还需要知道每个渠道的新增用户、每个渠道的新增转化率、每个渠道的新增用户价值等。

## 建立指标体系的四个步骤

### 前置知识：指标的构成

工作中遇到的指标都是派生性指标：

```
派生性指标 = 原子性指标 + 修饰词（可选） + 时间段（必选）
```

- **原子性指标**是最基础的、不可拆分的指标，比如交易额、支付金额、下单数；
- **修饰词**基于某种场景，是可选项，比如"通过搜索带来的"交易；
- **时间段**是必选项，比如时间周期选的是双 11 这一天。

三者组合就衍生出一个派生性指标——"双 11 这一天通过搜索带来的交易额"；如果不需要修饰词，就是"双 11 这一天的交易额"。同样，次日留存、日活、月活、日转化率都是派生指标。这些知识在做数据仓库时非常有用（参见[数仓：数据仓库的三种类型表](./45-数仓：数据仓库的三种类型表.md)）。

### 第一步：厘清业务阶段和方向

要知道当前业务处于什么阶段、具体的业务方向是什么。一家公司往往经历三个阶段：

- **第一阶段：业务前期（创业期）**——更多是想快速抢占市场份额、看公司盘子大小，最关注用户量。此时的指标体系应该紧密围绕用户量提升做各种维度的拆解，比如说渠道。
- **第二阶段：业务中期（快速发展期）**——除了关注盘子的大小，还要看产品的健康度；除了关注用户量走势，更重要的是优化当前的用户量结构。如果留存偏低，必然跟产品模块有关系，是不是某功能流量承接效果太差。
- **第三阶段：业务后期（成熟发展期）**——看变现能力以及市场份额。整个行业市场格局已定，一定要看收入指标、各种商业化模式的收入，同时做好市场份额和竞品监控，防止后来者居上。

### 第二步：确定核心指标

第二步最重要的是找到正确的核心指标。这不是一件容易的事——不是因为这件事很难，而是因为让所有人重新接受一些客观事实很难。

**案例：失真的日活**。某款产品的日活口径是"打开 App"，通过不断买量、外部刷量，日活一直在上升，业务方觉得挺好。但分析师发现，打开 App 的用户中 3 秒跳出率达 30%，非常不健康。这说明当前的核心指标（日活）有问题，更好的核心指标是**停留时长大于 3 秒的用户数**。

每个 App 的核心指标都不太一样，所以一定要多花时间考虑这件事，不只是看日活和留存。核心指标确定好之后，更重要的是对核心指标进行维度拆解。

### 第三步：指标核心维度拆解

核心指标的波动必然是由某种维度的波动引起，所以监控核心指标，本质上还是监控维度的核心指标。通用的拆解方法是**先对核心指标进行公式计算，再按照业务路径或者业务模块进行拆解**。

例如核心指标是停留时长大于 3 秒的用户数：

```
停留时长大于 3 秒的用户数 = 打开进入 App 的用户数 * 停留时长大于 3 秒的占比
```

- 对于**打开进入 App 的用户数**，要提升就要看各个渠道的转化率是多少、用户从哪里来、通过什么方式打开 App（点击桌面图标还是点击通知栏）、这些用户的画像是什么。
- 对于**停留时长大于 3 秒的占比**，要看具体停留时长的分布——有多少是 3 秒，同时了解停留大于 3 秒的用户特征以及行为特征，有没有作弊或刷量的可能性。

核心维度的拆解需要多跟业务方沟通，把能考虑到的模块都放进去，基本就比较全面。

### 第四步：指标宣贯、存档、落地

- **宣贯**：很多人忽略了这一步，往往和业务核心人员沟通好之后就直接开始建报表。实际上搭建好指标体系后，要当面触达所有相关的业务接口人，最好开会并邮件。
- **存档**：对指标的口径和业务逻辑进行详细描述存档，如某功能日渗透率 = 该功能的日点击人数 / 日活。只有到这一层，后面的人才能一眼看懂口径的意思。
- **落地**：建核心指标的相关报表。实际工作中，报表都会在埋点前建好，这样一旦版本上线就立刻能看到数据，同时这时各方的配合度都很高。

四个步骤中每一步都非常关键。很多数据分析师经常抱怨临时提数需求太多，本质是因为指标体系没做好、指标体系很分散。

## 知乎 App 指标体系实操

以知乎 App 为例，按上述步骤看它的指标体系。

### 第一步：厘清当前业务发展的阶段

知乎当前处于业务发展期和成熟期之间，有两个论点：

- 业务在一个快速调整期，内容向娱乐大众化转型；
- 商业化进行较大的探索，例如"大学"模块包含一些付费课程，但做得不是很重。

从主界面也能佐证：当前知乎的主界面上没有广告。如果业务已经处于比较成熟的阶段，界面上会掺杂很多广告。实际工作中判断业务发展处在什么阶段，只要看明年的业务规划就能得到答案。

### 第二步 + 第三步：确定核心指标并拆解

知乎 App 有非常多的功能：较上位置的"关注""推荐""热榜""视频"导航栏，下面还有"首页""想法""大学""通知""我的"等模块，每个模块都由不同的产品经理负责，他们面临的核心指标不一样。

以首页推荐模块为例，最重要的指标是问答数：

```
问答数 = 提问数 + 回答数
       = 提问人数 * 人均提问数 + 回答人数 * 人均回答数
```

提问人数没有必要按漏斗模型来拆。

::: warning 相关性不等于因果性
有人可能觉得评论、点赞、收藏数应该是核心指标。实际上评论点赞多跟产品的健康度没有直接关系：评论点赞多的本质原因是提问回答比较精彩——这是一个相关性关系而不是因果性关系。很多做内容的人觉得"只要评论做上去了，日活就能涨上去"，数据相关性上是这样，但业务逻辑上不对。评论、点赞、收藏是二级功能，更底层的理解是增加 App 的社交属性。
:::

### 第四步：指标宣贯、存档、落地

- **宣贯**：拉上产品和研发开会议过流程——产品负责使用、研发负责打点；
- **存档**：对不太好理解的指标做单独解释，比如什么是日活、具体操作是怎样；
- **落地**：确定好打点之后就建表，确保数据第一时间出来、能及时发现问题。

::: tip 不需要大而全
实际工作中根本不需要一套大而全的指标体系，只需要围绕当前的核心指标解决最重要的问题。有些分析师把某产品模块的指标体系画得非常复杂、包含七八个模块——但要问一句：最后到底看哪个指标？这些难道都要打点吗？一个产品七八个模块都很重要基本是不可能的，唯一的解释就是产品想做的东西太烦琐。
:::

## 总结

- 指标体系本质上代表业务人员和分析师的逻辑性；
- 不同业务阶段指标体系不一样，核心指标一定要正确；
- 核心指标拆解的通用模式是先公式拆解，再按照业务模块、路径来分；
- 指标体系的宣贯和存档工作必不可少。

# 流量分析：如何分析数据的波动？

> 指标体系与报表建立之后，分析师和业务方最重要的事情就是每天看数据，这个过程就是流量分析。这里的流量是广义流量——用户从哪来（渠道分析）、经过什么过程（转化分析）、产生什么价值（价值分析）、为何波动（波动分析）。本篇逐一展开这四个环节的方法与指标。相关主题：[指标体系搭建](./34-指标体系搭建：指标体系的经典四步.md)、[路径分析](./36-路径分析：用户的使用路径网络分析.md)。

## 流量分析的定义

从定义出发，流量分析分为四个部分：

- **渠道分析**——从哪来；
- **转化分析**——经过什么过程；
- **价值分析**——产生什么价值；
- **波动分析**——日常的监控分析。

## 渠道分析

渠道分析包含三部分：常见渠道及渠道分类、渠道推广的整个过程、渠道的关键指标及分析方法。

### 常见渠道及渠道分类

渠道分为**内部渠道**和**外部渠道**：

- **内部渠道**：内部的产品矩阵。例如今日头条会给抖音带量，内部渠道往往免费使用。
- **外部渠道**：往往需要付费，包括四类——搜索引擎（如百度搜索结果中的广告推广）、App 内广告（如今日头条里的京东或双 11 链接）、社交媒体（如微信朋友圈广告）、软件市场（如应用宝、华为手机市场、豌豆荚等）。

内部渠道和外部渠道都是为了拉新、拉增而用。对于一款健康的 App，前期靠渠道（特别是外部渠道）的品牌带量，后期靠自传播或免费推广。大多公司会单独设有渠道运营经理岗位，分析师在这部分的价值体现不会很大。

再从**量级 × 质量**两个维度给渠道分类：横坐标是渠道带来的量级（从左到右越来越高），纵坐标是渠道本身的质量（一般用留存衡量，也可以用收入衡量——留存跟收入本来就是高度相关的指标）。按量级和质量画四象限，可以把渠道分为 4 类：

![image (1).png](/data-practice-images/i/image/M00/2D/41/Ciqc1F8C9puAS-ZnAAA6F6sGuM0341.png)

| 量级 | 质量 | 策略 |
|---|---|---|
| 少 | 高 | 需要扩量，在扩量的基础上仔细观察数据 |
| 多 | 高 | 渠道非常好，加快变现能力 |
| 多 | 差 | 用户不匹配、交互有问题，需要拆解、精细化运营 |
| 少 | 差 | 直接放弃 |

所有的分析都是先分析一级渠道，然后在此基础上拆解：比如一级渠道的 A 渠道留存很差，要进一步对 A 渠道做二级渠道拆解，看是所有二级渠道差还是部分二级渠道差。所有质量的好与差都是相对大盘来说的。

### 渠道推广的整个过程

渠道推广的完整流程是一条漏斗：**外部渠道展示文案 → 点击进入落地页 → 落地页引导下载 → 下载后打开 App → 浏览 → 注册 → 直到退出**。从外部渠道到注册的整个过程是一个漏斗，分析师可以在其中提供优化建议。

以百度搜索为例：

![image (3).png](/data-practice-images/i/image/M00/2D/41/Ciqc1F8C9rmAS4dsAAQd4Akcn10821.png)

假设搜索"外卖"两个字，出现的第一个链接是"外卖送药 京东到家"，链接下方带有广告标签——这是"京东到家"在百度搜索投放的外部渠道。点击进去后，文案展示有"15 元优惠券"的提示，下方有一个输入横框——这里有一点不合理：没有提示输入什么，第一次打开的用户会犹豫是不是要输入手机号码。输入手机号码点击"立即领取"后，出现下载页面，下载过程中又有很多弹窗（如外部风险提示等）。App 下载完成后，用户打开、浏览或注册——所有这些步骤就是渠道推广的整个过程。看似简单的例子，在页面交互、设计、产品文案方面都有很多优化点。

### 渠道的关键指标及分析方法

**关键指标**：前期看有效用户数和次留，中期看次日、7 日、30 日留存，后期看 ROI。

::: warning 有效用户数可能被刷量
渠道都是收费的，所以有效用户数有刷量的嫌疑。除了看直接量级，还要看有主动行为的用户数，比如[指标体系篇](./34-指标体系搭建：指标体系的经典四步.md)中的"停留时长大于 3 秒的用户数"。所有渠道最终的目的都是商业变现，一定要计算每个渠道的 ROI，及时把 ROI 小于 1 的渠道砍掉。
:::

**分析方法**包括四种：

- **结构分析**：先按照一级渠道拆解，再按照二级渠道拆解；
- **趋势分析**：看每个渠道的变化趋势，包括量级和留存；
- **对比分析**：不同渠道间的趋势对比；
- **作弊分析**：包含用户行为分析和机器学习，可以用 Python 完成。

## 转化与价值分析

渠道转化和价值的分析分为两点：漏斗分析，以及功能模块分析（常规分析、价值分析）。

### 漏斗分析

漏斗分析是数据分析师看一款产品必不可少的环节。[电商篇](./30-电商数据分析：京东 App 的详细产品分析.md)已以京东 App 电商模块为例完整演示过漏斗模型，这里补充转化率提升的核心思想：**按照用户基础属性和行为属性来细分**。

- **基础属性**：手机品牌、地域、imei 特征。例如主界面全部 UV 到店面页 UV 为 50%，想提高至 60%，需要进一步拆分——华为手机和苹果手机等品牌各自的转化率是多少，华北、华南、华东等地域的转化率是多少。按照这些维度拆解，最后甚至可以拿到用户的基础画像，实现更精细化的运营。
- **行为属性**：入口、时段、用户活跃度、用户标签。例如用户是通过桌面图标、弹窗还是外链进入页面，早中晚的用户量级，用户活跃度的区分，不活跃的老用户被激活后的活跃度观察。

总之要按照用户的基础属性和行为属性拆分，对有问题的群体进行针对性优化。

### 功能模块的常规分析

用户进入主页面之后不一定走漏斗，还可以使用各种功能。功能模块主要看三个指标：

- **功能渗透率** = 功能用户数 / 大盘用户数（使用某功能用户在大盘的占比）；
- **功能的功能留存率** = 第一天使用该功能且第二天也使用该功能的用户数 / 第一天使用该功能的用户数；
- **功能大盘留存率** = 第一天使用该功能且第二天是大盘用户的用户数 / 第一天使用该功能的用户数。

后两个指标的区别：功能留存要求第二天还使用该功能，大盘留存只要求第二天打开 App。

另外一个必须关注的数据是**大盘用户**：大盘用户 = 所有功能用户排重 + 不使用任何功能的用户（逛一逛的用户）。对不使用任何功能的用户也要监控起来，只有这样才是完整的大盘。

### 功能模块的价值分析

衡量功能的真正价值有三个指标：

- **功能核心用户数**：符合某种要求的功能用户数，一般用使用次数、使用时长、使用天数等行为来定义"核心"。单纯看用户数可能出现一个悖论——所有功能在涨，但大盘在跌。
- **功能对大盘贡献度**：比如对大盘留存提升的贡献。

```
功能 A 对大盘留存的提升贡献 = 功能 A 渗透率 * 功能 A 的大盘留存率提升数
```

严格来说，只有 A/B 测试才能说明功能对大盘的贡献度（参见[AB 测试：AB 测试的效果监控](./43-AB 测试：AB 测试的效果监控.md)），但实际应用中不可能所有功能都做 A/B 测试，所以这种计算可以对不同功能做横向对比。

- **功能带来的收入对比**：每个功能每个月赚多少钱。分析师对收入部分可能没接触过，但实际过程中会有单独的计费系统——拉一个月的收入数除以功能用户数即可，计算非常简单。

**案例：功能 A 的用户数与核心用户数背离**。功能 A 最近两周的用户数呈直线上升趋势，但核心用户数指标实际上没有涨，中间反而还跌了一段时间（核心用户数口径是产生点击行为的用户数，即必须使用这个功能的用户数）：

![image (6).png](/data-practice-images/i/image/M00/2D/4D/CgqCHl8C9wCAIilrAAFyDTsisEs359.png)

这种情况在实际工作中很常见：分别看用户数和核心用户数，趋势可能不一样——这就是核心用户数的价值。只有核心用户数才是功能的真正用户，其他用户很可能通过其他方式带量，比如上线了一个小图标、有一个红点提示。

**案例：功能 B 与功能 C 的大盘贡献**。功能 B 渗透率 20%，对大盘留存的提升为 3%（由 55% 提升到 58%）；功能 C 渗透率 25%，提升 1%（由 45% 提升到 46%）。则功能 B 对大盘周留存的提升贡献为 20% × 3% = 0.6%，功能 C 为 25% × 1% = 0.25%——功能 B 当前对大盘的贡献更大。

日常看功能时，除了使用 UV 还要看更多数据，才能真正说明功能有没有问题、是不是健康。三条经验：

- 产品的每一次决策都要基于逻辑性很强的数据证明——"我觉得"没有任何说服力，很容易被挑战；先有数据再有结论，不要先入为主。
- 每个产品经理都有自己内部的指标，但必须衡量当前做的事情对大盘 KPI 的贡献度——只有大盘好才是真的好。
- 敢于说真话、实事求是——没做好就是没做好，关键是接下来怎么做、当前有没有找到真正问题。

## 流量波动的逻辑性分析

常见的流量波动分析对象是日活和留存。

### 日活

日活波动受外部影响和内部影响：

- **外部影响**：行业变化和竞品变化，而竞品的变化跟竞品的策略有关，所以外部影响分为常识、外部事件、竞品策略。
- **内部影响**：包含数据统计、用户基础属性、用户行为属性三类——
  - 数据统计：数有没有搞错——数据采集和统计口径；
  - 用户基础属性：用户从哪里来、通过什么方式进入——渠道（新增用户变化）、入口（手机型号）、画像；
  - 用户行为属性：用户进来干了什么——具体功能的变化，跟版本可能有关。

按照金字塔原理的逻辑拆分产品，就不会有遗漏，这就是日活波动的逻辑性思考。

### 留存

留存相对复杂一些。留存波动包含新用户留存和老用户留存：新用户留存与渠道和渠道过程有关；老用户留存有两个影响因素——核心功能用户留存、非核心功能用户留存，要区分来看。

老用户留存 = 核心功能的留存 + 非核心功能的留存，其中核心功能可以进一步拆解为功能 A 的留存 + 功能 B 的留存 + 功能 C 的留存。

假设留存下跌，会出现两种情况：

- **A、B、C 中有 1 个留存下跌**：最好解释，直接解释由于谁下跌即可；
- **A、B、C 中有两个以上留存下跌**：要看谁是主要下跌因子并找到它。如果下跌幅度都差不多，需进一步观察；如果还是持续下跌，必然是产品某核心部分出问题，围绕指标体系做一次产品全盘分析找到它；如果跌了几天之后回去了，可能跟外部影响因素有关，暂时不管。

留存是比例，排查起来比较费神，保持耐心跟业务方多沟通，就一定能找到主要影响因子。

### 数据敏感性

流量分析是分析师每天都要做的事情，小到看日报，大到波动排查几个月。要非常熟悉各类核心数据，能够说出数据的规律并进行预测——数据出现稍微一点异常时，能敏锐地感觉到并去排查。

例如某产品近三天日活分别是 1000w、1020w、1025w，按照产品规律第四天应该在 1050w 左右，如果第四天是 1035w，就说明必然某部分出问题了。为什么第四天应该是 1050w 左右？原因是单一变量会带来的增量幅度，可以画一个模拟的坐标折线图来观察——但这里的聚焦点是数据敏感性。

::: tip 什么是数据敏感性
数据敏感性就是对数据产品的微观感知能力，需要大量的沉淀和思考才能做到。
:::

## 总结

流量分析本质上解决用户从哪来、干了什么、带来什么价值，整体概括为三个部分：

- **渠道分析**——渠道的整个过程和分析方法；
- **功能模块价值分析**——漏斗分析、功能常规指标和价值指标分析；
- **流量波动逻辑性分析**——一定要有逻辑性，在过程非常严密的基础上得到正确的结果。

# 数据获取与分析：常见的 SQL 技巧和分析方法

> 本篇覆盖分析师的日常主线工作：用 SQL 提数前的准备事项、提数过程中的常见问题与应对，以及提数完成后的五种常用分析方法（结构分析、对比分析、时间序列分析、相关性分析、机器学习），每种方法均配有一个数据案例。分析方法背后的问题拆解思路可参考[问题定义和拆解：如何去定义问题、拆解问题？](./40-问题定义和拆解：如何去定义问题、拆解问题？.md)。

## 数据获取前期准备

一般来说，在正式写 SQL 之前，要花 1 天时间做以下几件事：

- 了解清楚业务方和研发说的是哪张表、哪份日志；
- 了解这些表和日志的筛选条件是什么，为什么要这么筛选；
- 了解这些表和日志之前有什么坑，是不是哪天数据有缺失；
- 验证现在是否有坑——`select *`，先跑一个核心数据看下。

做完这几件事之后，对表和数据就会有一定的感觉。在此基础上，再把问题的拆解模块构思一次，哪些点不好做，心理上要有个预期。前期准备非常重要：很多人在提数这块花了大量时间，原因就是前期工作做得不到位，太相信埋点。

## SQL 提数常见问题

提数的最终目的是分析。SQL 提数看似很简单，但往往会因为其他事项而比较花时间，常见的干扰有四类：

- 被各种各样的其他事情打扰；
- 遇到一些坑需要思考；
- 突然找到一个新点，就一直往下深挖；
- 自己本身不会提数和分析，不知道如何看数据。

逐一来看应对方法。

### 被打扰：集中时间管理

首先要有集中时间管理的意识，其次要认识到当前最重要的事情就是 SQL 提数和分析——目前所有事情当中优先级最高的就是这件事。时间管理上的具体建议：

- 早上时间一定要利用好，早点到公司。下午大部分时间都有会，会议时间不好控制；
- 提前了解好会议主题，确认是否必须参加，不要被拉去开一个与自己无关的会；
- 中间所有进来的插队需求，先靠边站；
- 利用晚上、周末时间在这件事上多下功夫。一旦进入专注状态，别人也不太好意思打扰。

### 踩坑：文档化沉淀

踩坑是必然的，不过可以通过踩坑来观人阅事——某个团队中谁比较靠谱、谁比较好说话、谁尽量不要接触。遇到坑之后，一定要用文档详细记下来，这样做有两个好处：一是可以让团队中的其他人知道，节省团队时间；二是每月总结的时候，知道自己在哪块花了大量时间，可以为后续做分析节省时间。

### 深挖新点：先完成主线

分析不同年龄段的用户上网时段分布后，可能突然发现未满 18 周岁的群体分布很奇怪，觉得终于找到一个亮点，然后持续往下研究这部分人为何这样，最后往往花了大量时间也没什么结论。一定要跳出小的圈子——最重要的事情是先把问题的拆解模块做完。

### 不会提数：刻意练习

如果不会 SQL 提数，就要学如何提数：可以参考同事是怎么写 SQL 的；前期可以多接需求、多帮别人提数，熟能生巧。

## 常用的分析方法

提数完成之后，如何分析？常用的分析方法有以下五种。

### 结构分析

例如渠道新增用户数，五个渠道 A、B、C、D、E 对应的新增用户分别如下：

| 渠道 | A | B | C | D | E | 合计 |
|---|---|---|---|---|---|---|
| 新增用户 | 1w | 2w | 3w | 4w | 5w | 15w |

结构分析回答的是"渠道的构成是什么样子"：D 和 E 渠道的新增用户数总和占全渠道新增用户数的 60%，这就是结构分析。这是最基础的数据结构分析，而且管理层一定会问目前渠道的分布是什么样子，所以拿到数据之后都要做结构分析。

### 对比分析

所有的数据只有对比才有意义。每年的双 11 都会与之前的双 11 进行消费额对比。实际工作中，最常见的对比对象就是大盘：比如新上线一个功能，评估这个功能效果时，除了看功能使用人数，更要做的是这个功能的留存和大盘留存的对比。

另一个例子：需要看自身 App 跟竞品的重合用户，与自身 App 的所有用户在客户端内的消费差异，从而针对这些重合用户做针对性运营——目的是看竞品用户到底喜欢什么。

以微视这款 App 为例，对比微视与抖音的重合用户消费分类和微视大盘消费分类的消费 CTR 数据，可以算出重合用户更加偏爱哪些分类。

![微视与抖音重合用户的分类偏好](/data-practice-images/i/image/M00/38/E6/CgqCHl8ehl-AZIlLAACcvaG4hys460.png)

图中相对值 diff 的计算方式是：重合用户的消费 CTR 除以大盘的消费 CTR 再减 1。可以发现搞笑、舞蹈、明星、美食分类的相对值是很明显的正向。因此，会针对这部分重合用户多推这些内容、减少其他内容权重，这就是对比分析最直接的效果。

### 时间序列分析

看某个指标时，一般会把时序周期拉长，看数据趋势。而数据都是波动的，所以都会进行拆解分析，寻找具体的波动项。

例如：新增用户的次日留存近半年出现下降，需要进行渠道维度拆解分析，看整体下降是因为所有渠道都下降，还是某个渠道下降导致的。

这是模拟数据的曲线：

![次日留存趋势模拟数据](/data-practice-images/i/image/M00/38/DB/Ciqc1F8ehmaAZWF6AABYesH2eVY376.png)

对应的原始数据：

![次日留存原始数据](/data-practice-images/i/image/M00/38/DB/Ciqc1F8ehm2ARhdAAABfiKswGO4134.png)

根据原始数据，用透视表功能按渠道维度拆出"日期 × 渠道"的二维数据：

![日期与渠道的二维数据](/data-practice-images/i/image/M00/38/DB/Ciqc1F8ehoyAZyo9AAEHqyfZ1s8288.png)

再基于这个二维数据插入图表，从图表可以发现：A 渠道变化不大，C 渠道是上升的，只有 B 渠道是下降的。因此是 B 渠道出现问题，需要对 B 渠道进行优化，这就是时间序列分析的效果。

### 相关性分析

分析中涉及很多变量、很多因子时，就要去分析因子之间的相关性。例如在传统行业的数据分析中，产品单价和销售额之间有没有明显的正相关性，就需要做相关性分析。

### 机器学习

当变量、因子众多时，还可以用机器学习的方法从结果中找出最关键的影响因素。

![用户影响因素分析](/data-practice-images/i/image/M00/38/E6/CgqCHl8ehsSAXK6TAARNB9wtKnE357.png)

从结果发现，开通月数和电子支付这两个变量是目前最能够影响用户的变量，那就针对这两个变量去做优化。

## 总结

所有的分析都是基于用户的基础属性和行为属性。如果暂时没有思路，可以从 5W1H 出发，每次分析时以这个为模板展开：

| 维度 | 含义 |
|---|---|
| Who | 用户基础属性、用户画像 |
| Where | 渠道分析、渠道入口，用户从哪里来 |
| When | 时间上的特征 |
| What | 用户使用了什么功能，哪些行为更加重要 |
| Why | 为什么要这么做，用户是主动还是被动做的 |
| How | 怎么做的，行为路径是什么 |

提数和分析完成之后，先不要急着写报告，要先把一些关键数据和初步结论同步给业务方核心人员，约个时间一起看下。这样做有两个目的：一是看业务方怎么理解这个数据、有无明显问题；二是业务方基于这些数据结论准备怎么落地，需要他们提前想方案。在这个基础上，再去撰写报告。

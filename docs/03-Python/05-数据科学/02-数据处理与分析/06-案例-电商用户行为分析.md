# 案例：电商用户行为分析

无论哪个方向，数据分析都能显著提升业务效果，是电商业务不可或缺的一环。

本文利用前文学习的 pandas 知识，对一个真实的电商数据集进行分析，一方面系统性复习 pandas 知识，同时展示电商数据分析实战项目的分析流程。

## 任务背景

电商网站阿普闪购计划策划一场推广活动，通过发短信的形式，向潜在用户发送广告和优惠信息，吸引他们来阿普闪购注册并购物。

由于预算以及短信服务商的限制，无法对大范围的用户投放，需要缩小人群范围，找出最有可能产生转化的人群。此外，用户的下单行为往往和时间呈现一定相关性，营销短信的投放时间也很重要。

作为阿普闪购的数据分析师，需要完成以下目标：

- 通过数据分析，找到最有可能转化的人群特征（年龄、性别、地域）等；
- 通过数据分析，决定最有利于转化的营销短信投放时间。

经过与多个部门沟通，从阿普闪购的数据部门申请到以下数据权限。

- 用户行为表：最近 6 个月的用户行为记录。
- VIP 会员表：用户 VIP 会员开通情况。
- 用户信息表：用户的相关信息。

## timestamp 疑云

前面的内容提到，user_log 表中存在两个时间戳字段，比较迷惑。这两个字段究竟代表什么？

可以看出，两个时间戳字段 time_stamp 和 timestamp 的值不一样。time_stamp 看起来是个整数，值比较小，而 timestamp 看起来是个浮点数，值比较大，普遍在五位数，其他暂时看不出什么有用的信息。

对于含义不明确的字段，通常的做法是先看一下它的边界（即最大值和最小值）。

新建 Cell，输入以下代码并执行。下面的代码分别通过 pandas 的 max 函数和 min 函数，获取了 time_stamp 与 timestamp 的最大值与最小值，并通过 print 函数打印出来。因为打印的时候要和提示字符串进行拼接，所以 max 和 min 函数返回的结果都使用 str 函数进行了类型转换，将整数转换为了字符串。

```
time_stamp_max = str(df_user_log['time_stamp'].max())
time_stamp_min = str(df_user_log['time_stamp'].min())
print("time_stamp max: " + time_stamp_max, "time_stamp min: " + time_stamp_min)
timestamp_max = str(df_user_log['timestamp'].max())
timestamp_min = str(df_user_log['timestamp'].min())
print("timestamp max: " + timestamp_max, "timestamp min: " + timestamp_min)

```

输出以下结果：

```
time_stamp max: 1112, time_stamp min: 511
timestamp max: 86399.99327792758, timestamp min: 0.10787397733480476

```

可以看到，time_stamp 的最大值为 1112，最小值为 511，而 timestamp 的最大值为 86399.99，最小值为 0.1。

从数据集的描述来看，用户行为表是用户 6 个月的行为，那 time_stamp 最大 1112、最小 511 看起来特别像日期，代表最小日期是 5 月 11 日，最大日期是 11 月 12 日。

既然 time_stamp 是日期，那 timestamp 会不会是具体的时间？timestamp 的最大值为 86399，而一天最大的秒数为 24*3600 = 86400，两个数字非常接近，基本可以认定 timestamp 代表一天中的第几秒发生了这个行为。

破解了两个时间字段的问题，为了避免后面有歧义，将 time_stamp 列重命名为 date。

新建 Cell，输入以下代码并执行。

```
# 注意：Pandas 已弃用 inplace 参数，更推荐写法 df_user_log = df_user_log.rename(columns={'time_stamp':'date'})
df_user_log.rename(columns={'time_stamp':'date'}, inplace = True)
df_user_log

```

重命名 DataFrame 的某一列的名字，可以使用 rename 函数。第一个参数代表要重命名的列的映射关系，这里表示把 time_stamp 重命名为 date；第二个参数 inplace = True 代表在当前 DataFrame 中生效（Pandas 已弃用该参数，推荐将结果重新赋值）。

输出结果为：

可以看到，原来的 time_stamp 列已经被改为 date。

## 数据分布分析

接下来进入本次分析的核心环节：数据分布分析。

从数据分布中分析出最有可能转化的用户特征。直白地说，就是分析出目前阿普闪购的用户中，什么年龄段的用户最多、什么性别的用户最多。进一步，分析下单的用户里年龄和性别的分布，这样才能知道给哪个年龄段、哪个性别的用户发营销短信最有用。

这里用到一个非常强大的 pandas 函数：value_counts。value_counts 一般针对 Series 对象，用于统计 Series 中有多少个不同的值，以及每个值出现的次数。比如：

```
ser1 = pd.Series([1,1,3,3,3,3,4,5])
ser1.value_counts()

```

输出为：

```
3    4
1    2
5    1
4    1
dtype: int64

```

左边是值，右边是出现的次数，并且按照出现的次数从高到低排序。

通过 value_counts 函数可以非常便捷地实现某个字段的分布分析。

### （1）用户年龄分布分析

第一步，先分析用户表中用户的年龄段分布。如上文所述，数据分布可以直接使用 DataFrame 的 value_counts 函数。

```
df_user_info.age_range.value_counts()

```

输出：

```
3.0    110952
0.0     90638
4.0     79649
2.0     52420
5.0     40601
6.0     35257
7.0      6924
8.0      1243
1.0        24
Name: age_range, dtype: int64

```

除去未知的数据不看（假设未知的部分的分布符合整体的分布），除去取值为 0（代表未知）之外，取值为 3.0 和 4.0 的占到绝大多数。回顾数据集的定义，取值为 3 代表 25～30 岁，取值为 4 代表 30～34 岁。所以可以得出，25～34 岁之间的用户占绝大多数（age_range 取值 3.0、4.0）。

然后通过代码计算 25～34 岁用户的比例。首先通过 loc 函数筛选出所有不等于 0 的记录，然后计算年龄段等于 3.0 与年龄段等于 4.0 的总数除以所有非 0 记录的总数，计算的代码如下：

```
user_ages = df_user_info.loc[df_user_info["age_range"] != 0, "age_range"]
user_ages.loc[(user_ages == 3) | (user_ages == 4) ].shape[0] / user_ages.shape[0]

```

输出：

```
0.5827529275078729

```

可以看到，25～34 岁用户占到了 58% 的比例。

从用户群体的分析上，已经勾勒出目标用户画像：25~34 岁之间的女性群体。但目前分析的只是注册用户的信息，会不会存在男性虽然注册用户少但购买力却更强的情况？为了验证这个假设，需要结合订单数据来分析。

### （3）user_log 与 user_info 表合并

用户群确定之后，下一步要确定发送的时间。下面分析用户下单的时间特征。

### （6）不同日期的下单行为分析

虽然可以直接对 date 字段进行 value_count，但更希望找到一个适合投放的日期范围，而不是具体某一天。所以使用分组的 value_count，下面的代码将把所有日期分成六组，统计每组的订单量分布。

对 value_counts 的结果进行分组，可以通过给 value_counts 函数增加 bins 参数实现，bins 的值代表要分成几组，之后的数据分布就会按组输出。在这里，因为数据集是半年的，所以分六组（看每个月的分布）。

```
df_user_log.loc[df_user_log["action_type"] == "order", ["date"]].date.value_counts(bins = 6)

```

输出：

(911.0, 1011.0]      69427
(510.399, 611.0]     68776
(611.0, 711.0]       62901
(711.0, 811.0]       54053
Name: date, dtype: int64

```

可以看到，用户在 10 月中下旬一直到 11 月上旬这个时间段，下单量较为集中。分析完日期分布后，接下来分析一天中的时间段分布。

### （7）不同时间段的下单行为分析

timestamp 字段存储了每条记录下单的时间，是从当天零点开始累积的秒数，并不是很直观，更希望基于小时级的数据去分析。所以考虑基于 timestamp 这一列，新创建一列时间来表示小时。

根据高级索引章节学习的内容，新建列只需直接给对应的列名赋值即可，值需要是一个合法的 Series。在这里，以 timestamp 列为基础，将其值除以 3600，然后用这个值创建一个新的列 time_hours_view。

```
df_user_log["time_hours_view"] = df_user_log["timestamp"]/3600
df_user_log

- 针对原始表进行数据分布分析（user_info 表）；
- 多个表联合查询数据分布（user_info 联合 user_log 表）；
- 对于连续值，通过 bins 参数实现分段统计。

再回顾一下这个案例中用到的关键技术：

- 解决 timestamp 问题时，通过 max 函数和 min 函数，分析了部分列的边界；
- 清洗数据时，使用 isnull 函数帮助发现缺失值，使用 dropna 函数删除包含缺失值的记录；
- 在分布分析时，使用 value_counts 计算某个字段的数据分布，并且针对部分数据范围很大的字段，使用 bins 参数对分布结果进行分组；
- 当将具备共同字段的多张表拼接到一起时，使用 join 函数，并且在参数中通过 set_index 指定共同字段；
- 在部分字段不方便直接分析时，比如一天中的秒数，通过向量运算（timestamp/3600）派生出一个易于分析的新字段，比如小时级的数值；
- 在需要数据筛选时，使用 loc 函数配合条件，可以筛选出 DataFrame 中符合条件的一个子集，比如 user_log 表中仅关注下单的记录，就可以通过 loc 函数配合 action_type=="order" 筛选出相应的记录。

# 提升可访问性动画的关键技巧

## 概念说明

Web 动画是一个存在争议的话题：糟糕的动画非常显眼，而精心制作的动画则无缝融入背景。处理得当时，动画可以为 Web 应用或网站增添个性、提供视觉提示并减轻认知负担。但可访问性与动画常被视为两个"阵营"——以动画、视频或 GIF 形式呈现的运动可以带来更大的背景和洞察力，对另一些人来说，动画可能产生令人不适的体验。

运动敏感性对不同群体的影响不同：

- 对注意力障碍用户，动画会带来额外挑战，阻碍其专注于内容。
- 对有认知障碍或前庭功能障碍的用户，任何形式的运动都可能触发身体不适，表现为恶心、头晕和头痛等症状。
- 在更极端的情况下，光敏性癫痫患者可能因某些类型的视觉刺激诱发癫痫。

在运动敏感性与使用动画增强界面之间取得平衡的方法是：理解不同用户群体的需求，并使用一系列关键技巧，包括媒体查询、优化动画参数、考虑前庭障碍等，使动画既令人印象深刻，又对所有用户友好。

## 共情动画

### Web 共情与共情动画

**Web 共情**指在 Web 设计和开发中考虑用户的感受和需求，以创造更人性化、体贴和易用的用户体验，包括关注用户的情感状态、心理需求和潜在挑战。

**共情动画**则是将 Web 共情原则应用到 Web 动画上：通过动画效果增强用户体验，同时考虑用户的感受和需求。这类动画旨在自然、流畅地响应用户操作，提供直观、友好的界面反馈，与用户建立情感连接。实践中通常包括微交互和过渡动画，以细致的方式传达信息、帮助用户理解界面变化——前提是谨慎使用，确保不引起用户不适或干扰正常使用。

### 创建共情动画的自检问题

创建可访问的 Web 动画时，可以从三个问题入手：

- **这个动画有用吗？** 答案取决于 Web 应用或网站的定位。个人作品集可以尽情发挥；但用户试图提交纳税申报时，古怪的加载动画不会受到好评。动画进度条则是一个不错的选择，同时提供用户操作的视觉反馈。
- **动画是否转移了对重要信息的关注？** Web 主要是一个信息系统。当用户试图阅读时，使文字动起来或在附近播放循环动画会极大分散注意力，对注意力缺陷障碍或多动症用户尤其明显。出色的动画有助于集中注意，而不是干扰用户。
- **是否允许用户选择退出？** 对运动敏感的人而言安全最为重要。前庭（内耳）障碍患者可能因 Web 动画感到头晕、头痛甚至恶心。

需要正视的事实是：在某些情况下给 Web 应用或网站添加动画并非好事。动画无论大小都可能对用户体验产生不利影响——分散注意力、过度刺激、令人反感，有时还会触发晕动病或眩晕等疾病。用户对 Web 动画的反应五花八门：有积极的、消极的，有时根本没有反应。这带来一个现实挑战：是保留这些动画还是彻底删除？如果删除，如何向用户提供反馈？没有动画又将如何影响用户对产品的理解？

## 可访问 Web 动画的重要性

### 三类障碍视角

谈论可访问 Web 时，容易将可访问性与永久性残疾联系起来，但临时性或情境性障碍同样影响用户体验：访问产品的用户可能没有前庭功能障碍，但可能经历暂时的视力丧失或脑震荡，或仅因整天盯着屏幕而视觉疲劳。

Web 可访问性意味着每个人都可以感知、理解、导航、与 Web 交互并为 Web 做出贡献。可访问性涵盖所有影响网站访问的条件，包括视觉、听觉、物理、语言、认知和神经功能障碍。动画占据视觉、交互、认知等多个方面，因此尤其需要关注。

### 把控制权交给用户

制作可访问 Web 动画的核心思路是：**把控制权交给用户，通过做减法使动画服务于所有用户**。当下很多终端都提供了用户偏好的相关设置。假设用户开启了减少运动（Reduced Motion）偏好，产品就应让这些用户看不到或少看到动画。目标是将减少动画偏好无缝地整合到 Web 应用或网站中，为所有用户的福祉做出贡献。

## 为什么要减少运动

减少运动偏好（Reduced Motion Preferences）是一种用户喜好的行为，大多数设备都提供了该项设置，Web 开发者即使使用纯 CSS 也可以获得这些信息。

自 2013 年 iOS 7 发布引发数字界面变革以来，业界认识到：屏幕上的动效即使是界面的一部分，对动效敏感的人也可能产生身体上的影响。动效敏感的根本原因个体间差异很大——可能源于平衡障碍、偏头痛或其他因素，引发原因因人而异，甚至每天都可能不同。个体因动效经历的身体症状从轻微的头晕、头痛到恶心或更严重的情况不等。

围绕动画做出的设计选择直接影响对动效敏感的人群。了解哪些动效可能引发问题、如何通过设计选择减轻这些问题，有助于设计对受众安全且不会造成意外伤害的体验。动画仍可以对 UX 产生积极影响，但必须负责任地使用，就像负责任地使用其他设计工具一样。

用户更喜欢减少运动的两个最常见原因：

- **注意力**：许多用户面对 Web 动画时难以保持注意力，可能由注意力缺陷障碍导致，或单纯更喜欢设计不与内容竞争的界面。
- **前庭障碍**：一种内耳疾病，可能在响应动画内容时引发恶心、头痛和眩晕等症状。

无论原因是什么，尊重用户的运动偏好至关重要。有些用户可能只是被高度动画的网站困扰；有些用户则可能必须完全停止使用，以防止不良的身体反应。

## WCAG 对运动的标准

设计减少运动时首先需要区分两个概念：**动画并不等同于运动（Animation ≠ Motion）**。虽然所有移动的元素都是动画，但并非每个动画元素都涉及位置的改变。

WCAG 提供了与界面运动相关的三个标准：

- **[暂停、停止和隐藏](https://www.w3.org/TR/WCAG22/#pause-stop-hide)**：允许用户暂停、停止或隐藏任何移动、闪烁或滚动的内容，以及自动启动或更新、持续时间超出五秒并与其他内容同时呈现的内容。
- **[移动或闪烁的元素](https://www.w3.org/TR/WCAG22/#seizures-and-physical-reactions)**：避免癫痫和负面身体反应的准则，避免闪烁频率超过每秒三次的间歇性动画，因其可能引发癫痫发作。
- **[通过交互产生的动画](https://www.w3.org/TR/WCAG22/#animation-from-interactions)**：用户应能够与 UI 进行交互而不仅依赖动画；用户应能够停止任何类型的运动，除非动画对功能或传达信息至关重要。

### 暂停、停止和隐藏

WCAG 对动画的第一条建议就是"[暂停、停止和隐藏](https://www.w3.org/WAI/WCAG21/Understanding/pause-stop-hide.html)"，规定原文如下：

> 对于任何开始自动播放、持续时间超过五秒，并与其他内容并列呈现的移动、闪烁和滚动信息，用户都应该有一种机制可以暂停、停止或隐藏它，除非该移动、闪烁或滚动是必不可少的一部分。

这条建议适用于自动启动而无需用户交互的动作。就 Web 动画而言，大多数动画持续时间都远低于五秒，但有一些常见模式适用于此建议：自动播放的轮播或幻灯片、动画背景、动画插图。这些模式中的单个动画可能很短暂，但整体运动往往持续超过五秒——尤其是动画被设置为无限循环时。

如果应用或网站存在较长的动画，就需要添加暂停、停止和隐藏机制，允许用户关闭可能存在问题的运动动画（Motion Animation），例如给自动播放的轮播或幻灯片组件添加暂停和播放控件。WCAG 规范并未规定这些控件的外观，设计上可自行把控。

### 移动或闪烁的元素

制作动画时应考虑元素的移动是否过度。屏幕颜色类似霓虹灯的闪烁效果、元素在屏幕上快速来回移动，都可能导致光敏性癫痫患者惊厥。据估计，[3% 的癫痫患者](https://www.epilepsy.com/what-is-epilepsy/seizure-triggers/photosensitivity)遭受过光敏反应，这种症状在女性和年轻人中更常见。

WCAG 对移动或闪烁的元素提出两条建议：

- 在任意一秒内闪烁不超过三次；
- 在低于[常规闪烁和红灯阈值](https://www.w3.org/TR/WCAG21/#dfn-general-flash-and-red-flash-thresholds)时闪烁。

其背后的主要原因是：屏幕上的明显闪烁往往导致用户无法使用 Web，最严重的还会导致疾病。简而言之，**Web 上不应包含在任何一秒内闪烁超过三次的内容，或者闪烁应控制在一般闪烁和红色闪烁的阈值以下**。

WCAG 提供了屏幕闪烁可被认为是安全的尺寸、比例和观看角度的详细信息。对大多数人来说，最容易的方法是避免任何在一秒内闪烁超过三次的内容。很少有设计师会刻意让屏幕过度闪烁，但这种情况确实会发生——追求视频游戏感觉或故障感的设计可能涉及每秒更多次的屏幕闪烁。

对任何极端运动，务必使用[光敏性癫痫分析工具（PEAT）](https://trace.umd.edu/peat/)进行测试：

> Tools: https://trace.umd.edu/peat/

PEAT 是一款免费工具，用于确定屏幕内容、视频或动画是否可能导致惊厥。并非所有内容都需要通过 PEAT 评估，但出于安全考虑，包含浅色和深色背景之间闪烁或快速过渡的内容应进行评估。

关于动画和运动的另一个判断维度：元素的移动对理解屏幕上的内容或操作是否至关重要。如果并非必要，应考虑去除元素中的所有移动，甚至微移动。如果认为该移动可以增强整体体验，或因其他原因无法移除，则应遵循 WCAG 的[运动准则](https://www.w3.org/WAI/WCAG21/Understanding/pause-stop-hide.html)：构建选项让用户能够暂停、停止或隐藏自动启动、持续超过五秒且属于非必需的移动、闪烁或滚动元素。

### 通过交互产生的动画

该准则涵盖与前两者不同类型的动画。"暂停、停止和隐藏"与"移动或闪烁的元素"通常适用于由 Web 应用或网页本身启动的动画，而本准则更适用于由用户交互启动的动画：

> **可以禁用由交互触发的运动动画（Motion Animation），除非动画对功能或传达的信息至关重要**。

WCAG 将"运动动画"定义为用于"营造移动幻觉"的动画，并明确指出"运动动画不包括颜色、模糊或不透明度的变化"。实质上，运动动画指通过图形、图像或元素的动态变化——逐帧改变元素的位置、形状、大小或其他属性——营造物体移动或变化的视觉效果，可以是简单的平移，也可以是更复杂的形状变化或旋转。

简单地说，某些类型的动画营造出了移动的感觉，另一些则没有。该准则关注的是那些营造出移动感觉的动画。在讨论动画和可访问性时保持这种区别，有助于高效地集中精力。

WCAG 给出的三条建议：

- **避免不必要的动画**：结合 Web 应用或网站的上下文评估动画量是否合适。视频或游戏网站上令人惊叹的动画效果放到政府网站上，可能让用户感到不必要或不合适。
- **为用户提供关闭任何非必要运动的控件**：对运动敏感人士可能带来不适的运动，应提供关闭控件（如一个按钮）。根据 WCAG 的定义，任何可能被视为运动动画的效果都应包含一个减少版本（减少运动）。典型的视差动画对运动敏感的人普遍存在问题，但仍是流行技术；要求完全终止所有视差效果并不现实，提供控件使用户在一定程度上控制（关闭或减少动画）是有意义且负责任的做法。
- **利用减少运动的功能**：很多操作系统长期提供指定减少运动偏好的无障碍设置，它使操作系统不使用应用启动动画等装饰效果。应用本身也应遵循此设置并移除所有不必要的动画。可以在 CSS 或 JavaScript 中访问该设置，并使用返回的值为希望使用减少运动体验的人提供相应体验。

### 两类运动与设计方法

从上述三条标准出发，减少运动设计需要考虑两种类型的运动或动画：

- **自动启动的运动或动画**：自动发生的移动、闪烁、滚动或自动更新，对应"暂停、停止和隐藏"与"移动或闪烁的元素"，包括自动播放的视频、无限循环的 GIF、自动播放的轮播或幻灯片。这类动画在 Web 上很常见。
- **由用户交互引起的运动或动画**：由用户交互产生，例如视差滚动效果。

针对不同类型，可以为用户提供不同的方法来减少或退出运动、暂停或关闭动画。常见方法如下：

**设计备用内容**：可访问的开发始于可访问的设计。例如为客户网站设计视差滚动效果时，应在设计阶段而非事后解决可访问性问题：

- 提供相应的标识，告知前庭障碍用户该效果可能引起不适；
- 探索减少运动的替代方向，例如采用淡入淡出效果替代视差滚动，既精致又避免不适。

**赋予用户控制全局站点动作设置的权力**：使用媒体查询切换 Web 应用或网站运动是提高可访问性的好方法。但一些用户可能不知道如何更新系统设置，或希望立即选择加入或退出。为此可以添加一个全局切换按钮用于打开或关闭动画，例如《[动物之森](https://animalcrossing.nintendo.com/)》网站：页头包含一个切换按钮，启用动画时背景通过旋转动画更改、前景角色跳入画面；禁用时背景更改但没有旋转效果，角色淡入。

> 动物之森：https://animalcrossing.nintendo.com/

## 如何减少运动：prefers-reduced-motion

### 检测用户偏好

CSS 媒体查询 `prefers-reduced-motion`（[属于媒体查询 Level 5 规范中的一部分](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion)）允许检测用户是否在系统中开启了**减少运动（Reduce Motion）** 偏好设置。现在很多操作系统都提供"可访问性"（Accessibility）设置，允许用户在系统级别根据喜好设置动画偏好。勾选后，这些偏好设置会导致操作系统不使用应用启动动画等装饰效果；应用本身也可以且应该遵循此设置，移除所有不必要的动画。

::: info 不同设备的入口差异
不同设备开启减少运动的方式略有差异。例如在 iPhone 上，需依次进入"设置"→"辅助功能"→"动效"，再开启"减弱动态效果"。
:::

`prefers-reduced-motion` 有两个选项：

- **`no-preference`**：用户未修改系统动画相关特性。
- **`reduce`**：用户修改了系统设置，将动画效果最小化，最好所有不必要的移动都能被移除。

当设置为 `reduce` 时，媒体查询会匹配用户在系统级别的偏好设置。只要启用了该设置且浏览器支持，就可以用 `prefers-reduced-motion` 配置动画以符合用户偏好：

```CSS
@media (prefers-reduced-motion: reduce) {
    .result {
        animation-delay: -1ms !important;
        animation-duration: 1ms !important;
        animation-iteration-count: 1 !important;
    }
}
```

假设用户勾选了减少运动选项，页面上将看不到动画效果：

> Demo 地址：https://codepen.io/airen/full/ExGwooV

Web 动画案例中常见的下面这段通用代码，即基于该媒体特性——将所有动画和过渡的时长替换得极短，使其不再引起注意：

```CSS
@media (prefers-reduced-motion: reduce) {
    *,
    ::before,
    ::after {
        animation-delay: -1ms !important;
        animation-duration: 1ms !important;
        animation-iteration-count: 1 !important;
        background-attachment: initial !important;
        scroll-behavior: auto !important;
        transition-duration: 0s !important;
        transition-delay: 0s !important;
    }
 }
```

### 减少运动不等于没有运动

需要注意的是，**减少运动并不等于没有运动**。有些情况下删除动画会阻碍用户理解其支持的内容，此时减缓事物而不是完全删除可能更有效——通过减缓和简化组件的动画，使概念得以传达而不触发可访问性问题。

可以借助 CSS 自定义属性高效实现：为动画和过渡的持续时间定义默认属性，再根据声明上下文修改：

```CSS
/* 设置默认持续时间 */
:root {
    --animation-duration: 250ms; 
    --transition-duration: 250ms;
}

/* 在特定情境下缩短持续时间 */
@media screen and (prefers-reduced-motion: reduce), (update: slow) {
    :root {
        --animation-duration: 0.001ms !important; 
        --transition-duration: 0.001ms !important;
    }
}

@media screen and (prefers-reduced-motion: reduce), (update: slow) {
    /* 在用户请求减少动画体验时，为所有未知动画移除持续时间 */
    *, *::before, *::after{
        animation-duration: var(--animation-duration);
        animation-iteration-count: 1 !important;
        transition-duration: var(--animation-duration);
    }
}

/* 当动画对理解至关重要且设备支持时，更新持续时间 */
@media screen and (prefers-reduced-motion: reduce), (update: fast) {
    .c-educational-concept {
        /* 设置一个新的针对该组件的动画持续时间 */
        --animation-duration: 6000ms !important;
        animation-name: educational-concept;
        /* 使用局部动画持续时间 */
        animation-duration: var(--animation-duration);
    }
}
```

这为用户体验提供了可访问的定制选项。示例中还使用了 `update` 媒体查询，它可以检测输出设备在呈现内容后修改外观的频率（如果有的话）。

### 非 animation/transition 场景：scroll-behavior

`prefers-reduced-motion` 除用于关键帧动画和过渡动画外还有许多应用。例如将 `scroll-behavior` 属性的值重置为 `auto`：

```CSS
@media (prefers-reduced-motion: reduce) {
    *,
    ::before,
    ::after {
        scroll-behavior: auto !important;
    }
 }
```

通常在 `html` 元素或滚动容器上显式设置 `scroll-behavior: smooth`，为用户提供更平滑的滚动体验——用户点击页面内锚链接时，页面将平滑滚动到适当位置：

```CSS
:root {
    --scroll-behavior: auto;
}
.item__wrapper {
    height: 100vh;
    scroll-snap-type: y mandatory;
    overflow-y: scroll;
    scroll-behavior: var(--scroll-behavior);
}
```

> Demo 地址：https://codepen.io/airen/full/wvOaWNy

将 `scroll-behavior` 从 `auto` 切换到 `smooth` 后点击底部缩略图（页面内锚链接），页面将平滑滚动到适当位置；点击列表中最后一个缩略图时页面滚动非常快且丝滑。这种体验对普通用户是愉悦的，但对运动敏感的用户，如此丝滑的滚动反而是一种不愉悦的体验。CSS 中目前没有其他属性可以单独控制这种行为，但可以通过 `prefers-reduced-motion` 防止在用户有减少运动偏好的情况下应用该行为：

```CSS
:root {
    --scroll-behavior: auto;
}

.item__wrapper {
    height: 100vh;
    scroll-snap-type: y mandatory;
    overflow-y: scroll;
    scroll-behavior: var(--scroll-behavior);
}

@media (prefers-reduced-motion: reduce) {
    :root {
        --scroll-behavior: auto !important;
    }
}
```

如此一来，即使 `scroll-behavior` 被设置为 `smooth`，用户点击页面内锚链接时页面也不会快速滚动：

> Demo 地址：https://codepen.io/airen/full/poYJEJY

该示例先将 `scroll-behavior` 设为 `auto`，用户点击页面顶部切换按钮后才切换到 `smooth`；若用户在系统级别设置了减少运动，值会再次重置为 `auto`——这实际上是给了用户更多的控制权。如果页面没有提供其他控制按钮，可以反过来做：默认 `auto`（无论用户有没有设置减少运动都不会快速滚动），再用 `no-preference` 重置为 `smooth`：

```CSS
:root {
    --scroll-behavior: auto;
}

.item__wrapper {
    height: 100vh;
    scroll-snap-type: y mandatory;
    overflow-y: scroll;
    scroll-behavior: var(--scroll-behavior);
}

@media (prefers-reduced-motion: no-preference) {
    :root {
        --scroll-behavior: smooth;
    }
}
```

用户在系统级别设置了减少运动时，上述代码同样不会使页面快速滚动。

### JavaScript 中的检测：window.matchMedia

CSS 媒体查询 `prefers-reduced-motion` 对 CSS `animation` 和 `transition` 制作的动效控制良好，但对 JavaScript 制作的动画、Canvas、SVG 动画、视频和 GIF 等就不太好控制了。此时可以使用媒体查询的 JavaScript API，即 `window.matchMedia`：

```JavaScript
function getPrefersReducedMotion() { 
    const QUERY = '(prefers-reduced-motion: no-preference)'; 
    const mediaQueryList = window.matchMedia(QUERY); 
    const prefersReducedMotion = !mediaQueryList.matches; 
    
    return prefersReducedMotion; 
}
```

说明：若用户未勾选"减少动态效果"，`mediaQueryList.matches` 返回 `true`。由于检测的是 `no-preference`，用户勾选后 `no-preference` 为 `false`，因此用 `!mediaQueryList.matches` 反转布尔值来确定用户是否勾选了"减少动态效果"。

也可以使用事件监听处理偏好变化：

```JavaScript
const QUERY = '(prefers-reduced-motion: no-preference)'; 
const mediaQueryList = window.matchMedia(QUERY); 
const listener = event => { 
    const getPrefersReducedMotion = getPrefersReducedMotion(); 
}; 

mediaQueryList.addListener(listener); 
mediaQueryList.removeListener(listener); 
```

当用户在操作系统中切换"减少动态效果"时，该侦听器将触发。监听此事件的目的在于：用户勾选"减少动态效果"时立即终止动画，即使页面已加载或动画正在进行。在 React 中可以自定义一个相关的钩子函数：

```JavaScript
const QUERY = '(prefers-reduced-motion: no-preference)'; 
const getInitialState = () => ( !window.matchMedia(QUERY).matches ); 

function usePrefersReducedMotion() { 
    const [ prefersReducedMotion, setPrefersReducedMotion ] = React.useState(getInitialState); 
    
    React.useEffect(() => { 
        const mediaQueryList = window.matchMedia(QUERY); 
        
        const listener = event => { 
            setPrefersReducedMotion(!event.matches); 
        }; 
        
        mediaQueryList.addListener(listener); return () => { 
            mediaQueryList.removeListener(listener); 
        }; 
    }, []); return prefersReducedMotion; 
} 
```

通过这种方式可以为用户提供组件级别的控件和更多选择。

### 站点级切换控件

CSS 媒体查询 `prefers-reduced-motion` 有一个缺点：只服务于在系统中设置了减少运动的用户。很多用户不了解该设置；一些用户正在使用借来的计算机，无法访问系统级别设置；还有一些用户对多数网站上的动画感到满意，但发现使用大量动画的站点难以忍受。仅为访问某一个网站而调整系统偏好会很烦人。因此应在 Web 应用或网站上为用户提供可选择的控件——例如《[动物之森](https://animalcrossing.nintendo.com/)》网站在页头底下提供了减少运动的切换控件：

> 动物之森：https://animalcrossing.nintendo.com/

这可以通过 JavaScript 实现：

```CSS
@layer motion {
    @media (prefers-reduced-motion: no-preference) {
        body {
            --playState: running;
        }
    }
}

@layer animation {
    @keyframes lights {
        0%,30%,100% {
            opacity: 0;
        }
        40%,90% {
            opacity: 1;
        }
    }

    .lit {
        animation: 2s linear infinite lights var(--playState, paused);

        &.yellow {
            animation-delay: 0.5s;
        }

        &.blue {
            animation-delay: 1s;
        }

        &.red {
            animation-delay: 1.5s;
        }
    }
}
```

```JavaScript
const toggle = document.querySelector("[data-toggle]");
const buttonText = document.querySelector("[data-btn-text]");
const prefersReducedMotion = window.matchMedia("(prefers-reduced-motion: reduce)");
const bodyEle = document.body;

const setReducedMotionStyles = () => {
    buttonText.textContent = ": Off";
    toggle.setAttribute("aria-checked", "false");
    bodyEle.classList.remove("allow-motion");
    bodyEle.style.setProperty("--playState", "paused");
};

const setMotionStyles = () => {
    buttonText.textContent = ": On";
    toggle.setAttribute("aria-checked", "true");
    bodyEle.classList.add("allow-motion");
    bodyEle.style.setProperty("--playState", "running");
};

const getMotionPreference = () => {
    const localStoragePreference = localStorage.getItem("prefersReducedMotion");

    if (localStoragePreference) {
        return localStoragePreference;
    } else {
        return prefersReducedMotion.matches ? "reduce" : "no-preference";
    }
};

const setInitialStyles = () => {
    if (getMotionPreference() == "reduce") {
        setReducedMotionStyles();
    } else {
        setMotionStyles();
    }

    toggle.hidden = false;
};

setInitialStyles();

toggle.addEventListener("click", () => {
    if (getMotionPreference() == "reduce") {
        localStorage.setItem("prefersReducedMotion", "no-preference");
        setMotionStyles();
    } else {
        localStorage.setItem("prefersReducedMotion", "reduce");
        setReducedMotionStyles();
    }
});
```

> Demo 地址：https://codepen.io/airen/full/xxBGpzg

示例中彩灯不断闪烁。初始的动画样式由用户的系统偏好设置（`prefers-reduced-motion`）确定，用户可以通过按钮切换动画的开关——切换时向 `body` 添加 `.allow-motion` 类，并根据所选偏好设置样式。

实现原理是 CSS 自定义属性 `--playState`：用户点击"动画切换"按钮时，`--playState` 在 `paused` 和 `running` 之间切换，用它控制彩灯动画的播放或暂停。首先将播放状态默认设置为暂停：

```CSS
.lit {
    animation: 2s linear infinite lights var(--playState, paused);
}
```

用户未开启减少运动偏好（`no-preference`）时，将播放状态设置为运行：

```CSS
@media (prefers-reduced-motion: no-preference) {
    body {
        --playState: running;
    }
}
```

用户点击切换时，自定义属性在 `body` 上更新。

## 何时减少运动

"何时减少运动"指 Web 开发者在创建动画时何时使用 `prefers-reduced-motion` 媒体查询。原则是：**创建的动画若可能成为前庭障碍触发器，就应在 `prefers-reduced-motion` 媒体特性匹配时禁用该动画或提供变体**。以下是常见的触发场景。

### 缩放和变焦

缩放和变焦是制作流畅 Web 动画的必要特性，但视觉缩放或变焦动画会使用户产生在物理空间中前后移动的幻觉，一些带模糊效果的动画也会产生类似的幻觉。例如鼠标悬浮在视频播放按钮上时海报（缩略图）缓慢缩放的效果。为避免缩略图的缩放动画触发前庭障碍，可以在 `prefers-reduced-motion: reduce` 下禁用缩放效果，改用瞬间动画替代。

再如 3D 缩放加模糊的动画效果，给用户一种物理位置和焦点在改变的感觉。为避免该效果触发前庭障碍，苹果团队的工程师在 `prefers-reduced-motion: reduce` 下将其简化为一个简单的滚动效果，[macOS 网站](https://www.apple.com/macos/sonoma/)多处采用相似方案。将 `prefers-reduced-motion` 的值从 `no-preference` 切换到 `reduce` 时，带 3D 缩放的效果图会变成一张静态图。

### 旋转和旋涡效应

[CodePen](https://codepen.io/collection/npbzOM/) 上有很多使用螺旋或旋转的动画效果，配上色彩或其他图形形状十分炫酷：

> Demo 地址：https://codepen.io/tmrDevelops/full/RWGNrv

但它们对前庭障碍人士极其不友善——可能导致患者失去平衡或垂直方向的方向感；即使没有前庭障碍的用户，看久了也会头晕眼花。

一个更具体的案例：[Viljami Salminen 网站的首页](https://viljamisdesign.com/)使用 Canvas 绘制旋转的视差星场效果，为了不给前庭障碍用户带来不适，该团队使用 `prefers-reduced-motion`——用户开启减少运动偏好后看不到旋转的视差星动效，看到的将是静止的星点。

类似场景在 Web 上很常见，例如圣诞节主题应用中的雪花飘落动画，甚至会添加旋转、漩涡等效果以增强逼真度。创作这类动画时应为前庭障碍用户做考虑。

### 多速度或多方向运动

视差滚动效果容易触发前庭障碍。除此之外，其他多速度或多方向运动的动画也可能触发前庭障碍。以早期 iOS 10 网站为例，该网站以不同速度垂直移动图像为特色；配合 `prefers-reduced-motion` 可以为前庭障碍用户提供极简版本——滚动时没有图片偏移效果，即简化滚动视差，只保留简单的滚动效果。

以上仅是常见情境，用于帮助判断何时运用 `prefers-reduced-motion`。

## 如何创建可访问 Web 动画

考虑 WCAG 设定的标准和动画与运动之间的区别，可以将动画分为三大类型：**不符合 WCAG 标准的动画**、**可以移除的非必要动画**和**可以调整的必要动画**。

### 不符合 WCAG 标准的动画

Web 上很多动画不属于任何类型的运动，无需进行任何调整，因为它们对前庭障碍或减少运动偏好的用户没有触发效应。例如：

- 瞬间出现和消失而无需过渡的对象；
- 过渡颜色或不透明度的元素，最常见的是对象状态变化。

以 Web 上的按钮为例：设计师通常为按钮不同状态提供不同视觉效果，例如悬浮时改变按钮背景颜色。只要悬停效果没有激进的改变，且颜色对比度足够、按钮易读，就可以认为它是安全的，符合 WCAG 标准。

反之，如果按钮的悬浮效果包含激进改变，例如呼吸灯动画——对象的运动看起来在不断地闪烁——该效果不符合 WCAG 标准，会给部分有障碍的人士带来不适。对不符合 WCAG 标准的动画需要做考量和评估，最好为有障碍的人士提供适合的动画效果。

### 可以移除的非必要动画

有些运动对界面来说并不重要——对理解内容或界面状态并非至关重要，且可能使一些人士感到不适或烦恼。比如：

- 占据屏幕三分之一以上或在屏幕上移动的动画对象；
- 具有自动播放或自动更新的元素；
- 视差效果、多方向运动或沿着 `z` 轴移动的元素（如 3D 透视）；
- 具有闪烁或循环动画的内容；
- 具有漩涡、缩放、变焦或模糊效果的元素；
- 动画插图，如变形的 SVG 形状。

这些是用户开启减少运动偏好时可以完全移除的动画——它们不影响内容呈现，移除后可提供更具可访问性和舒适性的体验。

具体处理方式：

- **大位移与复杂动画**：在 [Material 设计系统](https://m2.material.io/design/motion/understanding-motion.html#brand-expression)中有很多占据屏幕三分之一以上或移动对象的动画。针对这类动画可以为开启减少运动的用户提供额外效果，如最小化不必要的移动、用平滑过渡替代瞬间过渡，既传达关键信息又不造成不适。原始版本服务于普通用户，减少版本服务于开启减少运动偏好的用户。

> 原始动画效果和减少运动的动画效果的对比，后者服务于开启了减少运动偏好的用户

- 《[动物之森](https://animalcrossing.nintendo.com/)》首页动画亦如此：默认情况动画占据屏幕三分之一以上、移动对象多且效果复杂炫酷；为减少运动偏好人士提供的版本没有复杂的旋转效果，只有简单的淡入淡出。
- **自动播放与循环元素**：视频、自动播放的轮播图和幻灯片等都可视为可移除的动画。应给予用户绝对的控制权决定何时发生过渡——轮播图更合适的方式不是自动播放，而是把播放权留给用户。
- **简化替代**：为减少运动偏好的用户提供简化版动画，例如用淡入淡出替代水平滑动，不增加额外运动。

> 轮播图效果中，只有用户触发才会滚动；左侧滚动切换是一个平滑的动画效果，右侧是一个淡入淡出的瞬间过渡，后者主要用于开启减少运动的用户。

- **视差与多方向运动**：将视差滚动和涉及缩放、变焦、模糊和漩涡效应的多方向运动用瞬间过渡动画替代。
- **插图动画**：直接为开启减少运动偏好的用户提供静态版本。图像仍然提供上下文，使用户能够理解内容，而无需额外的运动。

### 可以调整的必要动画

有些动画对使用和理解用户界面是必要的（例如加载指示器），直接移除会影响功能。这类动画面临两难：

- 对 Web 应用或网站而言，它向用户传达功能、帮助理解界面；
- 对前庭障碍用户而言，它可能引起不适，甚至触发癫痫发作。

这是最具挑战性的一类：必须在必要的动画和保持可访问体验之间取得微妙平衡。最佳方法是**调整动画使其更为微妙**。例如调整动画的持续时间，使其播放更长、更慢——较慢速度的动画对普通用户是良好体验，对前庭障碍用户也更容易接受，通常不会引起不适或触发疾病。

以 Web 最常见的加载指示器（Loading）动画为例。加载指示器是有必要的：在页面加载、文件上传等场景中，它向用户传达页面是否加载完、文件是否上传完，提供界面活动的反馈；若在界面未更新时停止，用户可能理解成失败或卡住。

与其完全删除动画，不如针对加载指示器做分析，依据 WCAG 对运动的标准找出可能引起问题的方面，例如：

- 动画元素旋转速度是否过快？
- 动画元素是否不断地改变大小？
- 动画元素是否在一个无限循环中运行，直到消失？
- 动画元素是否在不断移动和闪烁？

据此即可找到为减少运动偏好用户提供的另一版本方案：

- 减缓动画元素旋转速度；
- 消除动画元素的缩放效果；
- 将最大持续时间设定为五秒。

调整后的版本只在用户系统级别开启减少运动偏好时呈现，与原始版本形成对比：原始版本服务于普通用户。

对重要且必要的动画都可以按这种方式制作。代价是开发成本上升——开发者除知道如何创建动画外，还需知道什么情况会引起用户不适。但这是值得的：努力不会再伤害到别人。

## 实践要点

综合全文，可提炼出以下核心认知：

- 并非每台可以访问网络的设备都能渲染动画，或平滑地渲染动画。
- 减少运动并不等于没有运动。
- 动画并不等同于运动（Animation ≠ Motion）。
- 并非所有 Web 应用或网站都会使用 `prefers-reduced-motion` 来减少运动，它也可能不足以满足需求。

创建动画时应为更多用户考虑，为 Web 应用或网站提供减少动画的机制。以下通用代码是最低成本的实现：

```CSS
@media (prefers-reduced-motion: reduce), (update: slow) {
    *,
    ::before,
    ::after {
        animation-delay: -1ms !important;
        animation-duration: 1ms !important;
        animation-iteration-count: 1 !important;
        background-attachment: initial !important;
        scroll-behavior: auto !important;
        transition-duration: 1ms !important;
        transition-delay: 1ms !important;
    }
}
```

## 小结

Web 动画可以提高 Web 应用或网站的可用性和参与度，还能丰富页面并吸引用户；同时它也可能给前庭障碍用户带来伤害。这两者并不矛盾——因为 Web 属于用户，而不是开发者。始终调整创建的动画以满足用户的需求。

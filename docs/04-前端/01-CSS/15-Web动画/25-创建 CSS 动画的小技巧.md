# 创建 CSS 动画的小技巧

## 概念说明

Web 动画是提高用户体验(UX)的强大工具,可以利用它来解释复杂的概念,使其更易于理解。CSS 动画(过渡动画和关键帧动画)已成为制作 Web 动画的主流工具之一,现代 CSS 特性几乎提供了创建令人难忘、引人入胜的动画所需的全部工具。精心制作的 CSS 动画可以为 Web 应用或网站注入生机,吸引用户。

要制作出精致、流畅、给人感觉良好的动画,需要掌握一些制作技巧。以下技巧涵盖动画的持续时间、延迟、缓动曲线、硬件加速、`will-change` 的使用边界、动画数量与幅度的克制,以及可访问性处理。

## 核心要点

- **持续时间**:界面动画最佳时间在 `200ms ~ 500ms` 之间;淡入淡出和颜色动画小于 `100ms`;简单效果 `100ms ~ 300ms`;复杂或大规模动画大于 `300ms`;连续过渡总时长 `300ms ~ 800ms`;进入动画比退出动画略长。
- **交错延迟**:链式动画与交错动画依赖 `animation-delay`/`transition-delay`;配合 CSS 自定义属性和 `calc()` 可按元素索引自动计算延迟,实现顺序进场。
- **缓动曲线**:避免依赖内置缓动曲线,优先用 `cubic-bezier()` 或 `linear()` 定制;入场用 `ease-out`,退场用 `ease-in`;多个属性过渡可为每个属性指定不同缓动。
- **硬件加速**:只有 `transform` 和 `opacity` 等少数属性能利用 GPU 加速;避免动画化触发重排的盒模型属性;硬件加速与否最终由浏览器决定。
- **will-change**:不是万能药,过度使用反而损害性能;应在动画或过渡之前使用,且只在动画不流畅或闪烁时作为最后手段。
- **少即是多**:动画元素数量和变化幅度都应克制;低调的动画比过于张扬更好。
- **可访问性**:使用 `prefers-reduced-motion` 媒体查询尊重用户减少运动的偏好;减少运动不等于没有动画。

## 使用适合的持续时间

花了很大精力创造的动画,创作者可能会很满足地欣赏它,但用户并不像创作者一样着迷,也没有足够的耐心来欣赏——用户来这里是完成任务的,比如购物、查看信息等,不愿意花更多时间等待,即使动画很炫酷。

**核心原则:尽量使过渡效果尽可能快,而不至于太短,以至于用户可能错过。任何一个不良动画的绝对致命点之一,就是它的持续时间太长。**

许多研究发现,用户界面上的动画最佳时间在 `200ms ~ 500ms` 之间。[Material Design](https://material.io/design/motion/speed.html#duration) 在这方面做过大量研究和实践,建议在移动设备上动画持续时间限制在 `200ms ~ 300ms` 之间为佳;平板电脑的持续时间应比移动设备长 `30%` 左右,大约在 `400ms ~ 450ms` 之间。

这些数据是经验法则,适用于 Web 上大多数动画及其应用情境:

- 对于淡入淡出和颜色动画,使用几乎瞬时的持续时间(小于 `100ms`)
- 对于简单效果和相对较小的动画,使用较短的持续时间,大约在 `100ms ~ 300ms`。还可用于用户发起的需要反馈的操作,例如触摸、点击和滑动等
- 对于更复杂的效果和较大规模的动画(如页面过渡或屏幕内外的对象移动),使用较长的持续时间(大于 `300ms`)
- 保留慢动画(大于 `500ms`)用于大幅移动和影响氛围的背景元素

对于简单的反馈动画,比如显示复选框或切换开关,总持续时间应大致为 `100ms`。这个持续时间对用户来说感觉是立即的,创建了物理操纵对象的错觉。`100ms` 位于可察觉运动的较低端,几乎像是从一个位置瞬间跳到另一个位置,但足以使反馈引人注目。

动画涉及屏幕发生较大变化时,过渡就越显眼。切换按钮动画与模态框弹出动画有很大区别。不要让大的变化发生得太快:模态框移入视图,`200ms ~ 300ms` 的持续时间可能是合适的。元素移动的距离越远,保证平稳且不刺眼就越重要(特别是对运动敏感的人,比如癫痫障碍的用户)。

动画效果不是单一过渡而是连续过渡时,可以在单一过渡动画的持续时间上增加一倍。大多数单一过渡的动画持续时间在 `150ms ~ 400ms` 之间效果最佳,因此连续过渡动画总持续时间应在 `300ms ~ 800ms` 之间,甚至可以再加一点时间——不希望两个独立的动画匆匆忙忙地结束,这会让用户感到突兀。一个元素移出、然后另一个元素移入的效果就是连续过渡。

对象出现或进入屏幕的动画通常需要比对象消失或退出屏幕的动画略长的持续时间。例如弹出窗口可能需要 `300ms` 来出现,但只需要 `200ms` 或 `250ms` 来消失。

这些经验法则可能并不适用于所有动画。一个可复用的调试方法是:

> 给动画加速,即设置较短的动画持续时间,直到感觉动画太快,然后再稍微减缓一点(加长动画持续时间)

这是一个不断重复的过程——精致的、使用户感到舒适的动画,本来就是不断调试、修复、完善的结果。此外,动画的感觉可能并不总是与它实际持续时间一致:以很慢的缓入开始的动画可能看起来没有立即开始;带有较长持续时间的动画在技术上可能看起来已经完成。

> 感知就是现实,所以变化的感觉比在代码中技术上持续时间更重要!

## 使用交错的延迟

Web 上有很多使用 CSS 制作的链式动画或交错动画,主要表现:

- 一个元素上应用了多个动画
- 多个元素上应用了相同的动画
- 多个元素上分别应用了不同的动画

链式动画的最大特征之一是同一元素上应用了多个不同的动画,例如给元素创建一个用于旋转的动画、一个用于调整大小的动画、一个用于调整不透明度的动画;或者在同一页面的不同元素上应用不同动画,这些动画的播放有一定的时序(先后顺序)。

交错动画的最大特征是在多个元素上应用同一种类型的动画,每个元素的动画开始播放时有一定的先后顺序。

构建这两种动画时,不要低估动画的延迟时间(`animation-delay` 或 `transition-delay`)可能产生的效果。没有延迟和有延迟的动画效果不同:前者在放大的过程中同时在旋转,后者先放大、再旋转。

链式动画相对复杂,可能需要大量微调来同步所有运动的属性,但它提供了对每个动画属性的时间(持续时间、延迟时间)、缓动函数、播放状态的精细控制,能用更少的 CSS 代码创造更复杂的动画。开发链式动画时不要遗忘动画编排:把情境中所有动画想象成一台舞台剧,所有动作(动画)和演员(元素)都由时间轴统一安排。

链式动画还会应用到 CSS 多动画的概念。注意:同一个元素应用多个不同动画时,动画可能作用于同一属性(例如在不同的 `@keyframes` 中作用于 `transform`)。单个 CSS 变换有一个固定原则——先位移、再旋转、然后缩放;需要的变换计算不是这个顺序时,可以使用动画合成来规避麻烦(详见《多个 CSS 动画与动画合成:创造更复杂的动画效果》)。

**交错动画示例**

在铃铛示例的基础上,点击正在运动的小铃铛后,通知信息以动画形式从屏幕右侧飞入:

```CSS
@keyframes slideIn {
    from {
        translate: calc(100% + 1rem);
        opacity: 0;
    }
    
    to {
        translate: 0;
        opacity: 1;
    }
}
  
@keyframes slideOut {
    from {
        translate: 0;
        opacity: 1;
    }
    to {
        translate: calc(100% + 1rem);
        opacity: 0;
    }
}
  
.notification__item {
    animation: slideOut .3s ease-out 0s both;
    
    .play & {
        animation: slideIn 0.3s ease-in 0s both;
    }
}
```

此时通知信息列表的进场和退场都是同时完成的,效果并不理想。给每个列表项添加不同的延迟时间,使每次进入和退出都有先后顺序,效果会好很多:

```CSS
.notification__item {
    --delay-ratio: 0.2s;
    /* 这个延迟将在隐藏元素时生效 */
    --delay: calc(var(--delay-ratio) * (var(--items) - var(--index)));
    animation: slideOut .3s ease-out var(--delay) both;
    
    .play & {
      
        --delay: calc((var(--index) - 1) * var(--delay-ratio));
        animation: slideIn 0.3s ease-in var(--delay) both;
    }
}
```

> Demo 地址：https://codepen.io/airen/full/QWoNGmR

上面示例使用了 CSS 自定义属性:设置一个与元素索引相等的自定义属性,用 `calc()` 计算动画延迟时间,使元素按顺序进行动画。自定义属性以联样式的方式设置在 HTML 元素上,可与动态内容配合工作:

```HTML
<div class="notifications" style="--items: 5;">
    <div class="notification__item notification--success" style="--index: 1;"></div>
    <div class="notification__item notification--info" style="--index: 2;"></div>
    <div class="notification__item notification--warning" style="--index: 3;"></div>
    <div class="notification__item notification--danger" style="--index: 4;"></div>
    <div class="notification__item notification--done" style="--index: 5;"></div>
</div>
```

这种技巧还经常与 [Splitting.js 库](https://splitting.js.org/)配合使用来制作文本跳动的动画效果。Splitting.js 会把文本字符串按字母分组,并为每个字母分配相同的自定义属性,以及用于总项数的另一个自定义属性。

> Demo 地址：https://codepen.io/BlogFire/full/mdpvmVy （更多关于 Splitting.js 制作的作品可以[点击这里获取](https://codepen.io/collection/XpROaV/)）

请注意适度为佳:这类动画很容易过度使用,特别是在有许多元素做动画时。应用得当,交错的延迟可以帮助提升 Web 动画的效果。

## 加速和减速

速度和时间对动画的重要性,与迪士尼动画核心原则中的"挤压和拉伸"(Squash and Stretch)高度契合。该原则灌输"感知"的概念:通过挤压或拉伸运动中的元素,给它们一种更快(或更慢)速度的错觉,为页面带来真正的流动感。

在现实世界中,几乎不会看到任何类型的运动立即跳到最大速度或瞬间完全停止,Web 中的动画亦是如此。当动画看起来有些不对劲时,很可能是因为它要么以不自然的突然性开始,要么以不自然的突然性结束。避免这种运动曲线,Web 上的动画就会看起来更"真实"和直观。

任何运动都与距离、时间和速度紧密相关。同一段距离、同样的运动时间,速度不同,最终呈现的运动效果也不同。CSS 动画同样遵循这一自然现象。例如元素从容器最左侧(`0` 位置)移动到容器最右侧(`100%`):

```CSS
@keyframes move {
    to {
        translate: calc(80vw - 1.25rem);
    }
}
```

所用时间(动画持续时间)也一样,总共用时 `3s`:

```CSS
.element {
    animation-duration: 3s;
}
```

但元素在运动过程中速度不一样,最终呈现的动画效果差异很大。

### CSS 内置缓动曲线

CSS 动画通常用缓动曲线描述动画的运动曲线(即速度)。CSS 内置了一些可用的缓动曲线:`linear`(线性,恒速)、`ease`(默认缓动函数)、`ease-in`(渐进,加速)、`ease-out`(渐出,减速)、`ease-in-out`(渐进渐出,先加速再减速)、`cubic-bezier()`(三次贝塞尔曲线)和 `steps()`(步进缓动)。

将内置缓动曲线应用于同一个动画,即使距离和时间相同,最终呈现的动画效果也有显著差异:

```
.element {
    animation-timing-function: var(--animfc, linear);
}
```

> Demo 地址：https://codepen.io/airen/full/BabKmma

使用 CSS 定制缓动曲线是另一种动画技术,它允许控制动画或过渡过程中事物减速或加速的速率。内置缓动曲线虽然方便,但也非常普通,许多工具或动画库构建的动画也容易陷入同样的同质化。希望创作出更好的动画效果,应尽可能避免使用内置缓动曲线,而创建定制的缓动曲线:可以有速度变化,比如更快开始或结束的动画,甚至可以超越目标然后弹回。

即使是轻微的,也建议在使用 `cubic-bezier()` 函数时,在动画的缓动曲线中添加一点点的缓动——这种微小但可察觉的加速和(或)减速,可能是动画给人感觉平滑与稍显不足的关键之处。

### 定制缓动曲线示例

四个正方形围绕自身中心点旋转一圈 `1turn`(即 `360deg`),分别应用不同的三次贝塞尔曲线:

```HTML
<div class="element" style="--easing: cubic-bezier(.9,.03,.69,.22);">A</div>
<div class="element" style="--easing: cubic-bezier(.17,.84,.44,1);">B</div>
<div class="element" style="--easing: cubic-bezier(.62,.16,.13,1.01);">C</div>
<div class="element" style="--easing: cubic-bezier(.5,-0.53,.14,1.23);">D</div>
```

```CSS
@keyframes rotate {
    50%, 100% {
        rotate: 1turn;
    }
}

.element {
    animation: rotate 2s var(--easing, ease) infinite;
}
```

> Demo 地址：https://codepen.io/airen/full/KKEzyLq

示例中 `A` 和 `D` 的旋转动效开始或结束得较突然,而 `C` 的旋转效果好得多,它的自定义曲线在更优雅的运动中缓入缓出,实现了加速和减速;`D` 的运动曲线加入了类似弹簧的曲线,整个旋转效果带有一定惯性。

这个示例再次说明:"即使动画的持续时间相同、运动距离相同,不同的缓动曲线也能真正改变动画的感觉"。想发挥动画的最大潜力,应超越最常见的内置缓动曲线。以下是一份可直接复用的缓动曲线变量库:

```CSS

    /* Default Easing Function */
    --linear: cubic-bezier(0, 0, 1, 1);
    --ease: cubic-bezier(0.25, 0.1, 0.25, 1);
    --ease-in: cubic-bezier(0.42, 0, 1, 1);
    --ease-out: cubic-bezier(0, 0, 0.58, 1);
    --ease-in-out: cubic-bezier(0.42, 0, 0.58, 1);
    
    /* Sine Easing Function */
    --sine-in: cubic-bezier(0.47, 0, 0.745, 0.715);
    --sine-out: cubic-bezier(0.39, 0.575, 0.565, 1);
    --sine-in-out: cubic-bezier(0.445, 0.05, 0.55, 0.95);
    --ease-in-sine: cubic-bezier(0.12, 0, 0.39, 0);
    --ease-out-sine: cubic-bezier(0.61, 1, 0.88, 1);
    --ease-in-out-sine: cubic-bezier(0.37, 0, 0.63, 1);
    --ease-out-in-sine: cubic-bezier(0.05, 0.445, 0.95, 0.55);
    
    /* Circular Easing Function */
    --circ-in: cubic-bezier(0.6, 0.04, 0.98, 0.335);
    --circ-out: cubic-bezier(0.075, 0.82, 0.165, 1);
    --circ-in-out: cubic-bezier(0.785, 0.135, 0.15, 0.86);
```

### 突然开始与瞬间停止的适用边界

虽然 `cubic-bezier()` 或 `linear()` 定义的缓动曲线能使动画更接近自然物体的运动规律(不是立即加速或立即减速),但并不意味着突然开始和瞬间停止一无是处。建议是少用或尽可能避免,但在某些情境中可以使用:例如用户看不到的情境,最常见的如淡入动画——效果突然开始可能没有太大问题,因为动画的开始在第一眼可能不可感知;反之亦然,元素淡出到 `opacity: 0` 时,动画瞬间结束也不太重要,因为最后它不可见。

### 为不同属性设置不同缓动

动画的缓动曲线和时间(持续时间和延迟时间)类似:同一元素应用多个动画,或同时对多个属性做过渡时,应考虑应用不同的缓动曲线。例如通过 `scale` 缩放元素的同时使用 `opacity` 改变透明度,可以对两个属性应用相同的缓动曲线:

```CSS
.element {
    transition: all cubic-bezier(0.5, 0, 0.5, 1) 0.5s;
}

@keyframes animn {
    from {
        opacity: 0;
        scale:0;
    }
}

.element {
    animation: animn 0.5s cubic-bezier(0.5, 0, 0.5, 1) forwards;
}
```

取决于实际情况,这样应用缓动曲线,动画效果可能还不错。但某些情况下,相同的缓动曲线并不适用于每个过渡属性——适用于 `scale` 的缓动曲线可能不太适用于 `opacity`。此时为每个过渡属性设置独特的缓动曲线更妥当。CSS 的过渡动画(`transition`)和关键帧动画(`animation`)都接受以逗号分隔(`,`)的多个值,可通过拆分 `@keyframes` 或指定多个过渡属性,为每个属性指定不同的缓动曲线:

```CSS
.element {
    transition: opacity linear 0.5s, scale cubic-bezier(0.5, 0, 0.5, 1) 0.5s;
}

@keyframes scale {
    from {
        scale:0;
    }
}

@keyframes fadeIn {
    from {
        opacity: 0;
    }
}

.element {
    animation: scale 0.5s cubic-bezier(0.5, 0, 0.5, 1) forwards, fadeIn 0.5s linear forwards;
}
```

哪种更好?这完全取决于要实现的效果。这种情况不常发生,但发生时这个技巧非常方便且容易被忽视。还可以改变每个属性的持续时间,但要小心:应用不好会使动画效果变得不协调。针对该情境,建议使用动画编排或借助浏览器开发者工具的"动画"调试面板进行微调。

### 入场与退场的缓动选择

CSS 中使用 `cubic-bezier()` 和 `linear()` 函数可以获得各种缓动曲线,这些曲线通常分为三种类型:**开始慢**(如 `ease-in`)、**结束慢**(如 `ease-out`)和**开始与结束慢,中间快**(如 `ease-in-out`)。

通常情况下,元素入场(入场动画)使用结束慢(`ease-out`),离场(退场动画)使用开始慢(`ease-in`)。以轮播图或模态框的进入和退出为例,这些效果实际上都包含两个过渡:新元素入场,旧元素离场。新元素入场应该逐渐停止,需要一个 `ease-out`(例如模态框从屏幕外飞入屏幕中);旧元素离场则相反,应该开始缓慢,需要一个 `ease-in`(例如模态框关闭时从屏幕中向屏幕外飞出)。两者结合会创造出无缝衔接的动画效果。

速度和时间对动画至关重要,值得深入研究的相关主题包括:

- CSS 缓动函数基础:为 Web 动画注入灵魂
- 使用 cubic-bezier() 函数创建高级动画
- 使用 steps() 函数创建分段动画
- 使用 linear() 函数创建令人惊叹的动画曲线
- 深入了解 CSS 动画的持续时间和延迟时间

## 依赖硬件加速

并非所有 CSS 属性在所有设备和浏览器上都能平滑地进行动画或过渡。动画能否带来好的体验,取决于其是否流畅。Web 开发者和动画师在创作动画时都以 `60fps` 为目标,通常通过硬件加速实现最流畅、最高帧率的效果。

CSS 只有少数几个属性能够利用设备的硬件加速:浏览器可能借助设备的图形处理单元(GPU)加速渲染,使渲染速度显著提高,但仅在某些条件下才能实现。CSS 中总是可以进行硬件加速的属性是 `transform`(包括所有形式的平移、缩放和旋转,以及它们的 3D 对应项)和 `opacity`。有时某些 SVG 属性、`filter`(取决于浏览器和滤镜类型)以及 `canvas`、WebGL 等非 CSS 的东西,也可以利用硬件加速(详见《制作流畅动画的技巧与实践》)。

简而言之,`transform` 比想象的更强大:除移动、旋转和缩放元素之外,它还可以改变元素的大小和形状等;最重要的是,应用 `transform` 不影响布局,最小化重新计算的次数,保持浏览器平稳运行。通过 `transform` 和 `opacity` 组合,可以实现 Web 上许多常见的动画和过渡效果。

制作动画时,无论如何都要避免直接更改元素的大小或位置。直接更改可能影响布局的属性,例如 `height`、`width`、`border`、`margin`、`padding`、`top`、`right`、`bottom`、`left` 及对应的逻辑属性,会因为执行这些更改所需的计算而明显减慢页面速度——这些属性触发重排,重排本身就是昂贵的计算,放到动画中每秒不断重复,代价更高。

如果确实需要对这些属性做动画,请务必在所有可能的设备和浏览器上测试。Safari 默认情况下处理动画的性能表现较差,特别是在 iOS 上;Firefox 紧随其后。只在高性能设备上测试可能意识不到这些问题——世界上还有很多人使用低端 Android 设备,不要忽略对这些设备的测试。

同时,硬件加速并不是制作流畅动画的万能钥匙:某些东西可以进行硬件加速,并不意味着它真会被硬件加速,最终的决定权在浏览器手中。浏览器放弃硬件加速的潜在原因是:GPU 更快,但也消耗更多能量;设备电量不足或处于省电模式时,浏览器可能选择电池而不是图形性能。

**示例:呼吸灯动画的两种实现**

```CSS

        0% {
            box-shadow: 0 0 0 0 rgb(136 80 211 / 1);

        100% {
            box-shadow: 0 0 0 10px rgb(136 80 211 / 0);
        }
    }
    
    .ping {
        animation: ping 1s cubic-bezier(0, 0, 0.2, 1) infinite;
    }
}
```

## 慎用 will-change

很多 Web 开发者认为 `will-change` 可以让动画变得流畅。然而,`will-change` 并不是万能药:过度使用反而会损害页面性能。对 `will-change` 不了解时请慎用它,尤其是在动画创作中。浏览器对每个应用 `will-change` 的元素会创建一个新层(有点像一个新的 `z-index` 级别),使合成变得更加复杂;谨慎使用时这种交互是值得的,使用不当则会为浏览器带来更多工作(计算量更大)。

使用 `will-change` 时,不要在动画或过渡的地方使用,而应在动画或过渡之前使用。`will-change` 应该告诉浏览器即将发生的变化,以便浏览器为其做好准备——浏览器无法为当前正在发生或已经发生的变化做准备。

反例——直接在动画发生的地方添加:

```CSS
.element:hover {
    will-change: color;
    color: red;
}
```

这样做弊大于利。`will-change` 是将来时态,应在元素的初始状态添加(此时尚未发生任何变化):

```CSS
.element {
    will-change: color;
    transition: color 300ms ease-in-out;
}

.element:hover {
    color: red;
}
```

或者将 `will-change` 放在 `.element` 的父元素上:

```CSS
.parent-element:hover {
    will-change: opacity;
}

.element:hover {
    transition: opacity .25s ease-in-out;
}
```

这样可以让浏览器提前知道要优化这个变化。**只有在动画不流畅或闪烁时,才应将其视为最后的手段。**

以下情境中应避免使用 `will-change`:

- **在动画或过渡期间**:不要在元素正在进行动画或过渡时应用。只有在变化即将发生或可能在不久的将来发生时使用,以便浏览器有足够的时间优化其渲染;变化已经发生时使用可能对浏览器造成压力并影响性能。
- **变化不可预测**:元素的变化经常或意外发生时,`will-change` 可能不值得,会导致不必要的性能开销。
- **小元素**:优化小元素的渲染收益微乎其微,`will-change` 可能适得其反。
- **不可动画的属性**:应用于 `font-family` 或 `display` 等不可动画属性时,可能对性能没有影响,甚至产生负面影响。
- **滥用**:在页面多个元素上应用 `will-change` 可能损害性能,导致浏览器占用机器资源、减慢页面加载。只在可能很快发生变化并从优化中受益的元素上使用。

最理想的情况是:**当与不影响布局的属性一起使用时,这可以让浏览器完全将计算卸载到 GPU 上,以获得最高的帧率和最顺畅的性能**。但仍需强调:**`will-change` 旨在作为最后的手段使用,以尝试解决现有的性能问题,不应该用于预测性能问题**。`will-change` 更详细的介绍参阅《制作流畅动画的技巧与实践》。

## 少即是多

"少即是多"是一个设计指导原则,但在不同上下文和设计场景中可能被解读为相互矛盾的指导方针:

- **简单与表达力的平衡**:"少即是多"强调简单、精炼的设计,但某些情况下需要通过更复杂的元素或动画传达特定的信息或情感,简化设计可能牺牲表达力
- **用户期望的可预测性**:简单的设计通常更易于理解和操作,但创新性应用中用户可能期望更复杂、令人惊喜的交互和动画,此时"少即是多"可能与创新性相矛盾
- **适应不同的品牌风格**:一些品牌注重极简主义,另一些更喜欢丰富多彩的设计,"少即是多"对品牌来说并不总是适用
- **上下文和目标受众**:该原则可能在特定上下文和目标受众中更有效,其他情境下可能需要更复杂和独特的设计

实际应用中需要灵活运用,权衡简洁性与复杂性。某些情况下,少量的复杂元素可能更有利于传达设计意图。

**示例:按钮悬浮缩放**

在动画制作中,"少即是多"强调在动画效果中保持简洁和精炼,确保用户体验的清晰度和可理解性。考虑一个简单的按钮,悬停时应用缩放效果:

```CSS
.button {
    transition: scale 0.3s ease;
    
    &:hover {
        scale: 1.1;
    }
}
```

`transition` 属性定义了 `scale` 属性的过渡变化在 `0.3s` 内以 `ease` 缓动曲线进行;鼠标悬浮时按钮放大到 `1.1` 倍,创造一个简单而明显的悬浮动效。该案例中"少即是多"体现在:

- 单一属性变化:只改变按钮的 `scale` 属性,不涉及其他属性,使悬浮效果更集中明确
- 简单而明显的变化:缩放是直观的变化,不需要用户花费过多认知资源就能理解
- 短暂而流畅的过渡:过渡时间 `0.3s` 足够产生效果又不至于太长,有助于保持用户的关注

通过精心选择动画属性和过渡效果,按钮的悬浮效果既引人注目又不分散用户注意力。

不过,很多开发者容易认为页面上的每一件事都应该动画化,认为只有这样做页面才显得炫酷。事实上,使用动画时,低调(精简或精致)通常比过于张扬更好:元素在动画过程中变化越大、页面中动画化的对象越多,动画带来的风险也越大。除非是开发个人网站、只想要点创意,否则过多的动画总是弊大于利。

"少即是多"中的"多"有两层意思:一层是字面上的数量过多——页面上同时有多个动画元素,或同一元素上同时有多个动画;另一层是大或"夸张"。应对方式:

- 制作淡入动画时,通常将 `opacity` 从 `0` 过渡到 `1`(反之亦然),可以尝试缩小范围,例如从 `.4` 过渡到 `1`
- 将元素缩放到全尺寸时,通常将 `scale` 从 `0` 过渡到 `1`,可以尝试略微减小,例如从 `.5` 到 `1`,避免元素小到看不到
- 给元素添加滑动效果时,元素移动的范围大约在 `5px ~ 40px` 之间较为合适;更小则可能太微妙甚至察觉不到,更大则可能变得笨拙

以下示例同时对元素的 `opacity`、`translate` 和 `scale` 做动画:

```CSS
@layer animation {
    @keyframes fadeIn-a {
        0%,
        10% {
            opacity: 0;
            translate: 0 8rem;
            scale: 0;
        }
        30%,
        100% {
            opacity: 1;
            translate: 0 0;
            scale: 1;
        }
    }

    @keyframes fadeIn-b {
        0%,
        14% {
            opacity: 0;
            translate: 0 1rem;
            scale: 0.95;
        }
        15% {
            opacity: 0.25;
        }
        30%,
        100% {
            opacity: 1;
            translate: 0 0;
            scale: 1;
        }
    }

    .element--a {
        animation: fadeIn-a 3s ease-out infinite;
    }

    .element--b {
        animation: fadeIn-b 3s cubic-bezier(0.14, 0.18, 0.16, 1.02) infinite;
    }

```

相比之下,`A` 的动画幅度比 `B` 大得多;`B` 元素的 `opacity`、`translate` 和 `scale` 在动画化时减弱了一些,并加快了一些。至于哪个效果更好,关键在于找到动画刚好能够产生效果的那个点。

总体而言,"少即是多"是在 Web 动画制作中取得平衡的方法:提供简洁、直观的用户体验,同时保持页面性能。过于简化或过度复杂的动画都可能带来问题,关键在于在具体情境中灵活应用。

## 构建包容性和可访问性的 CSS 动画

Web 最大的特色之一是包容性,所有人都平等享受 Web 带来的一切,动画亦如此。动画应用得当时,能吸引用户注意力、帮助用户理解界面的工作方式;但添加动画也需谨慎——一些患有前庭障碍的用户很容易因动画感到不适,最糟糕的情况下动画还可能引发晕动症、恶心等。

引起不适的程度和触发原因因人而异。因此应提供更具包容性和可访问性的动画,尊重用户的偏好——构建的动画应满足用户减少运动的偏好。

在 CSS 中,使用媒体查询 `prefers-reduced-motion` 可以很容易做到这一点:

```CSS
@media (prefers-reduced-motion: reduce) {
    *,
    ::before,
    ::after {
        animation-delay: -1ms !important;
        animation-duration: 1ms !important;
        animation-iteration-count: 1 !important;
        background-attachment: initial !important;
        scroll-behavior: auto !important;
        transition-duration: 0s !important;
        transition-delay: 0s !important;
    }
 }
```

**减少运动并不意味着没有运动,甚至根本没有动画**。一种常用技术是:在检测到减少运动偏好时,更改关键帧动画:

```CSS
@keyframes slideIn {
    from {
        opacity: 0;
        translate: 0 2rem;
    }
}

@keyframes slideInReduced {
    from {
        opacity: 0;
    }
}

.animated-thing {
    animation-name: slideIn;
}

@media (prefers-reduced-motion) {
    .animated-thing {
        animation-name: slideInReduced;
    }
}
```

此外,有些情况下保留动作可能更好。例如后台加载内容时显示的进度条,或音频、视频文件上显示的播放指示器,是 UI 中的关键信息。与其完全消除该指示器,不如考虑使运动变得微妙而不引人注目;或者允许用户隐藏运动;或者以不同方式表示信息(例如使用数字百分比计数器而不是动画条)。

至少,用户应该能够暂停所有连续的动画,包括视频和 GIF。理想情况下,应根据用户的设备偏好来预测需求,而不是迫使用户处理其已表示宁愿不看到的东西。更深入的探讨可阅读《提升可访问性动画的关键技巧》。

## 小结

Web 动画能使界面栩栩如生,让用户感到愉悦。由于 CSS 发展迅速,实现 Web 动画并控制它们的感觉比以往任何时候都更加容易。制作动画时,以下关键技巧和注意事项有助于创造出吸引人、流畅且有意义的动画:

- **选择合适的动画类型**:不同场景和目的需要不同类型的动画。考虑使用过渡、关键帧动画、滚动故事(scrollytelling)等技术,以匹配设计和用户体验目标。
- **关注细节**:注意动画中的细节,有助于创造更真实、自然的体验。细节是体验的"黄金线",可以增加真实感并提高用户的参与度。
- **选择适当的缓动函数**:缓动函数影响动画的速度变化。使用合适的缓动函数可以使动画更加自然,例如使用 `ease-in-out` 来模拟物体的加速和减速。
- **利用硬件加速**:某些 CSS 属性可以利用硬件加速,提高动画的流畅性,常见的是 `transform` 和 `opacity`。避免直接改变可能影响布局的属性。
- **遵循"少即是多"原则**:不要过度使用动画。适度的动画能够增强用户体验,过多的动画可能让界面显得杂乱,产生负面效果。
- **考虑可访问性**:确保动画对所有用户都可访问。使用 `prefers-reduced-motion` 媒体查询检测用户是否希望减少动画,提供更舒适的体验。
- **制定动画指南**:在大型项目中建立动画指南和设计系统,包含动画的目的、类型、时长、缓动函数等信息,确保团队在使用动画时保持一致性。
- **考虑可持续性**:动画应该是可持续的,不应在短时间内引起视觉疲劳。确保动画的频率和强度可接受,避免不必要的刺激。

制作动画需要综合考虑设计目标、用户体验和性能。通过选择合适的技术并注意细节,可以创建出引人入胜的动画效果,提升用户与界面的互动体验。

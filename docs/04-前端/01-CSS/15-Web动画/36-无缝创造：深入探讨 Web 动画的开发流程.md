# 无缝创造：深入探讨 Web 动画的开发流程

## 概念说明

在当今数字时代,Web 设计不再仅仅是静态图形和文本的展示,而是通过生动的 Web 动画增添活力和交互性。Web 动画作为现代 Web 设计的核心元素之一,为设计师和开发者提供了丰富的创作空间。

创作 Web 动画需要掌握的知识包括:动画的基础理论、设计原则、动画作用、动画开发技术和技巧等。掌握这些内容后,即可独立创作符合需求的 Web 动画。但创作复杂的、炫酷的动画很费时间和精力,无论是设计师还是开发者,都期望有更快速、更高效的方式创作出质量更高的 Web 动画。这正是了解 Web 动画工作流程、理解设计师与开发者如何协同工作的意义所在。

## 核心要点

- Web 动画开发的主要痛点:团队协作、性能问题、兼容性困扰、调试困难、复杂性和维护、学习曲线。
- 传统动画开发模式:设计师设计动画 → 导出视频/GIF 演示文件并提供参数 → 开发者用代码还原。沟通成本高、还原效果有偏差。
- 当前主流开发模式:动画由工具或软件(如 AE + Lottie/PAG)创建并直接导出描述动画的数据文件,开发者用播放器库(如 Lottie-web)渲染,业务逻辑通过 JavaScript 插入。
- Lottie-web 的使用前提:获取 Lottie-web 库、获取描述动画的 JSON 文件(AE 导出或第三方平台获取)、调用 `loadAnimation()` 渲染。
- `loadAnimation()` 的关键参数:`container`(渲染容器)、`path`/`animationData`(JSON 数据)、`renderer`(渲染格式 svg/canvas/html)、`loop`(循环播放)、`autoplay`(自动播放)。

## Web 动画开发的痛点

Web 动画开发中存在一些普遍挑战,它们有时令人头痛,但也是创造精彩作品的灵感来源:

- **团队协作**:与设计师和其他开发者协同工作时,设计师的创意和开发的可行性之间可能存在差距,需要更多沟通和协调,以确保最终呈现的动画符合所有人的期望。
- **性能问题**:动画在开发环境中运行流畅,放到真实浏览器中却可能变得缓慢,即使在高性能设备上也可能发生。大量元素和复杂的动画轨迹可能成为性能的绊脚石,解决它需要对代码调优和性能测试。
- **兼容性困扰**:动画在一个浏览器中运行完美,在另一个浏览器中却可能一团糟。不同浏览器对 CSS、JavaScript 和 SVG 的支持程度不同,需要额外的时间解决和测试,确保用户在各种浏览器中都能正常欣赏动画。
- **调试困难**:动画突然停滞或不按预期运行时,调试 Web 动画相对复杂,需要深入了解代码并使用浏览器开发者工具。定位问题和使用调试工具是一个逐渐培养的技能。
- **复杂性和维护**:复杂动画几个月后可能变得难以管理,在保持代码整洁的同时添加新功能具有挑战性。
- **学习曲线**:从基本的 CSS 动画到复杂的 JavaScript 库,学习路径颇具挑战性;理解关键概念、熟悉工具和语法都需要时间和耐心,但也是一个充满乐趣和成就感的过程。

这些痛点并非无法克服。每一位经验丰富的开发者都曾经历过新手阶段,通过不断的实践和学习逐渐掌握这门艺术。每一个挑战都是一次成长的机会。

## Web 动画开发流程的演进

创作 Web 动画可能使用以下技术之一:

- 使用 CSS 创建过渡或关键帧动画
- 使用 WAAPI 创建动画
- 使用 SVG 和 SMIL 创建动画
- 基于 JavaScript 动画库创建动画
- CSS、SVG 和 JavaScript 结合创建动画

无论使用哪种技术,都有一个具体的开发流程。目前的开发流程主要有两种:传统动画开发模式和当下流行的动画开发模式。

### 传统动画开发模式

对于大多数 Web 开发者或团队而言,传统 Web 动画开发模式与平常的 Web 开发模式非常相似,主要有三个步骤:

- 首先由 Web 设计师设计出 Web 动画
- 然后设计师将设计好的 Web 动画转换成视频或 GIF 等格式的演示文件提供给 Web 开发者;出色的设计师还会将动画相关的参数一并提供
- 最后,Web 开发者根据设计师提供的演示文件和相关参数,使用代码还原设计师所创作的动画,并最终呈现给用户

这是一个痛苦的过程:增加了设计师和开发者的沟通成本,也增加了设计师的工作量。此外还有动画效果之间的差异——即使开发者用尽各种方式最终还原出来的动画效果,总会令设计师略感失望;设计师认为自己的创意没有达到预期还原,开发者则认为这已然是最好的效果。

正因如此,设计师和开发者都希望 Web 动画的开发模式有所改变:动画效果能不能更丝滑、效果还原能不能更接近、能不能有创意和创新、能不能创作更复杂的交互动效。

### 当前动画开发模式

Web 动画的开发模式已发生很大改变:专业的人做更专业的事——设计师专注设计,开发人员专注业务开发。Web 动画的创建由工具或软件实现,然后使用 JavaScript 脚本将业务插入到转化后的 Web 动画中。

这是时下 Web 动画的主流开发模式。例如国外的 [Lottie](https://lottiefiles.com/) 和国内的 [PAG](https://pag.art/) 创建 Web 动画都使用了类似的开发流程:

> Lottie: https://lottiefiles.com/

> PAG: https://pag.art/

经常创作 SVG 动画的场景,还可以直接使用 [SVGator](https://www.svgator.com/):

> SVGator：https://www.svgator.com/

## 使用 Lottie-web 创建动画

> Lottie-web：https://lottiefiles.com/web-player

创建 Web 动画可以考虑 Lottie 的 [Lottie-web](https://lottiefiles.com/web-player),它可以快速、精确地实现设计师设计的 Web 动画效果。使用 Lottie-web 需要具备几个前提条件:

- 获取 Lottie-web 库
- AE 导出的 JSON 文件(或其他平台获取的描述动画的 JSON 文件)
- 使用 Lottie-web 渲染 AE 导出的 JSON 数据,让动效在 Web 上渲染

### 获取 Lottie-web 库

获取 Lottie-web 最简单的方式是从 [CDN](https://cdnjs.com/libraries/lottie-web) 获取:

```HTML
<script src="https://cdnjs.cloudflare.com/ajax/libs/lottie-web/5.12.2/lottie.min.js" integrity="sha512-jEnuDt6jfecCjthQAJ+ed0MTVA++5ZKmlUcmDGBv2vUI/REn6FuIdixLNnQT+vKusE2hhTk2is3cFvv5wA+Sgg==" crossorigin="anonymous" referrerpolicy="no-referrer"></script>
```

除引入静态 CDN 地址外,还可以使用 NPM 或 Yarn 安装 lottie-web:

```
npm i lottie-web 

// 或 
yarn add lottie-web
```

然后在 JavaScript 中引入相应的 Lottie-web 脚本:

```
import lottieWeb from "https://cdn.skypack.dev/lottie-web";
```

在 Codepen 等演示环境中,直接通过 CDN 引入 Lottie-web 即可。打开浏览器开发者工具,可以看到 `lottieWeb` 对象相关的参数,调用 `loadAnimation` 即可渲染动画:

```HTML
<div id="lottie"></div>
```

```JavaScript
const animation = lottieWeb.loadAnimation({
    // 动效加载到的DOM元素
    container: document.getElementById("lottie"), // 必须项
    
    // 包含动效的JSON文件的相对路径，也可以是绝对路径
    // 必须项，描述动效的JSON文件，一般由AE软件中导出的JSON文件
    path: "https://lottie.host/7401522f-2d8b-4049-ad18-eb0edb6af224/CE9lFrNlEH.json",
    
    // 动效渲染出来的格式，可以是svg、canvas和html
    renderer: "svg", // 必须项，除了svg选择之外还可以是canvas和html
  
    // 用于指定动效是否循环播放，true是循环播放，false不是循环播放
    loop: true, // 可选项
  
    // 指定动效是不是加载后就立即播放，true是立即播放，false不是立即播放
    autoplay: true, // 可选项
});
```

> Demo 地址：https://codepen.io/airen/full/jOROXeY

注意:具体渲染出什么样的动画效果,由 `loadAnimation` 中 `path` 参数引入的 `.json` 文件决定。引入的 `.json` 文件需要符合 [Lottie-web 的规范与要求](https://github.com/airbnb/lottie-web?tab=readme-ov-file#how-it-works),否则有可能不会正常渲染出所需动画效果。也可以通过 `loadAnimation` 提供的参数控制动画的播放方式,例如是否循环播放。

### 获取 JSON 数据

使用 Lottie-web 的一个关键点,是需要一个描述动画效果的 JSON 文件。这个 JSON 文件可以由 AE 设计软件导出,也可以在第三方平台获取。不熟悉 AE 的开发者,获取 JSON 文件最直接的方式是第三方平台,例如从 [LottieFiles 市场](https://lottiefiles.com/marketplace)获取:

> LottieFiles：https://lottiefiles.com/marketplace

在 LottieFiles 市场上可以购买动效,也可以获取许可证允许的免费 JSON 文件。不过大多数情况下,仍需要自己创作才能满足更具体的需求——在市场上找到完全符合需求的动画数据成本较高。

获取到相应的 JSON 数据后,只需像上例那样替换 `loadAnimation` 的 `path` 参数:

> Demo 地址：https://codepen.io/airen/full/BaEaMow

要获得完全符合自己需求的动画效果 JSON 数据,需要使用相关的设计软件设计动画,例如 [AE](https://www.adobe.com/products/aftereffects.html)(Adobe After Effects)。如何使用 AE 设计动画超出本文范畴,感兴趣的读者可在网上搜索相关教程,或[阅读 AE 软件提供的操作文档](https://helpx.adobe.com/support/after-effects.html)。

假设已具备 AE 制作动画的能力,或设计师已提供 AE 制作的动画效果文件,接下来就需要从 AE 中导出描述动画效果的 JSON 文件。这个过程中有一个关键点:从 AE 导出来的 JSON 文件需要提供给 Lottie-web 解析渲染,因此必须符合 Lottie-web 的要求。为避免不必要的麻烦,[可以在 AE 软件中安装 LottieFiles 扩展插件](https://lottiefiles.com/plugins/after-effects),这样从 AE 导出来的 JSON 文件就是 Lottie-web 所需的文件。

使用 LottieFiles 插件还有另一个好处:可以直接在插件中引用 LottieFiles 市场的动效模板文件。

按照前面的示例,把导出来的 `data.json` 文件放到 `loadAnimation()` 的 `path` 中:

```JavaScript
var animation = lottieWeb.loadAnimation({ 
    // animationData: { /* ... */ }, 
    container: document.getElementById('lottie'), // required 
    path: './data.json', // required 
    renderer: 'svg', // required 
    loop: true, // optional 
    autoplay: true, // optional 
})
```

### 渲染动画

在项目中引入 Lottie-web 之后,它会提供 `loadAnimation` 方法,该方法提供渲染和控制动画的相关参数:

```JavaScript
const animation = lottieWeb.loadAnimation({
    // 动效加载到的DOM元素
    container: document.getElementById("lottie"), // 必须项
    
    // 包含动效的JSON文件的相对路径，也可以是绝对路径
    // 必须项，描述动效的JSON文件，一般由AE软件中导出的JSON文件
    path: "https://lottie.host/7401522f-2d8b-4049-ad18-eb0edb6af224/CE9lFrNlEH.json",
    
    // 动效渲染出来的格式，可以是svg、canvas和html
    renderer: "svg", // 必须项，除了svg选择之外还可以是canvas和html
  
    // 用于指定动效是否循环播放，true是循环播放，false不是循环播放
    loop: true, // 可选项
  
    // 指定动效是不是加载后就立即播放，true是立即播放，false不是立即播放
    autoplay: true, // 可选项
});
```

上面代码中的 `renderer: "svg"` 会将 JSON 数据渲染成 SVG 动画:

> Demo 地址：https://codepen.io/airen/full/BaEaMow

将 `renderer` 设置为 `"canvas"`,则会将 JSON 数据渲染成一个 Canvas 动画:

> Demo 地址：https://codepen.io/airen/full/BaEabKM

还可以根据动画需求调整 `loadAnimation` 的其他参数。

## 小结

Web 动画开发存在团队协作、性能、兼容性、调试、维护和学习曲线等痛点。以此为着手点,Web 动画的开发流程从"设计师设计 → 开发者还原"的传统模式,演进为"工具创建动画 → 数据文件 → 播放器渲染"的主流模式。基于 Lottie-web,设计软件(AE)设计的动画可以直接导出为 JSON 数据,在 Web 上以 SVG 或 Canvas 形式精确还原,大幅降低沟通成本与还原偏差。

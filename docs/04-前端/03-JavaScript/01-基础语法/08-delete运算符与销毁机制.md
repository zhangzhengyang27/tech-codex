# delete运算符与销毁机制

## 概念说明

delete 是 JavaScript 中一个元老级的语言特性:JavaScript 很早就支持了 delete 运算,但它实际上是从 JavaScript 1.2 中才开始有的,与它一同出现的是对象和数组的字面量语法。有趣的是,声名狼藉的 typeof 运算是在 1.1 版本中提供的,比 delete 还要早——提及 typeof 的原因是,delete 的操作与类型的识别是相关的。

delete 这个运算的表面意思是"试图销毁某种东西",但落到具体语法上,`delete 0`、`delete x`、`delete obj.x` 各自删除的东西并不相同,背后牵涉值(Value)、表达式求值结果(Result)与引用(Reference)三个层面。

## 核心要点

- delete 运算尝试删除值数据时会返回 true,用于表示没有错误(Error);返回值只表明执行过程没有异常,实际执行行为是"什么也没发生"。
- `delete 0` 的本质是删除一个表达式的求值结果(Result);`delete x` 的区别只在于 Result 是一个引用(Reference)。
- delete 的正式语法是 `delete UnaryExpression`,即"删除一个表达式的结果",而不是"删除某个东西"。
- ECMAScript 约定:任何表达式计算的结果(Result)要么是一个值,要么是一个引用;对象属于"非引用类型"的值。
- delete 真正能删除的只有一种引用,即对象的成员(Property)。因此只有在 `delete x` 等价于 `delete obj.x` 时(如 `with (obj) ...` 语句中,或 x 是全局属性时),delete 才有执行意义。
- 引用不能直接参与值运算,需经内部操作 `GetValue()` 取出值;赋值表达式的语义是"把右端(rhs)的值赋给左端(lhs)的引用"。
- 属性存取 `obj.x` 返回一个引用,该引用将对象 obj 传递给函数调用运算 `()`,使方法内部能通过 this 访问 obj——这是方法调用机制的根基。
- 从环境中查找名为 `x` 的引用的过程称为 ResolveBinding;不同环境下绑定的标识符/名字对应不同的引用。

## 习惯中的"引用"

早期的 JavaScript 在推广时采用传统的数据类型分类方法,宣称同时支持值类型和引用类型的数据,并且,所谓值类型中的字符串是按照引用来赋值和传递引用(而不是传递值)的。这些都是当时"开发人员的概念集"中已有的、容易理解的知识。至于什么是引用类型,JavaScript 强行定义了"Object 和 Function 就是引用类型"——这样一来,引用类型和值类型就给开发人员讲清楚了:对象和函数按引用来传递和使用。

绝大多数情况下,这样解释行得通,但到了 delete 运算这里就不行:

- 按这种解释,`delete 0` 就是删除一个值;
- `delete x` 既可能是删除一个值,也可能是删除一个引用;
- 而 JavaScript 同时约定"在 global 对象上声明的属性等同于全局变量",于是 `delete x` 还可能是删除一个 global 对象上的属性——尽管它在执行时看起来像是一个全局变量的名字。

考虑 `delete 0`:其中 `0` 是一个具体的、字面量表示的"值"。一个字面量值"0"无法在现实世界中被"销毁"——假定它销毁了,难道在这个语言当前的运行环境中就不能使用 0 这个值了吗?显然不合理。所以 JavaScript 的约定是:"所有删除值的 delete 直接返回 true",表明该行为过程中没有异常。JavaScript 1.2 的时代还没有结构化异常处理(try…catch 语句),通过函数调用返回 true 来表明"没有异常"是常规做法。然而返回值只表明执行过程中没有异常,实际的执行行为是"什么也没发生"——不可能真的把"0"从执行系统中清理出去。

剩下的是删除变量和删除属性。由于全局变量实际上是通过全局对象的属性来实现的,删除变量时也就存在识别这两种行为的必要性。例如:

```javascript

delete x

```

这行代码究竟在删除什么?JavaScript 是动态语言,从根本上无法在语法分析期判断 `x` 的性质,因此需要有一种方法在运行期标识 `x` 的性质,以便进一步处理。这就导致了一种新的"引用"类型呼之欲出。

## delete 到底在删除什么?

`delete 0` 到底是在删除什么?对一门编译型语言来说,"0"是一个值,可以是基础值(Primitive values),也可以是数值类型。但如果上升到编译之前的语法分析阶段,"0"就被称为一个记号(Tokens)。一个记号没有语义,记号既可以是语言能识别的,也可以是语言不能识别的;唯有把二者同时纳入语言范畴,语言才能识别所谓的"语法错误"。

delete 不仅仅要操作 `0` 或 `x` 这样的单个记号或标识符(例如变量),因为这个语法实际起作用的是一个对象的属性,即"删除对象的成员"。它真正需要的语法其实是:

```javascript

delete obj.x

```

只不过因为全局对象的成员可以用全局变量的形式来存取,所以它才有了:

```javascript

delete x

```

这样的语法语义。这正好将传统的认识倒转过来:删除的是 x 这个成员,而不是 x 这个值。既然没办法表达异常,而 `delete 0` 又不产生异常,它自然返回 true。更进一步:`obj.x` 既不是引用类型也不是值类型,与 `typeof(x)` 识别的所有类型都无关——它是一个表达式。所以 delete 操作的正式语法设计并不是"删除某个东西",而是"删除一个表达式的结果":

```javascript

delete UnaryExpression

```

## 表达式的结果是什么?

在 JavaScript 中,表达式是一个很独特的东西:所有表达式运算的终极目的都是为了得到一个值,例如字符串;然后再用另外一些操作将这个值输出出来,例如变成网页中的一个元素(element)。这是 JavaScript 语言创生的原力,也是它的基础设计——正因为这种设计,它才既像面向对象的语言,又像函数式语言。

在 JavaScript 中,有两个东西可以被执行并存在执行结果值(Result):语句和表达式。用 `eval()` 执行一个字符串,执行的实际上是一个语句,并返回语句的值;用一对括号强制一个表达式执行,括号运算得到的就是这个表达式的值。表达式的值,在 ECMAScript 的规范中,称为"引用"——这是一种称为"规范类型"的东西。

## 规范中的"引用"

这个概念出现得很早。从 JavaScript 1.3 开始,ECMAScript 规范就在语言定义层面正式推出上述"(真正的)引用类型",把"Object 和 Function 就是引用类型"这个天坑补起来。但由于当时规范的影响力在开发人员中并不大,开发人员仍然习惯性地将对象和函数称为引用、其它类型称为值,并继续按传统理解来解释 JavaScript 对数据的处理。

在这种情况下,一个引用只是在语法层面上表达"它是对某种语法元素的引用",与执行层面的值处理或引用处理无关。于是下面这行简短的语句:

```javascript

delete 0

```

事实上是在说:JavaScript 将 0 视为一个表达式,并尝试删除它的求值结果。所以这里的 0 其实不是值(Value)类型的数据,而是一个表达式运算的结果值(Result)。在进一步的删除操作之前,JavaScript 需要检测这个 Result 的类型:如果它是值,则按照传统的 JavaScript 约定返回 true;如果它是一个引用,那么对该引用进行分析,以决定如何操作。

这个检测过程说明,ECMAScript 约定:任何表达式计算的结果(Result)要么是一个值,要么是一个引用。需要留意的是,在这个描述中,所谓对象其实也是值——准确地说,是"非引用类型"。例如:

```javascript

delete {}

```

这里要删除的一对大括号表示一个字面量的对象,当它被作为表达式执行时,结果也是一个值。这类表达式通常被称为"单值表达式",这里并没有所谓的"引用"。细致而准确地解释这一行代码:单值表达式的运算结果返回那个"对象字面量"的单值;然后 `delete` 运算发现它的操作数是"值 / 非引用类型",就直接返回了 true——什么也没有发生。

## GetValue 与手性

在 JavaScript 内部,"引用"可以转换为"值"以便参与值运算。因为表达式的本质是求值运算,所以引用不能直接作为最终求值的操作数。这依赖于一个非常核心的内部操作 `GetValue()`。所谓内部操作,也称为内部抽象操作(internal abstract operations),是 ECMAScript 描述一个符合规范的引擎在具体实现时应当处理的那些行为。`GetValue()` 是从一个引用中取出值来的行为。例如这行代码:

```

x = x

```

x 其实是一个引用,上面的表达式是一个赋值表达式,那么"引用 x 赋值给引用 x"有什么意义?从语法层面解释很直接:所有赋值操作的含义,是将右边的"值",赋给左边用于包含该值的"引用"。所以 `x=x` 其实被翻译成:

```

x = GetValue(x)

```

来执行。JavaScript 区分两个 x 的方法,称为"手性",即"左手端(lhs, left hand side)"和"右手端(rhs)"。这个词本来用于描述自然语言语法中修饰词放在主体的前面还是后面;在程序设计语言中,它说明一个记号(Token)放在赋值符号(例如"="号)的左边还是右边。

简单结论:区别上例中两个 x 的方法就是——如果 x 放在左边作为 lhs,那么它是引用;如果放在右边作为 rhs,那么就是值。所以 `x=x` 的语义并不是"x 赋给 x",而是"把值 x 赋给引用 x"。

由此可以完整回答标题的问题:`delete x` 归根到底,是在删除一个表达式的、引用类型的结果(Result),而不是在删除 x 表达式,或者这个表达式的值(Value)。`delete` 是 JavaScript 中很罕见的、能直接操作"引用"的语法元素——这里的"引用"是 ECMAScript 规范层面的概念,语言中能操作它的语法元素非常少,而 delete 就是其中之一。

## 引用的实际用途:属性存取与方法调用

即便从不执行 `delete 0` 这样的操作,理解引用也有实际意义:`obj.x` 也是一个引用。对象属性存取是 JavaScript 面向对象的基本操作之一,本质上日常开发早就在使用"引用",只是它太习以为常,容易被视而不见。

"属性存取(`.` 运算符)"返回一个关于"x"的引用,然后它可以作为下一个操作符(例如函数调用运算`()`)的左手端来使用,这才有了著名的"对象方法调用"运算:

```

obj.x()

```

在对象方法调用时,函数 _x()_ 来自于 `obj.x` 这个引用,这个引用将 `obj` 这个对象传递给 x(),这才让函数 _x()_ 内部通过 this 访问到 obj。根本上来说,如果 `obj.x` 只是值,或者它作为右手端,那么它就不能"携带" obj 这个对象,也就完成不了后续的方法调用操作。

对象存取 + 函数调用 = 方法调用,这是 JavaScript 通过连续表达式运算来实现新语义/语法的经典示例。所谓"连续运算"其实是函数式运算范式的基本原则。也就是说,`obj.x()` 是在 JavaScript 中集合了"引用规范类型操作""函数式""面向对象"和"动态语言"等多种特性于一体的一个简单语法。它对语言基础特性的依赖就在于:

- `delete 0` 中的 `0` 是一个表达式求值;
- `delete x` 中的 `x` 是一个引用;
- `delete obj.x` 中 `obj.x` 是一组表达式连续运算的结果(Result / 引用)。

于是,当 x 是全局对象 global 的属性时,`delete x` 其实只需要返回 `global.x` 这个引用就可以了;而当它不是全局对象 global 的属性时,则需要从当前环境中找到一个名为 `x` 的引用。找到这两种不同引用的过程,称为 ResolveBinding;这两种不同的 `x`,称为不同环境下绑定的标识符/名字。

## 小结(知识回顾)

delete 运算符尝试删除值数据时,会返回 true,用于表示没有错误(Error);delete 0 的本质是删除一个表达式的值(Result);delete x 与上述的区别只在于 Result 是一个引用(Reference);delete 其实只能删除一种引用,即对象的成员(Property)。所以,只有在 `delete x` 等价于 `delete obj.x` 时,delete 才会有执行意义——例如 `with (obj) ...` 语句中的 delete x,以及全局属性 global.x。

关于标识符从声明到发现的全过程(ResolveBinding 的完整机制),是这一主题的下一步延伸内容。

# 解构赋值与对象本质

## 概念说明

本文讨论 JavaScript 中对象的本质：**对象到底是什么**。结论先行：

- **对象，是对数据的封装**——它本质上是一个数据结构（关联数组）
- **解构，就是从封装的对象中抽取数据**——解构赋值将这个结构解开，取出值完成赋值

理解这两个结论，需要先回顾"对象"这一抽象概念的历史由来，再分析它背后的两种基础数据结构。

## 对象的前生后世

面向对象技术并非与生俱来地成为占有率最高的编程技术。在早期，面向对象并不受待见：它的抽象层级较高，意味着离具体的机器编程较远——当时没有哪种硬件编程技术需要所谓的面向对象。最核心的编程逻辑通常是写寄存器、响应中断或发送指令，这些都是面向机器逻辑的行为。

关键历史节点：

- **1967 年前后**，艾伦（Alan Kay）提出了称为"对象"的抽象概念和基于它的面向对象编程（object-oriented programming），这成为他发明的 Smalltalk 语言的核心概念之一
- 这个最初的"对象"抽象概念中**只包含数据和行为两个部分**，分别称为**状态保存**和**消息发送**——也就是今天所说的"属性"和"方法"
- 在此基础上出现了状态（数据）的局部保存、保护和隐藏等概念，即对象成员的**可见性**问题
- 最初的对象概念中**没有继承，也没有多态**——历史上最早出现的所谓对象，其实只是对数据的封装

正因如此，最近十余年来，众多的语言流派对"继承"以及相关的"多态"特性发起非难。追根溯源，这两个概念并非"面向对象"思想的必然产物，它们的存在可能增加系统抽象的复杂性。具体到 JavaScript，一些新的面向对象特性也总会在 ECMAScript 规范的草案阶段碰壁。例如近两年最受非议的 "Class Fields" 提案：在添加了"私有字段"概念之后，"保护属性"问题被推给了远未成熟的注解提案，原因是"字段"与"继承性"之间存在概念和实现模型的冲突。TC39 中存在大量对面向对象特性持谨慎态度的成员（常被戏称为 "OOP 敌视者"），虽是玩笑，但也反映了面向对象编程思想在这门语言中的微妙处境。

近年来的新语言除了使用"字段""记录"等抽象概念替代面向对象之外，还广泛拥抱函数式编程。这既带来更深层面的问题，也使面向对象的生存环境进一步恶化：

- 面向对象的封装、继承和多态三个核心概念中，多态有一部分与继承性相关——去掉继承性，多态就失去了一半
- 另一半被"接口（Interface）"概念取代
- 整个 OOP 体系中只剩下"封装"在概念上还能独善其身——这与 Alan Kay 最初的意图一致，他提出"面向对象"本意就在于提高封装性
- 引入函数式编程后情况发生变化：函数式语言不考虑数据封装问题，逻辑之间的数据由函数参数传递，函数自身强调"无副作用"，不影响函数之外的数据——函数外也就没有任何数据封装（例如隐蔽）的要求

于是，对象概念归结为一个最原始的定义：**所谓对象，是对数据的封装**。赋值表达式右边的 "y"，正是这样的一个"对象"。**解构赋值，就是将这个结构解构了，拿去赋值**。关键问题在于：对象，是怎样的一个数据结构？

## 两种数据结构

所谓"某某编程思想"，本质上说的是两件事：在编程中**怎么管理数据**，以及**怎么组织逻辑**。结构化（具体到"数据结构"）是把系统中的数据用统一的、确切的、有限的数据样式管理起来——小到一个位（bit）、一个字节（byte），大到一个库（Database）、一个节点（Node），都是对数据加以规划的结果。

这些思想背后有一个核心问题：**如何抽象"一堆"数据，使它们能被方便且有效地管理**。在单机系统或 JavaScript 这类应用环境中，数据被假设放在"有限的存储空间"里，这个假设模拟了内存和指令带宽的基本性能。

抽象层级与编程复杂度的关系：数据结构的抽象层次越低级，对它的编程就越复杂——如果需要面向"位（bit）"编程，差不多就要写机器指令或手工搬动逻辑电路的开关。

在"有限的存储空间"里，最高的抽象层级只能表达为一个"**块**"：在不了解一堆数据的具体性质时，只能称它为"一堆数据"，而"块"是对"有限空间"的边界分解。由此带来的问题是：**在一个有限空间中，如何找到一个"块"？**从块的相关位置（位置关系）出发，只有两个解：

1. 为所有**连续的**块添加一个连续的"**索引**"
2. 为所有**不连续的**块添加一个唯一的"**名字**"

"连续/不连续"在语义上是二分的，所以只需要两个解：

- "索引"对应于连续性本身，可计算地表达为 `a[i]`（a 的下标 _i_）
- "名字"对应于"找到块"这一目的本身，表达为一个可计算的函数 `f()`（可以认为 `f` 是 `find` 的简写）。一旦系统认为函数 `f()` 可以用于找到需要计算的数据，数据就可以理解为 `b[f()]`，函数 _f()_ 的实现可以交给"另外的一个系统"完成

有人会问：为什么不能将 "i" 也理解为"找到 i"？——如果这样理解，"索引"也可以作为名字，可以为 `a[i]` 引入一个用于计算索引的函数 f，只是该函数 _f()_ 的唯一作用是返回 "i"：

```javascript

function f() { return i }
a[i] === a[f()];

```

由此得到两种数据结构——"连续的块"与"不连续的块"，它们存在统一的"找到块的模式"：**通过一个函数来找到块**：

- 对于索引数组，这个函数是取数组成员的"索引"
- 对于关联数组，这个函数是取数组成员的"名字"。关联数组是用一对"名/值"创建的数组；为了将无穷尽的"名字"收敛在有限范围内，实现中通常用值的 HASH 作为名字

因此，在"怎么管理数据"这个问题上，所有数据只具有两种数据结构：**索引数组**（对应可索引的块）和**关联数组**（对应不可索引的块）。究其根本，**索引数组其实是关联数组的一个特例——被存取的数据所关联的名字就是它的索引**。

JavaScript 的"对象"在本质上就是关联数组；而"数组（Array）"——即索引数组（Index array），正是作为关联数组的一个特例来实现的。JavaScript 以此实现了两种数据结构的大统一：**数组（Array class）是一种对象（Object class）；对象本质上是关联数组（Associative array）**。

## 解构

对象不过是"稍微复杂一点的数据结构"：相比稍早出现的"记录/结构体"，它只是"没有顺序存储限制、以及添加了成员名字的"结构体。

![](https://static001.geekbang.org/resource/image/96/2d/96cd29a13a022c630b5d618ea20cb02d.png)

> 图引自：《程序原本》"10.1 抽象本质上的一致性"

计算的本质是求"值"，几乎所有引用类型最终都会将"与它相关的运算结果"指向"值"。原因很简单：物理的计算系统最终只能接收"字节、位"等值类型数据。但在高级语言或应用编程中，程序员需要高层级的抽象来简化编程，于是有了结构体以及对象。还原这个过程意味着：**"结构"是应用编程的必须，而"解构"是底层计算的必须**。从一个结构（数据结构或对象等复杂结构）中把值数据取出来，就称为解构。

本文标题中的代码就是一个解构赋值，目的是"从一个结构中提取值"：

```

 [a, b] = {a, b}

```

这段代码的求值过程分析：

- **等号右侧**是一个对象的字面量，语义是将 `a`、`b` 两个数据变成"对象"这个数据结构中的两个成员。由于 a、b 都是既已约定的名字，作为对象成员时"名字 + 值"都已具备，完全符合"关联数组（名/值数据对）"的语义要求
- **等号左侧**不是数组，而是一个"（数组）赋值模板"。赋值模板是"变量名字"和"它的值"之间位置关系的说明，是描述型的、声明风格的——它在 JavaScript 语法解析阶段就完成了处理，不会产生任何运行期的执行过程。左侧的"赋值模板"只是声明了一组变量，与代码 `var x, y, z = 100` 中的 `x,y,z` 名字声明没有差异，处理方式也相同

区别在于：赋值模板中声明的变量，每一个都"绑定"了一段赋值过程，即"初始器赋值"（在函数的非简单参数中同样使用该机制）。ECMAScript 中两者调用相同的"赋值过程"，但存在语义区别：

- 当赋值模板用作**声明**（var/let/const）时，"赋值过程"作为值绑定的初始器
- 当该模板用作**赋值运算**的左操作数时，右操作数将作为"赋值过程"的传入参数

因此对于标题中的代码，存在三种语义上并不相同的逻辑：

```javascript

// 1. lhsKind is assignment, call DestructuringAssignmentEvaluation
[a, b] = {a, b}

// 2. lhsKind is varBinding, call BindingInitialization,
// and env will be current function scope.
var [a, b] = {a, b}

// 3. lhsKind is lexicalBinding, call BindingInitialization and current env
let [a, b] = {a, b}

```

三种写法的结果相同：左侧的 `a` 和 `b` 都将被赋以右侧对象 `{a, b}` 解构出来的"值"。但实际运行标题中的代码，结果可能与预期不同——左侧的 `a` 和 `b` 与已有的变量 "a、b" 并不相同（假设这些变量已存在）。三个示例中，示例三（let/const）的赋值不能成立，因为右侧的对象无法被创建：

```text

> let [a, b] = {a, b}
ReferenceError: Cannot access 'a' before initialization

```

前两个示例在代码逻辑上可以成立，只是"一般来说"运行会抛出异常：

```text

# “赋值未声明变量”
> a = 100, b = 200;

# 示例代码（与使用 var 声明相同）
> [a, b] = {a, b};
TypeError: {(intermediate value)(intermediate value)} is not iterable

```

如何让这行代码可以执行？这就引出本文标题的核心话题。

## 两种数据结构的统一

对象和数组在本质上都是存放"一堆数据"的结构，差异只在查找过程。模拟它们不同的查找过程，就可以在这些结构之间完成统一的"赋值行为"。

"数组赋值模板"引用的是数组的下标索引过程：ECMAScript 将索引次序用专门的增序管理，并将右操作数视作"迭代器"来取值。重点在于两者的区别：**"迭代器"的取值是序列的，但并没有确定使用数组的下标（例如序号）**。因此，只要让右侧的对象成为一个"可迭代对象"，赋值表达式就知道如何将它赋给左侧的模板：

```text

# 模拟成数组的迭代器
> Object.prototype[Symbol.iterator] = function() { return Array.prototype[Symbol.iterator].call(Object.values(this)); };

# 测试
> a = 100, b = 200;
> [a, b] = {a, b}
...

```

也可以不借用数组的迭代器，使用更简单的版本：

```javascript

Object.prototype[Symbol.iterator] = function*() { yield* Object.values(this) };

// 测试
a = 100, b = 200;
[a, b] = {a, b}  // a = 100, b = 200

```

也就是说，只需要将"对象成员"的列举变成"对象成员的值"的列举，关联数组就可以用作索引数组。实际代码中通常不需要修改原型，写成下面这样就已经足够：

```text

> [a, b] = Object.values({a, b})

```

### 反向：数组赋给对象赋值模板

对象赋给数组（赋值模板）可行，那么数组赋给"对象（赋值模板）"是否可行？答案是可以——前提是在模板中"描述"索引与名字之间的关系：

```text

# 在对象赋值模板中声明变量名与索引的关系
> ({0: x, 1: y} = [a, b])
> console.log(x, y);
100 200

```

如果直接使用没有关系描述的代码（即标题代码反过来）：

```

{a, b} = [a, b]

```

由于没有这种关系描述，右侧的数组被"强制地"作为一个对象使用，变成取 `a`、`b` 这两个成员的值，结果不可预知。这种不可预知来自"将右侧数组作为对象并尝试取得具体成员"的行为，并且还受原型对象的影响。

### 展开语法：不受原型影响的桥梁

避免原型影响的方法是**展开语法（Spread syntax）**（其执行机制参见《展开语法的执行机制》）。与本文相关的两个能力——"对象展开（Object spread）"和"剩余参数（Rest paraments）"——都只处理那些**"可列举的、自有的"属性**，因此展开过程不受对象原型的影响：

```text

# 测试变量
> var a = 100, b = 200;

# 将数组展开到一个对象（的成员）
> obj = {...[a,b]}
{0: 100, 1: 200}

# 或，将对象展开到一个数组
> iterator = function*() { yield* Object.values(this) };
> obj[Symbol.iterator] = iterator;
> arr = [...obj]
[ 100, 200 ]

```

## 小结

本文从抽象层面认识了对象与数组这两种结构，以及它们更学术的名词概念：关联数组和索引数组。核心结论：

- 对象本质是关联数组，数组（索引数组）是关联数组的特例——被存取数据所关联的名字就是它的索引
- 由于索引数组本质上是关联数组的特例，JavaScript 用关联数组（对象）实现索引数组（数组对象）是合理的，且有深层的理论根基
- 两种数据结构既相关又相同，它们之间相互转换的行为本质上是**名字和索引变换的游戏**；展开语法正是这两种数据类型之间的桥梁
- 解构赋值 `[a, b] = {a, b}` 不可直接运行的原因在于：赋值模板的求值依赖迭代器协议或成员名字的对应关系，而对象默认不可迭代、数组默认没有 `a`、`b` 这样的成员名

理解"如何让标题代码运行"所涉及的知识，与 JavaScript 较深层面的运行原理以及较高层次的抽象结构密不可分。无论是为了理解 JavaScript 代码，还是理解语言中最本质的那些假设或前设，都建议动手运行本文的示例代码。

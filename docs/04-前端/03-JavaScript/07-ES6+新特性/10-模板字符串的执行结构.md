# 模板字符串的执行结构

模板是 JavaScript 中出现得很晚的一个语法元素。它的表面行为非常简单：把一个字符串里的占位内容替换成计算结果。C 语言的 `printf()` 具备类似功能，Bash 脚本也可以直接在字符串里替换变量。但在语言机制层面，模板并不是"简单字符串替换"，而是一类特殊的可执行结构。

## 概念说明：什么是可执行结构

JavaScript 中存在语句和表达式两种基本的可执行元素，这是大多数语言通用的设计。但 JavaScript 中可执行的并非只有语句和表达式——模板就是一种**特殊的可执行结构**。

所有特殊可执行结构都来自某种固定的、确定的逻辑：这些逻辑语义明确、输入输出确定，因此能够被设计成标准的、易于理解的可执行结构。在一门语言中添加过多有特殊含义的执行结构，会让语言逐渐产生"坏味道"——越来越多的抽象概念固化成特殊逻辑或结构，试图通过非正常逻辑影响程序员的思维过程。

抛开标准库中的 Map、Set 等运行时对象，专门考察语言及语法层面定义的特殊可执行结构，可以归纳出以下几类：**参数表、缺省参数与参数展开、赋值模板、引用（Reference）**。模板字面量是它们的集大成者。

## 核心要点

- 参数表是独立的语法组件，在 ECMAScript 规范中被统一为标准的规范类型 List，作为独立部分参与运算。
- 缺省参数、剩余参数、参数展开都是参数表作为可执行结构的组成部分；参数展开是唯一能动态影响"传入参数个数"的语法。
- 赋值模板（AssignmentPattern）适用于任何"向左操作数赋以右操作数的值"的语义过程，远不限于赋值符号本身。
- 引用（Reference）是"发现（Resolve binding）"过程的产物，属性引用 `obj.foo` 负责为后续方法调用保留并传递 `this` 信息。
- 模板字面量调动了引用、求值、标识符绑定、内部可执行结构存储以及函数调用的全部能力。
- "模板字面量调用（TemplateLiteral Call）"是唯一使用模板字面量引用形态的操作，这种形态称为"标签模板（Tagged Templates）"。

## 原理与规范

### 参数表

参数表在 JavaScript 语言的内核中是一个独立的语法组件：对于函数来说，参数表是函数调用时传入的参数 0 到 n；对于构造器以及 `new` 运算来说，参数表是 `new` 运算的一个运算数。二者略微有区别，在远古时期的 JavaScript 中很难区分。ECMAScript 规范将参数表统一成了标准的 List——这是一种规范类型，与引用、属性描述符等规范类型类似，在相关操作中作为一个独立的部分参与运算。

JavaScript 的反射机制可以证实这一点：使用代理对象能够拿到函数调用的入参，或者 `new` 运算过程中传入的参数，它们都表示为一个标准的数组。

```javascript
handler.apply = function(target, thisArgument, argArray) { ... }
```

这里 `argArray` 表示为数组，但这只是参数表在传入后通过"特殊可执行结构"执行的结果。这个列表实际是根据形式参数的样式（Formal of Parameters），按照传入参数逐一匹配出来的。任何实际参数在传入函数的形式参数时，都会经历这样的执行过程，它是"将函数实例化"这个内部行为的一个处理阶段——即把函数从源代码文本变成一个可执行的、运行期闭包的过程。参数表作为可执行结构，其执行结果是将传入的参数值变成与形式参数规格一致的实际参数，并将这些参数中的所有值与它们"在形式参数表中的名字"绑定起来，作为函数闭包中可以访问的名字。

概括而言：把参数放在 arguments 列表中，让 arguments 中的值与参数表中的名字对应起来，这就是对"参数表（argArray）"这个可执行结构的全部操作。

由此得出两个重要推论：

- **箭头函数没有参数表**：箭头函数采用与上述完全一致的处理逻辑，只是最后没有向闭包绑定 `arguments` 这个名字。
- **简单参数（Simple Parameter List）**：指可以在形式参数表中明确数出参数个数、没有使用扩展风格声明参数的参数表，它与 argArray 的使用存在直接关系。

### 扩展风格的参数表

扩展风格的参数表也称为"非简单的参数列表（Non-Simple Parameter List）"，与缺省参数等可执行结构相关。缺省参数的形态如下：

```javascript
function foo(x = 100) { ... }
```

这意味着在语法分析期，JavaScript 就要为该参数登记下 `100` 这个值；在实际处理这个参数时，至少需要一个赋值表达式操作，将这个值与它的名字绑定。所以 `foo()` 函数调用时，总有一段执行逻辑来访问形式参数表并执行这个赋值表达式。

复杂之处在于：这个默认值可以是一个表达式的运算结果。由于表达式可以引用上下文中的其它变量，所谓"登记"就不能只记下一个字面量值，而必须登记一个表达式，并在运行期执行它。

```javascript
var x = 0;
function foo(i = x++) { console.log(i); }
foo(); // 1
foo(); // 2
```

每次调用 `foo()` 时，`x++` 都会得到执行。因此缺省参数本身就是一种可执行结构，是参数表作为可执行结构的逻辑的一部分。同理，剩余参数和参数展开也都具有类似性质。

**参数展开**是唯一一个可以影响"传入参数个数"的语法：

```
foo(...args)
```

这个语法的关键不在形式参数的声明，而在实际参数的传入：传入时实际只用到了一个参数 `args`，但 `...` 语法对这个数组进行了展开，并根据 `args.length` 扩展了参数表的长度。由于其它参数都按实际个数计数，参数展开就成了唯一能动态创建和指定参数个数的语法。

在传统 JavaScript 中，这一语法要使用 `foo.apply()` 替代。历史上 `new Function()` 语法没有类似于 `apply()` 的创建和处理参数表的方式，早期的 JavaScript 需要较复杂的逻辑或调用 `eval()` 处理动态的 `new` 运算。如今它可以用一行代码替代：

```javascript
new Func(...args)
```

这正是"函数和（使用 `new` 运算的）构造器的参数表不一样"所带来的差异。参数展开的实现依赖迭代器：参数展开是数组展开的一种应用，而数组展开在本质上依赖迭代器。任何内置迭代器的对象（即 `Symbol.iterator` 符号属性有值的对象）都可以使用展开语法，按迭代顺序生成相应多个"元素（elements）"并用于需要的地方，例如 `yield*`，又例如模板赋值。迭代器有一组界面约定，这个迭代器界面本质上也是一种可执行结构。

### 赋值模板

赋值模板是 ECMAScript 6 之后提供的一种声明标识符的语法，依赖一个简单的赋值过程，可以抽象地理解为：

```
a = b
```

等号的左侧称为赋值模板（AssignmentPattern），右侧称为值（Value）。在 JavaScript 中，任何出现类似语法或语义过程的位置，本质上都可以使用模板赋值：即使没有赋值符号，只要语义是"向左操作数（lhs）上的标识符，赋以右操作数（rhs）的值"，就适用于模板赋值。"向参数表中的形式参数的名字赋以实际参数的值"也是这样的过程，所以 JavaScript 在语法上支持在参数表中使用模板赋值，以及在任何能够声明变量或标识符的地方使用模板赋值。

```javascript
function foo({x, y}) { ... }
for (var {x, y} in obj) { ... }
```

所有这些位置的赋值模板都在语法解析期被分析出来，并在 JavaScript 内部作为可执行结构存放；运行期用它们完成"从右操作数按模板取值，并赋值给左操作数"的过程。这与将函数的参数表作为样式（Formal）存放、运行期逐一匹配传入值是异曲同工的。

### 引用（Reference）

上述执行结构都可以归为一个大类："名字和值的绑定"——执行的结果都是一个名字，执行的语义是给这个名字一个值。但除了给名字一个值，最终还得使用这个名字进行更多运算。这个"找到名字并使用名字"的过程称为"发现（Resolve binding）"，其结果称为"引用（reference）"。

任何名字以及任何字面量的值，本质上都可以作为被发现的对象。在代码的语法分析阶段，发现一个名字与发现一个值本质上没有不同，所以下面两行代码：

```
a = 1
1 = 1
```

都可以通过语法解析并进入实际的代码执行阶段。`1 = 1` 被设想为一个运行期错误（ReferenceError），而不是语法错误（SyntaxError）。

> 编者注：现行 ECMAScript 规范为赋值目标增加了静态检查（IsValidSimpleAssignmentTarget），现代引擎对 `1 = 1` 会直接在语法分析期报 SyntaxError（Invalid left-hand side in assignment）；此处论述反映的是该早期错误机制确定之前的语言设计思路。

"发现的结果——引用（Reference）"不是一个简单的语法标识符，而是一个可执行结构。如下面这些代码，每一个都会导致一个引用（的可执行结构）：

```javascript
a
1
"use strict"
obj.foo
```

正因如此，上面第三行代码才会成为"可以导致当前作用域切换为严格模式"的指令：它是引用，也是可执行结构，JavaScript 只需像调用函数一样将它处理成一段确定逻辑。

这几个引用中有一个非常特殊：`obj.foo`，称为**属性引用（Property Reference）**。属性引用不是简单的标识符引用，而是属性存取运算的结果，即表达式运算的结果可以是一个引用。它的特殊性在于：它是为数不多的、可以存储原表达式信息并将该信息"传递"到后续表达式的特殊结构。这与 JavaScript 中"方法调用"语义的特殊实现有关——JavaScript 不是静态分析的，无法在语法阶段确定 `obj.foo` 是不是函数，也不知道后续代码要拿它做什么。

```

obj.foo()

```

直到运行期处理到下一个运算时，JavaScript 引擎才会意识到这里要调用一个方法。方法调用需要将 `obj` 作为 `foo()` 函数的 `this` 值传入，而这个信息只能在上一步的属性存取 `obj.foo` 中获得。所以 `obj.foo` 作为属性引用，有责任保留该信息并传递给下一个运算，才能完成"将函数作为对象方法调用"的过程。引用作为函数调用（以及其它某些运算）的左操作数（lhs）时需要传递上述信息，这就是"引用"这种可执行结构的确定逻辑：帮助 JavaScript 的执行系统完成"发现 / 解析（Resolve）"过程，并在必要时保留过程中的信息。

在引擎层面，如果一个过程只是将"查找的结果展示出来"，最终就表现为值；如果包括这个过程信息，通常就表现为引用。JavaScript 执行的最终结果到底表达为引用还是值？答案是"值"——引用（包括其过程信息）无法打印出来，用户真正关心的是计算结果。JavaScript 创建引用、处理这些引用或特殊结构的执行过程，最终目的仍是计算求值。

## 模板字面量：可执行结构的集大成者

前面所有可执行结构铺垫了理解模板字面量（TemplateLiteral）的基础。标题所指的这行代码就是一个模板字面量：

```javascript
`${1}`
```

模板字面量是上述所有可执行结构的集大成者。它本身是一个特殊的可执行结构，但调动了包括引用、求值、标识符绑定、内部可执行结构存储以及执行函数调用在内的全部能力。这是 JavaScript 厘清了所有基础可执行结构之后，才在语法层面将它们融汇如一的结果。

与参数表和赋值模板相似，模板字面量也是将它的形式规格（Formal）作为可执行结构来保存的。区别在于：参数表与赋值模板关注的是名字，存储的是"名字（lhs）"与"名字的值（rhs）的取值方法"之间的关系，执行结果是 argArray 或当前作用域中绑定的名字；而模板字面量关注的是值，存储的是"结果"与"结果的计算过程"之间的关系。由于模板字面量的执行结果是一个字符串，当它作为值来读取时，就会激活它的运算求值过程并返回一个字符串值。模板字面量与所有其它字面量（能作为引用）相似，也可以作为引用。

```
1 = 1
```

`1 = 1` 包括了 `1` 作为引用和值（lhs 和 rhs）的两种形式，在语法上是成立的。

```javascript
foo`${1}`
```

同理，这行代码在语法上也成立。因为这个表达式中，`${1}` 使用的不是模板字面量的值，而是它的一个"（类似于引用的）结构"。"模板字面量调用（TemplateLiteral Call）"是唯一一个会使用模板字面量引用形态（并且也没有直接引用它的内部结构）的操作。这种引用形态的模板字面量也被称为"标签模板（Tagged Templates）"，主要包括模板的位置和那些可计算的标签的信息。例如：

```text
> var x = 1;
> foo = (...args) => console.log(...args);
> foo`${x}`
[ '', '' ] 1
```

## 实践要点

- **引擎对模板的缓存**：模板字面量的内部结构主要包括将模板多段截开的一个数组、原始的模板文本（raw）等。引擎处理模板时只将该模板解析一次，并将这些信息作为一个可执行结构缓存起来（避免多次解析降低性能），此后只使用该缓存的一个引用。当它作为字面量被取值时，JavaScript 在当前上下文中计算各个分段中的表达式，将表达式的结果值填回模板拼接成一个结果值并返回。
- **理解"为什么需要模板调用"**：标签模板的设计使得字符串模板的解析过程（分段数组、raw 文本、位置信息）可以作为引用形态传递给标签函数，这是国际化、DSL、模板过滤等能力的语言层基础，具体机制可进一步阅读 ECMAScript 规范中关于模板缓存与模板调用的章节。
- **区分值与引用两个视角**：同一个模板字面量，取值时走求值过程，作为标签模板使用时走引用形态——这与 `1` 在 `1 = 1` 中同时承担 lhs 和 rhs 的机制一致。

## 小结

模板字面量是一种可执行结构，也是 JavaScript 各类特殊可执行结构的集大成者：参数表、缺省参数、参数展开与赋值模板解决"名字和值的绑定"，引用解决"名字的发现与信息传递"，而模板字面量将这些能力融汇于一处。JavaScript 中的这类可执行结构通常以固定的逻辑、在确定的场景下交付语言核心语法能力，理解它们是理解模板字符串执行机制的关键。

# 面试要点汇总

本篇汇总前端面试的核心考察要点：专业基础知识清单、项目经验维度、算法基础与项目亮点打造方法，便于系统自查与复习。

## 一、专业知识考察清单

### JavaScript（面试核心）

面试官常考察 JavaScript 语言设计（原型继承、单线程）与运行过程（作用域和闭包、执行上下文与 `this`、Event Loop），以及以手写代码形式出现的题：

- 手写实现 `call` / `apply` / `bind`
- 手写实现 `Promise`；为什么要使用 `async` / `await`
- `0.1 + 0.2` 为什么等于 `0.30000000000000004`，如何用代码解决
- 怎样让 ES6/ES7 代码跑在各浏览器（Babel 与 polyfill）；`let`/`const` 作用域如何实现
- 介绍 `Set` 和 `Map` 数据结构

编码过程的思考、编码风格与思路本身也是考察点。

### HTML 与 CSS

- HTML：DOM 操作与性能、事件冒泡/委托、虚拟 DOM 设计，多结合浏览器机制考察（`<script>`/`<style>` 标签的处理过程）
- CSS：页面布局原理（盒子模型、文档流、浮动）与布局技巧（传统布局、Flex、Grid），常以编码实现居中/对齐等题考察；布局涉及浏览器渲染过程，需注意性能

### 浏览器 / Node.js / 网络 / 安全

- 浏览器：经典题"在浏览器地址栏里输入 URL 回车后会发生什么"，串起 HTTP 请求过程 → 浏览器架构、线程与进程协作 → 渲染流程
- Node.js：与浏览器的区别除全局对象外还有 Event Loop 机制差异
- 网络："一个完整的 HTTP 请求过程"、HTTP 协议应用场景（缓存、WebSocket、短轮询与长轮询、登录态）、网络性能优化（缓存、分片/压缩/懒加载/预加载、DNS 与 CDN、HTTP/2）
- 安全：XSS 与 CSRF 的攻击手段与防范方案（这也是框架能规避大部分 XSS 的原因）

### 算法与数据结构、计算机通用知识

大公司会考察算法基础（可在 LeetCode 平台刷题）；大型前端应用确实会用到算法与数据结构（如 VSCode 文本缓冲区使用红黑树）。计算机基础、网络基础属于通用工程师素养，掌握不足常成为前端开发者职业发展的瓶颈。

## 二、项目经验考察维度

面试中项目经验相关的知识点主要包括：前端框架与工具库、Node.js 与服务端、性能优化、工程化、前端监控、开发效率提升。

- **框架与工具库**：不止会用，要理解各框架的区别、设计与实现原理，便于技术选型和借鉴解决方案
- **Node.js 与服务端**：偏方案选型与场景；注意前端与后台的知识体系差异——前端深挖页面性能优化、模块抽象与数据渲染拆离、工程化；后台更关注计算机资源、多进程、数据库索引、并发与事务
- **性能优化**：表现为空间（内存/CPU/缓存占用过多导致卡顿）和时间（加载/渲染/可交互耗时）两类。实践上从页面启动、请求资源、解析数据、渲染页面各阶段分析耗时后针对性优化：
  - 首屏提速：按需加载/懒加载/预加载、秒看、SSR 直出、客户端容器化与离线化
  - 网络请求优化：CDN、缓存、HTTP/2、Gzip 压缩、合并请求、域名拆分、减少 DNS 查询
  - 性能会随迭代下降，可做性能分析的自动化
- **前端工程化**：构建/打包工具、脚手架、CI/CD 与流水线、代码部署与灰度发布、代码规范与流程自动化
- **前端监控**：数据上报与实时监控，涉及页面访问、性能、告警；灰度方案与上报落盘、数据清洗与团队系统架构相关
- **开发效率**：组件与公共库封装、兼容管理、用工具替代重复工作，是常见的加分项

## 三、算法基础：复杂度与 TimSort

### 时间复杂度与空间复杂度

复杂度用 O 表示，参数一般为 1 或 n 的表达式。时间复杂度取决于表达式执行次数：

```javascript
// 遍历求和：执行 n 次 → O(n)
arr.reduce((acc, cur) => acc += cur, 0)
// 等差数列求和公式一次计算 → O(1)，优于 O(n)
```

空间复杂度按临时变量占用空间计算：

```javascript
// 原地移动数组元素，只借助一个临时变量 → O(1)
let tmp = arr[0]
for (let i = 0; i < arr.length - 1; i++) {
  arr[i] = arr[i + 1]
}
arr[arr.length - 1] = tmp

// 结果存入新数组 → O(n)
let newArr = []
for (let i = 0; i < arr.length - 1; i++) {
  newArr[i] = arr[i + 1]
}
newArr.push(arr[0])
```

复杂度简写原则：多项式取最高次项并省略系数（O(3n+1) → O(n)）；不同参数统一用 n 表示（遍历 m×n 数组 O(mn) → O(n²)）。只能优化系数或非最高次项时，在复杂度上意义不大。常用复杂度从优到劣：

```text
O(1) > O(logn) > O(n) > O(nlogn) > O(n^2) > O(x^n)
```

### TimSort：Array.prototype.sort 的底层算法

JavaScript 引擎把高效排序写进了数组的 `sort()`，这就是 **TimSort**——一种同时采用折半插入排序和归并排序的混合算法（Java、Python 也在用）。最好情况 O(n)，最坏 O(nlogn)，空间复杂度最好 O(1)、最坏 O(n)。

实现步骤：

1. 根据数组长度计算子数组 run 的最小长度 minRunLength：数组长度小于 MIN_MERGE（V8 中为 32）时整段做一次折半插入排序；否则逐位右移得到位于 [MIN_MERGE/2, MIN_MERGE) 的值，控制 run 数量、避免超长 run 与超短 run 合并；
2. 遍历数组，从当前索引找最长的有序子数组作为 run，若方向与排序方式不一致则反转；
3. run 长度小于 minRunLength 时，用折半插入排序合并出更长的 run；
4. 将 run 压入栈 pendingRuns，等待合并；
5. 合并部分 run，使栈内始终满足 `pendingRuns[i].length > pendingRuns[i+1].length + pendingRuns[i+2].length && pendingRuns[i].length > pendingRuns[i+1].length`；
6. 按次序合并 pendingRuns 得到最终结果。

V8 以 Torque（.tq）文件实现 TimSort，语法风格与 TypeScript/JavaScript 相近，可对照源码学习。

**折半插入排序**：用折半查找插入点取代顺序查找，优化插入排序（O(n²)/O(1)）：

```javascript
function binaryInsertionSort(arr) {
  for (var i = 1; i < arr.length; i++) {
    if (arr[i] >= arr[i - 1]) continue
    let temp = arr[i];
    let low = 0;
    let high = i - 1;
    while (low <= high) {
      const mid = Math.floor((low + high) / 2);
      if (temp > arr[mid]) {
        low = mid + 1;
      } else {
        high = mid - 1;
      }
    }
    for (var j = i; j > low; --j) {
      arr[j] = arr[j - 1];
    }
    arr[j] = temp;
  }
}
```

**归并排序**：分治思想，拆分子数组分别排序后合并（二路归并），O(nlogn)/O(n)：

```javascript
function mergeSort(array) {
  function merge(leftArr, rightArr) {
    var result = [];
    while (leftArr.length > 0 && rightArr.length > 0) {
      if (leftArr[0] < rightArr[0])
        result.push(leftArr.shift());
      else
        result.push(rightArr.shift());
    }
    return result.concat(leftArr).concat(rightArr);
  }
  if (array.length == 1) return array;
  var middle = Math.floor(array.length / 2);
  var left = array.slice(0, middle);
  var right = array.slice(middle);
  return merge(mergeSort(left), mergeSort(right));
}
```

TimSort 的优化思路与性能优化相通：归并拆分 run 是"做除法"，生成 run 时利用数据已有有序性（类似缓存）是"做减法"。

## 四、项目亮点打造

面试官问"你做过什么项目"，想听的不是流水账，而是增删改查之外的亮点。

### 普通开发者：需求级优化

**大文件上传（断点续传）**：上传 2GB 视频时直接 `axios.post` 一旦断网就要整文件重传。优化方案：把文件切片依次上传，重传时过滤已存在的切片；在前端计算文件 Hash 作为唯一标识向后端询问切片列表。

计算 2GB 文件的 Hash 会卡顿主线程，两种解法：

```javascript
// 解法一：Web Worker 计算哈希，不占主线程
async calculateHashWorker(chunks) {
  return new Promise(resolve => {
    this.worker = new Worker("/hash.js")
    this.worker.postMessage({ chunks })
    this.worker.onmessage = e => {
      const { progress, hash } = e.data
      this.hashProgress = Number(progress.toFixed(2))
      if (hash) resolve(hash)
    };
  });
}
```

```javascript
// 解法二：借鉴 React Fiber，用浏览器空闲时间切片计算
let count = 0
const workLoop = async deadline => {
  while (count < chunks.length && deadline.timeRemaining() > 1) {
    await appendToSpark(chunks[count].file)
    count++
    this.hashProgress = count < chunks.length
      ? Number(((100 * count) / chunks.length).toFixed(2))
      : 100
    if (count >= chunks.length) resolve(spark.end())
  }
  if (count < chunks.length) {
    window.requestIdleCallback(workLoop)
  }
}
window.requestIdleCallback(workLoop)
```

继续深挖：几十个切片同时 `Promise.all` 上传也会卡顿，需要手动管理并发数量；切片大小可借鉴 TCP 慢启动逻辑，按当前网速动态确定（完整演示见 [file-upload](https://github.com/shengxinjing/file-upload)）。

**长列表渲染（虚拟列表）**：成千上万条数据渲染导致卡顿时，只渲染视口中可见的 DOM 元素，滚动时维护窗口内的 DOM，避免 DOM 过多引起的卡顿。

### 骨干/负责人：项目级优化

- 团队脚手架：集成代码规范、Vite 配置、日志等能力，提高项目启动效率
- 基础组件库：发布到公司 npm，配套文档系统与 90%+ 单测覆盖率
- CI/CD：基于 GitHub Actions 自动化发布、一键回滚，提升研发效率与交付稳定性
- Low Code 系统：营销页面拖拽搭建，需解决物料系统设计、跨端搭建等问题
- 性能监控：制定性能指标、实时监控客户端性能并告警；分析用户访问日志预测访问页面，做路由级预加载

### 用 STAR 原则描述项目

STAR = Situation（情景）、Task（任务）、Action（行动）、Result（结果）。避免"我做过 XXX 项目"式描述，结果最好带数字。对比：

- 平淡版：2020-2021 在极客时间负责官网开发和后台管理系统。
- STAR 版：2020-2021 在极客时间带领 3 个同事开发和维护官网前端项目，作为核心开发者参与组件库设计，XX 个组件测试覆盖率达到 80%，性能优化了 XX%。

## 总结

面试考察分三层：专业知识（JS 基础与手写题是核心，浏览器/网络/安全围绕"URL 回车后发生了什么"串讲）、项目经验（性能优化、工程化、监控是重点维度）、项目亮点（从需求级优化如断点续传/虚拟列表，到项目级建设如脚手架/组件库/CI-CD）。算法方面重点掌握复杂度分析与 `sort()` 底层的 TimSort。表达上用 STAR 原则组织项目描述，结果量化。

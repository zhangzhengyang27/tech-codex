# 前端框架概述

## 前端框架发展史

### 石器时代：后端渲染与 MVC

前端框架的演进与前端技术本身的发展历史密切相关，理解这段历史有助于把握各框架的设计动机。

- 1990 年，第一个 Web 浏览器诞生，这是前端技术的起点，此后前端圈出现了大量里程碑事件
- 1994 年，网景公司发布第一个商业浏览器 Navigator
- 1995 年，网景工程师 Brendan Eich 用 10 天时间设计了 JavaScript，同年微软发布 IE 浏览器，浏览器大战由此展开
- 2002 年，IE 在浏览器大战中胜出，IE6 占有率超过 96%

整个 90 年代受限于网速，网页以静态页为主，显示形式单一，前端工作大部分只是切图和编写 HTML+CSS。

随着后端越来越复杂，代码开始分层：公司规模扩大后需要分部门、明确职责，代码也从揉在一起发展到 Model、View 和 Controller 分别负责不同功能，这就是后端 MVC 模式的盛行。后端渲染页面之前，会把数据库的数据显示在前端，此时除了 HTML、CSS 和简单的 JavaScript 动效，也开始用到 JSP 和 Smarty 等模板技术：

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8">
    <title>smarty test1</title>
  </head>
  <body>
    它的名字叫{$name}
  </body>
</html>
```

上述代码写出的页面可以直接显示后端数据库里的数据，这就是动态网页。动态页面使前端的丰富程度大大提升，迎来了整个互联网开发的繁荣时期。但这种模式下任何数据更新都需要刷新整个页面，在带宽不足的年代会耗费不少加载时间。

> 这个时代的网页主要以显示数据和简单特效为主，比如当时的门户网站，普遍没有太多用户交互。

2004 年 Google 发布 Gmail，用户可以在不刷新页面的情况下进行复杂交互，此后 Ajax 逐渐成为网页开发的技术标准，并不断被应用于各类网站。Ajax 技术可以异步获取数据并局部刷新页面，前端从此不再受限于后端模板，Web 2.0 时代正式到来，前端工程师也正式作为一个独立工种出现。

### 铁器时代：jQuery 与 DOM 操作

Gmail 诞生后，尽管仍存在浏览器混战和兼容性问题（例如绑定事件在不同浏览器中要写不同代码），但业界已经意识到前端也可以承载复杂应用。jQuery 的出现迅速风靡全球，前端的具体开发不再被 JavaScript 的兼容性问题困扰。

这一时期 jQuery + Bootstrap 成为主流技术组合，前端代码内嵌在后端项目中，写完直接发布，代码形态如下：

```javascript
$('#alert-btn').on('click',function(){
  $('#app .input').val('hi')
})
```

这种开发方式的核心是找到某个元素、进行 DOM 操作。随着前端项目规模逐渐提升，前端需要规模化开发时，这种模式就显得力不从心。

2009 年 AngularJS 和 Node.js 的诞生，宣告了前端工业革命的到来。

### 工业时代：三大框架与 MVVM

AngularJS 的诞生引领了前端 MVVM 模式的潮流；Node.js 的诞生让前端具备了服务端开发能力，也加速了前端工程化的进程。三大框架 Angular、React、Vue 的发展主线均由此展开。

MVVM 是指在前端场景下，把 Controller 变成 View-Model 层，作为 Model 和 View 的桥梁，Model 数据层和 View 视图层交给 View-Model 来同步。

## 前端三大框架的数据更新方案

在 MVVM 模式下，各框架的目标一致：利用数据驱动页面。但如何处理数据的变化，各框架走出了不同的路线。这些框架要回答的核心问题是：数据发生变化后，如何通知页面更新。

**Angular 1 的脏检查**。脏检查指的是 Angular 1 在数据变化的检查上，遵循每次用户交互时都检查一次数据是否变化、有变化就更新 DOM 的方法。这个方法看似简单粗暴，但属于数据驱动页面的早期实现，一经推出就迅速占领了 MVVM 市场。后来 Angular 团队完全抛弃 Angular 1，推出了引入 TypeScript、RxJS 等新内容的全新框架。这些设计虽然优秀，但不支持向前兼容、抛弃了老用户，这也是 Angular 在国内没有大面积推广的原因之一。

**Vue 1 的响应式**。初始化时 Watcher 监听了数据的每个属性，数据发生变化时就能精确地知道哪个 key 变了，从而针对性地修改对应的 DOM。这一过程可以按如下方式解构：

![image-20240426161041357](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202404261610408.png)

上图中左边是实际的网页内容，网页中使用 `{{}}` 渲染一个变量时，Vue 1 会在内部保存一个监听器监控这个变量，称为 Watcher。数据有变化时，Watcher 会收到通知并更新网页。

通俗类比：如果把网页数据看成被管理的员工，普通数据就是每次都需要主动找到并下达指令的人；响应式数据则是本身有任何变化都会主动发日报的员工。

**React 的虚拟 DOM**。Facebook 的 React 团队提出了不同于 Angular、Vue 的方案：页面初始化时，在浏览器 DOM 之上建立一个虚拟 DOM，即用一个 JavaScript 对象来描述整个 DOM 树，通过虚拟 DOM 计算出变化的数据，再进行精确修改。

```html
<div id="app">
  <p class="item">Item1</p>
  <div class="item">Item2</div>
</div>
```

在 React 中，这段 HTML 会被映射成一个 JavaScript 对象进行描述。这个对象相当于数据和实际 DOM 之间的缓存层，通过管理这个对象的变化来减少对实际 DOM 的操作。这种形式不仅保障了性能，还提供了用 JSON 描述网页的工具，并让虚拟 DOM 技术脱离了 Web 的限制，因此虚拟 DOM 在小程序、客户端等跨端领域大放异彩。

虚拟 DOM 在运行时就是这样一个对象：

```json
{
  tag: "div",
  attrs: {
    id: "app"
  },
  children: [
    {
      tag: "p",
      attrs: { className: "item" },
      children: ["Item1"]
    },
    {
      tag: "div",
      attrs: { className: "item" },
      children: ["Item2"]
    }
  ]
}
```

这个对象完整地描述了 DOM 的树形结构。数据变化时，先生成一份新的虚拟 DOM 数据，再与之前的虚拟 DOM 进行对比计算，得出需要修改的 DOM，最后到页面执行操作。浏览器操作 DOM 一直是性能瓶颈，而虚拟 DOM 的 Diff 逻辑能确保尽可能少地操作 DOM，这是虚拟 DOM 驱动的框架性能表现优秀的原因之一。

## 性能瓶颈与框架演进

Vue 和 React 的方案都解决了"数据变化后如何通知页面更新"的问题，并获得了很高的占有率，但二者都碰到了性能瓶颈：

- 对 Vue 来说，核心是"响应式"，即数据变化后主动通知。响应式数据需要新建 Watcher 监听，本身有性能损耗，项目变大后每个数据都挂一个 Watcher 会影响性能
- 对 React 的虚拟 DOM Diff 计算逻辑来说，如果虚拟 DOM 树过于庞大，使得计算时间超过 16.6ms，就可能造成性能卡顿

为解决这一瓶颈，Vue 和 React 走上了不同的道路。

React 借鉴操作系统时间分片的概念，引入 Fiber 架构：把整个虚拟 DOM 树微观化成链表，利用浏览器的空闲时间计算 Diff；一旦浏览器有更高优先级的任务，可以把未计算完的任务放在一旁，把主线程控制权还给浏览器，等待下次空闲再继续。这种架构虽然没有减少运算量，但巧妙地利用空闲时间分片，解决了卡顿问题。

![image-20240426161122639](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202404261611686.png)

上图中左侧是树形结构，树形结构的 Diff 很难中断；右侧把树形结构改造成了链表，遍历严格按照子元素 -> 兄弟元素 -> 父元素的逻辑进行，Diff 计算过程随时可以中断和恢复。

![image-20240426161224989](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202404261612617.png)

**Vue 1 的问题在于响应式数据过多，会带来内存占用过高的问题，所以 Vue 2 引入虚拟 DOM 来解决响应式数据过多的问题。**

这一方案使用虚拟 DOM 解决了响应式数据过多的内存占用问题，规避了 React 中虚拟 DOM 的性能问题，还通过虚拟 DOM 给 Vue 带来了跨端能力。响应式数据是主动推送变化，虚拟 DOM 是被动计算 Diff，一推一拉、方向相反的两种技术，被 Vue 2 通过组件级别的划分很好地融合在一起：组件之间的变化通过响应式通知更新，组件内部的数据变化通过虚拟 DOM 更新页面。这样响应式的监听器被控制在组件级别，虚拟 DOM 的量级也被控制在组件大小。

## 模板路线：template 与 JSX

除了响应式和虚拟 DOM 的差异，Vue 和 React 在模板书写上也走出了 template 和 JSX 两条路线：

- React 的世界里只有 JSX，最终 JSX 都会在 Compiler 层（工程化环节）编译成 JS 执行，因此 React 拥有全部 JS 的动态性。这也导致 React 的 API 一直很少，只有 state、hooks、Component 几个概念，其余主要是 JavaScript 本身的语法和特性
- Vue 默认使用 template，语法是限定的，例如 v-if 和 v-for 等指令。有了这些写法约束后，框架可以在上线前做很多编译期优化。Vue 3 的一个亮点是在虚拟 DOM 的静态标记上做到极致，让静态部分跳过虚拟 DOM 的计算，真正实现按需更新，显著提高了性能
- 除了 template 和 JSX，还出现了 Svelte 这类没有虚拟 DOM 的框架，直接把模板编译成原生 DOM，几乎没有 Runtime，所有逻辑都在 Compiler 层优化，是另一种极致路线

## Vue 的 MVVM 模型

在了解前端框架的发展历程和 Vue 的设计理念后，可以进一步理解 Vue 所采用的 MVVM 设计模式。

### MVC 模式

MVVM 模式是在 MVC 模式基础上演变而来的，后端经典的 MVC 模式如下：

![img](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202412092235933.png)

最早的 MVC 设计模式出现在后端开发中，主要目的是让视图层与数据层分离、职责更清晰、便于开发，典型代表如 Spring MVC。

随着 Ajax 技术的流行，前后端分离开发越来越普遍，前端需要处理复杂的视图与数据，急需一种设计模式进行分层处理，MVC 设计模式由此进入前端领域。

早期经典的前端 MVC 框架是 backbone.js。由于前后端差异较大，backbone.js 对传统 MVC 做了一些改良：

![img](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202412092235718.png)

backbone.js 存在的问题：

- 数据流混乱，尤其是多视图多数据场景下
- 控制层单薄，可有可无

### MVVM 模式

2009 年 Angular.js 横空出世，带来了全新的 MVVM 设计模式：除了 M 和 V 层以外，新增了 VM 层，即 ViewModel 层。

**MVVM 设计模式的核心思想是不让 Model 和 View 两层直接通信，而是通过 VM 层来连接**：

![img](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202412092235261.png)

MVVM 设计模式相比 MVP 模式的优势：

- ViewModel 能够观察到数据的变化，并对视图对应的内容进行自动更新
- ViewModel 能够监听到视图的变化，并能够通知数据发生变化

最早提出 MVVM 模式的是 Angular.js，但把 MVVM 设计模式发扬光大的是 Vue，Vue 也成为了当下最主流的前端框架之一：

![img](https://zhangzhengyang.oss-cn-beijing.aliyuncs.com/images/202412092236236.png)

**Vue 官网的表述：虽然没有完全遵循 MVVM 模型，但是 Vue 的设计也受到了它的启发。因此在文档中经常会使用 vm (ViewModel 的缩写) 这个变量名表示组件实例**。

**MVVM 模型中 M 和 V 不能直接操作，需要 VM 层加持。但 Vue 比较灵活，可以直接操作原生 DOM，也就是直接操作 V 层**。这主要依赖 Vue 中的 ref API：

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta http-equiv="X-UA-Compatible" content="IE=edge">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    <script src="/vue.global.js"></script>
  </head>
  <body>
    <div id="app">
      {{ message }}
      <input type="text" v-model="message">   <!-- View -->
    </div>
    <script>
      let app = Vue.createApp({
        data() {
          return {
            message: 'hello world'  /*  Model */
          }
        }
      })

      let vm = app.mount('#app')
    </script>
  </body>
</html>
```

## 小结

- 前端框架经历了后端模板渲染、Ajax、jQuery DOM 操作到三大框架的演进，驱动力始终是"用数据驱动页面"这一目标
- 三大框架对"数据变化后如何通知页面更新"给出了不同答案：Angular 1 的脏检查、Vue 的响应式推送、React 的虚拟 DOM 拉取
- Vue 2 用组件级虚拟 DOM 融合了响应式推送与 Diff 计算，兼顾内存占用与更新精度；React 用 Fiber 架构以时间分片缓解大树的 Diff 卡顿
- 模板路线上，React 选择动态性最强的 JSX，Vue 选择约束更强、便于编译期优化的 template，Svelte 则代表编译时直接产出原生 DOM 的第三条路线
- Vue 采用受 MVVM 启发的架构，文档惯例用 `vm` 表示组件实例，同时保留 `ref` 直接操作 V 层的灵活性

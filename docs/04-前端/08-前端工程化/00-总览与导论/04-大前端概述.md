# 大前端概述

## 如今前端行业现状

- 企业对复合型人才的需求在增加，内耗严重
- 入门门槛低，知识易获取筛选难，没有大项目来提升
- 技术更迭太快，学习不成体系，缺乏指引

### 行业内卷严重

顺应时代，变换角度思考，调整心态

寻找差异，做出特色、亮点，精准拔高

跳出舒适圈，创新赛道、弯道超车

### 前端行业破解内卷

1. 学习 Node.js 等后端 + 运维的知识，扩展自己的视野 + 应用面
2. 除了业务流程、还懂自动化 + 跨端 App 的开发
3. 了解设计、需求、熟悉业务及技术选型

### 痛点问题

技术单一、深度不够、3-5年 还在原地踏步

- Xmind 思维导图，整理知识点
- 不定期的回顾 + 实战，总结笔记、与人分享
- 通过复杂业务进行综合的应用

技术层出不穷，学不完，不知怎么学

- 明白新技术的应用场景
- 明白新技术的优势与缺点（兼容性）
- 小范围尝试 + 论证，最后才是全面铺开

缺乏大型项目全流程开发的机会

## 课程目标

能够解决实际业务问题，带动思考 + 提升动手能力

能够在工作中应用高效的工具，提升工程化质量、团队效率

建立完整的前端全栈知识体系，助力后续全面提升

## 一体化项目

- 全端全平台围绕同一业务场景进行展开
- 企业项目全流程 + 复杂大型项目全端打通
- 主流技术，非简单的技术堆砌，前后衔接紧密

## 项目需求分析

项目全局思维，需求分析重难点

案例项目需求分析，业务拆解、功能拆解

需求分析的工具及使用场景

### 需求分析痛点

- 不想就做
- 照单全收
- 未沟通/确认
- 放羊式管理

### 需求分析的难点

- 除了考虑功能实现，还要考虑时间/成本
- 形成需求文档，用户回馈确认
- 引导用户的需求，创造用户需求

### 需求分析组成部分

- 业务需求
- 用户需求
- 项目需求

## 需求变更

### 客户需求变更

1. 考虑需求是否合理
2. 是否是项目范围内的变更，对主体业务是否有影响
3. 明确需求变更的流程，确定需求变更

### 产品经理需求变更

1. 沟通是王道
2. 会哭有奶吃
3. 引导需求
4. 自我挑战

## 技术栈选择

- 团队技术实力与业务需求结合
- 能够复用，坚决不造轮子；需要造轮子，坚决不牵强
- 怎么简单怎么来，多考虑时间、进度、质量因素

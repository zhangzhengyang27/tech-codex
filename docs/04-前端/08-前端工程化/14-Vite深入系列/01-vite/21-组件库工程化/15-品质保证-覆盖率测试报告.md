# 品质保证-覆盖率测试报告

## 概念说明

自动化测试工具可以自动验证代码的正确性，但如果只有部分代码经过了测试，或者只是简单地跑通了代码，测试结果并不能说明代码合格。例如组件库只测试一部分组件，或者每个组件只测试了默认设置——按钮中某个属性、或某几个属性间的排列组合没有得到测试，这样的测试无法保证组件库功能完全正确。

客观评价测试完备程度的度量指标就是**代码覆盖率**。在挑选项目时，有经验的使用者都会根据代码覆盖率来确定代码的可靠性。

## 核心要点

- 代码覆盖率描述测试过程中（运行时）被执行的源代码占全部源代码的比例。
- 软件工程理论将覆盖率分为语句覆盖、判定覆盖、条件覆盖等多个层级，覆盖深度越高验证越全面，但实施成本也越高。
- JavaScript 实践中通常采用四级覆盖：函数覆盖、行覆盖、语句覆盖、分支覆盖。
- JavaScript 生态的覆盖率报告通常由 Istanbul 生成，Jest 与 Vitest 底层都使用它，原理是编译期代码插桩。
- 覆盖率报告的完整工程化链路：本地生成报告 → CI 自动生成并上传 → Codecov 平台展示 → 输出动态徽章。
- ⚠️ 常见误区：只做行级覆盖。两个 Case 跑完所有语句，仍可能没有验证到全部条件组合。
- ⚠️ 常见误区：一味追求高覆盖率。品质、进度、成本需要均衡，覆盖率应客观看待。

## 覆盖率指标

### 行级覆盖的局限

只是简单地做到行级覆盖远远不够，以下例说明：

```JavaScript
function getName(a, b) {
    if(a && b) {
        return 'Jane'
    }else {
        return 'Tony'
    }
}
```

以上代码只需要两个 Case，就可以将所有语句都跑一遍：

- Case01: a = true ; b = true;  期待：Jane

- Case02: a =false ; b= true;  期待：Tony

但是，这样测试甚至不能确定代码中 b 是否参与条件判断。下面这段代码也会出现相同的结果：

```JavaScript
function getName(a, b) {
    if(a) {
        return 'Jane'
    }else {
        return 'Tony'
    }
}
```

所以仅有行级覆盖远远不够。

### 软件工程理论中的覆盖率分级

软件工程理论中会把覆盖率分为：

- 语句覆盖（statement coverage）

- 判定覆盖（decision coverage）

- 条件覆盖（condition coverage）

- 条件判定组合覆盖（condition decision coverage）

- 路径覆盖（path coverage）

- 多条件覆盖（multi-condition coverage）

- 修正条件判定覆盖（modified condition / decision coverage）

覆盖深度的提高会让代码功能验证更加全面，但相应的实施成本也会明显提高。理论指标虽然全面，但很多指标在实际生产中的指导价值并不大，因此实际生产中会进行简化。

### JavaScript 的四级覆盖

在 JavaScript 语言中，代码覆盖率通常会分为四级：

- Function coverage 函数覆盖 - 每个函数是否被执行；

- Line coverage  行覆盖 -- 每行是否被执行；

- Statement coverage 语句覆盖 - 每个语句是否被执行；

- Branch coverage 分支覆盖 - 每个 if 节点是否都被执行。

这是结合了函数式语言的特点和指标的实用程度的经验总结，也是 JavaScript 世界比较受认可的标准。

## Istanbul 覆盖率工具

代码覆盖率需要专用工具生成。JavaScript 程序中的代码覆盖率通常都通过 Istanbul 生成。Istanbul 名称的来历是伊斯坦布尔的地毯：覆盖率报告用颜色表示代码的运行情况，好像给代码铺上了地毯。

Jest 以及组件库使用的 Vitest 测试框架，底层都使用 Istanbul。Istanbul 的实现原理是**编译期代码插桩**。原理细节可参考：

[覆盖率原理介绍](http://www.alloyteam.com/2019/07/13481/)

## 生成覆盖率报告

在 Vitest 中只需在命令行添加参数 `--coverage` 即可生成覆盖率报告。

package.json

```json
"scripts": {
    "coverage": "vitest run --coverage"
  },
```

默认报告形式是一个静态网站。

如需进一步调整，可以在 vite.config.ts 中配置：

```TypeScript
test: {
    coverage: {
      provider: "istanbul", // or 'c8',
      reporter: ["text", "json", "html"],
    },
  },
```

常用的两项调整：

- 指定覆盖率引擎 istanbul；

- 指定输出格式。默认没有 json 格式，而 json 与后续的覆盖率展示（Codecov）有关，务必要加。

## 公布覆盖率报告

覆盖率报告放在本地只能为自己的单元测试提供依据，更大的用途是公布展示出来供使用者查看。常用覆盖率展示平台有 Codecov 和 Coveralls。

Codecov 是一个开源的测试结果展示平台，将测试结果可视化。Github 上许多开源项目都使用 Codecov 展示单测结果。Codecov 与 Travis CI 一样支持 Github 账号登录，并同步 Github 中的项目，还会自动生成徽章。徽章会根据报告结果动态变化，属于客观的第三方数据，具有公信力。

配置步骤：

1. 登录 [Codecov 网站](https://codecov.io/)。
2. **一定要使用 Github 账号登录**，这样平台可以直接读取 Github 中的项目。
3. 添加访问授权。如果项目在名下组织下，也需要对组织进行访问授权。
4. 在网站上找到所有 Github 中的项目，选择 【Not yet setup 】，点击需要展示覆盖率报告的项目后的【 setup repo】链接，即可看到安装指南。
5. 安装指南针对所有语言项目，前端场景只需要从中获取**上传 Token**。

## 持续集成自动更新覆盖率报告

覆盖率报告最好能随最新版本自动更新，而不是手动上传，因此需要引入 CI 工具，编写一个 Action：

.github/workflows/codecov.yml

```YAML
# .github/workflows/main.yml
# This is a basic workflow to help you get started with Actions

name: Code Coverage

# Controls when the action will run. Triggers the workflow on push or pull request
# events but only for the master branch
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

# A workflow run is made up of one or more jobs that can run sequentially or in parallel
jobs:
  CodeCov:
    # The type of runner that the job will run on
    runs-on: ubuntu-latest
    # Steps represent a sequence of tasks that will be executed as part of the job
    steps:
      - uses: actions/checkout@v2
      - uses: pnpm/action-setup@v2.1.0
        with:
          version: 7.2.1
      - name: Install modules
        run: pnpm install
      - name: Run Test Coverage
        run: cd packages/smarty-ui-vite && pnpm coverage
      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v3
        with:
          directory: packages/smarty-ui-vite/coverage
          token: ${{ secrets.CODECOV_TOKEN }}
```

工作流要点：

- 触发条件：push 与 pull request 到 main 分支。
- 先安装依赖并执行 `pnpm coverage` 生成覆盖率报告。
- 上传环节使用现成的 codecov Action，需要传入 Token——把 Codecov 安装指南中得到的 Token 放入仓库的 Secrets 中。
- 提交代码后即可自动生成覆盖率报告。

Codecov Action 会自动识别语言与测试框架的覆盖率报告种类并上传相应数据。对 Vitest 而言，上传的是 json 格式的报告，因此需要确认确实生成了 json 报告（配置方式见上文 reporter 一节）。

## 添加覆盖率徽章

Codecov 网站可以将测试结果生成为徽章，徽章可直接放到 Github 中展示。在项目的【 Settings 】中可以找到对应的徽章。

## 小结

覆盖率是评价项目品质的客观指标：行级覆盖不足以验证条件逻辑，JavaScript 实践中采用函数、行、语句、分支四级覆盖标准。工程化落地路径为——Vitest 通过 `--coverage` 参数配合 `coverage.provider/reporter` 配置生成报告（Codecov 需要 json 格式），Github Action 在 push/PR 时自动执行覆盖率测试并通过 codecov Action 携 Token 上传，最终在 Codecov 平台可视化并输出动态徽章。同时需要注意覆盖率并非越高越好，品质、进度、成本三者需均衡。

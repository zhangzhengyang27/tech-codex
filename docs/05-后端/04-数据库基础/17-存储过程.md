# 存储过程

存储过程（Stored Procedure）是**预编译并存储在数据库中的一组 SQL 语句**，像一个"数据库端的函数"，可以被反复调用。它能封装复杂业务逻辑、提升性能（预编译）、降低网络开销。本文讲解存储过程的基础概念、语法骨架与工程权衡。

> **本文定位（分工卡）**：本文是 **通用 SQL 基础视角**的存储过程讲解——聚焦"是什么、为什么、怎么权衡"。MySQL 视角的完整语法与实战（全部流程控制语句示例、information_schema 管理、批量/分页实战案例、命名与注释规范）见《[SQL-存储过程](../01-MySQL/05-SQL与实战/05-SQL-存储过程.md)》；游标的专门展开见《[SQL-游标](../01-MySQL/05-SQL与实战/06-SQL-游标.md)》。

## 为什么需要存储过程

| 优势 | 说明 |
|------|------|
| 减少网络往返 | 多条 SQL 打包成一次调用 |
| 预编译优化 | 首次编译后复用执行计划 |
| 封装复用 | 复杂逻辑集中管理 |
| 权限控制 | 只暴露存储过程，不开放表级权限 |
| 业务一致性 | 事务在存储过程内保证 |

**劣势**：与代码逻辑耦合、跨库迁移成本高、调试困难、难以版本管理。所以**互联网应用常把复杂逻辑放应用层**，存储过程多用于数据完整性约束、批量任务、报表等场景。

## 创建、调用与删除

### 基本语法与 DELIMITER

MySQL 默认用 `;` 作为语句结束符，但过程体内部也有 `;`，所以创建前临时把结束符改成 `//`：

```sql
DELIMITER //

CREATE PROCEDURE sp_get_all_heros()
BEGIN
    SELECT id, name, hp_max FROM heros;
END //

DELIMITER ;
```

> **说明**：Navicat 等图形工具会自动处理定界符，MySQL 命令行需要手动设置。

### 调用、查看与删除

```sql
-- 调用
CALL sp_get_all_heros();

-- 查看已定义的过程
SHOW PROCEDURE STATUS WHERE Db = '数据库名';

-- 查看过程定义
SHOW CREATE PROCEDURE sp_get_all_heros;

-- 删除
DROP PROCEDURE IF EXISTS sp_get_all_heros;
```

> **注意**：`ALTER PROCEDURE` 只能修改过程特征（如注释），不能修改过程体；改过程体需删除后重建。

## 参数：IN / OUT / INOUT

| 参数类型 | 方向 | 说明 |
|---------|------|------|
| `IN`（默认） | 传入 | 调用时传入；过程内可修改其值，但修改不会影响调用方 |
| `OUT` | 传出 | 过程把结果赋给它，调用方接收 |
| `INOUT` | 双向 | 既传值又取值 |

```sql
-- 根据定位统计英雄数量，通过 OUT 返回
DELIMITER //
CREATE PROCEDURE sp_count_by_role(
    IN p_role VARCHAR(20),
    OUT p_count INT
)
BEGIN
    SELECT COUNT(*) INTO p_count
    FROM heros WHERE role_main = p_role;
END //
DELIMITER ;

-- 调用
CALL sp_count_by_role('战士', @cnt);
SELECT @cnt;   -- 取出 OUT 参数值
```

**两点工程提醒**：

- 参数名不要与表字段同名——`WHERE role_main = role_main` 会被解析成"列与列比较"，恒为 TRUE，返回全表数据；
- 局部变量用 `DECLARE` 声明（`SET` / `SELECT ... INTO` 赋值），以 `@` 开头的是会话级用户变量，不依赖存储过程存在。

## 流程控制一览

存储过程过程语言能力由"变量 + 分支 + 循环 + 游标 + 处理器"构成，语法骨架如下：

| 结构 | 语法 | 用途 |
|------|------|------|
| 分支 | `IF ... THEN ... ELSEIF ... ELSE ... END IF` | 条件判断 |
| 分支 | `CASE ... WHEN ... END CASE` | 多值匹配 |
| 循环 | `WHILE ... DO ... END WHILE` | 先判断后执行 |
| 循环 | `REPEAT ... UNTIL ... END REPEAT` | 先执行后判断 |
| 循环 | `label: LOOP ... LEAVE label ... END LOOP` | 需手动退出的循环 |
| 跳过 | `ITERATE label` | 类似 continue，跳过本次 |

完整的逐个示例（成绩分级 IF/CASE、累加求和 WHILE/REPEAT/LOOP、ITERATE 跳奇数）见《[SQL-存储过程](../01-MySQL/05-SQL与实战/05-SQL-存储过程.md)》流程控制一节。

## 错误处理（条件处理器）

用 `DECLARE ... HANDLER` 捕获异常，避免事务中断后无人回滚：

| 处理器 | 触发时机 |
|--------|---------|
| `CONTINUE HANDLER` | 出错后继续执行后续语句 |
| `EXIT HANDLER` | 出错后终止过程 |

典型用法是配合事务：`DECLARE EXIT HANDLER FOR SQLEXCEPTION` 中先 `ROLLBACK` 再返回失败信息。完整的"转账 + 错误回滚"示例见《[SQL-存储过程](../01-MySQL/05-SQL与实战/05-SQL-存储过程.md)》错误处理一节。

## 游标（CURSOR）

游标用于**逐行遍历查询结果集**，存储过程里处理多行数据时使用。使用遵循四步：

```text
DECLARE（声明游标，绑定查询）→ OPEN（打开）→ FETCH（逐行取数据）→ CLOSE（关闭）
```

必须声明 `CONTINUE HANDLER FOR NOT FOUND` 处理器，否则遍历到最后一行后会报错。游标的三种循环写法、实战案例（条件更新、数据迁移、排名计算）与性能优化建议，见《[SQL-游标](../01-MySQL/05-SQL与实战/06-SQL-游标.md)》。

## 存储过程 vs 函数 vs 触发器

| 特性 | 存储过程 | 函数 | 触发器 |
|------|---------|------|--------|
| 返回值 | 可无（OUT 参数） | 必须有返回 | 无 |
| 调用方式 | `CALL` | 表达式/`SELECT` 中 | 事件自动触发 |
| 能否被 SELECT 用 | 不能 | 能 | 不能 |
| 事务 | 支持 | 有限 | 支持 |
| 用途 | 复杂业务/批量 | 计算返回单值 | 数据变更后自动处理 |

## 最佳实践

1. **参数校验**：入口校验输入合法性，避免非法数据进入；
2. **结合事务**：多步写操作包 `START TRANSACTION`，配错误处理器回滚；
3. **控制复杂度**：过长的存储过程难以维护，拆分成多个；
4. **注意迁移成本**：存储过程依赖特定数据库方言，跨库（MySQL→PG/Oracle）需重写；
5. **应用层优先**：互联网场景优先把业务逻辑放应用层，存储过程用于事务强约束、批处理、报表。

## 总结

存储过程 = 预编译的 SQL 集合，封装复杂逻辑、减少网络往返；参数 `IN`（入）/`OUT`（出）/`INOUT`（双向）控制数据方向；变量、流程控制、游标、条件处理器构成其过程语言能力。MySQL 需用 `DELIMITER` 修改结束符以创建多语句过程。工程上的核心权衡是：复杂逻辑优先应用层，存储过程用于事务强约束、批处理与报表场景——完整语法与实战案例见 MySQL 专题《[SQL-存储过程](../01-MySQL/05-SQL与实战/05-SQL-存储过程.md)》。

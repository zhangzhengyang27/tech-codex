# 结束语 抓住本质，是成为技术专家的不二法则

## 系列内容回顾

本篇为系列的结束语。系列首先从目的性的角度对后台系统的架构进行了归类，分为读、写和扣减三大类，这也是后续内容详细介绍的主线；最后对微服务的共性问题，比如 SDK 设计、依赖的治理、监控、重构升级等一一进行了讨论。经过这段时间的投入和学习，应对这些问题能够产生新的理解。

如果对某块内容还不太明白，建议有空再复习一次，以便加深理解，进一步增强后端架构技能。

除了系列讲解的后端通用架构技能之外，还有三个观点值得分享，希望能够在成为架构师的道路上助一臂之力。

## 建议一：抽象是抓住本质的最佳手段

在编写本系列之前，作者已将近年来参加和主动学习的各类型的后台系统解决方案进行了抽象总结，并从系统的目的性出发，将整个后台系统分成了三大类：读、写和扣减类。此后，遇到各种类型的业务需求时，先进行归类，再判断实现时具体属于哪一类型的系统。完成归类后，就可以直接复用已经整理过的三大类后台系统的最佳实践，极大地提升系统设计的效率。

**上述介绍的，将各种类型的后台系统进行归类的过程，就是架构抽象**。抽象有几个好处。

**首先，抽象是指将同一类系统进行集中研究并寻找其中规律的过程。** 假设第一次接触扣减类的业务需求时，它可能是用户每天可以登录公司某一个内部网站的次数限制。因为是内部站点，访问量和并发量很小，使用纯数据库即可满足。

但若借助这一次需求的机会，去研究所有扣减类的业务（如支付扣减、库存扣减等）需求的特点，以及如何实现扣减，并进行总结、对比形成一套套路，那么正走在成为扣减类系统架构专家的道路上。

**其次，当下一次再遇到其他披着各种业务场景外皮、但底层技术实现都是扣减的需求时，便可以轻松应对，提升效率。**

**此外，抽象在技术学习中也发挥了重要的作用。** 以 Java 的数据库 API 为例：在 Java 中，只需要将不同类型的数据库的驱动加入代码工程，就可以直接使用 JDK 中定义的标准 API 连接各种不同类型的数据库了，无需任何配置。比如将 MySQL 的驱动实现放到代码中，就可以直接使用标准 API 访问 MySQL 数据库了。

在不断寻找资料和阅读源码之后，可以了解到这叫 **SPI 技术**：它是需求方只定义标准接口并基于标准协议便可以自动选择三方实现进行装载的技术，而第三方的实现主要基于标准接口和协议进行实现，比如 MySQL 版、Oracle 版。

这种从 Java 自动装配数据库驱动出发，去寻找底层原理为 SPI 的方式，就是使用抽象化的方法寻找本质的过程。Spring Boot 的自动装配就是 SPI 的另一种实现，理解了 SPI 之后，学习它就变得非常简单。

从上面的经验可以看到：**理解了一项技术背后的本质，再遇到这项技术的变种场景时，很容易就能理解它，从而在技术上事半功倍**。

## 建议二：刻意练习才能形成肌肉记忆

在回顾系列内容时，如果不能随着潜意识说出大纲分类，以及每种类型的系统在实现时的技术要求和架构思路，说明对内容还没有形成肌肉记忆。

一项技能形成肌肉记忆才会真正成为自己的能力。面对一个需求评审或者面试时，能够很清晰、快速地输出对应的解决方案，而不是磕磕碰碰、努力地回想，无法真正解决问题或者说服面试官。

将一项技术或者技能形成肌肉记忆，最好的方式就是刻意练习。相关方法可以参考畅销书《刻意练习》。

以学习打篮球为案例：很多一起学习打篮球的同学，后来的篮球技术已经远远超出普通水平。产生这个差异的原因是：一些人在学会打篮球的基本技巧（如基本的投篮和运球）之后，就消耗大量的时间去进行娱乐赛；而另一些人学习了基本的投篮和运球技巧之后，还会努力去思考怎样把投篮姿势纠正得更好，如何让运球的手法变得更有熟练度，变得像 NBA 球星那样。后者在不断地刻意练习提升篮球技能，前者则在低水平线的篮球技巧上不断重复，没有进步。

学习也是一样。系列提供的技术和技巧，能够帮助在后台开发中解决一部分问题，但并不能就此止步。因为定位和篇幅的原因，还有更多技术值得深挖：

- Redis 为什么那么快？
- 还有哪些使用顺序写比随机更改快这一特点来解决问题的业务场景？
- MySQL 自身的 Binlog 是如何实现低延迟、无丢失的数据同步？
- 各类监控系统如何处理海量的监控数据？

这些待研究的问题都需要刻意练习，或者说需要钻牛角尖，搞明白其中涉及的所有技术点并不断地挖掘背后的本质。做到这一点，离成为一个真正的技术大牛就不远了。

## 建议三：不设限，广泛汲取，增加自己的护城河

在坚持上述两点建议后，在不久的将来就有机会成为技术大佬。

但不建议止步于此，因为现在这个社会需要的是"T"型人才，只有一项技能并不能无往不利。"T"这个字母由一横和一竖组成：这一竖，表示要有一项或多项非常专业的技能；这一横，代表要有很宽的知识面，综合能力强。

那怎么才能将一横变得越来越长、一竖变得越来越厚呢？

答案是：保持一颗好奇心、积极的心态，广泛地去涉猎。当遇到自己不懂的技术或业务领域时，不要产生抵触心理，而是积极地去了解它。比如说当前主要从事后端开发的工作，但当有机会接触大数据、前端、数据挖掘、终端等领域的时候，也能够先进行抽象、发现新领域的技术本质，再进行刻意练习。坚持下来，新接触的领域很有可能成为一项新技术专长，成为"T"这个字母中那一竖，或者至少能够拓宽"T"字母的那一横。

## 寄语

保持一颗初心，不断归零。在面对任何新接触的领域时，先去探寻它的本质并不断刻意练习，进而乘风破浪，早日成为所期望的那个人。

最后，感谢一路学完这份系列内容，希望这些关于架构设计的思考能有所帮助。

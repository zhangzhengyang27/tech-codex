## 五、高频追问链(面试官通常这样深挖)

- **CAP 题**:CAP 是什么 → 为什么不能同时保证 → 你的系统选了哪边 → 分区发生时怎么恢复。
- **分布式事务**:2PC 的问题在哪 → TCC 怎么补偿 → 本地消息表为什么可行 → 消息投递了但下游执行失败怎么办。
- **分布式锁**:为什么不用数据库锁 → Redis 锁为什么需要过期时间 → 主从切换导致锁丢失怎么办 → Redlock 的争议。
- **MySQL 索引**:为什么用 B+ 树不用 B 树/Hash → 聚簇索引和二级索引的区别 → 什么是回表、怎么避免。
- **Redis**:为什么快 → 持久化 RDB 和 AOF 怎么选 → 哈希槽怎么分配 → 缓存穿透/雪崩/击穿分别怎么防。
- **高可用**:你的系统可用性多少个 9 → 怎么度量的 → 出过什么故障、怎么复盘的。

## 六、答题模板(适用于所有系统设计题)

1. **澄清需求**:先问清规模(用户量/并发量/数据量)与核心约束,不急着给方案。
2. **给主干**:用一句话给出总体架构(分几层、关键组件、数据流向)。
3. **逐层展开**:按"接入 → 服务 → 存储"或"功能模块"顺序展开,每层给 2~3 个候选与取舍理由。
4. **主动谈可用性与性能**:度量指标是什么,故障了怎么办,流量涨十倍怎么办。
5. **收尾谈演进**:这套设计的边界在哪,业务再长大一步要改什么。

本专题 02 篇给出这套模板的完整推导;19 篇给出它在双十一抢购案例上的完整演练。

## 七、高频问题自查清单

- CAP 能画出来并讲清取舍粒度吗?Paxos 和 Raft 的差别能说一句吗?
- 分布式事务三种方案的适用边界能脱口而出吗?TCC 的 Try 阶段做什么?
- Redis 分布式锁的原子性与续期问题能写出演示代码吗?
- B+ 树为什么三层能扛千万数据?能从页大小推算吗?
- 缓存与数据库的双写一致性有几种方案,各自代价是什么?
- 所做系统的可用性/性能数字,能带着度量口径讲出来吗?
- 千万级流量的拆解,能按"时间与空间"两个维度各说三条吗?
- 高可用与高性能发生冲突时,取舍原则是什么?

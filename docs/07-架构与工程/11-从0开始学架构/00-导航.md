# 从0开始学架构 导航

本专题共 15 篇,主线是**从零基础的演进**:从"架构是什么"出发,经复杂度来源、设计原则与流程,逐维走完高性能、高可用、可扩展,最后以互联网架构全景收尾。本页是专题的权威入口。

## 一、定位声明:本专题是什么、不是什么

- **本专题(11-从0开始学架构)= 从零基础演进**:架构入门第一课,按"概念 → 心法 → 原则 → 流程 → 逐维方案 → 全景"的顺序建立完整框架。
- 它**不是**面试速答手册(见 [10-架构设计面试精讲](../10-架构设计面试精讲/00-导航.md)),也**不是**按维度组织的方案清单(见 [01-整体架构设计](../01-整体架构设计/00-导航.md))或大师课合集(见 [02-架构设计](../02-架构设计/00-导航.md))。
- 使用方式:第一次系统学架构按本专题顺序读;已有经验者可挑 05(复杂度)、07(流程)、11(异地多活)直接补课。

## 七、常见误区与学习提示

- **把"架构 = 画框图"**:01-03 篇强调架构是决策的记录,框图只是结果。
- **跳过复杂度直接背方案**:05 篇的六大来源是全部方案的推导起点,跳过它就只能死记。
- **把合适/简单/演化当成口号**:06 篇给了反例(亿级用户平台失败案),要用它来校准。
- **备选方案只做一个**:07 篇要求 3~5 个差异明显的备选,只有一个等于没设计。
- **高可用只谈冗余**:10-12 篇的推进是"冗余 → 状态决策 → 故障预案",缺一环都立不住。
- **可扩展 = 微服务**:13 篇把分层/SOA/微服务/微内核并列,微服务只是选项之一且陷阱最多。

## 八、常见疑问速答

- 已经有经验了还要按顺序读吗?——不必,直接从 05(复杂度)进入,再按需读 07/10/11/13。
- 本专题与 01 目录内容重复吗?——视角不同:本专题重推导,01 重清单;同主题对照见第五节。
- CAP 三选二是不是说只能丢一样?——不是,10 篇讲清了 P 必然存在时 C 与 A 的取舍粒度。
- 接口级故障四手段先上哪个?——12 篇给的顺序是先排队限流保住系统,再谈降级与熔断。
- 零基础一次能读完吗?——能,15 篇约一周一阶段、五周读完;每阶段用第四节的自检问题验收。
- 需要配代码实验吗?——建议配合:08/09 篇可用 Redis+MySQL 搭最小实验,10/11 篇可用两台虚拟机演练主从切换。

## 十一、每篇一句话精华

1. 架构是决策的记录,先分清模块、组件、框架,再用 4R 给定义。
2. 三大心法(抽象·分解·组合)贯穿软件史,危机倒逼范式进化。
3. 好抽象可组合,分解看粒度,组合有涌现——心法要循环用。
4. 架构设计只为一事:解决复杂度;评判先看 KISS 与正交性。
5. 高性能/高可用/可扩展/低成本/安全/规模,六源定主次。
6. 合适优先于简单,简单优先于演化;开闭原则管接口。
7. 四步流程:识别复杂度 → 3~5 备选 → 360 度环评 → 详细设计。
8. 存储高性能三板斧:读写分离、分库分表、缓存与 NoSQL。
9. 计算高性能两条线:单机并发模型 + 集群负载均衡。
10. CAP 落到细节才算懂;FMEA 把可用性变成可分析的对象。
11. 异地多活从业务分级开始,100% 多活不存在。
12. 接口级故障四手段:降级、熔断、限流、排队。
13. 可扩展一个字"拆":分层、SOA、微服务、微内核各有代价。
14. 五层模板看全景,重构三式:有的放矢、合纵连横、运筹帷幄。
15. 开源"选·用·改",技术演进靠判断:适者生存、旁敲侧击、未来已来。

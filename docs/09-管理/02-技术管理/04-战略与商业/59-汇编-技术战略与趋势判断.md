# 汇编 | 技术战略与趋势判断

技术战略的底色是判断力：架构师在有限资源与无上限需求之间做折中，管理者在浪潮起伏中抓住"不变的目的"，决策者对新技术既不神化也不轻视。本篇汇编七位嘉宾关于架构、技术生态、云计算、AI 与产业互联网的趋势判断与决策心法。

## 谭待：架构的本质是折中

原篇：《大咖对话-谭待：架构的本质是折中》（嘉宾时任百度搜索首席架构师兼区块链实验室主任，两获百度最高奖）

- **核心命题。** "架构的本质是折中，作为架构师，你拥有的是有限的资源，但你面对的是没有上限的需求……你不可能做出一个完美的解决方案，必然要牺牲一些东西来达成另一些需求。"
- **技术要结合业务步调。** "很多技术人在执行过程中，会不自觉的追求最前沿的技术……最终导致两者脱节。"他 2007 年参与的百度云计算项目"有最优秀的团队和公司支持，但最终失败了。最大原因是它没有吻合产品的发展步调"。
- **预判未来 3 年。** "在百度，设计系统的时候一般会去看业务三年以后的情况，这样做出来的系统至少在三年内能比较好的支撑业务发展。"
- **折中不是平庸，而是找到关键点。** "折中不是平庸，而是为了更好的在某些关键点上突出，为此可以在别的地方做出牺牲。"以斯坦门茨画线16圈的典故作结："作为架构师，你一定要成为那个划线的人。"
- **空间换时间的智慧。** 极速搜索项目的做法"不是看哪个地方慢就优化哪个地方，而是系统提前预测用户的搜索目标并实时抓取……基本可以把搜索请求时间缩短至原来的 10%"——代价是消耗更多资源。
- **管理者要克制对技术细节的干预。** "作为业务管理者，需要主动克制自己对技术的感觉，不要过多的参与到一些非常细节的技术讨论和判断中……需要将更多时间和精力分配到整体业务和战略上。"

## 杨晓峰：不可替代的 Java——生态与程序员是两道护城河

原篇：《大咖对话-不可替代的Java：生态与程序员是两道护城河》（嘉宾为 Java 核心类库北京团队 leader、首席工程师）

- **Java 的核心竞争力在生态与程序员。** "Java最大的核心竞争力来源于全球超过1200万的 Java 程序员，庞大的Java生态，海量的类库、工具、产品构建的无所不能的竞争力。""很多问题不是靠语言本身能解决的，而是要靠语言衍生出的各种类库和工具，因此，选择了Java 就相当于选择了一个最可靠的一站式解决平台。"
- **版本升级的前提是生态就绪。** "选择升级Java的前提是所有主要开源类库、软件、第三方厂商产品都已经支持了新版本。除此之外，还得考虑新版本中有什么特性是自己必须的，还有安全、性能等不同角度的考量。"
- **最大挑战来自计算模式而非语言。** "Java面临的最大的挑战并不在于外部语言的冲击，而是计算模式和场景的变化"——云计算时代需要快速启动、高数据密度、短时运行的工作负载；Java 正通过 Amber（开发效率）、Valhalla（数据处理）、Panama（本地交互）、Loom（并发协程）持续演进，同时"积极做瘦身，去掉一些已经退出历史舞台的技术"。
- **技术 Leader 的职责定位。** "Leader和manager是不同的……一方面思考更多的是团队未来的技术路线图……另一方面要让团队有士气、让团队出成果。""如果leader对目标的理解有偏差，很可能团队辛辛苦苦做事，最后却得不到认可，这是很伤士气的。"
- **质量优先原则。** "对Java来说，质量是首先要保证的，对质量的要求会远远高于对数量和对速度的要求……因为Java是一个非常基础的平台，一旦它出了问题，就会波及在它之上的所有工具、产品、厂商。"但"对于创业期的产品来说，可能会以一些可接受的质量代价来换取速度"。
- **用小里程碑维持士气。** "不能把目标设定的太大，即使是一个大的目标，最好也采用迭代的方式，把它拆分成一个一个小的可验证的里程碑……团队能一直看到成果，了解自己所做事情的价值。"

## 玉攻：四个维度看小程序与 App 的区别

原篇：《大咖对话-玉攻：四个维度看小程序与App的区别》（嘉宾时任蚂蚁金服资深技术专家）

- **小程序不会取代 App。** "从用户的角度来看，在一些高频的使用场景，App 的地位从不曾被动摇。一般情况下，用户每天打开使用频率最高的 App 不会超过 10 个。只有一些低频使用的 App 非常适合小程序实现。""大厂会并行走两条路，App 负责高频场景，小程序负责拉新试错。"
- **创业公司建议从小程序做起。** "一开始就做 App 的成本非常高，但是先开发小程序，就可以用最低的成本去验证业务的创新性和市场接受度。"
- **爆款背后是缺乏持续运营。** "很多人并没有搞懂小程序的持续迭代，不清楚小程序需要与场景深度结合……很多开发者还没有意识到小程序与 App 的区别，只是简单地将 App 现有功能移植到小程序上……这就解释了为什么有的人开发的 App 活跃度还不错，但转战到小程序却满盘皆输的原因。"
- **技术演进三阶段：Cloud-Based → Cloud-Ready → Cloud-Native。** IaaS 解决资源云化，PaaS"让应用变得更舒服一点"，而 Serverless 阶段"你已经不关心服务器这件事情了……你真正需要关注的只是你的应用和你的业务逻辑"。
- **多端统一与生态开放。** "整个阿里经济体在做小程序的时候，强调统一的技术架构和多端投放，我并不希望小程序变成巨头进行技术垄断的手段……开发支付宝小程序，表面上获得的是支付宝的渠道优势，其实它背后是整个阿里经济体系的支持。"

## 刘俊强：2019 年云计算趋势的看法

原篇：《大咖对话-刘俊强：谈谈我对2019年云计算趋势的看法》（嘉宾时任腾讯云资深架构师）

- **五大趋势。** 云服务市场将继续强劲增长；混合云和多云（Poly-Cloud）将逐渐成为主流；自动化将不可或缺（容器化"不光是部署环节的改进，实际上是软件或应用全生命周期的改造"）；合规性和安全性将受到重视；云服务将依然是新技术的最佳试验地。
- **公有云不是银弹。** "公有云并不是一种适用于所有类型需求的解决方案"；多云"并非全是好处，需要企业技术决策者根据企业的长短期目标来进行云产品组合的规划"。
- **上云不等于安全。** "选用公有云解决方案后并不代表就不会有云安全漏洞了。企业业务在上云之前做好云安全规划是非常重要的事情。"

## 陈天石：AI 芯片需要技术和资本的双重密集支撑

原篇：《大咖对话-陈天石：AI芯片需要技术和资本的双重密集支撑》（嘉宾为寒武纪创始人兼CEO）

- **专用化设计是 AI 芯片的必由之路。** 传统 CPU"通常需要成百上千条指令才能完成对一个神经元的处理"；GPU 虽与 AI 需求契合但"计算方式不是为深度学习算法专门设计，性能峰值无法被完全利用"；专用 AI 芯片"通过硬件神经元虚拟化、稀疏神经网络处理器架构等技术以及深度学习指令集……能效可以实现最大程度的优化"。
- **芯片设计需要双重密集投入。** "芯片从设计、制造到封装是一条几乎没有捷径的漫长链条，尤其是芯片的设计，需要技术和资本双重密集支撑。"
- **三大待解课题。** 算力资源储备——"网络规模变大之后，如何用足够的计算能力来支持庞大复杂的深度学习模型"；功耗与成本——"在超大规模并行计算中更好地兼顾性能与功耗"；性能与灵活度——"让算力适用于尽量多的行业与应用场景"。
- **独立芯片设计公司的价值。** "寒武纪的定位一直以来很明确——做独立的芯片设计公司……帮助大家解决'AI闭环路上最后一公里'的事情。"

## 高斌：过分渲染会过度拉高大众对人工智能的期望

原篇：《大咖对话-高斌：过分渲染会过度拉高大众对人工智能的期望》（嘉宾时任微软必应搜索广告部门首席机器学习科学家）

- **AI 落地三要素。** 明确技术应用的边界和程度——"我们要弄清楚在一个应用场景中哪些部分是人工智能技术可以解决的，可以解决到什么程度"；提升数据质量——"针对具体的应用问题来对数据进行选择和处理，包括对数据量的积累、取舍、降噪"；提高工程实现能力——"数据量、模型尺度的增长速度还是大于硬件发展的速度的，高水平的工程实现能力可以最高效地在硬件计算资源、数据量和算法模型之间找到平衡点。"
- **认知偏差的双重危害。** 恐慌影响（"AI取代人类"的恐惧导致盲目反对）与失望影响（"过度渲染拉高期望，实际表现落差导致质疑"）都会阻碍行业发展。
- **AI 将回归其本来位置。** "人工智能在未来会回归它原本的位置，成为人们比较关注的几个前沿技术领域，并会不断地带来改变人们生活的新技术。"
- **观点不一致的协商方法。** 项目目标不一致时"看是否可以分阶段完成，双方妥协取舍"；目标一致但方案不同时"论证每个方案可行性，按衡量标准做出认可选择"；通用原则是"本着解决问题的态度协商互相妥协"。

## 王龙：产业互联网是下半场的重中之重

原篇：《大咖对话-王龙：利用C端连接B端实现产业互联网是下半场的重中之重》（嘉宾时任腾讯云副总裁）

- **云的本质价值体系。** "自服务、高弹性、按需提供、免运维"，这些特性让云服务"天然成为开发者和创业者的最佳合作伙伴"。
- **产业互联网的判断。** "在泛互联网领域人口红利已经达到饱和的时候，利用 C 端连接 B 端实现产业互联网是互联网下半场的重中之重。线上线下连接需求的增加，会使得大量的新技术开始涌现。"
- **低谷期是锻炼良机。** "之前投融资环境比较好……会出现很多 to VC 的企业。现在这种情况会促使大家更谨慎地审视产品的价值，更小心的验证自己的商业模式。每经历一轮这样的低谷，云和开发者的能力都会得到更好的锻炼。"
- **跨经济周期的管理方法论。** 目标清晰（短中长期目标明确可衡量）；目标分解（帮助各层级负责人把目标拆成下一级能理解的小目标）；关注团队成长；跨部门协调（"具备同理心，通过同理心来寻找共同目标、共同利益点"）。

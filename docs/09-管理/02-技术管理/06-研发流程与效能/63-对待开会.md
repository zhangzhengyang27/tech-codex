# 对待开会

让很多程序员头疼的话题：开会。每天白天忙于参加各种会议，压缩了本来就少的可怜的工作时间。最可气的，有的人开完会工作就算完成了，而写程序的，还得下班后加班加点赶进度！

## 一、开会的认知

### 1.1 开会是有价值的

软件项目中有不少会议，其实有其价值所在。

- **评审会议**：让产品设计或架构设计在确定前收集大家的意见，及时发现问题。
- **每日站立会议**：及时了解项目进展、当前的困难和瓶颈，及时调整计划、解决问题；而且每个人都要当众讲一下做过的事情和计划要做的事情，这是一种无形的监督和约束。
- **项目立项会议**：创建一种仪式感，让每个人都知道项目的关键信息：
  - **项目目标**：这个项目是要干什么的，达到一个什么目标
  - **项目里程碑**：项目的开始结束时间、阶段划分，以及各个阶段的时间点
  - **角色分工**：项目成员的分工和角色是什么，每个人知道自己的任务是什么、遇到问题该找谁
  - **流程规范**：项目开发的主要流程是什么，基于瀑布还是敏捷
- **项目总结会议**：团队成员一起总结项目的得失，把经验总结下来，帮助团队在下一次做得更好。

### 1.2 开会是有成本的

开会的成本，就像房间里的大象——显而易见，而很多人却有意无意无视它的存在。

算一笔账：假设一个程序员月薪一万元，如果每天四分之一的时间在开会，那就相当于公司每月花了 2500 元在会议上。这还只是一个人的成本；如果开会的人多，整体会议成本其实非常夸张。

### 1.3 什么样的会议是有效率的

- **高效会议**：像每日站立会议——时间不长，收获很大；轻量级沟通建议的会议方式是"人少、面对面沟通"，这种小会往往很高效，经常能产生有价值的方案。
- **低价值会议**：领导冗长的讲话、一堆人偏离会议主题的讨论、与参会者没什么关系却被迫参加的会议。
- **判断标准**：会议是不是有效率，取决于它创造的价值是不是高于其成本。每日站立会时间短、人数少，成本低，创造的价值高于成本；人数多又偏离主题的讨论会，成本高而价值远不及成本，所以没有价值。
- **低效率会议存在的根源**：因为有的会议，本来就不是为了创造价值——比如花的成本不是组织者的，组织者得到自己的会议价值就可以了。

> 你是砍柴的，他是放羊的，你和他聊了一天，他的羊吃饱了，你的柴呢？

还有很多会议，是因为组织者和参与者都没有意识到开会其实是有成本的，浪费成本还不自知。这种情况还好，还是可以想办法改进的。

## 二、提高开会效率

提高开会效率、提升开会价值的方法，如同软件项目金三角：只要从两个角度去想办法——**减少开会的成本，增加开会创造的价值**。

先要认识一个前提：**要让大家意识到开会是有成本的，如果开会创造的价值不能大于其成本，就是浪费。**

### 2.1 砍掉没价值的会议

日常工作中很多会议其实并没有什么价值。如果一个会议符合以下标准，就要慎重考虑参加：

- **没有目标的会议**：大家都在随意发散，完全没有主题。
- **不能形成决策、没有会后行动**：一场会议开完没有什么结果，跟没开差不多。
- **参会者属于可有可无的角色**：会议与其关系不大，无法提供有效的反馈，也没有什么价值，只不过是被拉过去开会的。

在接受一个会议邀请之前，先问两个问题再做决定：这个会议是否真的有必要参加？是否有其他方式可以替代？其实很多问题并不是非要通过"会议"的方式解决。

**案例：用文档替代介绍会**。郑晔曾负责一个被其他组调用的服务，有一个组的同事想组织一个会议，请他介绍服务以及如何调用。他思考了一下：准备这个会议要写一个 PPT，开会还要花时间——这些时间足够写一份详细的说明文档，而且以后其他组再用，看文档就可以了。于是他回复：不用开会，发一个文档链接，有问题在聊天工具上沟通。后来对方看完文档，有几处不清楚的地方，咨询之后他把文档更新好，就没什么问题了，后面再也不需要为这件事开会。

### 2.2 减少参与会议的人

**会议的成本和两个因素相关：一个是人数，一个是时间。减少人数，就能减少成本。**

- 人一少，每个人都会更投入、更有效率，所以往往时间反而更少、产出更高。
- 如果要在会议上形成决议，人越多越难做决策，人越少越容易达成一致。要有决议的话，先开几个小会达成一致，再开大会——大会更多只是宣布一个结果。
- 业界实践：谷歌和 Facebook 对会议的态度是能不开就不开、无关的人不参与；Amazon 的规则也很简单——一场会议的人数，最多订两份披萨，超出这个规模就说明人数太多了。

### 2.3 缩短开会时间

减少开会成本的另一个方法是缩短开会时间。成熟可靠的方案可以选择，比如站立会议——通过站立的方式逼着大家快点结束。

### 2.4 提升会议所创造的价值

- **明确目的和主题**：每个会议要有明确的目的和主题，所有讨论都围绕会议目的展开。发现讨论偏离主题时要及时纠正——例如一个需求评审会，结果架构师在讨论技术细节，这就完全偏离了主题。此时应站出来提醒：既然是讨论需求，先不讨论技术问题，等需求确定了再慢慢讨论；或者把这个问题另外组织一个会议讨论。
- **明确结论与跟进**：开会后要有明确的结论、有后续的待办事项，落实到个人，并对待办事项有跟踪。
- **低价值会议的时间利用**：有些没什么价值的会议又必须参加，可以在参会前用一个本子把一个技术难题或一篇博客主题写下来；开会的时候把难题理清思路、把博客提纲写出来——一个会议开完，问题解决了，或者文章提纲也有了，同样收获满满，没有浪费太多时间。

## 三、小结

| 方向 | 具体做法 |
|------|---------|
| 砍掉没价值的会 | 无目标、无决策、可有可无的会议不参加；接受邀请前先问"有必要吗、有替代吗" |
| 减少成本 | 减少人数（先小会达成一致再开大会宣布结果）；缩短时间（站立会议） |
| 提升价值 | 明确目的主题、及时纠正跑偏；会后明确结论与待办并跟踪；必参加的低价值会用于思考难题或写提纲 |

对会议成本有了概念之后，可以据此找到很多提高开会效率、更好创造会议价值的方法——核心始终是那两条：减少开会的成本，增加开会创造的价值。

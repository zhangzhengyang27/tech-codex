# 软件工程

## 一、为什么需要软件工程

开发如果无法从系统层面整体看事情，虽然也能解决问题，但总有一种疲于奔命的感觉：

- 开发时没有分析没有设计，上手就写，后期难维护，加班熬夜去填"坑"
- 缺少理论指导，遇到新项目不能举一反三，工作很平庸
- 遇到需求变更这种事，除了抱怨两句客户，只能闷头做，无力反抗
- 做项目没计划性，想到哪做到哪，总是延期，比其他同事做得慢
- 不知道如何与团队协作，职业发展遇到瓶颈，无法得到晋升

**软件项目开发其实是一个工程，整个开发过程是可以有效组织起来的**：对于开发过程的各个阶段，已经有很多解决问题的最佳实践，有很多方法来帮助高效完成任务；还可以借助工具来协助管理，提升开发效率。

如果只停留在学习各种编程方法（术）上面，软件工程会引导人主动去思考这些"术"后面的"道"。这种对"道"的思考，能让人从单一的程序思维上升到系统的工程思维去看日常的问题，形成一套对于软件开发和项目管理的方法论。

在软件开发领域，有哪些知识十年前很重要、现在仍然重要、未来可能同样重要？这些知识不外乎：**数据结构、算法、面向对象思想、设计模式、软件工程。**

**只要从事软件开发相关领域，都绕不开"软件工程"**，因为现代软件项目开发多多少少都离不开软件工程知识的应用。日常工作中不管是前端和后端，都是软件工程相关的知识：

- 接到开发任务，如果想开发出客户想要的功能，要做需求分析
- 接手复杂的、大的功能模块，要做设计把复杂的拆成简单的，才能让大家一起分工去开发
- 完成一个功能模块，要保证质量，需要写一些测试代码，还要做一些功能测试
- 还有日常用的工具，像源代码管理、Bug 跟踪

技术更新迭代速度确实很快，但是软件开发背后的逻辑却万变不离其宗——将软件工程中的知识点和国内外前沿的、典型的项目案例结合起来学习，是理解它的重要途径。另外，在实际软件项目开发中，离不开各种工具的使用，像源代码管理、持续集成、看板、监控报警等，可以帮助团队更好地协作、规范项目流程、上线维护。

软件工程的知识可以从**"道、术、器"**三个维度展开：

- "器"就是软件工程中的各种工具
- "术"就是软件工程中的各种方法。例如如何做需求分析？如何对需求变更做变更管理？
- "道"就是软件工程知识的核心思想、本质规律。例如为什么要有需求分析？需求变更产生的深层次原因是什么？项目中决策的依据是什么？

## 二、软件工程知识体系的三大模块

软件工程的知识可以分成三大部分。

### 2.1 基础理论

从宏观的角度建立起软件工程的知识结构，展现软件工程学的全景图，掌握从软件工程的基础概念到主流的软件过程方法论。目标在于思维上的转变：尝试用工程化的思维模式，去分析和解决工作和生活中的问题。

### 2.2 项目过程

按照软件生命周期，把知识点拆成**规划、需求分析、设计、编码、测试、运行维护**这六个阶段：了解每个阶段要侧重做哪些事；分析每个阶段常见的问题，找到解决方法；了解各个阶段有哪些工具可以对项目有帮助，从而学会应用它们。

### 2.3 案例分析

通过案例分析可以看到大公司是怎么应用软件工程的。常有的疑惑是"软件工程学很虚、小公司用不着，或者不知道怎么在实际项目中应用"——其实软件工程的思想是润物细无声，包括微软、谷歌、华为、阿里巴巴这样的大公司早已深得其精髓，把它用得炉火纯青了。

大部分项目问题，都可以回到软件工程的逻辑里来解决。通过综合案例，可以把前面的知识融会贯通，并逐步内化为基础能力。简单来说，学习这些内容的目标是：从知到行，打好基本功，掌握软件工程学中涉及的方法和工具，学会举一反三，在软件项目的开发和管理过程中运用自如；同时让软件工程的思维帮助技术人脱离技术的拘泥，有更高的格局和视角去看待工作和生活中的问题。

## 三、软件工程的学习价值

软件工程是软件行业知识体系的内核。无论走技术路线，还是转向做管理，想要走得更快更稳，都绕不开软件工程。

软件工程的目标就是为了要**聚焦于质量，构建和维护高质量的软件。**

### 过程

构建高质量软件，则要解决软件过程中的混乱，将软件开发过程中的沟通、计划、建模、构建和部署等活动有效地组织起来。而软件过程，就是在软件项目的生命周期内——也就是软件从诞生到结束这期间——在开发与构建系统时要遵循的步骤。

在软件工程多年的发展中，逐步形成了两种主流的软件过程指导框架：**瀑布模型**和**敏捷开发**。

### 方法

方法是指在整个过程中，如何构建系统的方法学。比如如何分析用户需求、如何对产品进行测试验收、如何进行系统架构设计等。

### 工具的使用

需要工具来辅助方法的执行，提高效率。通过工具，可以把一些手动的工作自动化，比如自动化测试工具、自动构建部署工具；通过工具，可以帮助把一些流程规范起来，比如 Bug 跟踪、源代码管理；还可以通过工具帮助提高编码效率，比如各种编辑器 IDE、各种高级语言。

软件工程的核心知识点，**就是围绕软件开发过程，产生的方法学和工具。**用一个简单的公式理解软件工程：**软件工程=工具+方法+过程。**

## 五、学习软件工程的四重境界

软件工程的公式看起来简单，但这些内容一下子要吃透并不容易。学习软件工程有四重境界：

**第一重：用器**

"器"就是工具。工具规则简单，上手就可以用，也很快就能看到效果。比如原型设计工具可以帮助确定需求，持续集成工具可以帮助简化测试和部署的流程。对工具的学习是最为简单的，也是最基础的。

**第二重：学术**

"术"就是方法。学会方法，就能应用方法去完成一个任务——例如用需求分析的方法搞清楚用户想要什么，用 Scrum 去组织项目开发过程。掌握了术，甚至是可以脱离器的：没用原型设计工具，用纸和笔、用白板，一样可以去沟通确认需求。

**第三重：悟道**

"道"就是本源，软件工程知识的核心思想和本质规律。就像敏捷开发，本身并不是一种方法，而是一套价值观和原则；领悟了这个道，它就可以成为处理项目过程中各种问题决策的依据。道是可以产生术的——掌握了敏捷开发的道，就可以领悟出 Scrum、极限编程这样的术。

**第四重：传道**

当能把复杂的知识通过浅显易懂的方式传授给别人，就说明对知识的领悟已经到了更高的境界。同时，教学也是最好的学习方式：通过传授别人知识，可以对知识本身有更深入的理解。

## 六、做中学和教中学

**"做中学"，是一种自下而上的学习方法**：通过实践，从使用工具到学习方法，再从方法中提炼出道。

**"教中学"，是一种自上而下的学习方法**：通过教学，去进一步深入领会别人总结出来的道，去模仿推导方法，去学习如何使用工具。

例如，学习完一篇文章后，把学到的知识进行输出，写成微博或博客分享出去，或者在公司内部讲给同事们听。在教学分享的过程中，可以进一步深化吸收知识内容，构建自己的知识体系。"做中学"和"教中学"这两种方法可以配合起来使用。

## 七、参考书目

学习软件工程的过程中，推荐以下相关书籍：

- 《构建之法》

  作者邹欣是微软的研发总监，同时在多所高校进行了软件工程的教学实践，在此基础上对软件工程的各个知识点和技能要求进行了系统性整理，形成教材，是对相关内容知识很好的补充。

- 《人月神话》

  软件工程历史上的经典著作，内容发人深省，40 年来一直畅销不衰，里面的观点即使到现在也不过时。即使以前看过，隔一段时间再翻看一遍，可能都会有新的感悟。

- 《人件》

  如果说《人月神话》关注"软件开发"本身，《人件》则关注软件开发中的"人"。作者指出知识型企业的核心是人，而不是技术。

- 《知行合一：实现价值驱动的敏捷和精益开发》

  作者丛斌有二十多年从事软件工程教学、咨询和研究的经验，所以书写得特别接地气，书中有许多真实案例，对敏捷开发和 CMMI 都有很深入的描述。

- 《软件工程——实践者的研究方法》

  大部分高校采用的软件工程标准教材，可以作为一个参考。

- 《持续交付》

  讲述如何实现更快、更可靠、低成本的自动化软件交付，描述了如何通过增加反馈，并改进开发人员、测试人员、运维人员和项目经理之间的协作来达到这个目标。

- 《走出软件作坊》

  这本书生动地描述了国内小型 IT 企业在发展过程中遇到的一系列项目管理问题，以及作者是如何去解决这些问题的。

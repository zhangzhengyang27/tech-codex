# 系统性能验收：Unixbench、FIO 性能压测

系统性能验收是整体业务部署前的关键环节，用于考核服务器性能是否达标。获得一台服务器后，需要先对其整体性能做一番评估，以判断它是否适合部署目标服务和对应业务。本文介绍两款系统性能验收工具：Unixbench 与 FIO。阅读前建议具备 Linux 使用基础及操作系统原理知识。

## 一、测试前关注点

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__CgpOIF5gtPGAQgQyAAbHfhNzTM4078.png)

对系统进行基准测试前，先了解其用途和系统本身的情况是十分必要的。

### 系统自身情况

做系统性能测试时，需要重点关注引起性能变化的设置是否已优化：

- **CPU 功耗与性能管理设置**：p-state 和 c-state 状态值是否都已调到最优，尽可能把系统性能、CPU 的计算性能发挥到最优。
- **影响系统性能的内核参数**：如文件打开句柄、网络队列大小等内核参数是否已经优化。
- **系统本身的缺陷**：驱动模块、开发库缺陷、补丁等。例如给系统打上熔断、幽灵安全补丁后，操作系统性能损耗会因此增大。了解这些有助于分析测试结论和提高系统能力。

### 业务需求情况

系统最终需要承载业务，因此测试前还需了解业务需求情况：

- 业务特性：有没有高峰期和低峰期，什么时候需要承载多大的 QPS。
- 资源利用类型：运行的是内存型服务还是计算型服务。
- 服务架构：假设部署 Nginx，需要了解它是作为反向代理服务、缓存服务，还是仅作为静态元素的 Web 服务使用。

了解业务整体情况后，测试结果才更有针对性——不只是执行测试，而是向更高一层考虑问题。

## 二、性能测试分类

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__CgpOIF5gtQiADB-UAASwQDk9GjA321.png)

与运维相关的性能测试主要归纳为四大类：

| 类别 | 测试对象 | 典型工具 |
| --- | --- | --- |
| 业务压测 | 某个业务接口模拟海量请求 | ApacheBench（ab）、WebBench |
| 服务压测 | MySQL 等服务的指标 | Sysbench |
| 网络压测 | 网络的带宽和承受能力 | Netperf |
| 系统压测 | 硬件 + 操作系统 + 开发库 | Unixbench、FIO |

一个完整的系统测试主要涵盖以下组成部分：一是硬件，物理单元由 CPU、内存、磁盘、网卡等核心组件组成，其中 CPU、内存、磁盘是系统压测需要重点观测的指标——这三者在很大程度上决定了服务的承载能力，影响整体业务性能；二是操作系统本身及相关开发库。系统压测就是对硬件、系统、开发库这三个组成部分进行测试。

## 三、Unixbench 基准测试

### 基准分的由来

Unixbench 是一个基于系统（Linux、Unix）的基准测试工具。基准测试的含义是：给出一个通用标准基准的分数值，在它基础上对其他操作系统进行打分，用于衡量这个操作系统应该给多少分、和基础的差异有多大。

Unixbench 的基准分基于 1995 年一个叫作 George 的基准测试操作系统：一台配置较低的工作站，约 128 MB 内存，使用 Solaris 系统，压测数值检测结果为 10 分，这就是它的基准测试分数。

当前操作系统和硬件发展很快，用 Unixbench 压测会得出更高的分值。拿这个分值与基准分对比，可以进行非常形象的分析；同时还可以横向对比，比如和其他服务器的测试结果作对比，都参考这个基准分数。

### run 命令参数

Unixbench 工具需要手动下载，可到 GitHub 下载。安装成功后用 run 命令启动基准测试，run 命令后可选择添加以下参数：

- `-q`：不显示测试过程。
- `-v`：显示测试过程，即控制测试过程是否显示。
- `-i <count>`：执行次数，最低 3 次，默认 10 次，控制每一个基准测试项执行多少次。Unixbench 会对很多项操作系统能力打基准分，总分由多个测试项目综合得分组成，每个测试项测试多少次由 `-i` 加数字控制。
- `-c <n>`：多核 CPU 场景测试指标，用于了解操作系统上多核 CPU 的性能程度。比如一台机器是四核 CPU，设置为 `-c 4`，即运行 4 个 Unixbench 任务同时执行基准测试打分，从而更客观地得出 4 个 CPU 同时被使用时的大概分数。

### 执行方式与结果解读

执行示例：可用 `./Run` 直接运行，等待结果需要一段时间。若不能等待那么久，可选择后台运行：在命令前面直接加 `nohup`，后面加一个 `&` 符号，即可把 run 方式放到后台运行。

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__Cgq2xl5gtSGACDIrAAWj5rI_m3s047.png)

Unixbench 有很多个测试项，例如浮点运算效率、execl（exec 系统调用族）的每秒吞吐能力、管道的直接吞吐能力等。

Unixbench 执行完成后的结果包含三部分：

1. 测试进度展示；
2. 系统信息汇总，摘取并展示操作系统当前 CPU 的基础信息；
3. 测试结果（最关注的部分）。

测试结果分两种情况：

- 只启用单副本测试（如 `-c 1`，即单核 CPU 测试）时，只列出单副本测试结果；
- 多副本测试（`-c > 1`）时，会分别列出单副本测试和多副本测试的结果。

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__Cgq2xl5gtXGAB9S3AAH4TWbDc3k323.png)

### 对比案例：AMD 与 Intel

以一台 AMD 主机与一台 Intel 处理器主机的性能差异对比为例：选择两台配置相同的机器，磁盘类型一致、操作系统一致，仅 CPU 类型不同，对比最新一代的 AMD（Rome 这一代）CPU 和 Intel CPU 的性能差异。

安装 Unixbench 时，可以在 GitHub 上直接下载并安装，也可以使用脚本完成整个软件包的下载、安装，最后单独执行 run 命令。第一项测试中，如果没有指定 `-i`，最多测试 10 次；给 `-i` 指定更多数值则可以测试更多次数。由于测试时间较长，演示中直接中断了执行，直接查看执行完成后的结果。

结果记录了分别在 AMD 机型上和 Intel 机型上测试的结论、数据：首先列出每一项的测试内容、数值与所花费的时间，后面是每一项的基线分数。以上是两个 CPU 各跑一个副本时的测试结果；下面是两个 CPU 的系统上启用两个副本（`-c 2`）的测试结果，同样是先测出每一项的数值、单位、所花时间，再得出每一项测试结论与当前对系统测试打分的情况。

对比两份记录 Unixbench 测试结论的文件，可用 `vim -d` 将两个文件同时打开，分析数值跑分结果并作对比：AMD 的跑分数值比 Intel 的 CPU 分数更高，即最新一代的 Rome AMD CPU 性能优于另一款 Intel CPU。

Unixbench 测试项更多关注计算性能和内存 IO 等场景。操作系统除这两个性能指标外，磁盘 IO 处理能力同样重要——磁盘 IO 在很大程度上决定了操作系统上服务的性能，例如 MySQL 等数据库属于高 IO 型服务。对磁盘 IO 进行测试使用的就是下面介绍的 FIO 工具。

## 四、FIO 磁盘 IO 测试

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__Cgq2xl5gtYiAI2f-AAJp6_7gP_I248.png)

FIO 是一个开源的主流的 Linux 磁盘 IO 测试工具。磁盘测试主要关注三项指标：

| 指标 | 含义 | 评估内容 |
| --- | --- | --- |
| IOPS | 每秒进行读写（I/O）操作的次数 | 每秒对磁盘的操作次数和能力，次数越多说明读写越快 |
| 吞吐率 | 每秒对磁盘的读写数据量（MB/s） | 数值越高表示读写数据越多 |
| 读写延迟 | 单个 IO 操作写磁盘的耗时 | 做一次 IO 操作的耗时 |

::: warning 注意
使用 FIO 之前，建议尽量使用一台空闲的机器运行，以免因 FIO 对操作系统上的磁盘或文件的读写损坏文件系统。
:::

### 关键参数

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__Cgq2xl5gtaCAGekxAAmbidRaDZI069.png)

FIO 的参数比 Unixbench 多，重点注意以下三个：

- `bs`：块的大小。
- `iodepth`：队列的请求深度，可理解为请求 IO 时的并发数量，深度数值越大说明并发请求越多。
- `rw`：控制磁盘的读写模式。磁盘分为顺序读、顺序写、随机读写、混合读写等场景，需要指定特定场景时通过 `rw` 参数设置。

### 三类指标对应的测试设置

针对不同指标进行测试，需要控制好 FIO 的参数组合：

**延迟测试**：把队列深度调为 1（模拟单个队列对磁盘操作），块大小设置为 4k，即可测出单个队列上读写的延迟，着重得到硬盘的延迟指标。`rw` 参数里可指定磁盘读写类型，`randrw` 即随机读写的延迟测试。

**吞吐测试**：目标是硬盘的最大吞吐率带宽，需要尽可能把总线带宽或 IO 带宽跑满——把队列深度调到更大（32），块大小 `bs` 调到比较大的值（128k），即可用最大能力跑满整个磁盘带宽，这样的设置更能反映硬盘的吞吐能力。

**IOPS 测试**：目标是在单位时间内尽可能多地操作磁盘——把 `bs` 调小，同时把队列深度调到最大，即可测出单位时间一秒内能够读写操作磁盘的次数。

三类指标的测试都可参考上述设置，得出磁盘能力对应的结论。

### 对比案例：SAS、SATA、SSD

![](/ops-course-images/06-系统性能验收_Unixbench_FIO_性能压测__Cgq2xl5gtbaADDl1AAJw4GDZ46A089.png)

以本地盘 SAS、SATA、SSD 的性能差异测试为例：取三台机器，仅本地磁盘类型不同，其他配置保持一致。通过 FIO 测试后会得到测试数据，分别展示每种磁盘的 IOPS 及吞吐能力的大概情况。在只测试顺序读写模式的情况下，SSD 盘整个的吞吐能力和 IOPS 比 SATA 或 SAS 盘高出约 4 倍。

## 五、小结

- 系统性能验收发生在整体业务部署前，测试前需掌握两方面背景：系统自身情况（功耗设置、内核参数、补丁缺陷）与业务需求情况（峰谷特性、资源类型、架构形态）。
- 运维相关性能测试分四类：业务压测（ab/WebBench）、服务压测（Sysbench）、网络压测（Netperf）、系统压测（Unixbench/FIO）；系统压测重点观测 CPU、内存、磁盘。
- Unixbench 提供基准分对比，run 命令通过 `-q`/`-v`/`-i`/`-c` 控制过程显示、执行次数与多核副本，测试项侧重计算性能与内存 IO。
- FIO 通过参数组合分别测延迟（iodepth=1、bs=4k）、吞吐（iodepth=32、bs=128k）、IOPS（bs 调小、队列调大），测试须在空闲机器上进行。

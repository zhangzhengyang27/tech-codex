# 00-项目总览

> 项目：ERP-CRM ｜ 版本：v1.1 ｜ 生成日期：2026-10-05 ｜ 依据：源码分析（v1.1：2026-10-06 一致性回刷，与 16-20 篇对齐）

## 1. 项目定位与目标用户

本项目（目录 `erp/`，含 `erp-crm/` 后端与 `erpcrm-ui/` 前端两个独立 git 仓库）是一套**企业级 ERP + CRM 一体化 SaaS 系统**，源自慕课网课程《SpringBoot+Vue3 打造企业级 ERP+CRM 一体化 SaaS 系统》，但在课程原码基础上做了大量工程化重构：后端由 Spring Boot 2.5.8 七模块（center/auth/system/common/saas/crm/erp）合并为**单模块 Spring Boot 3.5.16**（见 `erp-crm/pom.xml`，artifactId `ec`，version 3.9.2，`<finalName>erpcrm</finalName>`）；前端由 Vue2 → Vue3（vite-vue3 分支）→ 2026-09 整体替换为 **pure-admin 模板底座**（当前 pure-admin 分支，业务代码保持 JS）。

项目的核心卖点是**基于"独立数据库物理隔离"的多租户 SaaS 架构**：每个租户（订阅企业）拥有一个独立的 MySQL 数据库，由主库 `erp-crm-master` 中的 `master_tenant` 表登记各租户库的连接信息，运行时按请求头 `tenant` 动态路由数据源。该结论在源码中的证据链非常完整：`erp-crm/src/main/java/com/ec/auth/interceptor/TenantInterceptor.java`（拦截请求头并注册数据源）、`erp-crm/src/main/java/com/ec/auth/datasource/DynamicRoutingDataSource.java`（动态路由数据源）、`erp-crm/src/main/java/com/ec/auth/web/service/TenantRegisterService.java`（注册时真实 `CREATE DATABASE` 建库）。

目标用户分两类：

- **SaaS 运营方（平台管理员）**：通过 `system/tenant`（`SysTenantController`）管理租户生命周期（改套餐、停用、删除），通过 `saas/package`（`SaasPackageController`）管理订阅套餐；`TenantExpirationJob`（`erp-crm/src/main/java/com/ec/saas/job/TenantExpirationJob.java`）每日 03:00 自动巡检租户到期并停用。
- **租户企业用户**：租户内的管理员/销售/库管等角色，使用 CRM（客户/线索/公海/商机/合同/回款/审批）与 ERP（产品/供应商/仓库/采购/销售/零售/调拨/盘点/财务）两套业务模块。

两域业务并非并列的两座孤岛，而是首尾相接的一条价值链：销售在 CRM 侧从公海**领取线索**（`POST /crm/pool/receive/{id}`），跟进转化为**客户**，推进**商机**并在**合同**环节走 Flowable 审批流，签约回款后进入 ERP 侧生成**销售订单**，经仓库**采购入库/零售出库**改变库存，最终沉淀为财务侧的应收与库存资产总览。中间各环的数据口径（客户与订单的关联、产品与安全库存的联动）由《04-数据模型》承接。理解这条价值链后，功能清单里"CRM 七组 + ERP 十六组"Controller 的划分逻辑就一目了然：分组边界即业务域边界。在商业模型层面，SaaS 的"套餐-配额-到期"三件套把租户生命周期闭环：注册时选套餐计算有效期，租户内新增/导入用户前由 `TenantQuotaService` 校验套餐 `maxUsers` 上限，每日 03:00 的 `TenantExpirationJob` 巡检临期（默认提前 7 天提醒）并自动停用到期租户，运营方在主库侧可随时改套餐或手动停用。

### 3.3 运行端口与基础设施

- 后端业务端口 **9090**，Actuator/指标端口 **9091**（`application.yml`）。
- 前端 dev 端口 **80**，`/dev-api` 代理到 `127.0.0.1:9090`（`vite.config.ts` server.proxy）；生产以 nginx 托管，`/prod-api` 反代后端（`erpcrm-ui/nginx.conf`）。
- MySQL 主库 `erp-crm-master`；租户库按 `ec_` 前缀 + 随机串建库（如 `ryt_nelub7xr` 为历史租户 tenant1 的库）。

选型上有三处权衡值得展开。**其一，七模块合并为单模块**（2026-09，见 `AGENTS.md`）：课程原码按 center/auth/system/common/saas/crm/erp 拆分 Maven 模块，但七者本就同进程构建发布，拆分只带来依赖管理的额外复杂度；合并后包结构 `com.ec.{auth,common,saas,sys,web,crm,erp}` 仍保留原边界，属于"用包边界替代模块边界"的务实收敛。**其二，Flowable 引擎表落主库**：审批流是平台级能力而非某个租户的业务数据，落主库避免每注册一个租户就复制一套 ACT_* 表的膨胀，代价是审批数据与租户业务数据分属两库，一致性靠跨库补偿式设计（见《05-核心流程》审批流一节）。**其三，前端基座 TS、业务层 JS**：pure-admin 底座保持 TS 以获得模板自身的类型收益，views/api/components 保持 JS 则把课程存量代码的迁移成本压到最低——两轮前端改造（Vue2 → Vue3 → pure-admin）都遵循"换底座不重写业务"的路线，旧实现保留在 `vite-vue3` 分支可随时对照。

## 5. 快速上手

前置条件：JDK 17、Maven 3.9+、Node ≥22.22.1（实测 v24 可用）+ pnpm 10、本机 MySQL 8.4 与 Redis 7（Redis 必须运行）、一个内容 ≥64 字节的 JWT 密钥。

```bash
# 1) 初始化数据库（主库 + 一个租户库）
mysql -uroot -p -e "CREATE DATABASE \`erp-crm-master\` DEFAULT CHARACTER SET utf8mb4;
                    CREATE DATABASE \`ryt_nelub7xr\` DEFAULT CHARACTER SET utf8mb4;"
mysql -uroot -p erp-crm-master < erp-crm/sql/erp-crm-master.sql
mysql -uroot -p ryt_nelub7xr   < erp-crm/src/main/resources/init-sql-script/erp-crm-tenant-sample.sql
# 参照 erp-crm/.env.example 生成 erp-crm/.env（JWT 密钥/数据库凭据/Druid 账号等）
# 并将 master_tenant 中 tenant1 行的 url/username/password 修正为本机可用值（CI 脚本 backend.yml 第 70-81 行有同源示例）

# 2) 启动后端（端口 9090）
cd erp-crm && mvn package -DskipTests
java -jar target/erpcrm.jar          # 或 ./erpcrm.sh start（Linux/Mac）/ erpcrm.bat（Windows）

# 3) 启动前端（端口 80，/dev-api → 9090）
cd ../erpcrm-ui && pnpm install && pnpm dev

# 4) 登录验证
# 浏览器打开 http://localhost ，租户 tenant1 / 账号 admin / 密码 admin123（CI 与 compose 均按此口径补种 admin）

# 5) 在线工具
# 接口文档 http://localhost:9090/swagger-ui/index.html
# Druid    http://localhost:9090/druid/index.html（账号取 .env 的 EC_DRUID_USER/EC_DRUID_PASSWORD）
# 指标     http://localhost:9091/actuator/prometheus
```

后端测试（依赖本机 MySQL/Redis 与 `.env`）：`cd erp-crm && mvn test`（13 个测试类，覆盖登录认证链、审批流、采购入库、库存调拨、租户注册、租户到期巡检、配额、口令加密等）。前端质量门禁：`pnpm lint && pnpm typecheck && pnpm test`。Docker 一键栈见 `erp-crm/ops/deploy/docker-compose.yml`（细节在 06-部署运行篇展开）。

## 6. 阅读本套文档的路径建议

- 想理解"多租户怎么落地"：先读 01-系统架构.md 第 4 节，再读 05-核心流程.md 的租户注册与登录流程。
- 想改业务页面/接口：02-页面设计.md 与 03-接口设计.md 对照阅读，注意前后端均遵循 RuoYi 命名（`/crm/customer/list` ↔ `src/api/crm/customer.js`）。
- 想加表/字段：04-数据模型.md 的迁移机制一节（`db-backup/upgrade_*.sql` 的幂等写法可直接复用），并记得同步改租户模板 `init-sql-script/erp-crm-tenant-sample.sql`，否则新注册租户会缺表。
- 想上线：直接看 06-部署运行.md。

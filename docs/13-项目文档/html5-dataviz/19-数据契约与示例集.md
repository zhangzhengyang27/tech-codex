# 19 数据契约与示例集

> 项目：html5-dataviz ｜ 版本：v1.2 ｜ 生成日期：2026-10-06 ｜ 依据：源码分析

## 0. 本章定位

本章是"可复制的数据契约样册"：把新增一个案例（或大屏）时需要照抄的全部注册形态——manifest 清单条目、ChartExampleLocalMeta 全字段、各 loaderKind 的 JSON 条目、三种 EChartDemo 执行模式的 SFC 模板、antv/three/webgl 的自驱与壳组件模板、大屏组件映射配置——逐一给出**从源码摘录的真实示例**。与既有篇目的分工：《03-接口设计》讲契约的字段语义与测试锁定关系，《04-数据模型》讲 schema 的来龙去脉，《06-部署运行》第 5 节讲 SOP 步骤顺序；本章不重复论证，只提供"照着抄就能对"的样例集，每节开头用一行指明出处文件。所有示例均为源码快照摘录（2026-10-06），数字口径含 00-15 篇定稿后新增的 webgl 库（325 条）。

## 1. manifest 清单条目 ChartExampleLocalMeta（全字段示例）

定义于 `src/chart-examples/manifest.ts` 头部（echarts/antv 清单同文件、three 侧 `src/chart-examples/three-manifest.ts`、webgl 侧 `src/chart-examples/webgl-manifest.ts`），完整类型声明如下：

````
export interface ChartExampleLocalMeta {
  id: string
  title: string
  category: string
  tags: string[]
  /** three 库专用：资产根路径注入（ASSET_HOST/FILE_HOST/HOST），详情页挂载时透传给示例组件 */

四例合读可得三条书写规则。其一，`id` 是贯穿身份：等于 SFC 文件名（`{id}.vue`）、JSON 条目 id、缩略图文件名三者的公约数，跨库唯一（gen 脚本第 4 步校验）；新案例一律建议 kebab-case 英文（webgl 的中文 id 是迁移源既成事实，fs 不解码 URL 编码名的坑见《09-测试与质量保障》第 3 节）。其二，`tags` 首位是库标识习惯（three 条目带 'Three.js'、antv 条目带 'antv'/'g2plot'、webgl 带 'WebGL'），参与搜索域。其三，`globals` 注释写明"three 库专用"，但类型上不限制库——它是详情页向组件注入资产根路径的唯一通道，新增资产根约定时应同步 `three-data.test.ts` / `webgl-data.test.ts` 的逐字段对齐断言。清单统一出口为 `LOCAL_LIBRARY_MANIFESTS`（manifest.ts 尾部，Record 结构，键为四库 id）；echarts/antv 两份清单的生成器不在仓库内（手工维护 + git 留痕），three/webgl 两份由 `scripts/gen-three-registry.mjs` / `gen-webgl-registry.mjs` 生成、禁止手改。

两种维护方式并存的局面值得展开一句：同样是"生成物"，three/webgl 清单与 echarts/antv 清单的可信度并不对等——前者的生成器在仓库内、重跑即重建，后者的生成器已失联、任何修改都是"手改生成物"。因此本章样例在两个库系中的用法也不同：照抄 echarts/antv 条目时，请同时复刻它的字段形态与排序习惯（manifest 按 id 字母序插入、JSON 条目字段按 schema 顺序），并在提交信息中写明涉及 id（git 留痕是未来找回生成器后 diff 对账的唯一依据）；照抄 three/webgl 条目时则不应手改清单文件，批量场景一律走 gen 脚本，单条手工新增（无上游源时）虽属允许，但完成后应立即跑 `three-data.test.ts` / `webgl-data.test.ts` 确认三处（JSON、manifest、缩略图）对齐。这套差别对待不是双标，而是《13-技术债务与演进建议》第 1 条登记的风险在操作层的投影：生成器缺失的库，其清单一致性只能靠人的纪律兜底。

### 2.1 资产路径契约（注册数据之外的对齐面）

新增条目时除了 JSON 与清单，还有一组**由路径约定构成的隐式契约**需要同步核对，它们不出现在任何 schema 里，却决定了"数据条目与磁盘资产能否对上"。缩略图：JSON 的 `thumbnail` 指向 `public/` 下的真实文件（echarts 用 `/echarts-thumbs/`、antv/兜底通用 `/chart-thumbs/`、three/webgl 用 `/example-thumbs/{源}/{章节}/`），置 null 时列表页回落 `/chart-thumbs/{id}.webp` 兜底路径——兜底路径也要求文件真实存在，否则卡片以 📊 占位符静默降级（echarts/antv 侧无测试校验，是上线检查项而非测试项）。图表数据：echarts 官方脚本里的相对取数路径在运行时被拼上 `/echarts-data` 前缀（`EChartDemo.fetchJson` 一律拼、Renderer 相对路径拼、沙箱注入 ROOT_PATH 变量，三处语义一致），因此收录官方示例时要确认对应数据文件确实在 `public/echarts-data/` 下。地图：`requiresMap: true` 的条目由宿主预注册 china/world 两张（`/map-geojson/`），第三张地图须示例内 `ctx.registerMap` 自注册。three/webgl：资产根完全由 manifest 的 globals 决定，资产文件在 `public/{ASSET_HOST 指向目录}/` 下，路径拼写错一个字符的表现是运行时 404 而非任何构建期报错——这也是 gen 脚本第 4 步"缩略图存在性校验、失败退出码 1"存在的理由：把"路径对不上"提前到生成期暴露。

## 3. 三种 EChartDemo 执行模式的 SFC 模板（echarts 本地案例）

echarts 本地 SFC 的契约容器是 `src/chart-examples/EChartDemo.vue`（props/ChartContext 全表见《15-接口全量参考》第 4 节），三种执行模式的真实模板如下。选型判据先行总结：**能用 option 模式就不要用钩子**——option 是三者中唯一"声明式"的形态，容器能替它处理一切时序；onReady 用于"初始化需要异步数据或注册类 API"的场景；setup 用于"存在实例级副作用（定时器/事件监听）"的场景，它以返回清理函数为代价换取最强的控制力。三种模式可两两组合但语义有互斥细节（静态 option 与钩子互斥、onReady 先于 setup），逐条见各小节末尾。另需说明：以下三个源文件的脚本均为官方示例脚本的迁移改写产物（生成器统一注入"等待 v-chart 子组件挂载完成"的注释），阅读时把注释当作生成器签名而非代码逻辑。

### 3.3 setup 模式——定时器/交互/清理（源：`src/chart-examples/echarts/sankey/sankey-energy.vue`）

````
<template>
  <div class="demo-container">
    <EChartDemo :setup="setup" />
  </div>
</template>

<script setup>
import EChartDemo from '../../EChartDemo.vue'

function setup(ctx) {
  // 等待 v-chart 子组件挂载完成，确保 chartRef 可用
  ctx.myChart.showLoading()
  ctx.fetchJson('/data/asset/data/energy.json').then(function (data) {
    ctx.myChart.hideLoading()
    const option = {
      title: { text: 'Sankey Diagram' },
      tooltip: { trigger: 'item', triggerOn: 'mousemove' },
      series: [
        {
          type: 'sankey',
          data: data.nodes,
          links: data.links,
          emphasis: { focus: 'adjacency' },
          lineStyle: { color: 'gradient', curveness: 0.5 },
        },
      ],
    }
    ctx.setOption(option)
  })
}
</script>
````

setup 的适用判据：需要 setInterval/setTimeout、myChart.on 事件监听、或任何"实例级副作用"。关键契约义务：**函数体内创建了定时器/监听时必须返回清理函数**（`return () => { clearInterval(timer) }`），容器在重试与卸载两个时机统一调用——不返回清理函数的定时器类示例会在快速切换时叠加定时器，这是历史事故类别（《07-模块详解》4.2 节）。setup 与 onReady 可共存，执行顺序固定为先 onReady 后 setup；两者任一存在时静态 option 不生效（互斥语义见《12-FAQ与故障排查》第 7 节第一条）。含清理函数的完整示例可参考 `src/chart-examples/echarts/graph/graph-force-dynamic.vue`。

## 4. antv / three / webgl 的案例模板（自驱与壳组件模式）

本节的三个模板分别代表三种"无 EChartDemo 契约"的执行形态：antv 是完全自驱（示例组件自己管实例生命周期）、three 是厚壳托管（壳统一管 renderer 与渲染循环，示例只声明场景内容）、webgl 是薄壳直通（壳只提供 canvas，示例直接操作原生 WebGL 上下文）。三种形态的复杂度依次递减、自由度依次递增，选择权不在示例作者而在库的迁移策略——这是"库级约定优先于示例级偏好"的体现，同一库内的示例必须保持同构，否则生成器、清扫脚本与排查经验都无从复用。

    xField: 'month',
    yField: 'value',
    smooth: true,
    color: '#6366f1',
    point: { size: 4, shape: 'circle' },
    label: {},
  })
  line.render()
})
</script>

<template>
  <div ref="containerRef" class="chart-wrap"></div>
</template>
````

antv 不经过任何宿主组件：onMounted 里 `new Plot(container, options)` + `render()`，规范写法应配 `onBeforeUnmount(() => plot.destroy())`（防实例泄漏，与 EChartDemo 的 cleanupFn 语义对齐）。G2Plot 的类名即 loaderKind 为 antv-config 的兜底条目里 `plotClass` 字段的合法取值（'Line'/'Area'/'Column' 等）。

### 4.2 three 壳组件模式（源：`src/chart-examples/three/threejs-lesson/03-basics/dpr.vue`）

````
<template>
  <ExampleScene
    camera="perspective"
    :camera-position="[0, 0, 5]"
    :max-pixel-ratio="devicePixelRatio"
    @ready="onReady"
  />
</template>

<script setup lang="ts">
import * as THREE from 'three'
import ExampleScene from '../../ExampleScene.vue'

let cubes: any[] = []

function onReady(ctx: any) {
  const geometry = new THREE.BoxGeometry()
  const material = new THREE.MeshPhongMaterial({ color: 0x44aa88 })
  cubes = [-2, 0, 2].map((x) => {
    const cube = new THREE.Mesh(geometry, material)
    cube.position.x = x
    return cube
  })
  ctx.scene.add(...cubes)

  const light = new THREE.DirectionalLight(0xffffff, 1)
  light.position.set(-1, 2, 4)
  ctx.scene.add(light)

  ctx.addUpdateCallback(() => {
    cubes.forEach((cube) => {
      cube.rotation.x += 0.01
      cube.rotation.y += 0.01
    })
  })
}
</script>
````

ExampleScene（`src/chart-examples/three/ExampleScene.vue`，含 CSS3D/SVG/WebGPU/WebXR 变体壳）内部由 `stage/useExampleStage.ts` 统一管理 renderer/controls/渲染循环与 dispose——示例作者只做三件事：声明相机配置、在 onReady(ctx) 里向 `ctx.scene` 加对象、用 `ctx.addUpdateCallback` 注册逐帧逻辑。禁令：不要绕过壳自建 WebGLRenderer，context 上限防护（forceContextLoss）在壳里（ADR-007）。

### 4.3 webgl 壳组件模式（源：`src/chart-examples/webgl/webgl/kaikeba-webgl/01-webgl-入门-webgl/1-刷底色.vue`）

````
<template>
  <WebGLExampleScene @ready="onReady" />
</template>

<script setup lang="ts">
import WebGLExampleScene from '@webgl-examples/components/WebGLExampleScene.vue'
async function onReady({ canvas, container, addUpdateCallback, resize }: { canvas: HTMLCanvasElement; container: HTMLElement; addUpdateCallback: (fn: () => void) => void; resize: (w: number, h: number) => void }) {
  canvas.width = window.innerWidth;
  canvas.height = window.innerHeight;
  // 使用canvas 获取webgl 绘图上下文
  const gl = canvas.getContext("webgl")!!;
  // 指定将要用来清空绘图区的颜色
  gl.clearColor(1, 1, 0, 1);
  // 使用之前指定的颜色，清空绘图区
  gl.clear(gl.COLOR_BUFFER_BIT);
}
</script>
````

webgl 库与 three 同构但壳更薄：WebGLExampleScene 提供 canvas 与就绪回调，示例直接操作原生 WebGL 上下文（教学示例的意义就在于裸写管线）；教学代码常需 rAF/事件的全局资源回收，由 `@webgl-examples/composables/useGraphicsCleanup` 的引用计数 patch 机制统一承接（组件无需 import，场景内部自动接入）。`@webgl-examples` 别名在 `vite.config.ts` / `tsconfig.json` 双处注册，指向 `src/chart-examples/webgl`。

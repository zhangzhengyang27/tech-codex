## 0. 本篇定位

这是文档集的最后一篇，回答三个"用得着"的问题：**这个词到底指什么**（术语表，含跨篇用词的统一口径）、**这段代码在哪些篇里被讲过**（源码文件与篇目的反向索引）、**我现在要做某件事该按什么顺序读**（按任务的阅读路径）。前三篇式的"机制讲解"到此收束，本篇是查用型工具篇——它的成功标准不是通读酣畅，而是你在任意一篇里迷路时能从这里三步内找回坐标。

关于术语的口径先说一句总原则：本项目源码注释里的用词与 AGENTS.md 的产品词汇表并非处处一致（如 catalog.ts 注释称"64 项子生成器"而实际条目数在 52-66 间漂移，见《13-技术债务》第 3 条），本术语表以**文档集内部一致**为准绳，个别词条给出了"源码写法 / 建议口径"的双轨表述。术语定义尽量给出首次出现的篇目，那里有最完整的语境。

### 1.4 数据、网络与认证

这一组术语横跨前后端，最需要统一口径的原因是**同一件事在两侧的叫法不同**：后端源码说 `refreshAccessToken`（旋转），前端源码说 `refreshAuth`（静默刷新），文档里统称"刷新链路"；后端说"宽容模式守卫"，前端对应物是"401 全局处理器"，两者其实是同一条失败路径的两岸。下表词条以文档集用语为准，源码函数名在定义里注明。

| 术语 | 定义 | 首详篇目 |
|------|------|---------|
| AuthResult | 登录/注册/刷新统一的返回结构：`{ accessToken, refreshToken, expiresIn, user }` | 《19》§2 |
| 双 token | access token（JWT）+ refresh token（64 字节随机 hex 落库、可吊销、一次性旋转） | 《16》ADR-11 |
| 旋转与重用检测 | refreshAccessToken 的安全机制：旧 token 用后即吊销；已吊销 token 再用即判泄露并全量吊销该用户令牌 | 《19》§3 |
| 提前 5 分钟刷新 | authStore 的 `REFRESH_AHEAD_SECONDS = 300`：模块级定时器在过期前静默换新；恢复会话后必须重挂 | 《08》§2.2 |
| 宽容模式守卫 | 全局 JwtAuthGuard 特判：完全无凭证放行且 req.user 为 undefined，有凭证但无效才 401 | 《08》§3 |

### 1.5 易混术语辨析

有三组词最容易在阅读与沟通中串味，单独辨析。**"示例"一词的三种所指**：日常说"加一个示例"多指 JSON 示例（SOP-A）；SFC 演示在源码里也叫 demo/演示（PlaygroundPage 的演示清单）；而"示例数据"有时泛指整个内容域。书面沟通建议用全称（JSON 示例 / SFC 演示），本术语表 1.1 节的四个形态名即为标准口径。**"工具"与"生成器"**：catalog.ts 的类型是 `ToolItem`、注释常写"工具"（历史沿袭——板块曾叫 /tools 工具箱），拆分后站内只剩 CSS 工具，产品词汇表要求叫"CSS 实验室"，条目层面"生成器"指 gen-* 组件、"工作台"指三个独立页面、"速查表"指 cheatsheet，三者注册路径不同（见《15》§3.2 的例外注）。**"收藏"的两套实现**：示例收藏（favorites 模块，走后端）与知识库文档收藏（knowledge/favorites，冻结）同名不同物；前端 `useFavorites` 专指前者，含模块级状态与 clearFavorites 登出隔离语义，后者在本文档集一律带"knowledge 前缀"表述。

这张表的用法：改一个文件前，先扫它所在行的"★走读"列——那是最接近原文的讲解，能告诉你改动会落在哪些机制的交界处；review 别人的 PR 时同理。反过来说，若某文件你常改却在本表查不到（比如 `src/views/PlaygroundPage.vue` 只在《11》场景三出现），说明文档集对它的覆盖还是"操作级"而非"机制级"，照 AGENTS.md 第 15 节回写清单补篇即可。

## 3. 按任务阅读路径

五条路径覆盖维护者的五类高频任务，每条都按"最小路径（只读必需的，直接动手）— 展开路径（机制依据与易错点）— 验证清单"三段组织。路径的设计原则是**动手所需的知识不与理解所需的知识混编**：最小路径刻意只给操作文档（SOP），机制与决策篇目放在展开层——急于交付的人走最小路径不会迷路，想弄懂原理的人顺展开路径能一路读到 ADR 与走读实录。各路径共用同一个总入口约定：任何一步卡住，先查 §1 术语表确认用词，再查 §2 反向索引定位机制篇目，最后查《12-FAQ》对症状。

### 3.1 路径 A：新增一个 JSON 示例

**目标**：给示例库加一条内容。**最小路径**（约 15 分钟）：《11》场景一 → 《06》SOP-A → 动手。**展开路径**：动手前补读《04》§3（JSON 结构与编辑纪律：id 永不复用、不要手动重排、tags 复用词汇）与《03》§3.1（CodeExample 字段全表）；遇到"html5 主题预览布局不对"回《18》§1.2（example-stage 机制）；遇到"改了没生效"回《12》§1（localStorage 覆盖层残留是头号嫌疑）。**验证**：`pnpm lint && pnpm typecheck` + 详情页预览/源码/设备切换三检（《11》场景一的验证清单）。

### 3.2 路径 B：新增一个 CSS 生成器

**目标**：给 CSS 实验室加一个"调参数抄代码"的工具。**最小路径**：《11》场景二 → 《18》§4（BaseGenerator 契约与最小实现范本）→ 动手，全程应为"写一个组件 + 登记两行"。**展开路径**：《07》§2.2-2.3 理解路由分发与卡片墙聚合（决定你的 kind 要不要进 FAMILY 族）；《19》§10 是可直接照抄的最小配置；《04》§2.5（ToolItem 十色系统与字段语义）用于选 accent 与 icon。**易错点预读**：TOOL_ROUTE_PATHS 缺键会类型报错（这是保护不是障碍）；类型必须从 `generatorTypes.ts` 导入（TS2614 陷阱，《18》§4.1）。**验证**：`/css-lab/css/gen-xxx` 直达、首页 Bento 计数 +1、侧栏可搜索、代码浮层可复制（《11》场景二验证清单）。

### 3.3 路径 C：把内容接回数据库（反向迁移）

**目标**：若业务重新要求"后台即时改内容、不发版生效"，需要把内容域迁回 PostgreSQL 并恢复前端消费。**路径**（按依赖顺序）：《16》ADR-01/02/12 三条决策是前置认知——签名兼容承诺（ADR-02）意味着迁移只需替换 `src/api/examples.ts` 内部实现；《03》§5-6 是新 api 模块的编写惯例，《15》§1.4 是尚在服务的后端端点契约，《19》§8 有其报文实例；《07》§3.5 提示 examples 模块的 service 实现仍完整（含 QueryBuilder 过滤），恢复成本主要在数据回填（8 个 JSON → `server/scripts/` 导入脚本族）与覆盖层语义的取舍（localStorage 覆盖要么废弃、要么升级为服务端草稿，《05》流程二的建议是后者）。**决策清单**：先回答"内容是否需要不发版的运行时写入"（是才迁）；迁移后 `updateExample` 的落点要从覆盖层改回 API；最后按《13》第 2 条的流程处理 examples 模块从"冻结"转"活跃"的登记与测试补课。`⚠️ 待确认`：反向迁移前应先确认 HTML5 主题 categories 表数据与 8 分组的对应关系是否仍准确（治理产物 sourceGroup 的库内覆盖度未验证）。

### 3.4 路径 D：上线检查

**目标**：把项目部署到生产并确认安全与完整性。**路径**：《06》§3（构建与两种部署形态选型）→ 《06》§7 运维检查清单（九项核对）→ 《08》§8 安全核对单（JWT_SECRET/DB_SYNC/CORS/RUN_ADMIN_TOKEN/admin 限制/cookie Secure）。**展开**：遇到"刷新深链 404"查《06》§6 的 SPA fallback；遇到"预览白屏"查《08》§1 的 `<base>` 同源约束与《12》§3；字体外链与缓存头策略见《10》§6 第 2 条；发版后的"白屏一次自愈"属正常现象（《10》§4）。**一条最有用的实战建议**（出自《06》§6）：本地正常、部署后异常的案例九成落在路径差异、协议网络差异、环境变量差异三点上——`VITE_API_BASE_URL` 是构建期注入，改 env 必须重新构建而不是重启进程。

### 3.5 路径 E（附）：接手项目的第一个星期

若你是新接手的维护者，综合前四条路径的最优顺序是：第 1 天读《00》§6 跑起来 + 《01》§5（八条决策表建立全局观）；第 2 天沿《00》§8 第二站纵切面走一遍源码（列表页 → 数据层 → 沙箱）；第 3 天读《16》（12 条 ADR 把"为什么"补齐）与《13》（知道哪些是坑哪些是冻结资产）；第 4-5 天按 3.1/3.2 各做一次真实的内容提交走完整门禁。一周后你应当能独立回答三类问题：改动落在哪个域、哪篇文档讲了它、验证清单是什么。

这条路径背后有一个值得明说的学习理论：**先操作、后机制、再决策**。直接通读全部 21 篇的吸收率极低，因为机制描述在没有操作记忆支撑时会滑过去不留痕；反过来，先做一次真实提交（哪怕只是加一个示例），让"改了 JSON → 卡片出现 → 预览渲染"的因果链在手上过一遍，再读《07》的机制篇就会不断出现"原来当时是它在起作用"的印证感。ADR 放在第三天也是同理——决策的分量只有撞过它的后果才能体会，比如亲手经历过一次"改了示例没生效"（覆盖层残留），《16》ADR-12 的权衡取舍才会从文字变成经验。

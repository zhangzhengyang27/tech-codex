# 00 项目总览 — H5 游戏厅（html5-games）
> 项目：html5-games ｜ 版本：v1.0 ｜ 生成日期：2026-10-06 ｜ 依据：源码分析

## 1. 项目定位与目标用户

**H5 游戏厅**是一个纯前端的 HTML5 小游戏合集站点，包含 **79 款可直接游玩**的小游戏。根据 `package.json` 的 description 字段（"H5 游戏厅 — 79 款可游玩的 HTML5 小游戏合集（响应式 + 触屏适配）"）与 `README.md` 的自述，该项目从同组织下的 html5-examples 平台「游戏演示」模块独立拆分而来，拆分的核心动机是**解除 PC-only 限制**——即在保持桌面体验的同时，完整支持响应式布局与移动端触屏操作。

从 `src/config/games.ts` 文件头的演进注释可以还原项目历史：最初由原「视觉演示」（ui_visual_demos 表 game 引擎）改造而来，剔除 3D 与 CSS 动画后保留 15 款可玩小游戏，随后经历「主题化改造 + 经典示例填充」（23 款）→「GitHub 框架示例集成」（43 款）→「经典游戏精选集成」（63 款）→「第三批精选集成」（80 条配置、79 个实现文件，详见第 4 节统计口径说明）五个阶段，最终形成当前规模。`docs/plans/` 与 `docs/research/` 目录保留了各批次的实施计划与调研记录（如 `docs/research/framework-research-summary.md` 记录了从 8 个框架 36 个调研项目中精选玩法重写的决策过程），可作为历史背景阅读，但**事实以源码为准**。

项目的目标用户与使用场景：

- **玩家**：无需注册、无需安装、打开网页即玩的休闲玩家。所有游戏支持键盘、鼠标、触屏三种输入方式；最高分保存在浏览器 localStorage 中，回访即可继续冲击纪录。
- **开发者/维护者**：需要新增游戏、修复缺陷或调整大厅体验的前端开发者。本项目刻意采用了「登记一处配置 + 落盘一个组件」的极简接入模型（详见 06-部署运行.md 的「新增一款游戏标准操作流程」），单人即可完成一款新游戏的完整接入。
- **部署者**：构建产物是纯静态站点（无任何后端依赖），可部署到任意静态托管服务。

项目的三条核心设计原则（源自 README「要点」与源码注释，均已在源码中验证）：

1. **无后端依赖**：游戏目录、元数据全部本地化为 TypeScript 配置（`src/config/games.ts`），进度/最高分持久化走 localStorage（`src/utils/highScore.ts`），构建后为纯静态站点。这条原则的直接收益是运维成本归零：没有数据库迁移、没有接口版本兼容、没有服务端扩容；代价是没有跨设备同步与排行榜等社交能力——这是产品层面的有意取舍，接手者若要引入后端，应先评估它对「纯静态可部署」这一卖点的冲击。
2. **静态导入代替运行时编译**：79 款游戏组件经 `import.meta.glob`（`src/games/registry.ts`）在构建期完成代码分割，每款游戏一个独立懒加载 chunk；详情页不使用运行时 SFC 编译器，首屏完全不包含任何游戏代码。这条原则同时解决了「首屏体积」与「安全性」两个问题——产物里不存在 `vue/compiler-sfc`，也意味着任何游戏改动都必须走完整的构建发布流程，无法热插拔。
3. **零素材依赖**：79 张游戏封面由 `GameCover` + `src/components/games/gameCoverRender.ts` 程序化绘制（暗色基底 + 分类色辉光 + 由 id 哈希决定的几何符号），音效与背景音由 `src/composables/useGameAudio.ts` / `useGameBgm.ts` 用 WebAudio 振荡器实时合成，全项目仅 `public/media/mov_bbb.mp4` 一个视频素材（供「视频拼图」游戏使用）。零素材让仓库体积极小、无版权风险，也让「新增一款游戏」不需要美工与音频资源——但代价是所有视觉个性只能来自程序化生成参数，想要精细的美术表现时这条路需要重新评估。

从玩家视角走一遍典型旅程可以快速建立体感：打开站点落在 `/games` 大厅，首屏是欢迎语、主搜索框与四款「核心精选」横带；通过分类 chips（全部 79 / 益智 20 / 棋牌 7 / 动作 25 / 休闲 27）或搜索缩小范围，每页 24 款、URL 可分享；悬停卡片即后台预取游戏代码，点击进入整屏运行页，游戏在统一外壳（GameShell）中呈现——顶栏是标题与分数 HUD，右侧是玩法说明，舞台中央按设定的宽高比最大化；玩毕返回大厅，滚动位置与筛选条件原样保留，最高分已写入本机。整个过程没有一次网络请求指向后端，所有动态性都来自浏览器本地能力。

## 3. 技术栈速览

## 5. 快速上手

环境要求：Node.js ≥ 22、pnpm 10.23（`corepack` 可按 `packageManager` 字段自动取版）。

```bash
pnpm install          # 安装依赖
pnpm dev              # 启动开发服务器，http://localhost:5556（vite.config.ts 固定 host 127.0.0.1 / port 5556）
pnpm test             # 运行 vitest 单元测试（node 环境）
pnpm lint             # ESLint 检查
pnpm typecheck        # vue-tsc 类型检查
pnpm build            # 生产构建（输出 dist/，含每款游戏独立 chunk）
pnpm preview          # 本地预览生产构建
```

三条最常用的源码导航路径：

1. **看懂「一款游戏如何被打开」**：`src/pages/GamesPage.vue`（卡片点击 `openGame`）→ `src/router/index.ts`（`/game/:id` 路由）→ `src/pages/GameDetailPage.vue`（`gameModules` 动态挂载）→ `src/games/snake.vue`（任一游戏）。
2. **看懂「游戏长什么样是统一的」**：`src/components/games/GameShell.vue`——所有 79 款游戏的第一行模板都是 `<GameShell>`，标题/HUD/舞台/说明/浮层五个插槽决定了游戏的页面骨架。
3. **看懂「数据存在哪」**：`src/config/games.ts`（游戏目录）+ `src/utils/highScore.ts`（`h5g:<id>-best` 键）+ `src/composables/useGameAudio.ts` 的 `game-audio-muted` 键与 `useGameBgm.ts` 的 `h5g:bgm-muted` 键。

开发时的两个高频调试场景也在此提前给出答案。其一，**为什么改了游戏但列表没变化**：大厅数据来自 `src/config/games.ts` 的编译期常量，改完需要保存触发 Vite 热更新；若改的是测试断言相关文案（79 这个数字），记得同步 06 篇 SOP 列出的三处。其二，**为什么声音不响**：WebAudio 的 AudioContext 必须在用户手势内创建或恢复，直接刷新页面后程序化播放会被浏览器拦下——这是 `useGameAudio.ts` 里 `unlock()` 机制存在的原因，属预期行为而非缺陷；此外先检查 `localStorage` 里的 `game-audio-muted` 与 `h5g:bgm-muted` 两个键是否为 `'1'`。

# 00-项目总览

> 项目：react-travel ｜ 版本：v1.0 ｜ 生成日期：2026-10-05 ｜ 依据：源码分析

## 1. 项目定位与目标用户

**react-travel（小叶旅游网）** 是一个面向 C 端休闲旅行者的全栈在线旅游（OTA）展示与预订站点。它提供旅游线路的浏览、搜索、筛选、收藏、评论、加购物车、下单与模拟支付等完整闭环能力，覆盖国内（三亚、云南、北京、成都、西安等）与出境（日本、泰国、马尔代夫、法国等）18 个热门目的地的精品线路。

项目的目标用户可以分为两类：

- **旅行消费者（站点访客）**：希望按"周末游 / 跟团游 / 自由行 / 私家团 / 酒店+景点 / 当地玩乐 / 定制游"等类目快速找线、比价、看评价，并完成收藏与预订。未登录用户可浏览与搜索全部内容，登录后解锁收藏、评论、购物车、下单等个性化能力。
- **接手维护的开发者**：项目由经典的 CRA（Create React App）SPA + Egg.js 独立后端架构，整体迁移到 Next.js 15 App Router 全栈架构。仓库同时保留了迁移前的前端代码（`client/` 兼容层）与迁移后的新页面及后端（`app/`），因此文档需要特别讲清双层结构与边界，这也是本套文档的核心使命之一。

从工程角度看，该项目有四个鲜明特征：

1. **全栈一体**：前端页面与后端 API（Next.js Route Handlers）共处一个 Next.js 工程，同一个仓库、同一次构建、同一个 Node 进程，不再有独立的后端服务。
2. **迁移兼容**：旧 CRA 的 `src/` 整体平移为 `client/`，通过 `lib/router.tsx`（react-router-dom → next/navigation 的同名 API 垫片）实现旧组件"零改动"运行在 App Router 下。
3. **SEO/GEO 友好**：核心内容页（首页、详情、搜索、目的地、专题、游记）均改造为 React Server Components（RSC）服务端直取数据 + ISR 增量渲染，并注入 JSON-LD 结构化数据（`lib/seo.ts`、`app/sitemap.ts`、`app/robots.ts`、`app/opengraph-image.tsx`）。
4. **生产级防御**：JWT + Redis（可选）鉴权、内存限流（`lib/rate-limit.ts`）、HTML 净化（`lib/sanitize.ts`）、PostgreSQL advisory lock 防并发加购、价格快照防订单金额漂移等，均为源码中真实存在的工程细节。

## 2. 核心功能清单

| 内容浏览 | 关键词搜索 + 价格筛选 + 排序 + 分页 | `/search/[keywords]` | RSC 首屏 + 客户端接管（`app/search/[keywords]/page.tsx`） |

| 内容浏览 | 旅游专题（主题线路聚合） | `/topics` | RSC + ISR 3600s（`app/topics/page.tsx`） |
| 内容浏览 | 用户游记（图片预览/评分） | `/reviews` | RSC + ISR 3600s（`app/reviews/page.tsx`） |
| 内容浏览 | 关于我们 / 帮助中心（FAQ 手风琴） | `/about`、`/help` | 纯客户端静态页（`client/views/about`、`client/views/help`） |
| 搜索辅助 | 热词联想（300ms 防抖）+ 热门关键词 | Header / 首页搜索框 | `client/hooks/useHotKeywords.ts` + `app/api/commons/hotKeywords/route.ts` |
| 账号体系 | 注册 / 登录 / 退出 / 资料编辑 | `/register`、`/signin`、`/personal` | `app/api/auth/*`、`app/api/user/*`、`client/stores/useUserStore.ts` |

所有受保护功能（购物车、下单、收藏、评论写操作、个人资料）的登录判定由三层协同完成：`middleware.ts` 做"是否携带凭证"的粗过滤，各 Route Handler 内 `requireAuth()`（`lib/auth.ts`）做真正的 JWT 校验，客户端 `AuthGuard`（`app/_components/AuthGuard.tsx`）做受保护页面的跳转兜底。

## 3. 技术栈速览与选型理由

| 类别 | 技术 | 版本（package.json） | 选型理由（源码佐证） |
|---|---|---|---|
| 框架 | Next.js（App Router） | ^15.1.0 | 迁移目标：SSR/RSC 提升 SEO 与首屏；`next.config.js` 配置 `output: "standalone"` 支持容器独立部署 |
| UI 运行时 | React | ^18.3.1 | 与 Next 15 兼容的最低稳定线；RSC 与客户端组件混合渲染 |
| 组件库 | antd | ^5.24.2 | 原 CRA 时代即用 antd v5，迁移零成本；配套 `@ant-design/icons` ^5.6.1 |
| antd SSR | @ant-design/nextjs-registry | ^1.0.2 | antd v5 为 CSS-in-JS，需 `AntdRegistry` 在服务端抽取样式，避免首屏闪烁（`app/layout.tsx`） |
| 客户端状态 | Zustand | ^5.0.14 | 迁移中由 Redux Toolkit 简化而来；7 个轻量 store（`client/stores/`），localStorage 手工水合规避 SSR 报错 |
| ORM | Prisma | ^7.9.0 | 新版 `prisma-client` 生成器，产物输出到 `generated/prisma`；配合 `@prisma/adapter-pg` 驱动适配器直连 PostgreSQL |
| 数据库 | PostgreSQL | — | 原 Egg.js 用 MySQL（egg_house 库），迁移决策切换 PG（见 `NEXT_MIGRATION_PLAN.md` §0）；`prisma.config.ts` + `DATABASE_URL` |
| HTTP 客户端 | axios | ^1.8.1 | 沿用旧前端习惯；`client/lib/http.ts` 安装全局拦截器自动附带 `Authorization: Bearer` |
| 鉴权 | jsonwebtoken + ioredis | ^9.0.2 / ^5.4.2 | JWT 签发校验；Redis 缓存 token 实现服务端注销（可选，无 Redis 时优雅降级，`lib/auth.ts`） |
| 密码 | bcryptjs + Node crypto md5 | ^3.0.3 | 新账户 bcrypt（12 轮），存量账户保留 `md5(password+salt)` 兼容，`lib/password.ts` 渐进迁移 |
| 内容安全 | sanitize-html | ^2.17.7 | 富文本白名单净化（详情页 features/fees/notes 走 `dangerouslySetInnerHTML`），纯文本字段剥标签（`lib/sanitize.ts`） |
| 时间 | dayjs | ^1.11.21 | antd v5 官方配套日期库，`app/providers.tsx` 中设置中文 locale |
| 运行环境 | Node.js ≥ 20 / pnpm ≥ 9 | engines 约束 | `package.json#engines` 显式声明 |

补充说明两点工程性配置的意图：`next.config.js` 中 `images.disableStaticImages: true` + webpack `asset/resource` 规则，是为了让 `import img from "x.png"` 依旧返回 URL 字符串（对齐 CRA 语义），旧组件里的 `<img src={logo}>` 无需改动；`rewrites()` 把 `/auth/:path*` 映射到 `/api/auth/:path*`，是因为旧前端 slice 的登录/注册写死了 `/auth/login`、`/auth/register` 路径，保留 rewrite 可让 `client/` 层零改动。

**双层边界约定（新代码放哪一层）**：

- `app/` 层负责三件事：文件系统路由与页面外壳（RSC 数据直取 + metadata）、`app/api/**` 后端接口、跨页面客户端守卫（`_components/AuthGuard.tsx`）与全局 Provider。新页面应优先落在这一层，数据获取写 RSC（`await` 调 `lib/services/*`）。
- `client/` 层是"可渲染的 UI 组件库 + 状态仓"：`app/` 的 `page.tsx` 只做数据获取，然后把数据以 props 注入 `client/views/**` 的客户端组件；写操作与交互状态由 `client/stores/**` 承担。该层禁止直接访问数据库与 Prisma。
- `lib/` 层是唯一允许触碰 Prisma 的地方（RSC 与 Route Handler 共用 `lib/services/*`），保证"同一份业务逻辑，RSC 直取与 API 回退两条链路数据一致"。
- 判断口径：需要 SEO/首屏直出的内容 → `app/` RSC + `client/` 展示组件；纯交互页（购物车/订单/个人中心）→ `app/` 薄壳 + AuthGuard + `client/` 视图；任何数据访问 → `lib/services/`。

## 5. 快速上手

环境要求：Node.js ≥ 20、pnpm ≥ 9、PostgreSQL（默认 5432）、Redis（可选，登录注销增强）。

```bash
# 1. 安装依赖（postinstall 自动执行 prisma generate，产出 generated/prisma）
pnpm install

# 2. 配置环境变量
cp .env.example .env
#   DATABASE_URL=postgresql://user:pass@localhost:5432/travel?schema=public
#   JWT_SECRET=（开发可用示例值；生产必须 openssl rand -hex 32）
#   SALT=（同上，openssl rand -hex 16）
#   REDIS_URL=redis://localhost:6379（可留空）

# 3. 建表 + 灌入种子数据（32 条线路、8 个 demo 账号等）
pnpm prisma:push
pnpm db:seed

# 4. 启动开发服务器 → http://localhost:3000
pnpm dev

# 生产构建与运行（产出 .next/standalone，可用 node .next/standalone/server.js 独立部署）
pnpm build && pnpm start
```

种子账号密码统一为 `123456`（见 `prisma/seed-data/users.ts` 的 `DEMO_PASSWORD`），如"旅行达人小王""摄影师阿杰"等 8 个。验证后端可直连：`GET /api/productCollections` 返回三个推荐集合即说明 DB 链路正常；`POST /auth/login`（经 rewrite 到 `/api/auth/login`）返回 `token` 即说明鉴权链路正常。

开发期质量门禁：项目未配置单元测试框架（`package.json` 无 test 相关依赖），类型检查依赖 `tsconfig.json` 的 `strict: true`，实际门禁是 `pnpm exec tsc --noEmit` 零错误 + `pnpm build`（Next 构建内含类型检查）全绿——这也是迁移文档（`NEXT_MIGRATION_PLAN.md`）中每个 Phase 的验收标准。

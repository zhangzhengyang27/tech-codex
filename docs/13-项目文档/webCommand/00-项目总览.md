# 00 项目总览

> 项目：webCommand ｜ 版本：v1.0 ｜ 生成日期：2026-10-05 ｜ 依据：源码分析

## 1. 项目定位与目标用户

webCommand（工程名 `webcommand-nuxt`，见 `package.json` 的 `name` 字段，版本 `0.1.0`）是一个**极客风格的终端式浏览器主页**：用户把浏览器新标签页指向本站点后，看到的是一个几乎全屏的黑底终端界面，所有功能都通过"敲命令"完成——`baidu 关键词` 打开百度搜索、`todo add 写周报` 添加待办、`weather 北京` 查天气、`stock sh600519` 查股票行情。它不是远程 Shell，也不会在服务器上执行任何系统命令；"终端"只是交互形态，命令的解释与执行全部发生在浏览器前端，只有少数需要绕过 CORS 或涉及账号数据的操作才会请求自家后端 API。

源码出处方面，README.md 明确声明本项目是衍生作品：主体交互与多数命令实现来自 **YuIndex**（作者 yupi，21 个文件带 `@author yupi` 署名，如 `app/core/commands/gotoCommand.ts`、`app/components/shortcuts.ts`），`curl` 命令移植自 m4tt72 的终端主页项目（`app/core/commands/curl/curlCommand.ts` 标注 `@author m4tt72 (ported)`）。本仓库自研的部分包括：云同步合并语义与墓碑机制（`app/composables/cloudMerge.ts`）、运行期配置注入层（`server/utils/appConfig.ts`）、SQL 迁移器（`server/utils/migrations.ts`）、分级配额与账号准入（`server/utils/dataAccess.ts`、`server/utils/accountPolicy.ts`）、健康探活（`server/api/health.get.ts`）、双轨测试底座与部署脚本（`test/`、`scripts/`）。

目标用户可以归纳为三类：

1. **重度键盘用户 / 开发者**：习惯命令行思维，希望新标签页就是一个可以敲命令的工具箱，用 `help`、`Tab 补全`、`Ctrl+R` 反向搜索历史等终端习惯完成日常动作；
2. **多设备个人用户**：注册登录后，待办（todo）、空间（space）、速记（note）、自定义命令（custom）、终端配置（terminalConfig）、主题（theme）六类数据可在多设备间云同步；
3. **自建部署的运维型用户**：项目提供 Dockerfile、docker-compose 编排模板、部署与备份脚本，定位是"自建部署"的个人服务，而非多租户 SaaS。

工程形态上是**前后端合并单体**：Nuxt 4 以 SPA 模式（`nuxt.config.ts` 中 `ssr: false`）承载前端，同一工程内的 `server/` 目录由 Nitro 提供 REST API，生产环境以单个 Node 进程对外服务（静态资源 + `/api` 路由），数据库为 MySQL（Sequelize ORM）。

## 2. 核心功能清单

功能以"命令"为单位组织，命令清单唯一登记在 `app/core/commandRegister.ts`（数组顺序即 `help` 展示顺序），执行引擎在 `app/core/commandExecutor.ts`。按业务域归组如下：

| 功能域 | 命令（func） | 核心能力 | 是否需登录 | 实现位置（相对项目根） |
| --- | --- | --- | --- | --- |
| 网页导航 | `goto`（别名 to/open/visit/jump/跳转） | 打开 URL，支持空间条目名解析、`-s` 当前页打开 | 否 | `app/core/commands/gotoCommand.ts` |
| 网页搜索 | `search`/`baidu`/`google` | 多引擎搜索，`-f` 选源、`-c` 当前页、`-p` 搜图片 | 否 | `app/core/commands/search/*.ts` |
| 待办事项 | `todo add/list/delete/done/clear/stats` | 任务增删改查与统计，登录后云同步 | 同步需登录 | `app/core/commands/todo/` |
| 云端空间 | `space` 系（`ls/add/mkdir/rm/pwd/cd/mv/cp`） | 扁平 key-value 模拟的文件系统 + 收藏夹，提示符显示当前目录 | 同步需登录 | `app/core/commands/space/` |
| 速记 | `note add/list/rm/clear` | 随手记一句话，登录后云同步 | 同步需登录 | `app/core/commands/note/` |
| 自定义命令 | `custom add/list/remove` | 把常用命令文本映射为自定义名字（如 `g => goto`） | 同步需登录 | `app/core/commands/custom/` |
| 账号体系 | `user`（`login/register/logout/passwd/reset/delete`） | 登录、注册、注销会话、改密、邮箱验证码找回密码、注销账号 | — | `app/core/commands/user/` |
| 数据备份 | `export`/`import` | 导出 JSON 备份文件下载；粘贴 JSON 恢复 | 否 | `app/core/commands/data/` |
| 信息查询 | `weather`/`news`/`stock`/`ip`/`qrcode` | 天气（wttr.in 代理）、热搜（三源容错）、A股行情（新浪）、公网 IP（四源容错）、二维码 | 否 | 各命令目录 + `server/api/` 代理 |
| 开发小工具 | `calc`/`convert`/`json`/`b64`/`uuid`/`ts`/`regex`/`color`/`varbook` | 计算器、单位换算、JSON 格式化、Base64、UUID、时间戳、正则、取色器、变量命名助手 | 否 | `app/core/commands/calc|convert|devtools|varbook/` |
| 终端本身 | `clear`/`history`/`help`/`info`/`ping`/`date`/`timing`/`shortcut` | 清屏、历史、帮助、站点信息、连通测试、日期、定时器、快捷键表 | 否 | `app/core/commands/terminal/` 等 |
| 个性化 | `background`/`theme`/`hint`/`welcome`/`reset` | 终端背景（自定义 URL 或随机壁纸）、8 套配色主题、输入提示开关、欢迎语、配置重置 | 同步需登录 | `app/core/commands/terminal/config/`、`theme/` |
| HTTP 工具 | `curl` | 浏览器端发起 GET 等 HTTP 请求并输出文本（受 CORS 限制） | 否 | `app/core/commands/curl/curlCommand.ts` |

除命令外，终端还内置了完整的交互基础设施：`↑/↓` 翻阅历史、`Ctrl+R` 反向增量搜索、`Ctrl+K` 命令面板（模糊过滤全部命令与自定义命令）、`Tab` 循环补全命令名/子命令/选项、`Ctrl+L` 清屏、`Ctrl+O` 全部折叠/展开、输出快照刷新恢复、密码参数自动脱敏入历史等（见 `app/components/shortcuts.ts`、`app/components/Terminal.vue`、`app/components/outputSnapshot.ts`）。

阅读建议：想理解"一条命令如何被执行"，从 `app/pages/index.vue` → `app/components/Terminal.vue` 的 `doSubmitCommand` → `app/core/commandExecutor.ts` 这条线读起；想理解"登录与数据如何上云"，从 `app/core/commands/user/userCommands.ts` → `app/composables/cloudSyncRegistry.ts` → `app/composables/useCloudSync.ts` 读起；想理解"服务端如何挡住非法请求"，从 `server/utils/response.ts`、`server/utils/rateLimit.ts`、`server/utils/dataAccess.ts` 三个文件读起。

## 5. 快速上手

前置条件（README.md 明确要求）：Node ≥ 22.18（跑测试需要原生类型剥离；22.12/22.15 会报 `ERR_UNKNOWN_FILE_EXTENSION`，24.21 已实测可用）、pnpm、一个可连接的 MySQL。

```bash
# 1. 准备环境变量（复制示例并填写 DB_*；本地库可直接 localhost/root）
cp .env.example .env

# 2. 安装依赖（postinstall 会自动执行 nuxt prepare）
pnpm install

# 3. 启动开发服务器（http://localhost:3000，前端与 /api 同源）
pnpm dev
```

数据库表无需手工创建：Nitro 启动时 `server/plugins/migrate.ts` 会执行 `server/utils/migrations.ts` 中的幂等 DDL，建出 `user`、`user_data` 与水位表 `schema_migrations`。

常用质量命令（均来自 `package.json` 的 scripts）：

```bash
pnpm lint          # ESLint（代码质量）
pnpm typecheck     # nuxt typecheck（vue-tsc 全量类型检查）
pnpm test          # node --test test/*.spec.ts（纯函数 + 静态契约）
pnpm test:routes   # vitest run（路由层）
pnpm test:all      # 两套测试依次跑
./scripts/check-all.sh   # 格式 → lint → 类型 → 两套测试，一条命令全跑
```

真实数据库端到端冒烟（不碰生产库）：`./scripts/init-test-db.sh` 生成 `.env.test` 与 `scripts/init-test-db.sql`，手工执行该 SQL 建库建账号后，`./scripts/smoke-cloud-sync.sh` 会在 3100 端口起 dev 服务对 `webcommand_test` 库跑 26 条断言，覆盖迁移建表、blob 逐字往返（含 4 字节 emoji）、跨用户隔离、白名单与尺寸上限、改密与注销闭环、限流 429。

上手验证路径：打开首页后输入 `help` 应看到命令总表；`user register -u test -p 12345678 -e t@t.com` 注册并自动登录；随后 `todo add 学一下 help 里的命令`、`theme set Dracula` 即可体验"本地持久化 + 登录后云同步"。

# 02-infrastructure 深导览

> 一句话：这一层管「被两个以上消费者共用的底座状态」——几何、可见、DOM 动作、值、派生顺序、渲染窗口、动画时序、叠序与文案；不管单个组件的 props 语义与外观（归 `03-components` 对应类篇），也不管 monorepo 拓扑、生成物链路与注入链本身（归 `A01`、`A02`、`A05`）。

## 一、这一层在解决什么

基座不是「小一号的组件」，而是把某一种跨组件共享的状态独占到一个目录里，让所有消费者只剩一条写入路径。按「这份状态是什么」切，16 篇可以排成八格：浮层该在哪是几何状态，归 `I01`；该不该在、什么时候在是可见状态，归 `I02`；节点包含、可见性、动态样式注入与事件封装是 DOM 侧的公共动作，归 `I03`；用户敲到第几步是值状态，拆成 `I04`（输入基座）与 `I13`（其余控件的受控内核）两半；排序筛选分页谁先跑是派生顺序，归 `I06`；哪几行进视口是窗口状态，归 `I05` 与 `I08`；动画播到哪一拍是时序状态，归 `I09`；谁压住谁是叠序状态，归 `I10`；话术与日期语言是文案状态，归 `I11` 与 `I07`。剩下的 `I12`、`I14`、`I15`、`I16` 不持有状态，只约束别人怎么接线。

真正的判据不是「谁更底层」，而是**这份状态有没有第二个写者**。`I08` 坑 6 记下的是同一份窗口数学存了两份拷贝、且已经开始各修各的；`I10` 坑 8 记下的是同一件发号工作有两个起跳值不同的实现，而换一条 import 连类型错都不报。遇到「近义基座」，先数写入路径有几条，比争论职责边界管用。

状态流向是这一层最反直觉的地方：基座普遍是「渲染先行、测量后置、回执只补一次」，而不是响应式数据流。`I05` 坑 1 里列宽必须等 DOM 测回来才有值，缺任意一格就把整块表头藏起来；`I01` 坑 6 说动画期发出的定位请求不排队、直接丢弃；`I02` §六 算出一次 hover 到动画开播最少跨两个宏任务加两帧 raf。排查时机类问题要按「谁在等谁」画箭头，而不是按依赖图。

分层在这一层只是约定，不是机制。`I05` §六 记录 vendor 层的 `Cell` 反过来 import 业务层的 slot；`I06` §六 记录一整套能跑、1,998 行的 composable 从来没被接进 `setup`，于是 `table-core` 的 flat 分支变成「测得最全但线上零引用」的孤儿（`I06` 坑 1、`C08-02` 论点 1）。`vc-*` 与业务目录之间没有编译期闸门，跨包侧更弱：`I15` 坑 7 说明 icons 连 `typecheck` 脚本都没有，`I16` §七 说明 core、utils、metadata 三包零测试，而 metadata 的漂移只有在消费方构建时才暴露（`I16` 坑 4）。

双实现并存是常态而不是事故，这点必须写进心智模型：虚拟化两套（`I08`）、发号器两套（`I10` §六 取舍三）、受控判定两套（`I13` §六 取舍三）、事件监听封装与裸调用两套（`I03` §六）、同名工具函数跨三层各一份（`I03` 坑 7）、motion 兼容转发层加整目录副本（`I09` §六 取舍四）。选错的代价通常是静默的——`I13` 坑 3 里把 `useState` 换成 `useMergedState` 或反向替换都不报错，只让组件悄悄失去受控能力。

测试面要按运行器的 glob 判、不能按目录位置猜，而且「有测试」不等于「测的是线上那份」。几何与时序侧的 `I01`、`I02`、`I05`，内核目录侧的 `I04` 四层、`I07` 的 `vc-picker`、`I08` 的引擎 A，适配与工具侧的 `I03`、`I12`、`I13`、`I15`，再加上 `I16` 的三个包，都是零直接用例（各篇 §七 都做了两法交叉）。剩下的几处也不是安全网：`I06` 只有 1 个测试文件而它测的正是死分支，`I08` 的 353 行只护引擎 B 且不含窗口数学，`I09` 的 JS 半边有两条曲线用例、CSS 半边零，`I11` 唯一那个文件里两条真正有断言意图的用例整条 `it.skip`。所以本层所有改动路线共用一条前提：**先数引用点，再数测试点**，`I03` 坑 5 与 `I13` 坑 8 都是「看着该修、其实零消费者」的实例。

## 二、选型表（近义组件怎么选）

读法：左两列解决「这个症状归哪个基座」，第三列解决「这件事其实不归基座，归谁」——本层最常见的误判不是选错基座，而是拿着基座的结论去改组件，或拿着组件的观感问题来翻基座。**判据列里的编号就是这一行的全部论证，展开在被引的那篇。**

| 要解决的问题 | 选它 | 而不是另一个 | 判据 |
| --- | --- | --- | --- |
| 浮层落在哪个方位、越界要不要翻面夹紧 | `I01` | 组件层自算 `left/top`，或改 Tooltip 的 placement 语义（`C07-03`） | placements 表把 placement 名翻成 points 对，基座与业务各存了一份反查（`I01` §六 取舍 5、`C07-03` 论点 4）；方位类名错配只在组件侧显形（`I01` 坑 3、`C07-03` 坑 2） |
| 什么时候弹、外部点击怎么算、渲染闸门归谁 | `I02` | Modal 与 Drawer 的遮罩、滚动锁定、销毁时机（`C07-01`、`C07-02`） | Modal 的滚动锁走 Portal 那条链，`Dialog` 里的 scrollLocker 分支对本路径恒不执行（`C07-01` 论点 5、`I03` 坑 5） |
| 节点包含、可见性、动态 style 注入、事件封装 | `I03` | `packages/utils` 或 `_util` 里的同名函数（`I16` §六） | 同一个名字在三层各有一份、强度不同，IDE 自动导入选错也能编过（`I03` 坑 7） |

| 长列表条目高度不可预知（图片、富文本、可展开行） | `I08` 引擎 A `vc-virtual-list` | `virtual-list` 与 `virtual-scroller`（引擎 B） | 引擎 B 全程不测单项高度，声明与实际不符就永久漂移（`I08` 坑 3）；按 key 寻址只有引擎 A 支持（`I08` §六） |
| 条目恒定，且要横向、双向、懒加载或仅追加 | `I08` 引擎 B 的公开件 `virtual-list` | 引擎 A；或为了「内部件」去引 `virtual-scroller` | 引擎 A 连横向坐标轴都没有（`I08` §六 能力矩阵）；公开件与内部件是同一份码，选谁只取决于能不能依赖 `vc-*` 目录（`I08` §六） |

| 告警去重、能力探测时机、URL 消毒、SSR 抽样式 | `I14` | 组件里的 SSR 判空与首屏缺样式（`C12-06`） | 公开 Portal 与浮层基座完全不通，挂载点是两套口径（`C12-06` 论点 1）；顶层求值探测会把「不支持」烧进服务端结果（`I14` 坑 8） |
| 新增一个图标、改一个图标名 | `I15` | 图标尺寸、旋转与观感对齐（`C01-02`） | 名字改动要同时覆盖四张表而没有任何机器校验（`I15` 坑 1）；`size` 得走 `font-size`，`spin` 与 `rotate` 是死 API（`I15` 坑 2、`I15` 坑 4） |

## 三、坑索引（症状 → 哪一篇的坑 N）

下面按症状分组，不做机制展开。同一条症状在基座篇与组件篇都出现过时，两边编号都给出来，改哪一边由 §二 的判据决定。

**浮层位置与裁切**

- **浮层被视口或容器裁掉、纵向该翻面却不翻** → `I01` 坑 1（调用方浅合并把 `overflow` 整块替换，「只关 X」变成「X 与 Y 全关」）；容器换了但节点没换是另一条，`I01` 坑 2。
- **右键菜单或点模式下面板方位类名指到别的方向，位置却是对的** → `I01` 坑 3；Tooltip 侧的同一症状登记在 `C07-03` 坑 2。
- **浮层在 DOM 里、`v-show` 为真却永不显示，控制台干净** → `I02` 坑 4 与 `I01` 坑 4 是同一条死锁的两端，链上没有任何超时兜底；移动端 `forceAlign` 空转是另一回事，看 `I01` 坑 8、`I02` 坑 5。
- **动画期与测量期的定位请求石沉大海，动效结束才归位** → `I01` 坑 6；想改这一条要同时动两处门禁，只改一处会造出新的死锁（同坑的改法段）。
- **滚动期不跟随、iframe 内焦点复原失效** → `I01` §六 取舍 4（不监听 scroll 是有意的）、`I01` 坑 7。

**弹出、关闭与事件**

- **配置传了却不弹或不关** → 先查词表 `I02` 坑 8（`showAction` 与 `action` 不是一套词），再查根节点数 `I02` 坑 1，最后查预热 `I02` 坑 2（`forceSubMenuRender` 正踩在上面，链路五跳）。
- **以为点浮层内容会把外层浮层误关** → `I02` 坑 7（这条症状 2026-09-30 实测**不成立**：document 侧收的就是 `mousedown`，被内容截掉冒泡后判定函数根本不跑；该坑剩下的是代码事实——`withModifiers` 的 capture 是空操作，当前可用靠的是顺序巧合）；Modal 用「按下与抬起」记账是组件层的另一套做法，看 `C07-01` 论点 3。
- **容器节点越攒越多、清不掉，选择器多出一层** → `I02` 坑 3；`destroyPopupOnHide` 与 `autoDestroy` 都管不到那层 wrapper。
- **共享的 motion 常量传给两个浮层，前一个的动画永不结束** → `I02` 坑 6；表现与 `I09` 坑 3 同形，判据是「animation 对象有没有被就地改写」。

**表格**

- **表格状态错乱、改了内核代码线上却没变** → `I06` 坑 1（flat 分支生产零引用）；这一族的半丢状态：档位锁死 `I06` 坑 2、`v-model:multi-sort-meta` 失同步 `I06` 坑 3、翻页丢展开 `I06` 坑 5、全选不等于本页 `I06` 坑 6、非受控过滤不成立 `I06` 坑 7。
- **切换列时表头整块消失一帧、固定列叠在一起、列宽串到别的列** → `I05` 坑 1、`I05` 坑 2、`I05` 坑 3，右固定列的取整缝是 `I05` 坑 4。
- **鼠标还在行上，hover 底色自己掉了；展开行收起后 DOM 与内存不回落** → `I05` 坑 7、`I05` 坑 8，两条都是「命令式写 DOM、渲染态不知情」的同族。
- **按类名覆盖固定列样式毫无效果** → `I05` 坑 5（一对方向相反的断链：一个有产无消、一个有消无产）；子列写 `fixed: undefined` 吃掉分组继承是 `I05` 坑 6。
- **`showHeader = false` 把固定在顶部的 summary 一起干掉** → `I05` 坑 9；`data-xy-scrollable` 恒不渲染是 `I06` 坑 4，目前无样式消费它，属潜伏缺陷。

**虚拟化（两类症状、两份实现）**

- **长列表滚动抖动、总高跳动、偶发白块** → 先定实现再定坑：可变高度走引擎 A，条目 key 不重复是 `I08` 坑 1、条目根节点必须单元素且能承 ref 是 `I08` 坑 2；恒定高度走引擎 B，`itemSize` 与真实不符是 `I08` 坑 3、行内状态串行是 `I08` 坑 5。
- **`scrollTo` 静默无效或定位后行号短暂错位** → 引擎 B 是 `I08` 坑 4（越界只校验下界、未挂载直接短路），引擎 A 的多帧重试语义见 `I08` §六。
- **修了一份拷贝，另一份缺陷二次出现** → `I08` 坑 6；组件侧的对应面是 `C08-07` 论点 1（孪生拷贝已各自分叉）与 `C08-06` 论点 3（一次 `scrollToIndex` 之后滞回缓冲被永久旁路）。改树或表格的行高导致错位，先读 `C09-01` 坑 1。

**动画与 reduced-motion**

- **动画根本不播、控制台与快照都正常** → `I09` 坑 1（JS 类名协议与 CSS 生成是两条互不调用的链路）。
- **动画结束后元素带着内联高度和裸类名残留** → `I09` 坑 3；同类表现为「前一个浮层永停在 motion」的是 `I02` 坑 6。
- **写了 `-enter-from` 永不命中** → `I09` 坑 6（from 阶段被改写为三段类名，只有 drawer 与 tabs 自己补齐）。
- **SSR 首屏所有已展开面板重放一次折叠动画** → `I09` 坑 7；自定义前缀后折叠动画静默失效是 `I09` 坑 2。
- **未响应 `prefers-reduced-motion`** → 这不是接线错，是根本没有通路：helper 已就位但零消费者，属设计缺口（`I09` §六 取舍五）；要连带决定静态检查落点时读 `I14` §六。
- **长时间运行后 raf 表只增不减、某条在途回调再也取消不掉** → `I09` 坑 4。

**层级**

- **给浮层的 CSS 加 `z-index` 完全不生效** → `I10` 坑 1（受管三件套走行内样式）；调 `zIndexPopupBase` 后只有一半组件跟着动、相对关系翻转是 `I10` 坑 2。
- **引导遮罩压不住通知与下拉** → `I10` 坑 3；Tooltip 与引导面板同为 `+70` 时谁在上头源码未定义，叠序随交互路径变化是 `I10` 坑 4。
- **反复开合后层级号单调爬升、最终撞上宿主站的 9999** → `I10` 坑 5；调用方自己写的 `zIndex` 被抹平是 `I10` 坑 6，`baseZIndex` 传了没生效是 `I10` 坑 7。
- **换了一个 import 路径，号段起点从 1 变成 1000 且不报类型错** → `I10` 坑 8；同一族的「选错同名工具」还有 `I03` 坑 7 与 `I16` 坑 3（两个事件总线是两个对象）。

**输入与受控**

- **拼音上屏后 `@input` 读到的事件缺字段** → `I04` 坑 5（重放的是裸 Event，没有 `InputEvent` 字段）。
- **点清空图标后 `e.target` 不是真实节点** → `I04` 坑 4；`:allow-clear="false"` 反而多出一层壳是 `I04` 坑 1，组件侧同症状是 `C04-01` 坑 1。
- **数字受控值每次按键白跑一轮** → `I04` 坑 2；`setScrollTop` 抛错被吞、Firefox 滚动位只修一半是 `I04` 坑 3。
- **`@resize` 永不触发** → `I04` 坑 6（观察器被 `disabled` 直接销毁）；lazy 有两个方向相反的开关，混用即静默失效是 `I04` 坑 7。
- **受控转非受控时值被清空而不是回退** → `I13` 坑 1，手写那份更彻底；`onChange` 重复触发是 `I13` 坑 2；事件里同步读回值是 `I13` 坑 4；ref 拿到的 DOM 跨周期失效是 `I13` 坑 5。
- **全局 `size`、`direction` 对某个组件零效果** → 根因是「给本该由注入链兜底的 prop 填了运行时默认值」，判形与活例见 `A05` 与 `C11-01` 论点 5（Spin 的 `size`）、`C04-08`（Rate 的 `direction`）。

## 四、改动路线（想动 X 之前先读哪几篇）

1. **想把定位落地从 `left/top` 换成 `transform`** → 先读 `I01` §六 取舍 2 与坑 6，再读 `I02` 坑 3（容器归谁）与 `C07-03` 论点 4（业务侧那份反查）。顺序不能换：`transform-origin` 的内联写入不解掉，缩放动画与定位平移会同台打架；而容器那条理由已被上面的仲裁作废。
2. **想给浮层补滚动跟随** → `I01` §六 取舍 4、`I01` 坑 2、`I14` 坑 8。这三篇合起来给出「高频重排怎么降频、探测结果什么时候求值」两问的现状与赔价。
3. **想把 `PopupInner` 的三段 pending 收敛成一个显式阶段机** → `I02` §六、`I02` 坑 6、`I09` 坑 3。`useVisibleStatus` 已经是七态骨架，缺的是把 timer 纳进去；漏掉 animation 对象改写这一处会引入新的「永不停止的 motion」。
4. **想接 `prefers-reduced-motion`** → `I09` §六 取舍五、`I09` 坑 1、`I14` §六。前两段给现成 helper 与零接线的定性，第三段决定「忘注册动效」这条约束该由哪道静态检查兜。

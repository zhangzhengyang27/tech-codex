# 03-navigation 深导览

> 范围：本类 14 篇（`C03-00` 类横写 + `C03-01` 至 `C03-13` 十三篇单体）之间的**跨篇路由**——近义组件怎么选、我撞到的症状归哪一篇。不负责：浮层的弹出时序与坐标求解（归 `A07` 与 `I02`）、受控与非受控 hook 的内部实现（归 `I13`）、卡片与面板的页签装配（归 `C02-07` 与 `C02-08`）、层级编排与动画本体（归 `I10` 与 `I09`）。另有一条现实约束要先声明：`C03-00` 的 §五、§六、§七 三段尚未成文，本篇引用它时只引 §三 与 §四 的论点，不引它的坑编号。

## 一、这一层在解决什么

导航类对外只回答一句话：**当前是哪一项**。这句话在本类没有任何共享实现。`C03-00` 把四套形态钉到了具体行号上，结论是「选中项的身份取自哪里」先把组件切成两个阵营——取 VNode 的 key 的（Menu 与 Tabs）与取渲染下标的（Steps 与 Breadcrumb 的序号链）（`C03-00 论点 1`）。导览要补的是其余三种身份策略：面板菜单在根层比较的是**整个对象**的深相等（`C03-03 论点 6`），右键菜单与面板菜单的递归子层各有一套「父键加下标」的位置键（`C03-09 论点 3`、`C03-03 取舍三`），锚点则把身份交给 `href` 字符串，由链接子组件在挂载时自报进一张运行时常量表（`C03-10 论点 4`）。所以选型的第一问不是「用哪个组件」，而是**我的数据能不能在每次重建后仍给出同一个标识**：不能的话，上面五种策略里只有深比较那一种能续住展开态，而它续住的代价是项内容自身一变就失联（`C03-03 坑 3`）。

第二件事是**状态持有者落在四个不同层级**，`C03-00 §三` 已把它画成图：Menu 在根组件、Tabs 在根组件的内层实例、Steps 在调用方（组件内部一个 ref 都没有）、Breadcrumb 在数据本身。本类其余各篇把这条轴拉得更长：分页的状态机干脆是 Options API 的 `data()` 加四个 `watch`，适配层一行响应式状态都没有（`C03-07 论点 3`）；下拉的开关状态是「两处存、一条回流」（`C03-08 论点 4`）；引导里同时存在两个互不同步的「是否打开」，一个是归一化过的、一个是裸 prop（`C03-13 论点 3`）。读任何一篇之前先定位「谁写、谁读」，比背 props 名单有用。

第三件事是**选中落到视觉只有两条通道**：类名通道与几何通道，后者额外引入一帧延迟与一张可能过期的量表（`C03-00 论点 5`）。走几何通道的是标签页的墨条与滚动位移（`C03-05 论点 4`）和锚点的墨条（`C03-10 论点 7`）；步骤条是这条轴上的极端反例，它全程不读 DOM 尺寸，连线几何交给 CSS（`C03-06 取舍三`）。凡遇「指示条位置不对」这类症状，先判组件在哪条通道上，再决定是去排查量表过期还是排查类名生成——这两条排查路径互不通用。

第四件事是**触发方式与逃逸能力**，它把本类分成三条互不隶属的线：常驻内联（Menu 的 inline、PanelMenu、MegaMenu）、浮层（Dropdown、ContextMenu、Tour）、几何驱动（Anchor、Affix、BackTop）。三条线的分水岭只有一个问题：面板能不能逃出宿主的裁剪与层叠上下文。大图菜单明确**没有**接浮层三件套，面板是绝对定位的后代，没有翻转、不引 Portal、层级永远压在局部 `zIndex: 1` 上（`C03-02 论点 5`、`C03-02 取舍一`）；右键菜单同样自建浮层，因为它的锚点是光标位置而不是元素矩形，接进 trigger 得先伪造一个零尺寸目标（`C03-09 取舍第一条`）；真正把这条链交给 `vc-trigger` 的只有下拉与引导，而下拉的厂商层只带一张六键定位表，与全库通用那张十二键的键名集合不同（`C03-08 取舍第二条`）。

第五件事：**受控语义在本类是三套而不是一套**，`I13` 的口径在这里会被第三方状态旁路。大图菜单把 hover 排在受控分支之前，鼠标停留在菜单内的任何时刻受控值都被绕过（`C03-02 论点 1`）；下拉里「点菜单项关闭」这条路径直接写本地状态，于是一个事件都不发（`C03-08 论点 4`）；标签页曾经每一层都同时做 `emit` 与 `callEvent`，父层传下来的回调正是这次 `emit` 的目标，实测一次点击把 handler 放大到 16 次——2026-09-29 已改成每层单投（`C03-05 论点 6`、`坑 2`）；固钉的状态干脆不是用户可控的值而是「上一次几何快照」，所以它有意不接受控 hook（`C03-11 取舍第三条`）。判形所需的五种谓词写法由 `C03-00 论点 2` 统一登记；而「选中」与「激活」是两条独立轴、本类只有 Menu 把两条都实现这件事，记在 `C03-00 论点 3`。

最后一件事必须写在选型表之前：**本类的测试面基本不构成反馈**。Menu 的形态切换用例处于 skip、测试里还在写一个源码中已不存在的内部字段（`C03-01 检查点 3`）；锚点名义 8 个用例实跑 2 个（`C03-10 坑 6`）；固钉存活的断言全在证明「某个不存在的属性依然是假」（`C03-11 坑 7`）；步骤条、分页、下拉、引导四家只剩 `mountTest` 量级的用例（`C03-06 §七`、`C03-07 §七`、`C03-08 §七`、`C03-13 §七`）。因此 §四 每条改动路线都把「先补哪一条断言」排在「改哪个文件」之前。

## 二、选型表（近义组件怎么选）

| 站点主导航：多级嵌套 + 折叠续命 + 水平溢出收纳 | `C03-01` Menu | `C03-02` MegaMenu | Menu 把折叠实现成「改写 mode 为 vertical 再加一枚标记」，代价是所有 `mode === 'inline'` 判定在折叠期自动失效（`C03-01 取舍一`）；MegaMenu 与 Menu 只共享命名约定、不共享状态实现，Menu 侧对选中轴的修正不会自动修好它（`C03-02 取舍五`） |

| 只把一块内容钉在视口边上，不参与任何「当前项」语义 | `C03-11` Affix | `C03-10` Anchor | 固钉必须做「目标顶边与占位顶边的带符号距离」算术，可见性观测给不出「现在该写多少 px」，所以它只能事件驱动（`C03-11 取舍第一条`）；横向落位它从不写 `left`，祖先带 transform 时钉住项会跟着跑（`C03-11 坑 4`） |
| 页面级回顶：只要显隐加一次滚动 | `C03-12` BackTop | `C03-10` Anchor | 回顶只比较数值阈值、完全不测 DOM 位置，因此隐藏态不需要占位与还原（`C03-12 取舍一`）；锚点则与 URL 彻底解耦，不写 hash、不读 hash、也不拦默认跳转（`C03-10 论点 5`） |

两条需要单独说明的轴：

**Tabs 与 Card 的「页签复用」不是 CardLike 复用。** 仓内曾经流传「`_shared/CardLike` 被 Card 与 Panel 共同复用」的说法，`C02-07 论点 6` 已经把它否证：Card 与 CardLike 是**平行副本**，`bordered`、`hoverable`、`loading` 三个类名开关与整套 Token 分支被写了两遍且已经不等价（`C02-07 取舍一`）；CardLike 的唯一消费者是 Panel（`C02-08 论点 1`）。所以「卡片带页签」这件事的真实依赖是 Card 直接值引用了重组件 Tabs（`C02-07 取舍三`），要改页签机制本体一律回到 `C03-05`，改 Card 那侧只会动到装配顺序；顺带两条既有后果是卡片内页签的 `size` 被硬写成 large（`C02-07 坑 3`）与 `xy-card-head-tabs` 是产出但零规则的死类名（`C02-07 坑 10`）。

**「vc-overflow 是 Menu 与 Tabs 共用的溢出容器」这句横写篇的表述不成立，以 `C03-05` 为准。** 这里发生了本目录唯一一次需要回源码仲裁的分歧：`C03-00 §一` 的依赖清单把 `vc-overflow` 写成「Menu 与 Tabs 的溢出容器」，`C03-01 §七` 的改动边界进一步要求「动 `vc-overflow` 时必须同时跑 Tabs，因为 TabNavList 也依赖它」；而 `C03-05 §六` 明确主张标签页用自研测量、不走 `vc-overflow`，并在检查点里给出了预期为零的判据。现 grep 两条：`grep -rn -e vc-overflow packages/xiaoye-ui/src/tabs` 输出 **0 行**；`grep -rln -e vc-overflow packages/xiaoye-ui/src` 只命中 `menu/src/Menu.tsx`、`menu/src/SubMenu.tsx`、`menu/src/MenuItem.tsx`、`vc-select/Selector/MultipleSelector.tsx` 四个文件。结论：标签页的溢出确实是独立的一套双向扫描算法（`C03-05 论点 3`），Tabs 目录对 `vc-overflow` 零直接依赖。但「改 vc-overflow 要顺带跑 Tabs」这条操作建议**本身仍然有效**，只是理由要换——耦合走的是「Tabs 的溢出下拉内嵌了一个 Menu 实例」这条二级路径（`C03-00 论点 4`、`C03-01 §一` 的被依赖清单），不是 Tabs 自己引了溢出容器。日后引用这条时请写「经 Menu 间接影响」，别再写「TabNavList 依赖 vc-overflow」。

## 三、坑索引（症状 → 哪一篇的坑 N）

- **只用键盘就整条导航不可到达，或者进得去走不动** → `C03-02` 坑 7（DOM 上写着 menubar 与 menuitem 语义，却没有可聚焦目标）；同族症状分别记在 `C03-03` 坑 5（Tab 进得去、方向键出不来）、`C03-09` 坑 1（键盘处理器声明成 emits 却从不 emit）、`C03-05` 坑 5（tablist 根本不支持方向键切换）、`C03-12` 坑 4（能聚焦不能激活）、`C03-04` 坑 6（无 `href` 的可点条目不可 Tab 到）。注意 Menu 的「方向键看起来没反应」是另一种成因：第二轴只有鼠标与焦点三个写入源（`C03-01` 坑 4）。
- **鼠标一划就改写调用方的 v-model，而受控值在此期间不生效** → `C03-02` 坑 1；同一条优先级链的另一半是 `C03-02` 坑 2（停在面板里点叶子不关闭）与 `C03-02` 坑 6（受控初值非空时没有外部点击关闭通道），三条都源于合并式激活态里 hover 排在最前（`C03-02` 论点 1）。
- **点了菜单项浮层不关，或者关了却一个事件都不发** → 受控看 `C03-08` 坑 4，非受控看 `C03-08` 坑 5，两条共用同一个根因：关闭路径绕过 `onVisibleChange` 直接写本地状态（`C03-08` 论点 4）。
- **不显式传 open 的用法：遮罩是一片没有洞的黑，卡片却定位正常** → `C03-13` 坑 1；根因是组件里存在两个互不同步的「是否打开」（`C03-13` 论点 3）。同类「同一语义两个数据源」的还有 `C03-13` 坑 3（步骤级 `arrow` 只关掉面板里那个节点）。
- **换了全局前缀后某一层彻底失去样式** → `C03-03` 坑 2（子层类名是硬编码字面量）、`C03-09` 坑 2（类名与注入前缀脱钩，菜单塌成裸列表）、`C03-06` 坑 8（图标类名由根前缀拼、样式表把名字写死）；卡片与面板那侧的同一族版本在 `C02-08` 坑 1。
- **传了 props 却完全不生效，而且不报错** → `C03-08` 坑 1（`menu`）、`C03-08` 坑 2（`Dropdown.Button` 的 `size`）、`C03-08` 坑 6（白名单之外的键静默丢弃）、`C03-07` 坑 3（`selectComponentClass` 的声明与用法相反）、`C03-10` 坑 4（`showInkInFixed` 的选择器匹配不到任何元素）、`C03-02` 坑 8（死样式规则与死插槽名）、`C03-01` 坑 8（想经 `ref` 调方法拿到 undefined）。这批的共同判据是「类型面比实现面宽」，逐项核对办法见 `A06`。
- **数据一变，展开态、高亮或序号就飘** → `C03-03` 坑 3（整对象深比较）、`C03-09` 坑 5（下标拼出的 key 随顺序漂移）、`C03-09` 坑 6（分隔符占下标不占视觉）、`C03-06` 坑 5（items 里的空位重排所有后续序号）、`C03-04` 坑 4（末项按对象引用判定，重复引用即误判）、`C03-02` 坑 4（不安全 URL 被降级成空 `href`，链接仍可点；后半句（空 href 会原地自跳、带 target 会开当前页副本）已在真实浏览器实测成立）。
- **受控值与真实视图分叉，组件既不报错也不回发事件** → `C03-05` 坑 3（受控删掉当前活动标签后停在无面板态）、`C03-07` 坑 5（受控 `current` 与缩小的 `total` 分叉）、`C03-01` 坑 1（折叠一次就向 `openChange` 抛空数组，受控方据此回写会钉死展开态）、`C03-01` 坑 2（用 `mode` 直接切形态时展开态不延续，对应测试恰是 skip）。
- **看不见的东西仍然能被点到，或者一份数据在页面上存在两个实例** → `C03-12` 坑 3（隐藏只做透明度，没有指针屏蔽）、`C03-01` 坑 7（body 里多出一棵隐藏菜单，按数量断言与快照全部失真）、`C03-03` 坑 6（折叠项仍被类名查询算进结果）、`C03-03` 论点 7（数据侧可见与 DOM 侧可见是两套口径）、`C03-02` 取舍二（面板全量常驻，代价由项数买单）。

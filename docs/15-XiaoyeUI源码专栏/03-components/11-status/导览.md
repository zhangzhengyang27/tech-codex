# 11-status 深导览

> 一句话：这份导览管「把状态可视化出来」这一族（Spin、Progress、Skeleton、Statistic 与 Countdown、MeterGroup、Timeline、Descriptions、Typography）的近义选型与坑路由，不管任何单个组件的内部机制（机制归 `C11-01` 至 `C11-08`），也不管进出场动画协议（归 I09）与浮层栈（归 C07-00）。

## 一、这一层在解决什么

本类九个组件在用户眼里是同一件事——「一块会动的信息区」，但在源码里它们分属三种互不相容的更新驱动源，分类轴是「谁持有时间」。Skeleton、Spin、Empty 把时间整个外包给浏览器：CSS 关键帧自循环，运行期一次 JS 都不跑（`C11-00 论点 1`）。Progress 把时间交给调用方：每推一次 prop 就触发一次 CSS 补间，本身没有心跳（`C11-00 论点 3`）。Countdown 是全类唯一把时钟握在组件手里的，`setInterval` 加 `$forceUpdate`（`C11-00 论点 4`）。这条轴不是修辞，它直接决定四件工程后果：精度上限、能不能停下来、能不能被主题改写、能不能在服务端复现（`C11-00 论点 5`）。

但**档位不是组件边界**，这是选型时最容易搞错的一层。同一个 Progress 靠一个 `status="active"` 就能从补间档跳进关键帧档，反向也成立（`C11-00 §五`）。同一个 Spin 在包裹态里同时踩两档：指示器走无限关键帧且显隐硬切，被包裹内容的变暗与面纱的浮现反倒都是真补间（`C11-01 论点 4`）。steps 分支更进一步，它把连续量直接量化成离散格，于是「推得多快」对它毫无意义（`C11-00 论点 3`）。所以本类的第一问从来不是「用哪个组件」，而是「这条呈现允许被推多快、需不需要一个能真正停下来的出口」。

第二根轴是**数据密度**，它把后四个组件串成一个阶梯。Statistic 只处理一个标量，并且明确不做数值过渡、不做本地化、不做四舍五入（`C11-04 §一`）。MeterGroup 把一组离散值映射到同一条轨道的分段几何，只做仿射夹取，不做加权也不做归一到 100（`C11-05 §一`）。Timeline 把一组条目摊成垂直轴，全部状态来自 props 与 slots，无内部响应式、无事件回流（`C11-06 §一`）。Descriptions 处理的是键值对，它的技术含量集中在两条算术上——`column` 从响应式对象降成一个数字，`span` 从数字变成每行剩余列宽的消费（`C11-07 §一`）。这四篇都在 §一 用「明确不负责」的格式把边界钉死，选型的判据基本就写在那四段里。

第三根轴是**状态流向**，而本类的整体答案是「单向、无回流」，一旦某个组件出现了回流，坑就跟着出现。Skeleton 连 `emit`、`expose` 与具名插槽都没有（`C11-03 §五`），Spin 没有任何对外事件（`C11-01 §五`）。真正有回流面的是两处：Countdown 的 `change` 与 `finish`，以及 Typography 的编辑与复制。前者的心跳不产生状态、只产生「读取时刻」，于是中途改 `value` 时显示的差值按新目标算、事件里的差值按旧目标算（`C11-00 坑 1`、`C11-04 坑 3`——同一件事的两次独立取证）。后者把同步 `execCommand` 的返回值丢掉，于是「已发起」被当成「已成功」（`C11-08 坑 3`）。

第四条贯穿线是本类最需要被记住的：**降级与可访问性没有统一通路**。`prefers-reduced-motion` 在全库只有一个孤岛式 helper、零调用点（I09 论点 6），落到本类的具体伤害面是三处无限循环——Skeleton 每 1.4 秒一次的横扫与 Spin 的四点循环（`C11-00 论点 5`）。这个结论的判形命令在 `C11-03 论点 7` 被重新取证并修正过一次：早期那条大小写敏感的命令匹配不到驼峰标识符、不具证伪力，现在以该篇的两条复核命令为准。数值播报这一侧同样是空的：Progress 全目录唯一的 aria 命中只有 `role="progressbar"`，读屏拿不到数值（`C11-02 §一`）；MeterGroup 确实写了 `aria-valuenow`，但走的是聚合口径，`min ≠ 0` 时与画面数学不等价（`C11-05 坑 1`）。也就是说「让辅助技术读到真实数字」这件事，本类没有一件组件能直接做到。

最后一条是**契约面比实现面宽**。这族组件的公开 props 与插槽里，有一批在运行期根本不被读取：`progressStatus` 被同名 computed 遮蔽成死 prop（`C11-00 坑 5`），Statistic 的 `formatter` 契约缺第二个实参（`C11-00 坑 6`），Descriptions 的 Item 是一个从不被实例化的 prop 容器（`C11-07 论点 3`），MeterGroup 声明了 `icon` 插槽却从不读它（`C11-05 坑 8`）。再叠上生成物的口径——`global.d.ts` 按目录登记、不认静态子成员，于是运行时能解析的标签在类型面上不存在（`C11-08 坑 6`、A02 论点 8）。选型表能帮你挑对组件，挑对之后能不能真的生效，得看下面这一节。

## 三、坑索引（症状 → 哪一篇的坑 N）

**A 组：传了 props 或插槽，运行期静默无效（API 面存活、实现死亡）**

- `:progress-status` 类型层面能过、运行期零效果，类名仍由 `status` 与 `percent` 推导 → `C11-00` 坑 5；同类还有 `C11-02` 坑 3（`status="active"` 在 circle 与 dashboard 上静默无效，因为规则只挂在 line 分支的 `-bg::before`）、`C11-04` 坑 7（Statistic 默认插槽声明了但渲染函数从不读）、`C11-04` 坑 8（给 Countdown 传 `precision` 与 `group-separator` 全部无效，因为 `formatter` 被强行替换）、`C11-05` 坑 8（`#icon` 插槽是文档里的死档）、`C11-06` 坑 1（条目的 `position` 被 `mode` 短路）、`C11-07` 坑 2（改 `Descriptions.Item` 的 `span` 默认值没有任何效果，因为 Item 从不实例化）、`C11-08` 坑 7（`<xy-link component="...">` 静默无效，而同族另外三件有效）。
- 自定义 `formatter` 里读 `config` 永远是 `undefined` → `C11-00` 坑 6；根因是 `Formatter` 类型声明两个入参而唯一调用点只传一个，Countdown 自己的包装函数反倒按两参解构，说明两处代码按不同时期的契约写。

**B 组：组件自己给 prop 填了默认值，全局配置被静默吃掉**

- `ConfigProvider` 或 Form 把全局尺寸设成 `small`，Spin 的指示器不变小 → `C11-01` 坑 2（机制在 `C11-01` 论点 5）；同族的另一件是 `C11-07` 坑 7（Descriptions 的 `size` 自带 `'default'` 硬默认值，且 `setup` 根本没解构 `size`，双重断路），以及 `C11-06` 的对照正面例（Timeline 不取 `disabled` 是**正确取舍**而非断链，判据是它确实没有可停用的交互，见 `C11-06` §一）。反例对照与机制族谱见 C04-08 论点 1 与 A05 论点 3。

**C 组：子件脱离父件就裸奔（样式没注册、前缀写死、类型面不存在）**

- 单独用 `Skeleton.Title` 得到零高度空标签，而且模板里合法的标签不是你以为的那个 → `C11-03` 坑 5；同族是 `C11-05` 坑 7（`xy-meter-group-label` 前缀写死、样式不注册、百分比文本消失）、`C11-06` 坑 7（脱离容器的 `xy-timeline-item` 无圆点无连接线）、`C11-08` 坑 6（四个子组件标签运行时能解析、类型面不存在）。这四条合起来是生成物口径问题，不是单件缺陷，见 A02 论点 8 与 A02 论点 11。
- 给某个 Item 写 `prefixCls` 会让**只有这一个条目**脱离样式表 → `C11-07` 坑 4；这是「喂给样式 hook 的 prefixCls 不是本组件自己的」那条检查的反向形态——父件的 hook 输入是对的，错在下传旁路。
- 骨架分支与非骨架分支不是同一棵树的两态：`class` 与 `style` 的宿主会随 `loading` 翻转换人 → `C11-03` 论点 6。

**D 组：主题覆盖通道名存实亡**

- `theme.components.Progress` 的 token 覆盖被静默丢弃 → `C11-02` 坑 5；同族还有 `C11-06` 坑 6（空 `ComponentToken` 加上 `styleFn` 内部二次 `mergeToken`）、`C11-04` 论点 7（statistic 在 Token 体系里只是类型占位）、`C11-05` 论点 6（三个 ComponentToken 声明的键从未进入主题登记表）。机制层结论统一归 A03 论点 4，不要在个案里重述。
- 主题调 `motionDuration*` 不会改变本类三条无限循环的速度 → `C11-00` 坑 4。
- 切主题时 Progress 的 success 段与渐变默认色不跟随 Token → `C11-02` 坑 6，这是全库唯一绕过 Token 层直取色板的组件。

**E 组：数值或时间语义被静默改写，画面看起来「对」但值不对**

- `precision` 让它四舍五入，它其实是截断 → `C11-04` 坑 1；`value` 给字符串就以为能分组 → `C11-04` 坑 2（这条是**故意的**，别顺手改成抛错）。
- 某项很小、为负、为 `NaN`，或 `max === min` 时，轨道上少一段而图例还在，控制台零告警 → `C11-05` 坑 2；给 `min` 传非零值后无障碍播报与画面从此分家 → `C11-05` 坑 1。
- `success.percent` 会改写整体 `status`、与 `percent` 抢方向盘 → `C11-02` 坑 2；`type="line"` 加了 `steps` 之后 `success` 整段失效 → `C11-02` 坑 1。
- `paragraph.rows` 传字符串数字会静默变一行、传非整数直接抛 `RangeError` → `C11-03` 坑 2；`loading="false"` 不带冒号会让骨架永远不消失 → `C11-03` 坑 1。

**F 组：事件与真值不是同一个来源**

- 倒计时进行中改 `value`，屏幕上的文本按新目标走而 `change` 报的是旧目标 → `C11-00` 坑 1 与 `C11-04` 坑 3（两篇独立取证到同一处闭包快照，可互为佐证）；用它驱动进度条或埋点会直接写脏数据。
- 挂载时 `value` 已是过去，`onFinish` 一次都不触发 → `C11-04` 坑 4；归零后 33 毫秒内卸载会补发一次 `finish` → `C11-04` 坑 5，回调必须写成幂等。
- 复制失败也显示「复制成功」 → `C11-08` 坑 3；连点两次复制，成功态会提前 3 秒复位 → `C11-08` 坑 4。

**G 组：SSR 与水合**

- 服务端渲染 `Statistic.Countdown` 时首帧文本与属性两处都必然 mismatch，这是架构性的而非能用 `nextTick` 绕开 → `C11-00` 坑 7；根因是渲染期直接读时钟，加一个服务端时刻落到 `data-for-update` 属性上。该属性在现有 `$forceUpdate` 链里究竟必需还是冗余，深读篇未能取证（见 `C11-04` §六 的标注），本篇按「未证实」搬运，不要当结论用。
- SSR 下对象形态的 `column` 恒退化为 3 列（含不写 `column` 的情形） → `C11-07` 坑 1。
- SSR 与客户端对同一份 `ellipsis` 给出不同类名，而本该拦住它的 `clientRendered` 字段是一个零读取点的死门闩 → `C11-08` 坑 5；能力探测在模块加载时求值、无 DOM 一律给假，机制归 I14 论点 4。
- 第二档（prop 补间档）唯一带 SSR 副作用的一支是渐变 id 的模块级自增 → `C11-00` 论点 5 与 `C11-02` 论点 7。

**H 组：可访问性与交互降级**

- 用 Spin 盖住表单来防重复提交，键盘路径仍然通（Tab 能进被包裹按钮并回车激活） → `C11-01` 坑 1；遮挡只靠 `pointer-events`，而 `pointer-events` 不参与焦点序列。焦点圈定这一层本库只有 Modal 一家做了，见 C07-00 论点 4。
- `disabled` 在 Typography 只产出一个类名，编辑与复制图标照样能点 → `C11-08` 坑 1；它命中共则的判据 ① 而非 ②（对照 `C06-05` 论点 5 是 ① 与 ② 都中、`C06-06` 论点 2 是更重的双层形态）。顺带一条：即使补上转发，TransButton 的键盘激活路径仍不看 `disabled`，要真禁用得在 Base 侧早退。
- 误以为给 Spin 加淡入淡出会生效 → `C11-00` 坑 3，**但作用域要按 `C11-01` 论点 4 收紧**：硬切只限指示器 `.xy-spin` 那一侧，内容容器与面纱都是带补间的，两处不能混谈。
- 以为换语言就能换分隔符 → `C11-04` 坑 6（默认值硬编码，组件不读 locale）；误以为 `-rtl` 与 `-skeleton` 两条选择器有效 → `C11-04` 坑 11；Skeleton 发出来的 `xy-skeleton-rtl` 类名不承担任何职责，方向实际由逻辑属性翻转 → `C11-03` 论点 7。
- `format` 返回长文本会溢出，因为尾部文字靠一个硬编码的 2em 沟槽排版 → `C11-02` 坑 8 与 `C11-02` 论点 8。

**I 组：几何与布局外包给了外部，改样式前要先确认祖先链**

- 被包裹内容超过 400px 高时旋转点偏到内容上部 → `C11-01` 坑 3；给 `<Spin style="…">` 写的内联样式只落在指示器而不是外壳或容器 → `C11-01` 坑 4；删掉 `key="loading"` 那层匿名 `div`，覆盖层会丢绝对定位 → `C11-01` 坑 6（选择器点名「子之孙」）。
- 竖排的段高完全由外部容器决定 → `C11-05` 坑 4；用了 `#meter` 插槽就得自己负责宽高，组件不再写任何几何 → `C11-05` 坑 3。该篇已注明竖排的最终解析值未取运行期证据，本篇按「依赖调用方给祖先高度」这一结构性结论搬运，不下运行时断言。
- `orientation` 或 `labelPosition` 拼错不报错，且各有一种静默变形态的落点（后者会让图例整体消失） → `C11-05` 坑 5；`color` 传一个包含预设色名子串的值会两条路都断 → `C11-06` 坑 2。
- 改头像或标题尺寸只改一处 CSS，会出现「独立骨架变了、组合骨架没变」 → `C11-03` 坑 3；想启用 `Skeleton.Image` 的微光却发现三个 prop 被整体删掉 → `C11-03` 坑 4 与 `C11-03` 论点 4。

**J 组：正确性挂在书写顺序上**

- 重排 pending 与 reverse 的两条 CSS 补丁就会翻转一种组合 → `C11-06` 坑 5，这是本类最脆的一处：语义正确性挂在对象字面量的书写顺序上，没有任何机制保护。
- 照仓库模板给 `TimelineItem` 补 `inheritAttrs: false`，会静默丢掉全部位置类与末项类 → `C11-06` 坑 4，因为容器是靠 `cloneVNode` 往子 vnode 写 `class`、再靠默认 attrs 透传落地的。

**K 组：测试面给的假安全感（改本类之前必读）**

- 以「skeleton 有测试」为前置去改宽度或类名映射，`vitest` 全绿而回归不受保护 → `C11-03` 坑 7（名义 5 个用例、文件内断言数为 0）。
- Spin 的 `index.test.js` 名义 3 个 `it` 只有 1 个有活断言，且唯一覆盖 attrs 落点与叠层隔离的两行被整段注释 → `C11-01` 论点 6 与 `C11-01` 坑 4。
- Timeline 的测试文件全文 7 行、`expect(` 计数为 0，且套件名写成 `Tag` 与 `tag` 的同名套件并列 → `C11-06` §七。
- Descriptions 的 13 个用例里 6 个没有任何 `expect`，而响应式档位由测试 polyfill 决定（只有 `xs` 可能为真）→ `C11-07` §七。
- Typography 一处 `vi.mock` 让复制恒返回真，于是「复制失败也显示成功」这条坑不可能被现有测试发现；`Text.tsx` 连 import 都没有 → `C11-08` 坑 8。
- Progress 的整段弧长计算、`useTransitionDuration` 的归零判据、`gapPosition` 四个方向分支都没有测试，`vc-progress/` 目录内没有任何测试文件 → `C11-00` §七 与 `C11-02` §七。

## 四、改动路线（想动 X 之前先读哪几篇）

1. **想把现在用 Spin 盖住的页面改成 Skeleton** → 先读 `C11-03` 坑 6、`C11-03` 论点 6、`C11-01` 论点 1。核心不是视觉而是两件事：子内容在 `loading` 为真时整块不渲染，以及两个分支的 DOM 宿主不同构。
2. **想接高频进度（上传、流式生成）** → `C11-02` 论点 5、`C11-00` 论点 3、`C11-00` 坑 5。先决定走 circle 还是 line，因为高频归零出口只有 circle 有；再确认你没有在用一个被同名 computed 遮蔽的死 prop 表达状态。
3. **想统一本类的动画时长，或加一条 reduced-motion 降级** → `C11-00` 论点 1、`C11-00` §六、`C11-03` 论点 7、I09 论点 6。改动点只在样式生成函数里，判形命令以 `C11-03` 论点 7 那两条为准。
4. **想动倒计时的心跳、事件或精度** → `C11-04` 论点 5、`C11-00` 论点 4、`C11-04` 坑 3 与 坑 4 与 坑 5。动手前先补一个 fake timers 用例：`C11-00` §七 明确记录整条心跳链路当前零测试保护。
5. **想让某个组件跟随全局 `size` 或 `direction`** → `C11-01` 论点 5、`C11-07` 论点 6、C04-08 论点 1、A05 论点 3。先查这个 prop 有没有被 `initDefaultProps` 填默认值，这是本类最常见的静默断链成因。
6. **要把 Group 或子件拆成可独立使用的标签** → `C11-05` 坑 7、`C11-06` 坑 7、`C11-03` 坑 5、`C11-08` 坑 6，再加 A02 论点 8。四件事必须一起补齐：样式注册、前缀走 `getPrefixCls`、独立样式根、生成物类型面（且不能手改生成物）。
7. **想给主题留可覆盖的组件量** → `C11-02` 坑 5、`C11-06` 论点 7、`C11-05` 论点 6、A03 论点 4。注意 `styleFn` 内部二次 `mergeToken` 会把覆盖整个吃掉，只补 `ComponentToken` 接口不够。
8. **要在 Descriptions 上做任何响应式或列数改动** → `C11-07` 论点 1、`C11-07` 坑 3、`C11-07` 坑 8、C02-01 论点 2。三件事连着一根线：订阅只在 `onBeforeMount` 建立、守卫只挡写入不重新注册、退订打在错误对象上导致监听器泄漏（后两条与栅格同源）。
9. **想动 Typography 的截断或复制** → `C11-08` 论点 4、`C11-08` 坑 2、`C11-08` 坑 3、I14 论点 4。CSS 与 JS 两条路径由六个开关合谋分流，而分流点依赖一个模块级单例 DOM 与两个加载期求值的能力常量。
10. **改本类任何一件之前先确认有没有回归网** → `C11-03` 坑 7、`C11-01` 论点 6、`C11-08` 坑 8、`C11-07` §七。本类的测试普遍是「文件存在但断言为空」的形态，`pnpm test:unit` 变绿不能作为改动的许可证，尤其是样式层与几何层。
